## 0. 先说清楚审稿人看到的是什么

审稿人拿到的 `gstar_v6.pdf` 是 v6 **还在补跑实验时的中间编译版**。当时：

- 整会议在线、因果性、归属等新结果的小节还没写进正文，所以 `sec:res-online`、`app:causal`、`app:attr` 显示为 `§??` / `Appendix ??`；
- 旧版 Limitations、Table 9（单侧 bootstrap）还没换；
- 但 v6 分支已经完成并提交（`paper/gstar_si_v6`）：因果性数值测试（前缀版分离器与流式输出一致，仅 4 帧 fp16 在 0.5 阈值上的舍入差异）、事后重标注、音色评测修正（v5 的中译英把输出与中文源文本匹配，修正后混淆率约 28–30%）、两侧会议级统计脚本（`bootstrap_v6`：会议簇 bootstrap、按会议置换、leave-one-meeting-out）、归属指标脚本。

所以意见分成三类：
- **A 类：v6 收尾时必须闭合**（结果已有或即将出来，只是没进 PDF；以及自相矛盾的文字）。这些属于 v6 分支原有的交付要求，现在就交给正在运行的 v6 分支。
- **B 类：v7 需要新增的实验**（v6 预注册修正里为算力削掉的项目、审稿人新提的分析）。
- **C 类：v7 的写作与定位。**

## 2. B 类：v7 新增实验

记号：**[算]** 用已有输出重算；**[解]** 新解码；**[训]** 新训练。

### 2.1 恢复 v6 为算力削掉的关键对照（M04、M11、Q5、Q6）

1. [解] **固定滞后**（MIST-Simul，L ∈ {1, 2} s）：先在 2,375 个参考窗口上跑（比整会议便宜），再在整会议子集上跑。
2. [解] **前缀模型上的 LA2** 扩到 Zh→En 和 AliMeeting（v6 只做了 En→Zh 子集）。
3. [解] **流式级联**：在线 turn 切分 + 每个 turn 用 LA2 同传，同一窗口规则、同一 Talker，整会议子集上跑。
4. [训] **匹配数据的 deadline 对 stable-prefix**：同样 8k 窗口、同样读入间隔 {0.5, 1, 1, 2}、同步数、同初始化，只换目标（约 5 小时 × 4 卡）。附录 J 和 Table 15 明确区分「全量 deadline」「8k deadline」「8k stable-prefix」三行。
5. 所有同传对照画在同一张质量–文本延迟–听众延迟–计算量图上，结论按「相对最强非 oracle 基线」重写。

### 2.2 整会议在线评测扩到全部会议（M02、M14、M17、Q7、Q9）

1. [解] MIST-Simul、离线 MIST + LA2、前缀模型 LA2、流式级联在 AMI 全部 16 场和 AliMeeting 全部 20 场上运行（v6 是 8+10 场子集）。会议之间相互独立，每张卡同时跑两场会议，受显存上限约束。
2. [算] 主表列：原始语音覆盖率、tcpBLEU、cpBLEU_sess、DER、人数准确率、漏译/重复、文本提交延迟、语音起播/播完延迟 p50/p90/p95、峰值积压、会议结束后额外播放时长、RTF。
3. [算] 积压分析：译后语音到达率（译语秒数/源墙钟秒数）、队列长度随时间曲线；对比播放端变体（积压时提速 1.1–1.15×、块内静音压缩）。
4. [解] **单卡 batch 1 实时测量**（2 场会议）：每次读入的耗时、p95、首 token 延迟、峰值显存；编码器漂移测试——同一前缀在 t 与 t+Δ 编码，比较重叠部分的 audio embedding 是否改变（回答「是否能复用 KV」）；如实写明当前每次读入从头 prefill。
5. [算] 一场会议的完整时间轨迹（每次读入的 t、音频采样数、已定稿分离器帧、slot、token 数、提交文本、wait/eos、音色提示可用时刻、TTS 开始/结束、队列长度），作为附录图和补充材料。
6. [算] 在线窗口按「1 s 静音关闭」与「20 s 强制切开」分组报告错误；窗口边界前后 2 s 的漏译/重复；关闭检测的真实延迟（不是源中静音开始时刻）；0.2 s/0.3 s 填充造成的跨窗重复与去重规则。
7. [算] 长期身份：按 5 分钟分段画 slot 漂移、重返发言者识别正确率、人数和重叠负载。

### 2.3 统计与 seed（M05、M06、Q16、Q17）

1. [训] En→Zh MIST-Simul 再补 1 个 seed，凑满 3 个；报告逐 seed 分数、均值 ± 标准差、延迟、失败率。
2. [算] 16 场会议时按会议符号翻转的置换检验可以精确枚举（2^16 种）；子集 8 场时最小两侧 p 约 0.008，表注写明。
3. [算] 每个主比较给每场会议差值点图和 leave-one-meeting-out 的最小/最大差值及最敏感的会议。

### 2.4 说话人人数、零时长时间戳、重叠（M12、M15、T09、T20、Q10、Q12）

1. [算] 主文同时列单/多说话人窗口的人数准确率；对 En→Zh 多说话人窗口 MIST 72.8% 低于级联 78.7% 做分解：少数/多数/错人，按语句时长与重叠时长分层；把「finds the right number of speakers more often」改为分条件的精确表述。Table 12 加入同数据级联一行。
2. [算] 零时长段：后处理约束 β ≥ α+1（越界时向前借一格），重算 DER、时间 F1、起止误差、tcpBLEU；单列 20 s 边界截断造成的零长度比例；统计零时长段中短回应的占比。
3. [解，P2] 约束解码版本（结束时间 token 至少比开始大 1），与后处理对比。
4. [算] 按真实重叠比例与时长报告检测/归属/翻译，区分同时说话人数。

### 2.5 覆盖率与过滤偏差（M08、Q11）

1. [算] 漏斗表：原始会议时长 → 参考窗口 → 保留语音秒数 → 保留重叠秒数 → 保留 ≤1 s 回应，三个测试集各一行；Table 4 加覆盖率列。
2. [算] 用整会议在线结果回答「丢弃窗口对 MIST 与级联的相对排名有无影响」：在保留/被过滤区域分别计分（被过滤区域只报说话人检测与归属）。

### 2.6 真实中文（M09、T19）

1. [算] AliMeeting 每场差值图、单/多/重叠/短 turn/会议时长分组。
2. [算] AliMeeting 英文参考是机器翻译：用无参考质量估计（CometKiwi 类，缺模型则下载公开权重）给全部参考打分，报告低分比例，并检查结论在去掉低分参考后是否改变。人工双语审查按此前决定不做，写进局限。

### 2.7 敏感性与消融（T05–T08、M10，P2）

- [解] 分离器阈值 0.3/0.5/0.7 对级联切分和在线开/关窗的影响；
- [训] K=10、统一 loss 权重、无噪声增强（En→Zh 离线各一次）——GPU 时间不够就写进局限；
- 事后重标注与交织的差异在多说话人窗口上的显著性检验（Q4），据此定交织的贡献表述。

## 3. C 类：v7 写作与定位

1. **主张二选一（Q18）**：等 2.2 的全量整会议结果出来再定。若整会议在线结果与窗口结果差距可控且优于最强非 oracle 基线，主张为「整会议在线的说话人归属译文与语音」；否则收窄为「参考窗口上的说话人归属同传，附整会议在线评估与其差距」。
2. 交织的贡献：依据事后重标注结果，贡献表述为「联合输出说话人、时间、译文与 wait 的解码格式 + deadline 提交训练 + 语音输出服务」，交织本身归功 G-STAR；相关工作加一张「功能—已有工作—本文新增证据」表（T25）。
3. 新增 0–5 s 单窗时间线图：音频到达 → 分离器帧定稿 → 编码前缀 → Thinker 输出 → 音色提示可用 → 播放开始；注明 TTS 与下一次读入是否并发。
4. 段序问题（T04）：按源起点排序导致的队头阻塞，用 2.2 的数据量化，给出短回应被阻塞的实例。
5. 两个 AMI 方向共用 16 场会议，讨论里写明不是独立复现。
6. Figure 2 放大 0–4 s，分开画文本 LAAL 与听众播完延迟，加会议级 CI；Table 6 注明 batch 改动不影响输出（v6 已有 T13 的批次不变性检验时引用）。
7. 局限首段：参考窗口与过滤、整会议子集/全量范围、单声道积压、真实中文无优势、MT 参考、无人工听评、seed 数。
