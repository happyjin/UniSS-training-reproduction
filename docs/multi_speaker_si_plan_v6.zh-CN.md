# 多说话人语音翻译系统方案 v6(定稿):Nemotron-3 分离 + 非贝叶斯同传 baseline,先离线后同传

- 日期:2026-10-26(v1–v5 保留不动)
- 本版采纳的决定:
  1. 离线和同传都用**之前的非贝叶斯 baseline**;
  2. 输出用分支同款特殊 token;
  3. 不做 C0 级联,直接测试端到端系统。

---

## 0. 回答

**先离线还是直接同传:建议先离线。**
在"非贝叶斯 baseline"的前提下,同传系统就是同一个离线模型加上 LocalAgreement-2(LA2)提交策略。这和我们论文里 LA2 基线的做法一样,不需要单独训练同传。所以:
- 训一次离线模型,离线和同传两个系统同时得到;
- 离线结果就是同传的质量上限。

直接做同传,需要另外构造提交时间表并单独训练,也分不清问题出在说话人、翻译还是流式。

**"非贝叶斯"包括两层,都满足:**
1. 不用 SCOPE / 分支里的贝叶斯后处理:束重排、HMM 归属、序贯注册;
2. 同传支用我们之前的非贝叶斯 baseline:
   - 原版 Qwen3-Omni Thinker,不用合并了 ABC 的 m2;
   - 提交策略用 LA2,不用 ABC、TTB、SDR;
   - 音色用普通的说话人参考音,不用贝叶斯音色记忆。

**C0 可以不做,直接测试端到端系统。** 对照组只保留"不接说话人的同传 baseline"(原版 Thinker + LA2)。

## 1. 系统

```
会议单通道音频(IHM-mix 16 kHz)
 ├─ 说话人分离支:Nemotron-3-Diarization(冻结,8 槽位,整场槽位一致)
 │     离线:离线配置;同传:流式配置(1.04 s 前瞻)
 │     → 后验 [T, 8](10 ms,池化到 80 ms)+ RTTM(谁在什么时候说话)
 │     → 后验插值到音频 token 网格 → SD 投影器(Conv1d k5 s5 + MLP)→ 说话人 token s_j
 ├─ 同传支:原版 Qwen3-Omni-30B-A3B Thinker 的 AuT 编码器(冻结)→ 音频 token a_i(约 13/s)
 └─ 融合:<|audio_start|> a0..a4 s0 a5..a9 s1 … <|audio_end|>(K:1 交错,同分支 G-STAR)
        → 同一个 Thinker LLM(原版 + 注意力 LoRA r32)
        → 输出:<|spk k|><|t起|>译文<|t止|> …(按源开始时间排序)
        → UniSS Talker T1c(冻结):每个槽位一条流,音色 = 该槽位独自说话的源音频片段
        → 译音 + 会议记录(XML / JSON,分支同款)
```

| 模块 | 设置 | 训练 |
|---|---|---|
| Nemotron-3-Diarization | `pretrained_models/Nemotron-3-Diarization`(已下载);环境 `venvs/nemo_diar`(已建好并验证:NeMo 3.1.0,torch 2.11.0) | 冻结 |
| SD 投影器 | 照搬分支 `SDProjector`,约 6.3M | 训练 |
| Thinker | 原版 `pretrained_models/Qwen3-Omni-30B-A3B-Instruct`;AuT 冻结;LLM 注意力 LoRA r32(全部 48 层) | LoRA |
| 新 token | 251 个时间 token(80 ms,≤20 s)+ 8 个说话人 token,放在词表空闲行(空 388 行),不扩词表 | 只训练这 259 行 |
| Talker | UniSS T1c@1500;音色参考 = 该槽位"独自说话"(p_k > 0.5 且其他槽位 < 0.5)的源音频,取最多 6 s,普通 BiCodec 全局 token | 冻结 |

**输出格式的一处调整**:分支格式是 `<|t起|>文字<|t止|><|spk k|>`,说话人在段尾。同传必须在开口前就知道是谁说的(Talker 要选音色),所以改为说话人在段首:`<|spk k|><|t起|>译文<|t止|>`。导出会议记录时转回分支格式,内容完全一样。

## 2. 训练(只训练一次)

| 项 | 设置 |
|---|---|
| 数据 | 已审查的 IHM-mix 窗口:<br>① 参考句组;<br>② 按 Nemotron 活动切的窗口(1 s 无活动关窗,≤20 s)。<br>两种混合。窗口里有任何一句没通过审查,就整窗剔除。目标是窗口内全部句子的 `<\|spk\|><\|t\|>译文<\|t\|>`,纯犹豫词不出片段 |
| 后验 | Nemotron 离线配置和流式配置的后验各占 50%,让同一个模型在离线和同传两种输入下都在分布内;以 0.2 的概率加噪或平移 ±1 帧 |
| 说话人编号 | 全局槽位(整场一致):参考说话人按帧重叠用 Hungarian 匹配到 Nemotron 槽位(同分支 `map_speakers_to_slots`) |
| 单人保持 | 混入 15% 单人整句翻译行(原指令) |
| 损失 | 交叉熵;时间 token ×1.5,说话人 token ×2(分支的分层权重) |
| 配置 | Megatron 8 卡,GBS 64,MBS 8,全量 shuffle;LoRA 1e-4,投影器和新 token 5e-4;约 2 遍数据,约 1–1.5 h;`setsid nohup` 运行 |
| 产物 | LoRA 合进原版 Thinker;新 token 行写入空闲行;分词器加 token;投影器另存 |

## 3. 推理

### 离线

```
整场音频 → Nemotron(离线配置)→ 后验 + RTTM → 按活动切窗(≤20 s)
每个窗口:交错(音频, 后验)→ 一次生成全部片段 → 换算到整场时间 → XML / JSON
Talker:每段译音按源开始时间排布(超长就加速)→ 配音式译音
```

### 同传(同一模型 + LA2,不另外训练)

```
音频流 → Nemotron(流式 1.04 s)→ 因果切窗(1 s 无活动关窗,≤20 s)
窗口内每 Δ 秒读一次:交错(截至此刻的音频, 截至此刻的后验)+ 已提交前缀 → 贪心生成到结束
  LA2:本次续写和上次续写的最长公共前缀(以 token 计,含说话人和时间 token)→ 提交
  窗口结束时提交全部剩余
提交的译文按 <|spk k|> 进对应槽位的 Talker 流 → 单通道:max(提交时刻, 上一段结束) 播放,换人时停 0.2 s
```

- Δ 取 1 / 2 / 3 s,得到质量和延迟的曲线,和论文 m1–m6 的做法一致。
- **推理引擎**:交错输入要自定义嵌入,先用 HF 批量生成(同一轮的所有窗口拼一个 batch)。之后可以写 vLLM 插件提速。

## 4. 实验

| 编号 | 系统 | 目的 |
|---|---|---|
| **O-G1** | 离线:两支 + 交错 + 新格式 | 离线主系统 |
| O-nosd | O-G1,说话人 token 置零 | 说话人分离支的贡献 |
| O-oracle | O-G1 用参考 0/1 后验 | 分离误差上限 |
| **S-G1** | 同传:O-G1 + LA2,Δ = 1 / 2 / 3 s | 同传主系统(质量和延迟曲线) |
| S-oracle | S-G1 用参考后验 | 同传上限 |
| B-LA2 | 原版 Thinker + LA2,不接说话人(之前的非贝叶斯同传 baseline),同样窗口、同样 Δ | 不做多说话人的参照 |
| S-single | S-G1 在 RealSI 英→中、ACL60 英→中 | 单人能力是否退化 |

之后可选:同传专门训练(读取行训练 wait);编码器 LoRA;SCOPE 的 BSSC 和条件链。

### 判据

- O-G1 对 O-nosd:cpBLEU、DER、说话人数正确率显著更好。
- S-G1 对 O-G1:同一 Δ 下 cpBLEU 的损失量化清楚;Δ = 1 s 时 StreamLAAL ≤ 3 s(含 1.04 s 前瞻)。
- S-G1 对 B-LA2:cpBLEU 显著更高,不分说话人的 BLEU 不降超过 1。
- S-single 与 B-LA2 单人结果的差在 ±0.5 BLEU 以内。
