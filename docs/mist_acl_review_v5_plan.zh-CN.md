## 1. 总原则

1. **测试集只做测试**：AMI test、AliMeeting 不训练、不调参；新变体的超参数（在线端点阈值、固定滞后 L、相对时间戳 deadline 等）只在 AMI dev 上定。按既有规则，AliMeeting 不能用于任何适配训练（审稿人建议的「少量真实中文适配」只能换别的真实中文会议数据，见 §4 需要你决定）。
2. **质量门槛**：任何替换主系统的新变体，在 dev 上 cpBLEU_sess（语音为 ASR-cpBLEU）不得低于现主系统；未过门槛只作消融报告。
3. **确认性分析先登记**：多 seed、在线整会议评测、簇 bootstrap 的端点和统计口径，先写 `paper/gstar_si_v6/docs/prereg_v6.zh-CN.md` 并 commit，再运行。
4. 不删除、不覆盖任何已有文件和实验输出；新脚本只新增文件；每个检查过的改动单独 commit，主仓库推送 `private HEAD:main`。
5. GPU：与正在运行的 QABC v10 任务共用 8 卡，按 `logs/gpu_coord` 协调（zezhong 所在卡上限 126 GB，其他卡 136 GB），见 §3。

记号：**[写]** 只改文字；**[算]** 用已有输出重算；**[解]** 需要新解码（不训练）；**[训]** 需要新训练。

## 2. 逐条方案

### M01（Critical）只在参考切分的窗口上评测，没有整场连续在线测试

- **判断：成立，是录用的关键。**
- **改进：**
  1. [解] 新增在线整会议驱动 `gstar_meeting_online.py`（新文件）：
     - 说话人分离器按 NeMo 流式接口逐 chunk 真实增量运行（不再用整场一次跑出的结果），同时满足 M02 的因果性；
     - 开窗：因果后验中任一 slot 首次活跃；关窗（在线端点）：所有 slot 低于 0.5 持续 ≥E 秒，或窗口长到 20 s 时在最近 3 s 内活动最低的帧处切开；E 在 AMI dev 上选；
     - 端点由在线检测得到，所以端点处的最终提交是合法的；窗口内时间戳换算成会议绝对时间；
     - 说话人 slot 由分离器在整场会议内保持；Talker 播放队列全场不清空。
  2. [解] 在 AMI test 全部 16 场（En→Zh 用 IHM mix，Zh→En 用重配音中文整场音频）和 AliMeeting 全部 20 场上运行 MIST-Simul、MIST-Simul-M、LA2 基线、流式级联（见 M04）。
  3. [算] 整会议评分（新增 `gstar_meeting_score.py`）：
     - 会议级 cpBLEU：每个说话人整场译文拼接，slot 与参考说话人整场匹配后计算；
     - 时间约束版 tcpBLEU（参照 MeetEval 的 tcpWER）：输出段按时间（加 collar）分配给参考语句再计 BLEU；
     - 漏译率、重复率、说话人一致性；
     - 窗口评测中被过滤（无可信参考）的语句区域作为 don't-care，并报告其占比。
  4. [算] 在现有窗口评测上补报：最后一次读入被强制提交的 chunk 比例；因 >20 s 规则被丢弃的时长及占比。
  5. [写] 若整会议结果明显差于窗口结果，摘要和标题收窄为「预切分会议窗口」，部署闭环写进未来工作；若接近，就把整会议结果作为主结果之一。

### M02（Critical）声学流与说话人流的因果性没有被实验证明

- **改进：**
  1. [解] **数值等价测试**：每个测试会议随机抽 50 个读入点（共约 800 个），把音频截断到 t 后从头运行流式分离器，与「整场一次运行 + 遮蔽」在 ≤ t−1.04 s 帧上比较：最大绝对差、slot 排列是否一致；再用前缀版后验对 200 个窗口重新解码，比较输出是否逐 token 相同、cpBLEU 和 LAAL 是否不变。
  2. [写] 编码器：引用代码说明每次读入只送 x≤t；附 Algorithm 1（每次读入的输入、`wait`/`eos`/无活跃 slot/空语音分支）和「读入 r 时可用信息」时间线图，标出训练期才可用的参考说话人映射、词时间。
  3. [写] 明确 Eq.(9) 的匈牙利匹配只用于构造训练标签和评分时的置换匹配，测试推理不使用。
  4. 若测试发现不等价：所有流式结果改用前缀版后验重跑（M01 的在线驱动本身就是前缀版）。

### M03（Critical）只报文本 LAAL，没有听众实际听到的语音延迟

- **改进：**
  1. [解/算] 在整会议在线运行（M01）和现有窗口评测中都记录三个时间：文本提交时刻、语音首包可用时刻（Talker 实际计算后）、实际播放时刻（全场连续队列）。
  2. [算] 报告每个源片段/目标词的语音起播延迟、播完延迟的 p50/p90/p95，队列积压随会议时间变化的曲线，Thinker 和 Talker 的实时率 RTF、tokens/s、Talker 首包延迟和合成时长；所有系统使用同一 Talker、同一硬件（H200 单卡）、同一播放规则。
  3. [解，可选变体] 积压缓解：沿用单说话人论文的播放端措施（积压时提速到 1.1–1.15×、块内静音压缩），只作为播放端变体，需过 §1 门槛。
  4. [写] 主结果表把文本 LAAL 和听众侧延迟并列；Table 6/图 2 注明 Δ 是读入周期，不是实际延迟。

### M04（High）+10.99 的同传增益与基线强弱混在一起

- **改进（最小公平矩阵，En→Zh 全做，Zh→En 做 ①②④）：**
  1. [解] ① **在前缀训练过的 MIST-Simul（及 MIST-Simul-M）上跑 LA2**：直接回答 Q5「+10.99 有多少只是因为避免了离线模型在前缀上的失配」。
  2. [解] ② **固定滞后基线**：前缀训练模型每次读入生成到底，只提交模型自己预测的结束时间戳 ≤ t−L 的段，L ∈ {1, 2, 3} s（dev 上选取范围，测试报全曲线）。
  3. [训] ③ **同数据、同读入采样、同步数的稳定前缀目标模型**：与 deadline 模型使用相同窗口、相同 read 采样、相同步数，只换目标，隔离「目标本身」的作用。
  4. [解] ④ **流式级联**：在线 turn 切分 + 每个 turn 用 LA2 同传 + 同一音色提示规则和 Talker。
  5. [算] 画质量–延迟–计算量的 Pareto 曲线（含漏译、重复率），在匹配延迟处比较。

### M05（High）级联基线的信息和训练单位不公平

- **改进：**
  1. [训] ① 在级联自己的 turn 切分（训练集按同样规则切出的单人片段）上重新训练翻译器，解决训练/测试分布不一致；两个方向各一次。
  2. [解] ② 参考 turn 边界的级联（同一翻译器），把「切分错误」和「翻译建模错误」分开。
  3. [解] ③ turn 前后各加 2 s 上下文，并提示只翻译目标说话人。
  4. [写] 级联描述里写清翻译器的训练单位与测试输入。

### M06（High）说话人流消融不能隔离交织融合本身的贡献

- **改进：**
  1. [算] **无说话人流模型 + 分离器后处理重标注**：对 O-nosd 每个输出段，按其预测时间戳内因果后验的平均值选 slot；不用任何参考信息。只需重算，直接回答 Q7。
  2. [训] **加性融合**：把投影后的说话人向量加到对应音频 token 上，不插入 token；En→Zh 离线，与 MIST 同步数、同数据。
  3. [训，P2] 说话人摘要前缀 token。GPU 时间不够就写进局限。
  4. [算] 长期身份：按会议前、中、后三分之一报告 slot 切换错误，以及长时间沉默后重新发言时的身份一致性（T19）。

### M07（High）真实中文会议上没有优于级联

- **改进：**
  1. [算] AliMeeting 每场会议的差值点图；单/多说话人、重叠比例、会议时长分组，配簇 bootstrap 区间；leave-one-meeting-out。
  2. [解] **AliMeeting 语音评测**：对离线和同传输出用同一 Talker 合成英文语音，报告 ASR-cpBLEU、SIM、混淆率、听众侧延迟（真实中文会议上的端到端 S2ST 结果）。
  3. [写] 摘要与结论把「AMI 显著改善」和「真实中文会议持平」分开写，Table 2 与 Table 1 同等显眼，并加入单/多说话人分解（多说话人 13.56 对 12.14，单说话人 16.54 对 18.11）。

### M08（High）deadline 监督依赖粗糙的比例对齐和末读强制提交

- **改进：**
  1. [算] 在 En→Zh 训练/dev 窗口上，用自动词对齐器（SimAlign 类，多语编码器）+ 源词时间得到对齐版截止时刻，统计比例版 deadline 的误差分布，以及「必要源信息还没听到就被要求输出」的 chunk 比例；同时报告末读强制提交比例。
  2. [训] **Zh→En 用真实字级时间重建 deadline**：中文源是 TTS 重配音，可以用 Paraformer 的字级时间戳得到源时间，替换按时长线性插值的估计；按原配方重训 Zh→En MIST-Simul（3000 步），在 dev 过门槛后进测试。直接检验 v5 中「中译英持平是因为截止期是估计的」这一解释。
  3. [写，P2] ε 和标点切法的敏感性只做标签统计分析，不重训；写进局限。

### M09（High）「用本人声音」缺少感知证据，Zh→En 不支持强主张

- **改进：**
  1. [算] 逐方向报告：因果音色提示可得率、长度、纯净度（提示内其他 slot 的平均后验）、等待到可用提示的时间、回退比例；因果提示与离线提示的公平对比（两者代码已支持）。
  2. [算] 用第二个说话人验证模型（与评分模型不同，若缓存中没有就下载公开 SV 模型）做自动 ABX：在会议内全部说话人中识别合成语音属于谁，报告准确率和 bootstrap 区间。
  3. [写] 人工听评按你此前的决定不做，写进局限；标题与摘要把「本人声音」限定为 En→Zh，并说明 Zh→En 音色保持失败。

### M10（High）过滤可能删掉了最难的短重叠回应

- **改进：**
  1. [算] 披露每个测试集保留/删除的说话时长、人数、重叠时长、短句长度分布，按话语类型（≤1 s 回应、长语句、无单独发言者）统计覆盖率。
  2. [解] **压力测试**：对被过滤掉的片段（>20 s 组、≤1 s 回应、纯重叠、无单独发言者）照样运行系统；没有可信参考的部分报告说话人检测/归属（DER、人数估计）和播放失败率。

### M11（High）「端到端 S2ST」表述过强

- **改进（[写]）：**
  - 标题改为 *Who Said What, in Their Own Voice: Diarizer-Conditioned Speaker-Attributed Simultaneous Meeting Translation with Voice-Prompted Speech Output*（定稿时再精简）；
  - 引言第一段定义「端到端」的范围：从音频到结构化译文联合解码，分离器和 Talker 冻结、不联合优化；
  - 架构图标出梯度路径。

### M12（Medium–High）单 seed，统计口径不完整

- **改进：**
  1. [算] 每次 bootstrap 重采样都重新做说话人匹配，与固定匹配的结果对比；补双侧 p 值和置换检验；`p=0.000` 改为 `p<0.001`，并说明是单侧尾概率；边界结果（如 p=0.050）不作强结论；报告效应量。
  2. [算] 核心比较（En→Zh 增益、Zh→En 持平、AliMeeting 持平）的每场会议点图和 leave-one-meeting-out。
  3. [训] **多 seed**：En→Zh 离线 MIST 与同数据级联翻译器各补 2 个 seed；En→Zh MIST-Simul 补 2 个 seed（共 6 次训练，seed 列表先登记）。Zh→En 的 seed 视 GPU 时间定，不够就写进局限。

### M13（Medium–High）单一分数掩盖了时间对应错误

- [算] 新增：片段级归属 F1（时间重叠 + 语义相似度匹配参考语句）、起止时间平均绝对误差、漏译/重译率、说话人切换错误、时间戳覆盖率，按说话人、会议、重叠条件分组；tcpBLEU 与 M01 共用。

### M14（Medium–High）实时性、长期 slot 保持、人数上限未测

- **改进：**
  1. [算] RTF、显存峰值、平均与 p95 生成速度，来自 M01 的整会议运行。
  2. [写] 说明每次读入从头 prefill、没有跨读入 KV 复用，并给出相应的计算成本。
  3. [解，P2] 把两场会议叠加成 6–8 人的合成会议做压力测试；明确标注是合成数据。
  4. [算] slot 首次出现、长时间不活跃后重返、slot 用满时的行为统计。
