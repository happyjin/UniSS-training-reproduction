## 0. 结论

1. **审稿基本合理，数字全部属实。** M1–M6 引用的数字（+0.32/+0.58/−0.36，p_Holm 0.403/0.080/0.512；
   语速 2.40→3.49；Table 6 的 +0.16/+0.39；speech start +0.06/+0.06/+0.14 s）都与宏一致。
   以 v10 现在的写法（标题和贡献把两种对齐并列为方法），Weak Reject 是公平的判断。
2. **审稿漏掉了三点，对我们有利，v11 应该用上：**
   - **B+PA 本身在常规指标下也降了延迟，而且显著。** LAAL_block：B+PA − B = −0.09 / −0.11 / −0.33 s
     （AMI Zh→En / En→Zh / Ali，均 p<0.001）；speech start −0.03 / −0.04 / −0.13 s（均 p<0.001）。
     "常规延迟没变"只对完整系统 M（= B+PA+WA）成立，**原因是 WA 写得晚，把 PA 的提前抵消掉了**
     （M − B+PA 的 LAAL_block：+0.08 / +0.09 / +0.25 s）。
   - **审稿建议的两种 WA 修法我们已经试过，都是负结果**，只是写在附录里没人看到：
     允许提前一读写出的 lattice 过冲（文本 −1.92、ASR −1.70）；训练期延迟预算（方案 B，ρ=0.5）文本 LAAL
     只降 0.09 / 0.13 s（偏置降 0.38 / 0.36 s）。
   - 停顿 "8.3 应更正为 7.7" 不是错：7.7 是 M，8.3 是 B+PA，两个数都对，表里要标清楚是哪一行。
3. **现在的创新点和结果撑不起"两种对齐都是方法贡献"的写法，但能撑起另一种写法。**
   - 撑得起的：(a) 读入分离器的说话人优先联合解码在重叠区的归属收益（离线对级联有确认性检验）；
     (b) 重叠感知、整场会议、语音时间线的评测协议；(c) **播放对齐 PA**：在完全相同的文本上，ASR-BLEU、
     LAAL_block、speech start、EndOffset 全部显著改善。
   - 撑不起的：WA 作为正面方法贡献。三个测试集都不显著，Ali 为负，比 B 多训了 3,500 步（算力混淆），
     又带着 δ_w 和 3500 步两项非盲决定。
   - **建议 v11 把主系统改成 B+PA，PA 作为主方法；WA 降为分析（"似然训练的隐写出策略为什么必然往后漂"）。**
     这样做还有一个好处：审稿最重的 M1（非盲测）里，δ_w 和 3500 步两项只影响 WA 行，B+PA 不受影响
     （B 是 stage 1 的最终步，PA talker 在 dev 上选）。
4. **改写只能把分数拉到 borderline；要到 Weak Accept，需要补三件 P0 实验**：PA 在 B 文本上的逐因子消融
   （含语速匹配的规则对照）、一个从未用过的干净测试集（建议 AliMeeting Eval 8 场 + DiariST 人工英文参考）、
   以及 WA 与 B 在同延迟下的对照（B + δ 曲线，只在 dev 上）。详见 §3。

## 2. v11 的叙事和结构（推荐方案 A）

### 2.1 两个方案

| | 方案 A（推荐）：PA 为主方法，WA 为分析 | 方案 B：保留双对齐，靠新实验救 WA |
|---|---|---|
| 主系统 | B+PA | M = B+PA+WA |
| WA 的位置 | §6 分析：似然训练的隐写出策略向晚漂移，三种修法（偏置、预算、提前写）及同延迟对照 | 方法节核心 |
| M1 非盲问题 | 大部分化解（δ_w、3500 只在 WA 行） | 仍是核心问题，必须有干净集正面结果 |
| 成功概率 | 高：主要结论已显著，补实验只是加固 | 低：两种修法已失败；同延迟对照若 WA 不占优，论文没有主方法 |
| 风险 | PA 学习部分若与语速匹配规则持平，主方法变成"有效工程 + 负结果"，需要 §2.3 的保底写法 | 时间和算力大，结果不确定 |

方案 B 只在 P0-3（B + δ 曲线）显示 WA 在同延迟下明显占优时才值得重新考虑；即便那样，也要在干净集上确认后再写进标题。

### 2.2 新标题和贡献（方案 A）

候选标题（不再承诺 WA）：
- **Who Said What, and When It Is Heard: Backlog-Aware Playback Alignment for Speaker-Attributed Streaming Meeting Interpretation**
- 备选：Speaker-Attributed Streaming Meeting Interpretation with Backlog-Aware Playback Alignment

贡献改为四条：
1. 说话人优先、带时间戳的联合解码，把冻结分离器作为交错 token 读入（明确是 G-STAR 的适配，不是新结构）；重叠区的收益主要来自归属，诚实写出。
2. 重叠感知的整场会议评测：同一分离器的级联和重标对照、overlap 分层、CR；语音侧同时报 speech onset、LAAL_block、LAAL_spread、EndOffset、语速、停顿。
3. **播放对齐（PA）**：以积压为状态的线性链 CRF + 后验正则化的延迟预算，在完全相同的文本上显著提高 ASR-BLEU，并在常规 LAAL_block、speech onset、EndOffset 上都提前；逐因子消融分出合并、语速、候选选择和学习部分各自的贡献。
4. **负结果分析**：把写出时刻作为隐变量、用模型自身似然训练时，后验必然向晚漂移（更多源信息 ⇒ 同一译文似然更高）；证据链：deadline 质量 0.66→0.56，三种修法（推理偏置、训练预算、允许提前写）的结果，以及同延迟下与 B 的对照。

### 2.3 PA 学习部分若不占优的保底写法

如果逐因子消融显示 learned PA ≈ 语速匹配的规则：
- 贡献 3 改成"积压感知的播放层（规则或学习）是语音侧收益的主要来源；CRF 给出该规则的最优性解释和预算化的训练目标，但在本设置下学习部分不带来额外显著收益"。
- 标题去掉 "Backlog-Aware Playback Alignment"，换成 "…: Where the Latency of Speaker-Attributed Meeting Interpretation Comes From" 一类偏分析的题目，投 Findings 更稳。

## 3. 补充实验（按能改变审稿结论的价值排序）

所有新实验先写登记文件（prereg），再跑；测试集上不做任何选择；每个新方法只跑一个设置（不扫参）。

### P0-1 PA 在 B 文本上的逐因子消融（回答 M3，最重要）

固定 B（stage 1 最终步）的文本，同一听众时间轴、chunk 协议、两个 TTS 种子：

| 行 | 合并 rl | 语速 | 候选数 / 选择 | Talker |
|---|---|---|---|---|
| R0 = B | — | 固定 | 1 | base |
| R1 | ✓ | 固定 | 1 | base |
| R2 | ✓ | 队列规则 | 1 | base |
| R3 | ✓ | 队列规则 | 2 / CTC | base |
| **R3′ 语速匹配规则** | ✓ | 规则，平均语速调到与 PA 相同 | 2 / CTC | base |
| R4 | ✓ | PA（backlog token） | 1 | PA |
| R5 = B+PA | ✓ | PA | 2 / CTC | PA |

- 指标：ASR-BLEU（Whisper + 第二个 ASR）、LAAL_block、LAAL_spread、speech onset、EndOffset、语速、≥0.5 s 停顿/分钟、句中停顿、UTMOS、SIM。
- 关键比较：R5 vs R3′（学习部分的净增益）、R4 vs R2（无选择时的学习增益）、R3 vs R2（CTC 选择）。
- R3′ 的语速只按 dev 上 PA 的平均语速设定一次，不在测试上调。
- 先 dev（15 场），再测试三个集各一次。只需 Talker 推理和 ASR，可以叠加在占位卡上。估计 ~20–30 卡·时。

### P0-2 干净测试集确认（回答 M1）

- **AliMeeting Eval**（8 场，近场 headset 混成单通道，与现测试同样处理）+ **DiariST 的 dev 人工英文翻译**（DiariST 论文：dev 和 test 都是人工翻译）。从未用于训练、开发或测试 → 真实普通话 Zh→En 的确认性集合。
- 合规：AliMeeting 只做测试（记忆 realsi-acl-test-only），这里同样只做测试。
- 登记文件锁定：系统 {B, B+PA, M(s3500, δ=−1), M(s4000, δ=−1)}，主假设 H1：B+PA − B 的 ASR-BLEU > 0、LAAL_block < 0；H2：M − B+PA 的文本 tcpBLEU（探索性）。Holm 校正，跑一次。
- 需要下载 AliMeeting Eval 音频（openslr 119）和 DiariST dev 参考 → **需要你同意**。
- En→Zh 没有未用过的 AMI 会议。可选：ICSI（LDC，需许可）或 NOTSOFAR-1（远场、域差大）+ 同一 MT 流水线做参考。建议 v11 只做 Ali Eval，En→Zh 在文中标为探索性。

### P0-3 WA 与 B 在同延迟下的对照（回答 M2；只在 dev 上，不碰测试）

- B + δ ∈ {+1, +0.5, −0.5, −1}（B 本身也有 wait token），dev5 文本解码，和已有的 WA δ ∈ {0, −1, −2, −3, −5} 画同一条 BLEU–文本 LAAL 曲线。
- 先前 E6（只有 B + δ=−1）被否决过；这次的理由不同：审稿把它列为 P0，而且只在 dev 上做，不增加测试集选择。**需要你重新确认。** 约 2–3 卡·时。
- 可选：B 继续 deadline SFT 3,500 步（同算力对照），8 卡约 3 h，再 dev5 解码。只有 P0-3 显示 WA 在同延迟下占优时才做。

### P0-4 规则选定的 4000 步补测（回答 M1(a)）

- WA s4000 + δ=−1，测试三个集各一次（文本 + PA 语音）。方案 A 下这只是附录行，补上可以去掉"规则选的点从未在测试上解码"这句话。约 10 卡·时。

### P1-1 整场无竞争的实时回放（回答 M5）

- B+PA（和 M）在 2–3 场测试会议上整场回放：按 PID 停掉相应卡上的占位训练，独占卡，记录每秒源音频的 wall-clock、Thinker / Talker 分项、未处理 read 队列、播放队列、p50/p90 计算感知延迟，分说话人多通道和单通道两种布局。
- 单通道若语音产出率长期高于播放能力，如实写"积压无法消除"。约 6 卡·时。

### P1-2 种子

- PA talker 再训 2 个种子（每方向），配合 2 个 TTS 种子 → B vs B+PA 的不确定性。
- Thinker 种子（B 第二个种子）只在方案 B 下需要。

### P1-3 小规模听测

- 30–40 个片段 × B / R3′ / B+PA，5–8 名双语听者，评可理解度、语速舒适度、停顿自然度、说话人可辨性（MUSHRA 或 1–5 分）。先前决定不做人评；审稿把它列为 P1，主方法又靠"说得更快"，没有听测很难说服。**需要你决定。**
- 退而求其次：COMET-22 / MetricX 文本评分 + 第二个 ASR 做 ASR-BLEU，至少回应"CTC 选择偏向 ASR 友好"。

### P1-4 CPU 分析（现有输出，无需 GPU）

- 去重 tcpBLEU（同一参考单元的重复译文只留一次）；short-interjection content recall；speaker-attributed vs speaker-blind 质量；所有表加参考类型标注（人译 / 机译 / 合成源）。

### P2（可选，方法增量）

- **流畅性约束的 PA**：在 CRF 势函数里加语速/停顿项，作为第二个后验正则化约束（期望语速 ≤ r_max），只跑一个预登记值。目标：保住 ASR-BLEU（硬门槛）的同时把停顿压回基线附近。若成功，贡献 3 更完整（延迟与流畅性双预算）。Talker 每方向重训一次。
- 用新规则重跑强基线（固定延迟 / LocalAgreement / cascade）+ 最终语音层：工作量大，v11 不做，写进 Limitations。
