# M2 流畅度方案 v3：第 3 步（Thinker 训练）+ 第 4 步（Talker 语速）

依据：
- [m2_fluency_results_v2.zh-CN.md](m2_fluency_results_v2.zh-CN.md)；
- [m2_sudden_pause_analysis_v1.zh-CN.md](m2_sudden_pause_analysis_v1.zh-CN.md)。

**硬门槛：ASR-BLEU 不能降低。** 和 M2 相比，配对 bootstrap 不能显著更低，点估计最好 ≥ M2。每个阶段先过门槛，再进入下一阶段。

## 要解决的问题

1. **句首等待。** 剩下的停顿里，“新句未开口”占 25%–47%。在训练数据的 dump 里也能看到原因：句首读取点（还没提交任何内容）有 36% 的草稿一开头就和 oracle（全句模型的续写）不一致；句中只有 17%–18%。oracle 是调整过语序的全句译文，而只听到开头时的草稿是按源语顺序译的，两者对不上，ABC 就只能等。
2. **句中等待**（“Thinker 在等”）。
3. **译音太长**：译音时长是源语的 0.85–0.88。
4. **播放端变速有音质代价**：每加速 1.1 倍，UTMOS 约降 0.2。

## 第 3 步：同传风格的 oracle，重训 ABC adapter

**3.1 改写。** 脚本：`data_clean/rewrite_interpreter_style.py`。
- 用 Qwen3-Omni（听原音频加看原译文）把每个训练句的全句 oracle 改写成同传风格：按说话顺序、简洁、去掉口头禅和重复，信息不增不减。
- 8 卡数据并行，每卡一个 vLLM。

**3.2 逐句把关，保护 BLEU。** 一句改写只有满足以下全部条件才被采用：
- 句级 chrF(改写, 人工参考) ≥ chrF(原 oracle, 人工参考) − 1；
- 长度为原 oracle 的 0.7–1.05 倍；
- 不是空串。

**3.3 小规模先行。** 每个方向先改写 600 句，量两件事：
- 句首读取点上，草稿与新 oracle 一致（最长公共前缀 > 0）的比例，目标从 64% 提高到 ≥ 72%；
- 被采用的改写对人工参考的 BLEU 不低于原 oracle。

两项都达到才放量；否则改提示词再试一次，还不行就只保留“去冗余”、不改语序。

**3.4 造训练行。** `build_thinker_oracle_prefix.py` 加一个可选参数 `--oracle-rewrites`，默认行为不变。
- 句首读取点（已提交前缀为空）的目标改为 草稿 与 采用的改写 的最长公共前缀；
- 句中读取点和末次读取不变；
- 离线行（整句译文）一半用采用的改写，一半保持原样；
- 所有目标都套用 `si_fluency_rules.clean`，去掉口头禅和重复；
- 句首读取行加倍采样。

**3.5 训练。** 和 op_v3 同一配方：
- `run_thinker_sd.sh`，8 卡，MBS 32，GBS 256，LoRA r32 α64，第 32–47 层；
- TRAIN_ITERS 800，在第 200 和第 400 步存档；
- 合并 i200 和 i400。

**3.6 选择和评测。**
- 先在 RealSI 两个方向上跑和 v2 相同的推理配置：卫生 + 清洗，偏置扫 3 档；
- 选 ASR-BLEU 不低于 M2、延迟与 M2 相当的那一档；
- 再看连续评测和突然停顿分析。

## 第 4 步：Talker 语速控制

**4.1 先验证 speed token 本身是否有效。** 原来的推理策略按“距上次提交的源语时长 ÷ 文本正常时长”选 speed token，相当于每次都要求正常语速，所以测到的语速是平的，不能说明 token 无效。
- 实验：同一批块，`--speed-shift` 取 −3、0、+3、+6，每个方向 120 句；
- 量三件事：实际语速（秒/字、秒/词）、ASR-BLEU、UTMOS。

**4.2a 如果 token 有效：不训练，改推理策略。**
- 在 `si_infer` 里加 `--speed-policy queue`：Talker 是一轮一轮生成的，生成第 r 块时，前面各块的时长已经知道，可以算出这一块提交时的队列长度；
- 队列 ≥ 0.5 s 时加快 k 档（k 随队列增加，有上限），每句末块加快 1 档；
- 用它替代播放端的 WSOLA 加速，播放端只保留削静音、缓冲和块内压缩；
- 门槛：ASR-BLEU 不降，UTMOS 不低于 S1。

**4.2b 如果 token 无效：重训 Talker。**
- 用解码后经 WSOLA 变速、再重新编码的目标语音构造变速训练对（0.85–1.25 倍），speed token 取真实比例；
- 从 T1c@1500 继续训练；
- 门槛：正常档的 ASR-BLEU 不低于 T1c。

## 汇总对比

和以下系统比较：M2、v1 N1、v2 N1 + S1、v2 加缓冲和块内压缩。

**逐句指标**：ASR-BLEU（配对 bootstrap）、LAAL、异常停顿负担、有 ≥1 s 停顿的句子、单字块、Talker 读错率、UTMOS。

**连续评测**：连续 LAAL、积压、突然停顿 / 分钟、扎堆比例，以及按原因分的停顿比例。

如果有效，再做一个试听页：同一段演讲连续播放，对比 M2、v2 和 v3。

## 执行

- GPU 作业全部走 gpuq5 队列，各个作业并行。
- 训练独占 8 卡，期间推理作业排队。
- 新代码都通过新参数接入，不改默认行为；输出写到新目录，不覆盖任何已有结果。
- 每一处代码改动检查无误后就提交，最后推送到 `private` 的 main。

## 执行中的修订（2026-10-27）

**第 3 步：不改写译文，只调整读写时机。**
- 同传风格改写试验（3.1–3.3）没通过：句首首字一致率反而下降（英→中 64.4% → 62.5%，中→英 65.0% → 63.6%）；采用部分的 BLEU“提升”来自全角标点，语音 ASR-BLEU 里体现不出来。已放弃。
- 改用**前缀约束的句首 oracle**（`data_clean/build_start_oracle.py`）：在句首读取点，强制全句模型以草稿的前 1 个单位、一半或全部开头续写；如果整句与人工参考一样好，这个开头就作为新目标。
- 训练目标仍然是 Thinker 自己的草稿文字，不引入新译文。
- 人工核读发现三类坏样本后，加了严格过滤（`filter_start_oracle.py`）：不留 chrF 余量、长度比 0.85–1.2、中文不夹英文、不切开词语、实词要有参考支持、只有虚词的目标有限制。最终采用 4,403 + 3,687 条。审核网页：https://claude.ai/artifact/MrPjHX4uaBkDX4JzSbxG64
- 数据只来自 UniST 训练集（源语音频 + Thinker 自己的 dump），与 RealSI、ACL 无重叠；不使用任何同传译员音频或目标语语音。
- 训练起点与 M2 的 op_v3 相同：原版 Qwen3-Omni-30B-A3B-Instruct 上的新 LoRA（r32 α64，第 32–47 层），8 卡，GBS 256，800 步余弦调度。
- **v4**：句首读取行整体加倍采样，取 i200 和 i400。结果是更爱等，只沿着原来的延迟–质量曲线往高延迟方向移动。
- **v5**：只把被延长的句首目标重复 4 次，其余行与 op_v3 相同，取 i200。

**第 4 步：不重训 Talker。**
- 速度试验证明 speed token 有效：加快 6 档约快 10%，ASR-BLEU 基本不变，UTMOS −0.03 / −0.07。
- 改为推理策略 `si_infer --speed-policy queue`，按每块写入时的积压选 speed token。

## 读写时机：文献参考与可用的标签构造（补充）

调研结论：现在 ABC 的训练标签是“草稿中与全句续写字面一致的最长前缀”，和 MU 论文的基础算法相同：
R. Zhang et al., *Learning Adaptive Segmentation Policy for Simultaneous Translation*, EMNLP 2020, Algorithm 1。
那篇论文也指出“字面一致”过严，全句模型调整语序后，句首很难对上。之后的工作大多把标准放宽为“提交后整句的似然或质量不受损”，或者改用强化学习。

按 BLEU 风险从低到高，可用于本项目的做法：

| # | 做法 | 来源 | 本项目怎么用 | BLEU 风险 |
|---|---|---|---|---|
| 1 | **结果等价代替字面一致**：在任何读取点（不只句首）尝试更长的提交，只要全句模型以它为前缀续写后的整句质量不低于 oracle 就接受；先用 N 个候选（N-best 或采样）做预筛 | MU（EMNLP 2020，top-10 候选匹配）；RALCP（Wang et al., ALTA 2024, arXiv 2309.06706）；tailored reference（Guo et al., Findings EMNLP 2023, arXiv 2310.13588） | 前缀约束 oracle 已在句首实现（v4/v5）；下一步扩到句中读取点，并加入采样候选的投票预筛 | 低：门槛 ε 直接控制 |
| 2 | **用 Thinker 自身似然确定每个词的最早可写时刻**：对 oracle 译文的每个词 y_j，在各读取时刻 t 算 log p(y_j \| audio[:t], y<j)，取跳变最大的时刻，或首次接近全句水平的时刻，作为它的延迟；平滑成单调后，在读取点 t 提交所有延迟 ≤ t 的词 | Hibiki 上下文对齐（ICML 2025, arXiv 2502.03382）；BS-SiMT 二分搜索最优策略（ACL 2023, arXiv 2305.12774）；ITST（EMNLP 2022, arXiv 2210.12357） | 用 vLLM 的 prompt_logprobs 对每个读取点做一次强制解码；目标总是 oracle 的前缀 | 低到中：设最小滞后，防过早提交 |
| 3 | **保真约束的单调 oracle**：以早期草稿为前缀生成全句 oracle，只保留对参考 BLEU 不低于原 oracle 的 | MU++；Chen et al. EMNLP 2021（arXiv 2010.11247） | 即现在的严格过滤，可再加句级 BLEU 门槛 | 中 |
| 4 | **推理时的句首投票（不训练）**：在尚未提交任何内容的读取点采样 K=4–8 个草稿，提交投票一致度 ≥ γ 的前缀；或在连续两次读取的下一词分布稳定、最大概率 > α 时提交 | TAF（NAACL 2025, arXiv 2410.22499）；RALCP；LSG（AAAI 2025, arXiv 2501.00868） | si_thinker_stream 已有投票策略的实现，可只在句首启用 | 低到中：γ 可调；只在句首增加计算 |
| 5 | **偏好优化**：同一读取状态下，通过门槛的更长提交优于等待，等待优于不通过门槛的提交，DPO 加小的延迟项 | SimulPL（ICLR 2025, arXiv 2502.00634） | 用做法 1 的标签构造偏好对，LoRA 上做 DPO | 低到中 |
| 6 | **带门槛的强化学习**：奖励 = 部分输出对参考前缀的 BLEU + 最终 BLEU；只有最终 BLEU ≥ SFT 时才计入延迟奖励 | Hibiki-Zero（arXiv 2602.11072）；HPO 门槛（arXiv 2604.21045）；Seed LiveInterpret 2.0（arXiv 2507.17527） | 最后做；用 BLEU 而不是神经指标做门槛 | 中：长音频上有掉 BLEU、奖励投机的先例 |

文献提醒：只优化 COMET、MetricX 或单调性的方法往往掉 BLEU（HPO、SimPOTrans、MU++）。保证目标是原参考或 oracle 的前缀、或加入对参考 BLEU 约束的方法能保住 BLEU（tailored reference、Hibiki 上下文对齐）。本项目的硬门槛是 ASR-BLEU，所以优先做 1、2、4。

**执行顺序**：
1. v5（做法 1 的句首版）出结果；
2. 做法 4（推理时句首投票，不训练，最快）；
3. 做法 2（似然对齐延迟标签，重训 LoRA）；
4. 做法 1 扩到全部读取点；
5. 做法 5 和 6 作为第二阶段。

每一步都必须过 ASR-BLEU 门槛。
