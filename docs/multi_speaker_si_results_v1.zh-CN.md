# 多说话人同传 G-STAR-SI 结果报告 v1（AMI 英→中）

2026-10-27。方案见 `multi_speaker_si_plan_v7.zh-CN.md`（离线）和 `multi_speaker_si_plan_v8_streaming.zh-CN.md`（流式）。

## 结论

1. **端到端多说话人翻译成立。** 离线 O-G1 在 AMI 测试集（2,375 个审查通过的窗口，16 场会议）上整场 cpBLEU 42.29；原版 Thinker 只靠提示词时是 12.82。说话人数完全正确 88.9%，输出片段 DER 18.4%（同口径 Nemotron 自身 27.7%）。
2. **流式可用，代价约 2.5 BLEU。** 流式 S-T（Δ = 1 s，Nemotron 低延迟 1.04 s 前瞻）整场 cpBLEU 39.81，文本 LAAL 2.39 s，说话人分配不比离线差（说话人数正确 90.2%，DER 14.0%）。合成语音在原句结束后中位数约 2 s 开口。
3. **流式必须训练。** 离线模型直接套 LocalAgreement-2（S-LA2）只有 29.49，延迟相同（2.37 s），解码还慢约 2.5 倍（全测试集 39 分钟对 16 分钟）。
4. **Nemotron 的分离误差不是主要瓶颈。** 换成参考分离后，离线不涨（42.08），流式只涨 1.0（40.81）。剩下的说话人错误来自模型本身在重叠段的切分和分配。
5. **主要短板是多人重叠段。** 多人窗口的 cpBLEU 比单人低约 10 分；四分之一的多人窗口少报一位说话人，14–19% 的片段对不上参考句（多是重复的短回应）。
6. **分离支的作用是整场说话人一致。** 不接分离支的 O-nosd 翻译质量完全一样（不分说话人 BLEU 都是 43.70），单个窗口内也能分开说话人（窗口级 cpBLEU 42.30 对 42.80）。但它没法在整场会议里给同一个人保持同一个标签，整场 cpBLEU 从 42.29 掉到 18.29，DER 从 18.4% 升到 63.2%。在多人窗口里，分离支还把说话人数正确率从 57.5% 提到 70.2%。

## 1. 系统

| 部分 | 设置 |
|---|---|
| 分离支 | Nemotron-3-Diarization（Streaming Sortformer，冻结），8 个槽位，10 ms 后验池化到 80 ms。离线预设一次看完；低延迟预设只往后看 1.04 s |
| 融合 | 后验经 SDProjector（Conv1d k5 s5 + MLP → 2048 维），和 Qwen3-Omni 音频特征按 K:1 交错后替换音频占位 |
| 翻译支 | Qwen3-Omni-30B-A3B Thinker（release），LoRA r32 α64，48 层 q/k/v/o 共 192 个适配器；259 个新 token（251 个 80 ms 时间 token + 8 个说话人 token）占用词表空行 |
| 输出格式 | `<\|spk k\|><\|t a\|>译文<\|t b\|>`，说话人在前，方便流式 talker 先定音色 |
| 训练 | Megatron，GBS 64，MBS 8，8×H200，约 2.4 s/步；损失里时间 token ×1.5、说话人 token ×2 |
| O-G1 | 1,000 步，32,854 行（28,569 条 G-STAR + 4,285 条只做分离），IHM-mix，文本审查通过 |
| S-T | 从合并后的 O-G1 继续 2,000 步，128,879 行（含 20% 离线行和 15% 分离行）；每 1 s 读一次，1.04 s 之后的后验置零；策略 wait：一直生成到结束标记再提交 |
| 语音 | UniSS Talker T1c@1500，每个说话人槽位一路；音色参考取 Nemotron 判定为单独说话的片段（≤8 s）；离线按原句起点放置，流式按提交时刻放置 |

测试集：AMI test 16 场会议（EN2002、ES2004、IS1009、TS3003 各 a–d），2,375 个参考窗口，平均 5.9 s；其中单人窗口 1,544 个，多人窗口 831 个（824 个有重叠）。

指标：
- **整场 cpBLEU**：每场会议做一次说话人匹配（chrF + 匈牙利），再算中文 BLEU。同时衡量"谁说的"和"说了什么"。
- **不分说话人 BLEU**：去掉说话人后的翻译质量。
- **说话人数正确**：窗口里输出的说话人数等于参考的比例。
- **DER（输出）**：用输出片段的时间和说话人，对 AMI 整句起止算 DER。句内停顿算作说话，所以 Nemotron 自身在这个口径下是 27.7%。
- **LAAL**：文本层面每个译文字的提交延迟；**首次开口**：窗口第一个片段的提交时刻。

## 4. 错误分析

`gstar_analyze.py`：每个输出片段按时间 IoU + 文本相似度对到一条参考句。

| 系统 | 格式失败 | 少报说话人 | 多报 | 片段说话人错 | 起点误差 s | 终点误差 s | 参考句漏译 | 插入片段 |
|---|---|---|---|---|---|---|---|---|
| O-G1 全部 | 0.13% | 9.9% | 1.1% | 10.3% | 0.50 | 0.67 | 2.8% | 8.9% |
| O-G1 多人 | 0.24% | 28.3% | 1.6% | 16.4% | 0.61 | 0.76 | 4.1% | 14.0% |
| O-nosd 多人 | 0 | 40.4% | 2.1% | 74.9%† | 0.56 | 0.72 | 3.3% | 4.5% |
| S-LA2 多人 | 0 | 30.5% | 1.2% | 19.4% | 0.66 | 0.81 | 2.0% | 13.8% |
| S-T 全部 | 0 | 8.6% | 1.2% | 12.2% | 0.95 | 1.18 | 1.3% | 13.2% |
| S-T 多人 | 0 | 24.6% | 1.2% | 14.3% | 0.89 | 1.04 | 1.8% | 18.6% |
| S-T-oracle 多人 | 0 | 20.1% | 0.8% | 16.5% | 0.84 | 1.13 | 1.9% | 20.4% |

† O-nosd 看不到 Nemotron 的槽位，它的标签和槽位对不上是必然的，这一列只说明标签无法跨窗口对齐。

观察：

- **格式**：离线 3 个窗口格式失败，流式 0 个。
- **没有分离支**：O-nosd 在多人窗口里少报说话人 40.4%（O-G1 28.3%），插入反而更少（4.5%）。它倾向于把重叠的话并给一个人，而不是多编出一个人。
- **少报说话人**是多人窗口的头号问题：插话、附和（"yeah""okay"）常被并进主讲人或直接漏掉。参考分离也只把它从 24.6% 降到 20.1%。
- **插入片段**：流式多于离线（18.6% 对 14.0%）。典型情形是重叠处把同一句短回应（"是的，我有"）分给两位说话人，或重复几次。
- **时间误差**：流式起点误差约 0.9 s，离线约 0.5 s。主要是因为流式按标点切成短块，后半块要和整句的起点比较；开口时机本身由 LAAL 衡量。
- **极短词**（"Funky""K"）有时照抄英文不翻译。

## 7. 下一步建议

1. **重叠段的说话人**：参考分离也救不回来，问题在模型。可以尝试：
   - 给多人重叠窗口加权或过采样；
   - 把说话人损失只加在重叠区；
   - 在训练里加入"同时说话"的显式样本（两路参考同时活跃）。
2. **重复的短回应**：解码时对同一窗口内跨说话人的重复片段去重，或加重复惩罚；训练数据里检查短附和的参考译文是否一致。
3. **延迟**：S-T 现在用 wait 策略，延迟和 LA2 持平。可以试两步：
   - 在提交时机上加训练信号（例如提前提交的样本）；
   - 用 Δ = 0.5 s 换更低的首次开口。
4. **补测**：S-single 单人回归（RealSI），S-LA2 的 Δ 曲线，以及完整测试集上的语音 cp-ASR-BLEU。
5. **训练效率**：LoRA 训练 GPU 利用率只有 20–50%，可以用 MBS 16、GBS 128 提高吞吐（需要重新确认学习率）。
