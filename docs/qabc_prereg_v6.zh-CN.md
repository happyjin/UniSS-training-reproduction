# v6 预注册：连续时钟（一段录音一条播放时钟）下的 QABC

本文件在 v11 的任何测试集运行（RealSI 上的连续时钟解码、语音、打分）之前提交到 git，提交时间即登记时间。之后的结果无论好坏都按这里的规则报告；修改需新提交（修正 1、2……），并在论文中说明。v4 预注册（77cd4f8、b403f1b）和 v5 预注册（C1/C2）不变，其结果仍按原样报告。

**起因。** ICML 风格审稿（2026-11-01，v10，4/10）M1 指出 v10 Table 41 的"一条时钟"下 QABC 不领先 LA2。核对后，那张表是**事后重排**：句级解码得到的块，事后放回录音时间轴（`scripts/v10_talk.py`），决策时每句的队列都从 0 开始，QABC 没看到跨句积压，Talker 也没有任何吞吐控制。M2 指出连续阈值不赢二值门；在句级重置下两种规则只在约 5% 的读取上做出不同决定（v10 RealSI qrp5 dump）。本预注册定义一个真正的连续时钟协议，让决策看到跨句积压，并在其上检验 H1（QABC 对 LA2）和 H2（阈值形式）。

**范围（用户 2026-11-02 决定）。** 论文的主协议仍是标准的逐句/逐段评测（v4、v5 的注册检验）。连续时钟是额外的部署分析，结果无论好坏都如实报告；不领先时写成 Talker 吞吐的局限（对所有策略一样），不改变标题和主张的范围。

## 0. 连续时钟协议 CONT

- **talk**：RealSI 每段录音一个 talk（英→中、中→英各 10 个），句子按开始时间排序，句子在 talk 时钟上的位置就是它在录音里的位置。
- **跟踪队列**（`reports/qabc_v11/cont_queue.py`）：每个 talk 只有一个 Talker。在 talk 时刻 t 提交 n 个单位，跟踪队列尾部就从 max(busy, t) 起再加 n·r·exp(−γ·shift) 秒，其中 r = 0.191 s/字（英→中）、0.339 s/词（中→英），即 v4–v10 的 SDR 速率。时刻 t 的队列为 q = max(0, busy − t)。**与 v10 不同，队列从上一句带到下一句。** 中→英有 3 对句子在录音里重叠，后一句按上一句全部提交之后的队列计算（只影响队列估计，不影响内容）。
- **吞吐控制**（对所有策略一样，第 1 节在 dev 上选定）：块提交时若 q ≥ 0.5 s，向 Talker 多要 shift = min(S_max, round(K·q)) 档语速，叠加在 v4 的块配速之上（`si_infer_cont --speed-policy tracked`）。候选：none（不控制）、fr（K = 3，S_max = 6，即 v10 FR 的规则）、strong（K = 3，S_max = 12）。γ 为每档语速的实际加速，在 dev 上拟合（第 1 节），中→英、英→中各一个。
- **系统**（同一 s0 adapter、b0 = 1、同一 Talker T1c@1500、history ban 8、Talker 种子 {0, 1}）：
  - **LA2**：注册的 LA2 块文件（`realsi_thinker_stream_v1/blocks_<d>_w<w>.jsonl`，与 v10 主表同源；它的提交与队列无关），用同一函数标上跟踪队列和 shift，再由 Talker 按控制重新说出。
  - **QABC（p5）**：`si_qabc_cont.py --rules p5`，即注册的 QABC 规则（si_qabc_rules 的 p5，等同 selfwait），每次读取看到带过来的跟踪队列。
  - **H2 的规则**，同一 s0 后验、同一驱动：gate（v10 的二值门：q ≥ Δ 时 τ = 0.9975，否则 τ0）、linlogit（logit τ 随 q 线性增加，q ≥ Δ 时到 logit 0.9975）、seqb（v10 的块内规则，unit u+1 用 τ(q + r_eff·u)）。
- **读窗口**：{0.5, 0.75, 1, 1.5, 2, 3} s，所有系统相同。
- **语音和指标**：
  - 只用语音部分做 ASR（同 v4–v10），计算 ASR-BLEU。
  - **连续 LAAL**：每个单位以它所在块在 talk 时钟上的实际开始播放时刻、减去句子在 talk 中的位置来计时，源长度取句长（v10_talk 的定义）。块的开始时刻 = max(提交时刻, 上一块的结束时刻)，块长为 Talker 实际说出的时长。
  - **积压描述**：平均和 95 分位排队等待、积压漂移（等待对 talk 时间的斜率，s/min）、talk 结束后的播放尾巴、积压 > 2 s 的时间比例、Talker 语音总时长 / 源时长，以及决策时跟踪队列和实际队列的差。
  - 每个读窗口的工作点 = 2 个 Talker 种子的均值。

## 1. 吞吐控制和 γ 的选择（只用 dev）

- **dev 伪 talk**：自发语音 dev（`data/si_spont_v1/dev_<d>_ref.jsonl`，GigaSpeech/WenetSpeech dev，与训练集、测试集都不重叠），按文件顺序首尾相接，句间隔 0.3 s，每段约 4.5 分钟（英→中 8 段、中→英 9 段）。
- **系统**：v4 在这份 dev 上的句级块——LA2（`si_v4/devsp_la2`）和 A0（s0、b0 = 1、SDR，`si_v4/devsp_s0`），读窗口 0.5/1/2 s。每种控制都用 cont_queue 标注 shift（γ 先取 0.017），Talker 种子 0。
- **γ**：对 dev 上每个说出的块，以 log(实际时长/单位数) 对 shift 做最小二乘，取斜率的相反数为 γ_d。测试运行使用 γ_d。
- **ASR-BLEU 门槛**：一种控制合格，当且仅当在两个方向上，它在 6 个运行（2 系统 × 3 窗口）上的平均 ASR-BLEU 都不低于 none 超过 0.3 BLEU。0.3 BLEU 是 Talker 采样噪声的量级；none 总是合格。
- **选择**：在合格的控制中，选最弱的一个（按 none < fr < strong），要求两个方向的平均实际漂移都 ≤ 0.1 s/min。如果没有一种达到，就选两个方向漂移最大值最小的那一种。两个方向用同一种控制。选择结果、γ_d 和每种控制的 dev 数字都写进论文附录。

## 2. 确认性检验 H1：连续时钟下 QABC 对 LA2

- **统计量**：E1 = 等延迟增益，即 QABC 曲线减 LA2 曲线的 ASR-BLEU 差，在连续 LAAL 的 [lo, hi] 上按 0.05 s 网格取平均。曲线取上包络，工作点间线性插值。lo = 两条曲线起点的较大者；**hi = min(5.0 s, 两条曲线终点的较小者)**。5.0 s 是事先固定的上限，因为连续播放下的延迟比逐句评测高，而 v4 逐句评测用的是 3.0 s。若 hi − lo < 0.5 s，该方向记为"不可检验"，并如实报告。
- **重采样**：按 talk 的簇 bootstrap（每方向 10 个 talk，有放回抽 talk 及其全部句子，同一次抽样对所有系统、读窗口、Talker 种子共用），B = 1000，单侧，p = 抽样值 ≤ 0 的比例。两个方向做 Holm 校正。
- **判定**：H1 在方向 d 成立 ⇔ Holm p < 0.05。
- **一并报告（次要，不进 Holm）**：按句重采样的 E1；hi = 3.0 s 和 hi 取整个共同范围时的 E1；E2（等质量延迟节省，在 [lo, hi] 上定义）；各读窗口的 BLEU 和连续 LAAL；第 0 节的积压描述。

## 3. 确认性检验 H2：连续阈值对二值门（同一后验）

- **主比较**：p5（τ(q)）减 gate，在 CONT 上计算 E1，定义同第 2 节；按 talk 簇 bootstrap，单侧；两个方向一族 Holm（与 H1 分开）。
- **次要（探索性，不进 Holm）**：linlogit 减 p5、seqb 减 p5、gate 减 LA2。
- **区分能力（描述性）**：在 p5 流的每次读取上，用同一草稿和同一队列计算四种规则各会提交多少单位（`--dump` 的 alt 字段），报告两两做出不同决定的读取比例，以及队列状态（q = 0、0 < q < Δ、q ≥ Δ）的分布。同时报告 v10 句级重置下的同一比例（RealSI qrp5 dump），作为对照。
- **写法规则（预先写定）**：若 H2 在两个方向都不成立，论文写"队列信息有用（v10 Table 12：对常数风险 10 组配对全部为正）；推导出的 τ(q) 给出二值门的切换点和连续形式，二者在同等证据下都是可部署的选择"，不再主张连续形式本身更优。

## 4. 稳健性和描述性分析（预先指定，不设 Holm）

- **v10 事后重排结果**放进附录，写明"决策看不到积压、没有吞吐控制、不检验队列机制"，并按读窗口列出 BLEU。
- **第二个 adapter seed**（s1，若 GPU 时间允许）：H1 的 QABC 用 s1 再跑一遍，只作描述，不进检验。
- **三条时间轴**（M4，用已有的 v4/v10 运行）：提交时刻的文本、听到时刻的文本（同一文本按实际播放时刻计时）、词对齐 LAAL。每条轴上都报告 QABC 对 LA2 的 E1（按句重采样）。
- **不可撤销错误率**：已提交单位与同一模型对整句的输出、在同一位置不一致的比例（RealSI 上 p5 读取的 dump 带 full_units）。按语序交叉程度（v10 tab_crossing 的定义）分层，中→英单独报告。
- **严重错误（规则检测，自动）**：最终提交译文与参考译文、以及与同一模型整句输出之间，数字多重集是否不同、否定词是否一方有一方无（中文：不、没、未、别、无、非；英文：not、no、never、n't、none、nobody、nothing），按读窗口比较 QABC 和 LA2。这是自动检测，不是人工标注。
- **M5 目标偏移**：在 dev 读取上，分别用冻结 Thinker 和适配 Thinker 的整句输出作标签，报告 ρ_θ 的 NLL、ECE 和决策损失（v10 的 dump 已有两套标签）。不一致率直接给出 Theorem 2 新增偏移项的估计值。若 GPU 时间允许，再从训练集抽 2000 次读取，用适配 Thinker 打标签，报告同样的量。
- **各组件对队列延迟的贡献**：块配速、语速 shift、跨句积压，在 CONT 的 LA2/QABC 运行上分解报告。
