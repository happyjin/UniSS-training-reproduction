# M2 同传译音流畅度分析 v1

对象：UniSS 同传 M2 档（论文 *When to Speak* Table 1 的 m2 运行），也就是 fluency 提交包 `fluency_test/uniss_m2_fluency/` 里的同一批输出。
- 英→中：RealSI 346 句。
- 中→英：RealSI 431 句。
- 英→中长音频：ACL 60/60 dev 633 段。

对照组用同一个 Thinker、同一个 Talker、同一个 ABC+SDR 策略的高延迟档：m3（读取窗 3 s）和 m6（读取窗 6 s）。它们和 M2 只差读取窗，差出来的部分可以看作“流式”本身的代价。

## 结论

**有问题，而且主要不在 Talker 的音质，而在“什么时候、按多大的块提交”。**

1. **句中卡顿多。**
   - 一半以上的句子至少有一次 ≥1 s 的停顿：英→中 57%，中→英 51%；m6 只有 21% 和 12%。
   - 异常停顿负担：英→中 5.1 s/100 字，中→英 7.1 s/100 词，是 m6 的 2.5–3 倍。
   - 这些停顿有 96% 发生在源语说话人还在讲的时候。听众听到的是“译员卡住了”，而不是跟着原文的自然停顿。
2. **卡顿的根源是碎片化提交：挤一个字、长时间等、再一大段涌出来。**
   - 英→中 7% 的块只有一个字，中→英有 16% 的块只有一个词，通常是 “But / So / Then” 这类功能词。
   - 这种块后面的停顿平均长一倍，等完之后的那一块又是普通块的 2 倍长。
   - 最严重的是把词拆开：
     - “鲁本斯的画 / 作”中间停了 7.6 s；
     - “叶 / 伊恩”中间停了 9.3 s；
     - “Choose to / return directly…”中间停了 8.6 s。
   - 句中短语内和词内的停顿，占了全部异常停顿负担的 70% 左右。
3. **排队和拖尾。**
   - 约 30% 的块需要排队，等前一块说完才能开口。排队时间 p90 为 2.2–2.3 s，最长 8 s。
   - 24% 的句子说到最后仍落后 ≥1 s。
   - 源语结束后，译音中位数还要再说 2.3 s，p90 为 4.7–4.9 s。
   - Talker 的 speed token 实际上不起作用：无论哪一档，实际语速都在 0.20 s/字或约 0.29 s/词附近，所以积压没有办法靠加快语速消化。
4. **相邻块语速忽快忽慢，整体音质下降；但接缝处的音高和音量是连贯的。**
   - 相邻块语速差超过 1.5 倍的比例：英→中 24%，中→英 37%；m6 为 14% 和 19%。
   - 只看语音段（去掉等待）的 UTMOS 也比 m6 低：英→中 −0.22，中→英 −0.13，95% 置信区间都不跨 0。
   - 两块首尾相接时，接缝处的音高和音量跳变与块内部一样大，没有明显的“断开”。
   - 英文里，句中结束的块不像句末那样降调，说明 Talker 已经区分了“没说完”和“说完了”。所以韵律问题不是重点。
5. **和文献对比：静音比偏高。** M2 的静音比（停顿占“首次到最后一次发声”总时长的比例）为 0.33（英→中）和 0.32（中→英）。NaturalFlow 报告的范围是：真人说话 0.02–0.23，Hibiki 0.08–0.26，Seamless 0.14–0.65，StreamSpeech 0.25–0.62。
6. **内容层也有不流畅，以中→英为主。**
   - Thinker 把源语里的口头禅和重复照译出来：“uh, uh, uh”、“Their, their, uh, their”。每 100 个英文词有 2.7 个，28% 的句子有。参考译文里一个也没有。m6 也一样，所以这是翻译风格的问题，不是提交策略的问题。
   - Talker 碰到这种块经常整段漏读：中→英 Talker 读错率 8.9%，15% 的句子错超过两成。
   - ACL 上有 6.7% 的块只有标点。Talker 会把这种空块读成“嗯 / 对对对”，个别块还出现乱读。

**能解决，而且见效最快的几步都不需要重新训练。** 具体做法依次是：
- **提交卫生**：不在功能词或词中间结束一块；合并单字块和纯标点块；把“提交后会空多久”加进 ABC 的风险项。
- **口头禅过滤**。
- **有上限的平滑变速**。

再往后是三步需要训练的改动：
- 让 Thinker 学会压缩和省略；
- 让 Talker 带前瞻、有真正可控的时长；
- 用“质量 − 延迟 − 卡顿”做强化学习。

最终的方向是文本和语音一起流式生成。详见第 5 节。

## 1. 被测系统

- **Thinker**：Qwen3-Omni-30B-A3B Thinker，加 ABC adapter（摊销的 Bayes 最优提交）和 SDR（按语音队列调整等待代价）。
  - 英→中：Δ = 0.5 s，b0 = 1。
  - 中→英：Δ = 1 s，b0 = 0。

## 2. 怎么评价流畅度

### 2.1 近几年文献里的做法

目前没有一篇论文把口译研究那套完整的流畅度测量用在机器同传的输出上。机器同传论文测流畅度主要有四种做法。

**① 块间静音统计**
- **SimulEval**（Ma et al., EMNLP 2020 Demo，arXiv:2007.16193）
  - 时间轴规则：第 i 段的开始时间 = max(上一段结束, 提交时刻)。这和我们的规则完全相同。
  - 报告 NumChunks（段数）和 DiscontinuitySum / Ave / Num（插入静音的总长、平均长度、次数），任何 >0 的空隙都算，没有阈值。
- **StreamSpeech**（Zhang et al., ACL 2024，arXiv:2406.03049）和 **NAST-S2x**（Ma et al., ACL 2024，arXiv:2406.06937）报告这组指标。
  - NAST-S2x 发现：去掉静音后 ASR-BLEU 从 19.67 升到 24.90。块太碎时，一个音节被拆到两块里会听起来像结巴。
- **NaturalFlow**（Lee et al., arXiv:2606.13121, 2026）提出静音比：SR = 1 − 发声时长 ÷（首次发声到最后发声的总时长）。
  - 用 Silero VAD，最短静音 100 ms。
  - 各系统和真人的范围：真人说话 0.02–0.23；Hibiki 0.08–0.26；Seamless 0.14–0.65；StreamSpeech 0.25–0.62。

**② 语速和停顿是否跟着源语走**
- **Seamless**（arXiv:2312.05187）报告两个指标：
  - Rate：源语和译语每秒音节数的 Spearman 相关；
  - Pause：源语和译语停顿的对齐分。

**③ 人评**
- **Hibiki**（Labiausse et al., ICML 2025，arXiv:2502.03382）：自然度 MOS，1–5 分。
  - 自然度的定义：节奏和韵律是否自然，停顿是否平滑而不突兀。
  - 结果：Hibiki 3.73，Seamless 2.18，真人 4.12。
- **Hibiki-Zero**（arXiv:2602.11072）：0–100 分。Hibiki-Zero 67.2，Hibiki 57.0，Seamless 21.2。
- **Seed LiveInterpret 2.0**（arXiv:2507.17527）的 SVIP 评分表有四项，各 1–5 分，都有文字锚点：
  - 延迟：5 分是 <3 s，1 分是 ≥10 s；
  - 语速；
  - 发音；
  - 流畅度：5 分是“没有明显停顿、重复、犹豫”，3 分是“有明显问题，影响节奏”。
- **SimulS2ST-Omni**（arXiv:2607.19810）：和我们最接近的 Thinker–Talker 系统，测试集也是 RealSI 和 ACL。人评三项：Adequacy、Naturalness（节奏）、Fidelity（毛刺）。
- **SAT**（Zheng et al., Findings of EMNLP 2020，arXiv:2010.10048）：流畅度 MOS，同时给了真人译员作参照。
  - 英→中：wait-3 3.56，SAT 3.83，真人译员 3.85。
  - 中→英：wait-3 3.68，SAT 3.97。

**④ 和积压有关的延迟**
- StartOffset 和 EndOffset：EndOffset 会随积压增大。
- ATD（Kano et al., arXiv:2211.13173）：语音还在播放时，后面的内容也跟着被推迟，所以它会惩罚过长的输出。
- Liu et al.（Interspeech 2022，arXiv:2110.08214）的队列感知延迟。
- StreamLAAL 和 LongYAAL。
- 长音频上的延迟漂移（arXiv:2606.15059）。

**口译研究**把流畅度分成三个维度：速度、中断、修复。
- 代表文献：Bosker et al. 2013；Han 2015；Yu & van Heuven 2017；Han et al. 2020；Han & Yang 2023 的元分析；Song & Li 2020。
- 和人评相关最强的几项：
  - 含停顿的语速；
  - 发声时间比；
  - 平均语流长度（两次停顿之间说了多少）；
  - 无声停顿的平均时长。
- Han et al. 2020 发现，停顿时长加平均语流长度就能解释约 60% 的评分差异。
- 无声停顿的阈值常用 0.25–0.3 s。Song & Li 2020 研究同传时用 0.3 s。
- Apple 的 *Toward Machine Interpreting*（Sperber et al., arXiv:2508.07964）总结：
  - ≥2 s 的停顿容易被听成卡壳或漏译；
  - 停顿应该落在句与句之间，而不是句中；
  - 落后时不要“赶着说”。

**自动音质模型**：UTMOS / UTMOSv2、DNSMOS P.835、NISQA（有 discontinuity 维度，但针对的是电话掉线）、Audiobox Aesthetics。
- 它们只能当音质检查：训练用的都是短句，对时间轴上的停顿和积压不敏感。
- LLM 评委（AudioJudge、SpeechJudge）在自然度上和人的一致率约 70–77%，还不能代替人评。

### 2.2 本项目建议的指标体系

我们的时间轴规则和 SimulEval 一样，所以可以直接沿用它的指标。“已实现”一栏标的是本报告里已经算过的部分。

| 维度 | 指标 | 定义 | 已实现 |
|---|---|---|---|
| 延迟和积压 | 首次发声、源语结束后还在说（EndOffset） | 秒 | ✓ |
| | 排队时间 p50 / p90 / 最大；最后仍落后 ≥1 s 的句子 | 块开始播放时刻 − 提交时刻 | ✓ |
| | 积压曲线 B(t)、长音频漂移 | 未播放语音的秒数；排队时间随源语时间的斜率 | 待做（需要整场连续运行） |
| 中断 | 无声停顿：≥0.25 / 0.5 / 1 / 2 s，按每 100 单位和每分钟发声计 | 时间轴 wav 的 VAD 实测，去掉首次发声前和最后发声后 | ✓ |
| | 静音比 SR、无声停顿平均时长 | 同 NaturalFlow | ✓ |
| | 停顿位置和异常停顿负担 | 句末 / 从句 / 短语内 / 词内，按 0.15 / 0.30 / 0.50 / 1.00 s 容忍度计超额 | ✓（规则版；评分方用 LLM 版） |
| | 源语也在停的停顿 | 源语同时静音的停顿单列，不算“卡壳” | ✓ |
| 速度 | 语速（含停顿）、发音速率、发声时间比、平均语流长度 | 中文按字、英文按词 | ✓ |
| | 块语速的稳定性 | 相邻块每单位时长之比 >1.5 的比例；偏离中位数的块 | ✓ |
| 修复和内容 | Talker 读错率、漏读、多读 | 纯语音 ASR 对提交文本 | ✓（句级；建议改成块级并加尾部截断率） |
| | 结巴、口头禅、重复 | 语音比文本多出来的紧邻重复；译文比参考多出来的口头禅和重复 | ✓ |
| 接缝韵律 | 接缝处 F0 和能量跳变；非句末块是否降调 | 首尾相接的接缝对比块内部；句尾最后 0.3 s 的 F0 斜率 | ✓（英文可靠，中文受声调影响） |
| 音质 | UTMOS（纯语音） | 每句 | ✓（建议加块级 UTMOSv2 和 DNSMOS） |

人评建议分三部分。

**主评**：Seed SVIP 式四项评分，加两项补充。
- 四项：延迟、语速、发音、流畅度，沿用 Seed 的锚点。
- 补充一：Hibiki 的自然度定义。
- 补充二：一项 1–5 分的可懂度。
- 材料：2–5 分钟、按真实时间轴播放的片段。
- 评审：每个方向至少 5 名双语评审，最好是译员；报告 Krippendorff α。

**对比实验**：A/B 偏好，同一段源语播放两个系统的输出，用二项检验判断显著性（NaturalFlow 的做法）。

**校准**：P.880 式连续打分，评审边听边拖滑块。把分数下滑的时刻和时间轴事件（≥1 s 停顿、积压峰值、漏读）对齐，用来校准自动指标的阈值。最后用 Han et al. 2020 的回归方法，挑出少数几个最能预测人评的自动指标作日常监控。

## 3. 结果

统计脚本：`experiments/uniss_qwen3_omni_v1/evaluation/si_fluency_stats.py`。

停顿直接从时间轴 wav 上测，用能量 VAD：10 ms 一帧，比该句语音电平低 30 dB 算静音，≥0.15 s 计为一次停顿。首次发声之前的等待和最后发声之后的静音不计。

每个停顿再对到文本上：落在两块之间的叫“接缝停顿”，其余是块内停顿。接缝分四类，每类有一个容忍度，超出的部分叫“超额停顿”：

| 接缝 | 判定 | 容忍度 |
|---|---|---|
| 句末 S | 前一块以 。？！.?! 结尾 | 1.00 s |
| 从句 C | 前一块以逗号、顿号、分号、冒号结尾，或后一块以它们开头 | 0.50 s |
| 短语内 P | 词与词之间，没有标点（英文结尾是功能词的单列为 P-fw） | 0.30 s |
| 词内 W | 中文：落在 jieba 切出的一个词内部 | 0.15 s |

这四档容忍度和 fluency 包评分方的设置相同。区别在于这里用规则判定边界类型，评分方用 LLM 标注，所以绝对值不能和评分方直接对比，同一口径下系统之间的对比是可靠的。

UTMOS（utmos22 strong）在去掉等待的纯语音 wav 上打分。

### 3.5 Talker 的 speed token

M2 用 `--speed-policy block`：每一块按“距上次提交过了多久 ÷ 这块文本的自然时长”选一个 speed token（0–34 档）。实际情况如下：

- 英→中 M2 里各档都用到了，两端也不少：0–2 档占 10%，30–34 档占 14%。
- 实际语速几乎不随它变化：
  - 英→中各档都是每字 0.20–0.22 s；
  - 中→英各档都是每词 0.25–0.30 s，没有单调关系。
- 所以 Talker 现在既不能主动加速去追积压，也不能放慢去填等待。前面看到的语速忽快忽慢，主要来自块的长短和 Talker 采样，不是 speed token。

## 5. 解决思路

成本标记：
- 【推理】只改推理代码，不训练；
- 【Thinker 训练】重训 Thinker 的 LoRA 或做强化学习；
- 【Talker 训练】重训 UniSS Talker；
- 【架构】换架构。

### 思路一：提交卫生，并把“断流代价”放进 ABC 的决策　【推理】　针对 P1、P5，部分针对 P2

根因（第 4 节 P1）：ABC 只问“这几个单位以后会不会被改”，不问“提交之后会不会马上断掉”。

**规则层**，可以直接加在 `si_thinker_stream.py` 的提交步骤里：
1. **非末块不在悬空的位置结束**：
   - 英文不以冠词、介词、连词、助动词结尾（如 “Choose to”、“But”）；
   - 中文不在 jieba 词内结束（如 “画 / 作”、“叶 / 伊恩”）。
   - 只有这种悬空结尾的块，推迟到下一次读取和后文一起提交。
2. **队列为空时设最小块长**：例如 ≥3 个字或 ≥2 个词。末块和队列非空时不受限。
3. **纯标点块和空文本块**：并入下一块，不送给 Talker。
4. **数字、单位、专名**：没说完不提交（X2Streaming-TTS，arXiv:2608.18661 的待定缓冲）。

**决策层**：在 ABC 的 Bayes 决策里加一项“断流代价”。
- 设：提交 a 个单位产生 d(a) 秒语音（SDR 已经用 0.191 s/字、0.339 s/词估计）；当前队列 q；下一次能接着提交的期望时间 E[τ]。
- 预期空白为 g(a) = max(0, E[τ] − q − d(a))。
- 把 g(a) 和现有的延迟代价、改写代价一起最小化。小块后面如果会空很久，就不划算。
- E[τ] 可以用已记录的 drafts 估计：统计“当前草稿稳定的前缀之后，过多久能再提交 ≥n 个单位”。

**依据**：
- CLASI（arXiv:2407.21646）只提交完整语义块，切分方式来自专业译员的标注。
- X2Streaming-TTS 按容量分段：攒到一定量再在标点处切。
- SAT（arXiv:2010.10048）的做法正好相反、也互补：Talker 快说完时强制多提交一个词，避免断流。

**怎么验证**：
- 先用已记录的 drafts 离线模拟新规则，做初筛。这是近似：少提交以后，后面的草稿可能会变。
- 再正式重跑 Thinker 和 Talker，用第 3 节的整套指标，加上 ASR-BLEU 和 LAAL 对比。
- 建议的通过判据：
  - 有 ≥1 s 停顿的句子降到 m3 的水平（约 48% / 39%）以下；
  - 短语内和词内的超额停顿减半；
  - LAAL 增加不超过 0.3 s；
  - ASR-BLEU 不下降。

### 思路二：口语清洗　【推理 → Thinker 训练】　针对 P4，间接改善 P5

**推理层**，马上可以做：
- 提交前删掉口头禅：uh / um / er / ah，嗯 / 呃；
- 合并紧邻重复的功能词，例如 “their, their” 改成 “their”。
- 注意例外：“yes, yes” 这类有意义的重复，按参考译文的习惯可以保留一次。

**训练层**：把 Thinker 的训练目标改写成译员风格，去掉口头禅、重复和自我修正，并适当精简。
- CLASI 的合成数据就是用 LLM 做了这一步：去口头禅、精简。
- LLM-SI-Corpus（Sakai et al., EMNLP 2024，arXiv:2404.12299）：用 LLM 把译文改写成同传风格。
- Ko et al. 2023（IWSLT，arXiv:2306.08582）：加风格标签，在“同传风格”和“离线笔译风格”之间切换。

**预期**：
- 中→英的口头禅从每 100 词 2.7 个降到接近 0。
- 口头禅块是 Talker 漏读的主要来源，漏读也会跟着减少。

### 思路三：积压控制，压缩为主、变速兜底　【推理 + Thinker 训练，可选 Talker 训练】　针对 P2

已知事实：
- Talker 现在的 speed token 管不住语速（3.5 节）。
- SAT 测过：把语音加速到 1.33 倍，MOS 从 4.01 降到 3.34。
- Liu et al. 2022 测过：0.9–0.95 倍的时长缩放几乎没有代价，MOS 3.77、CER 5.1% 都不变。
- 所以：语速只能小幅调，大的积压要靠少说来消化。

1. **有上限的平滑变速**【推理】
   - 先削掉每块首尾的静音码。
   - 再在播放端用 WSOLA / PSOLA 做 0.9–1.15 倍的时间伸缩。倍率跟着队列长度走，用 EMA 平滑，相邻块之间的变化也设上限。
   - Hibiki 的做法是按落后程度平滑地加快，不在块之间突然跳。
2. **队列长时让 Thinker 压缩**【推理先用提示或规则，再做 Thinker 训练】
   - Zhang et al.（IWSLT 2026，arXiv:2601.11002）给机器同传加了“删减、断句”等译员动作，在 ACL 60/60 英→中上：BLEU 62.8 vs 57.2，LAAL 2.12 vs 2.52 s。
   - SAT 按积压程度调节压缩率，流畅度 MOS 接近真人译员。
   - 实现方式：把队列长度作为条件，“队列 >1.5 s 时用简洁风格”。
3. **让 Talker 的时长真正可控**【Talker 训练】
   - 构造变速训练对，让 speed token 的语速真正生效。
   - 或参考 IndexTTS2（arXiv:2506.21619），按语音 token 数精确控制时长。
   - 或参考 TransVIP（NeurIPS 2024，arXiv:2405.17809）的等时模块：输入“还剩多少时长”。

### 思路四：Talker 侧加固　【推理 → 小规模 Talker 训练】　针对 P5 和短块的读法

- **前瞻**：
  - Thinker 草稿里还没提交的部分，作为“只看不读”的前瞻文本交给 Talker，让短块知道后面要接什么。
  - 代码里已经有这两个开关：推理用 `si_infer.py --lookahead`，训练用 `pretrain_si.py --si-lookahead-max`。M2 推理时没有打开。
  - Liu et al. 2022 测过：由翻译模型自己给出的前瞻，效果相当于 1 个词的真实前瞻；随机或错误的前瞻反而更差。
- **防漏读、防乱读**：
  - 打开已有的 `--select-k`：一块采样多个候选，用 ASR 挑读得最准的。
  - 加 VALL-E 2（arXiv:2406.05370）式的重复感知采样。
- **只有在把块变长以后还有接缝问题时**，才考虑 boundary-aware 后训练（arXiv:2603.06444）：在随机词位截断句子训练 Talker，让它学会在边界停下，并给它 2 个词的前瞻。
  - 那篇论文提醒：不经训练、直接拿上一块的语音当提示，长音频上音色可能崩掉（说话人相似度降到 0.22，MOS 1.60）。
  - 我们的 Talker 本来就是在连续序列上训练的，3.6 节也显示接缝是连贯的，所以优先级低。

### 思路五：语音感知的强化学习　【Thinker 训练】　同时针对 P1 和 P2

- **奖励设计**：奖励 = 质量 − λ·延迟 − μ·异常停顿负担 − ν·拖尾。
  - 质量用 BLEU 或 COMET 的过程奖励（Hibiki-Zero 的做法）。
  - 时间轴用 Talker 时长估计来模拟（SDR 已有），不需要在训练循环里真的合成语音。
- **用质量给延迟奖励设门槛**（HPO，arXiv:2604.21045），防止奖励投机：
  - Seed LiveInterpret 2.0 报告过，只用时长奖励时，输出音频被砍掉约 35%，质量也下降；加上质量奖励后只缩短约 15%，质量不降。
- **可参考**：Seed LiveInterpret 2.0 的多轮奖励（延迟、主动翻译、质量）；SeqPO-SiMT（arXiv:2505.20622）；SimulPL（ICLR 2025，arXiv:2502.00634）。
- ABC 的 adapter 本身就可以作为初始策略。

### 思路六：文本和语音一起流式生成　【架构】　根治提交和合成分离带来的问题

- **SimulS2ST-Omni**（arXiv:2607.19810）：同样是 Thinker–Talker 结构，用一条联合的文本 + 语音码轨迹统一调度，RealSI 上的 ASR-BLEU 和 Seed LiveInterpret 2.0 持平。和我们现在的结构最接近，是升级成本最低的端到端方向。
- **Hibiki**（自然度 3.73 vs Seamless 2.18）和 **Hibiki-Zero**（67.2 vs 21.2）：
  - 按上下文对齐构造训练数据；
  - 用“随落后程度平滑提速”的 TTS 合成训练目标。
- **交错式流式 TTS**：CosyVoice 2（arXiv:2412.10117）、IST-LM（arXiv:2412.16102）、SpeakStream（arXiv:2505.19206）。
  - SpeakStream 带上下文的流式合成，自然度 3.7，而每次一个词独立合成只有 2.2。
- **代价**：音色克隆和英↔中的数据都要重建。

### 建议的执行顺序

| 步骤 | 内容 | 成本 | 主要看的指标 |
|---|---|---|---|
| 1 | 思路一的规则层；思路二的推理层；纯标点块和空块合并 | 1–3 天，不训练 | 有 ≥1 s 停顿的句子、短语内和词内超额停顿、单字块、Talker 读错率、ASR-BLEU、LAAL |
| 2 | 思路一的决策层（断流代价）；思路三的有上限变速和按队列压缩的提示 | 约 1 周 | 再加排队 p90、拖尾、相邻块语速跳变 |
| 3 | 思路二和思路三的 Thinker 训练（译员风格、按队列压缩）；思路四的前瞻 | 2–3 周 | 全套指标，再加一次小规模人评（SVIP 式 + A/B） |
| 4 | 思路五：强化学习 | 3–4 周 | 同上 |
| 5 | 思路六：联合流式 | 长期 | 同上，加长音频漂移 |

每一步都要和 M2 在同一套指标、同一个 Talker 种子下对比。fluency 评分方的结果回来以后，也用它核对第 3.2 节里规则版边界分类的结论。

## 6. 局限

- **边界分类**：用规则（标点 + jieba）判定，评分方用 LLM。jieba 会把一些词切开，例如“是 / 的”，所以词内接缝被低估了。
- **Talker 读错率**：包含 ASR 自身的错误，只适合系统之间横向比较。
- **ACL 是逐段跑的**：633 段各自从零开始，没有测整场演讲里的积压累积。上线时如果整场连续运行，积压可能更严重。
- **种子**：M2 只用了第一个 Talker 种子。m3 和 m6 用的是 seed1；中→英的 m3/m6 是 b0 = 1，M2 是 b0 = 0。
- **源语 VAD**：3.3 节在真实录音上用能量阈值做 VAD，结果是近似的。
- **UTMOS**：只在纯语音上打分，反映不了时间轴上的停顿。
