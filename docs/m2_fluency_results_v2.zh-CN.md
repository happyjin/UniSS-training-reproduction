方案：[m2_fluency_plan_v2.zh-CN.md](m2_fluency_plan_v2.zh-CN.md)。

前序：
- [m2_fluency_results_v1.zh-CN.md](m2_fluency_results_v1.zh-CN.md)：v1 结果；
- `reports/uniss_m2_fluency_results_v1/residual/`：v1 之后的剩余问题分析。

## 结论

1. **逐句评测掩盖了一个大问题：积压。**

   把 RealSI 的句子按原演讲拼回连续时间轴、队列跨句延续后，M2 的情况：

   | | 英→中 | 中→英 | ACL |
   |---|---|---|---|
   | 连续 LAAL（逐句只有 1.77 / 1.70 s） | 4.46 s | 3.90 s | 3.72 s |
   | 排队 p90 | 8.5 s | 6.6 s | 5.4 s |
   | 积压超过 2 s 的时间 | 49% | 46% | 45% |

   根本原因是**译音太长**：译音总时长是源语的 85%–88%，而演讲时间轴里 94%–96% 都是源语在说话。Talker 几乎要不停地说才能跟上，一旦某处一下子提交了一大段就会排队，而且很难消化掉。

2. **推荐配置：v1 的 N1 加 S1。** S1 是播放端的两个处理：削掉每块首尾超过 60 ms 的静音；只在身后有积压时加快播放，最多 1.10 倍，每句末块至少 1.05 倍，从不放慢。和 M2 相比：

   | | 英→中 | 中→英 |
   |---|---|---|
   | 逐句 ASR-BLEU | −0.48，不显著 | −0.08，不显著 |
   | 逐句 LAAL | 1.77 → 1.66 s | 1.70 → 1.67 s |
   | UTMOS | +0.03 | ±0 |
   | 异常停顿负担 | −25% | −22% |
   | 有 ≥1 s 停顿的句子 | 56.6% → 46.8% | 50.8% → 48.5% |
   | 句末 p90（源语结束后还在说） | 4.98 → 4.15 s | 4.71 → 4.00 s |
   | 连续 LAAL | 4.46 → 2.81 s | 3.90 → 2.75 s |
   | 排队 p90 | 8.5 → 3.6 s | 6.6 → 4.0 s |
   | 积压 > 2 s 的时间 | 49% → 30% | 46% → 30% |

   ACL：连续 LAAL 3.72 → 2.39 s，积压 > 2 s 的时间 45% → 24%；文本 BLEU 47.33 → 46.99，StreamLAAL 1.52 → 1.44 s。

3. **代价：积压和停顿此消彼长。** 在连续场景下，M2 停顿少，是因为它一直落后、队列里总有东西可说。积压压下去以后，Talker 追上了源语，就只能等 Thinker 出新内容：
   - 每分钟发声的 ≥1 s 停顿，英→中 5.4 → 7.3，中→英 5.7 → 9.0，ACL 5.6 → 7.7；
   - 逐句评测里，削静音也把一部分块首尾的静音挪进了块间空隙：有 ≥1 s 停顿的句子比 v1 的 N1 略多（英→中 43.9% → 46.8%）。

   要同时做到“不落后”又“不卡顿”，只能让 Thinker 更早地给出更短的译文，这是推理侧做不到的。

4. **三项改动各自的结果。**
   - **T（扣留设时限）：放弃。** 把扣下的碎片放出去以后，碎块和停顿又回来了。英→中 BLEU −0.94（显著），有 ≥1 s 停顿的句子 43.9% → 52.9%。
   - **U（空闲越久越催）：不作为默认。** 它降低了延迟：同样延迟下 BLEU 比直接调低偏置高约 1.3，ACL 的连续 LAAL 也最低。但它会把块切得更碎：在和 M2 相同延迟时，有 ≥1 s 停顿的句子回到 M2 的水平（英→中偏置 2：54.6%；中→英偏置 0.5：50.8%）。中→英偏置 0.5 时 BLEU +1.07（显著），可以作为“延迟和 BLEU 优先”的备选。
   - **S（播放端变速）：选用温和版 S1。**
     - 最初的 WSOLA 实现本身就会扣 UTMOS 0.24，即使几乎不变速也是如此。改用 20 ms 帧、周期 Hann 窗和归一化互相关后，不变速时只扣 0.05。
     - 加快 1.1 倍仍扣约 0.2，放慢到 0.92 倍同样扣分。所以去掉了放慢，只在有积压时加速。
     - 结果：S（含放慢）的 UTMOS −0.17 / −0.10；S1 的 UTMOS 与 M2 持平。

## 3. 变速的音质代价

N1 英→中 60 句，纯语音 UTMOS：

| 处理 | UTMOS |
|---|---|
| 原始 | 3.32 |
| 只削静音 | 3.29 |
| WSOLA v1，1.002 倍（几乎不变速） | 3.08 |
| WSOLA v2，1.0 倍 | 3.28 |
| WSOLA v2，1.1 倍 | 3.11 |
| 相位声码器，1.05 倍 | 1.48 |

所以变速只在有积压时才用，并设上限 1.10。在全集上，S1 的 UTMOS 与 M2 持平。

## 4. 是否做第 3 步和第 4 步

**第 3 步：训练 Thinker。建议做，而且现在就是主要瓶颈。** 三点证据：
1. 剩下的长停顿大多是 Thinker 自己在等，草稿里一个字都没有。推理侧的各种办法——调偏置、空闲催促、扣留时限——都只是在“延迟、BLEU、碎块”之间互相转移，降不下有 ≥1 s 停顿的句子。
2. 在连续场景下，译音时长是源语的 0.85–0.88。积压一被压下去，停顿就上来，反过来也一样。只有更短的译文才能同时减少两者。播放端加速的上限约 1.1 倍，再快音质就明显下降。
3. 中→英剩下的长停顿有 68% 在新句子开头，这需要译员式的顺译和重组，规则做不到。

建议的做法：
- **SFT**：用 LLM 把训练目标改写成译员风格。按源语顺序切段（顺译 / salami），删掉冗余，目标是“译音时长 / 源语时长”从 0.87 降到 0.70–0.75。中→英先做。
- **强化学习**：在连续时间轴模拟器上做（`si_talk_timeline.py` 的调度逻辑可以直接当环境），奖励 = 质量 − 连续延迟 − 积压 − ≥1 s 停顿，用质量给其他奖励设门槛。
- **目标**：不加播放端变速时，连续 LAAL ≤ 2.5 s，积压 > 2 s 的时间 ≤ 20%，有 ≥1 s 停顿的句子 ≤ 35%，ASR-BLEU 不降。

**第 4 步：Talker 侧。建议只做“时长真正可控”这一部分，和第 3 步并行或紧随其后；文本语音联合流式暂不做。**
- 播放端变速已经证明“按积压调语速”能大幅降低连续延迟（−1.1 ~ −1.7 s），但时域变速有约 0.2 的 UTMOS 代价。如果 Talker 能直接按 speed token 生成更快或更慢的语音（现在的 speed token 不起作用），就能拿到同样的收益而不损音质。
- 做法：用变速后的语音构造训练对，让 speed token 真正控制语速；或参考 IndexTTS2 按 token 数控制时长。
- 文本和语音联合流式（SimulS2ST-Omni / Hibiki 式）收益最大，但要重建音色克隆和英↔中数据，建议等第 3 步有结果后再评估。

## 局限

- 连续评测是事后拼接的：Thinker 仍是逐句或逐段跑的，SDR 的队列估计没有接上一句留下的积压。真正连续运行时，SDR 能看到积压，结果应该会好一些。
- 只有一个 Talker 种子；没有人评，UTMOS 和人的感受不一定一致。
- ACL 没有逐段参考译文，所以没有语音 ASR-BLEU。
