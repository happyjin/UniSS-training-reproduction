# M2 流畅度优化方案 v2：长音频连续评测 + 三项推理侧改动

承接：
- [m2_fluency_results_v1.zh-CN.md](m2_fluency_results_v1.zh-CN.md)：v1 的结果；
- `reports/uniss_m2_fluency_results_v1/residual/`：v1 之后的剩余问题分析。

起点 N1 是 v1 中不增加延迟的配置：
- 英→中：卫生（最小 3 字）+ 清洗，偏置 0.5；
- 中→英：卫生（最小 4 词）+ 清洗，偏置 −1。

这一轮不做外部评分，也不做人评。

## 第 1 项：长音频连续评测

**为什么需要**：RealSI 和 ACL 目前都是逐句或逐段评测，每一段都从空队列开始，看不到积压在整场演讲里的累积。

**做法**：`si_talk_timeline.py`。
1. 按演讲把各段拼回一条时间轴。每一块的提交时刻换算成：段在演讲中的偏移 + 段内提交时刻。
2. 只有一个 Talker：一块的开始时间 = max(提交时刻, 上一块结束时间)，队列跨段延续。
3. 音频从各段的时间轴 wav 中按块截取，拼到演讲时间轴上。

近似之处：Thinker 的 SDR 队列估计仍按段计算，没有接上一段留下的积压。

**指标**（逐演讲统计后汇总）：
- **积压**：排队时间 p50 / p90 / 最大；积压 > 2 s 的时间占比；
- **漂移**：排队时间随演讲时间的斜率，单位是秒/分钟；
- **演讲结束后还在说的时长**；
- **连续 LAAL**：每个单位取所在块在演讲时间轴上的实际开口时刻，减去段偏移，再按 LAAL 计算；
- **停顿**：≥1 s 停顿 / 每分钟发声、静音比、异常停顿负担（同 v1 口径）。

**数据**：
- RealSI：英→中、中→英各 10 场演讲；
- ACL 60/60 dev：5 场演讲，633 段。

## 第 2 项：三项推理侧改动

| 代号 | 改动 | 开关 | 针对的剩余问题 |
|---|---|---|---|
| T | 扣留设时限：规则扣下的内容在 Talker 空闲时最多再等一次读取 | `--hyg-hold-ms`（英→中 500，中→英 1000） | 英→中 59%、中→英 36% 的长停顿是规则扣着草稿里已有的内容 |
| U | 空闲越久越催：Talker 空闲时，等待偏置每秒下降 κ，下限 −3 | `--sw-urgency κ`（κ = 1、2） | 英→中 40%、中→英 63% 的长停顿是 Thinker 自己在等 |
| S | 播放端有上限的平滑变速（因果，只看当时的队列）：身后有积压时加快（最多 1.15 倍）；身后没有内容、源语未结束时放慢到 0.92 倍；每句末块至少 1.10 倍；相邻块倍率变化 ≤ 0.1。用 WSOLA 实现 | `si_talk_timeline.py --tempo` | 拖尾（全部来自最后一块）、积压，以及跟不上时的空隙 |

**变体**（每个方向）：
- N1 + T、N1 + U1、N1 + U2、N1 + T + U1、N1 + T + U2；
- 再加一组：把偏置调回 M2 的值后再加 T + U1，用来在延迟持平时比较；
- S 叠加在 M2、N1 和最好的 Thinker 变体上。

ACL 上跑 N1、N1 + T、N1 + T + U1，以及 M2（已有）。

## 指标和判据

**RealSI 逐句**，沿用 v1 口径：语音 ASR-BLEU、LAAL、流畅度全套、UTMOS，对 M2 做配对 bootstrap。

**判据**，相对 M2：
1. ASR-BLEU 不显著下降；
2. LAAL 不增加，或增加 ≤ 0.1 s；
3. 有 ≥1 s 停顿的句子比 N1 再降 ≥ 10%，或者拖尾 / 连续积压明显下降，同时异常停顿负担不回升。

**连续评测**：比较 M2、N1 和最终配置的积压、漂移、演讲结束后时长、连续 LAAL 和停顿。

## 执行

- 全部 GPU 作业放进 gpuq5 队列并行跑：Thinker 1 卡，Talker 2 卡，ASR 1 卡，空闲卡由占用程序占住。
- 连续评测、变速、UTMOS 在 CPU 上多进程并行。
- 每一处代码改动检查无误后提交，最后推送到 `private` 的 main。
