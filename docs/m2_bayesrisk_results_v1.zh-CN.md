# 严格 Bayesian 提交策略（bayesrisk）在 M2 上的实现与对比

- 模型：[m2_test_time_bayes_model.zh-CN.md](m2_test_time_bayes_model.zh-CN.md)
- 方案：[m2_test_time_bayes_plan.zh-CN.md](m2_test_time_bayes_plan.zh-CN.md)
- 对照基线 v3：[m2_fluency_bayes_v3cfg.zh-CN.md](m2_fluency_bayes_v3cfg.zh-CN.md)。v3 = ABC + SDR + 提交卫生 + 清洗 + SQ Talker + 播放 s1b1.2q。
- 数据和命令：`reports/uniss_m2_bayesrisk_v1/`。
  - `final_*.json`：全部系统，相对 v3 默认点做配对 bootstrap。
  - `pair_<v3 点>.json`：相对延迟最近的 v3 点做配对 bootstrap。
  - `matched.md`：同等延迟下，各指标与插值后的 v3 曲线对比。
  - `abrupt/`：连续时间轴上的突兀停顿分析。
  - `utmos_all.jsonl`：逐句 UTMOS。

成本、代价和后验全部只在训练域留出集（UniST dev 805 句）上选择和拟合。RealSI 只用于最后一次测试；ACL 没有使用。

## 结论

1. **bayesrisk 没有在所有指标上都胜过 v3，推荐配置仍是 v3。**
2. **en→zh：ASR-BLEU 无提升，流畅度变差。**
   - **ASR-BLEU 无提升。** 在 LAAL 1.8–3.7 s 的 9 个系统上，与延迟最近的 v3 点相比，配对差值在 −0.50 到 +0.72 之间，没有一个显著。LAAL ≥ 2.5 s 的系统全部略低于 v3（−0.24 到 −0.50），不满足“同等延迟下 ASR-BLEU 不降”的门槛。
   - **UTMOS 普遍更低。** 低 0.01–0.08，其中三个系统显著：拟合后验 b0.5 低 0.064、在线 b0.5 低 0.084、在线 b0.75 低 0.042。
   - **突兀停顿更多。** 从每分钟 2.4–2.7 次增加到 2.8–4.3 次（同等延迟的 v3 点）。
3. **zh→en：拟合后验 + 在线更新（brPO）的 ASR-BLEU 有一致提升，但流畅度代价很大。**
   - **ASR-BLEU 方向一致为正。** brPO 的三个点相对最近的 v3 点分别为 +0.49、**+1.22（95% CI [0.21, 2.24]，p=0.015）**、+0.60，且延迟都不高于对照点超过 0.07 s。共做了 20 组配对，只有这一组显著，单独看要打折扣；但三个点方向一致。
   - **UTMOS 持平。** −0.03 到 0.00，都不显著。
   - **流畅度明显变差。**
     - 单字块从 8% 升到 21–27%；
     - 突兀停顿从每分钟 1.3–2.1 次升到 4.7–5.6 次，约为 2.5–3 倍；
     - 静音占比多 4–8 个百分点；
     - Talker 读错率从 0.037 升到 0.06–0.07；
     - ≥1 s 的停顿反而更少：每 100 词 2.1–2.5 次，v3 在同等延迟下为 2.6–3.4 次。
   - **定位。** 它是“用流畅度换内容”的另一个工作点，不是对 v3 的 Pareto 改进。
4. **zh→en ABC 后验 + 碎块/切点代价（brA）：与 v3 基本打平。** ASR-BLEU −0.41 到 +0.29，都不显著；UTMOS 持平；突兀停顿与 v3 相当（1.9–2.1 次，v3 为 1.3–2.1 次）。
5. **原因有两条。**
   - **损失没有完整覆盖“听感”。** 模型对“这段文字会不会被改”的校准明显变好：dev 上 ECE 从 0.069 降到 0.006（en→zh）、从 0.076 降到 0.018（zh→en）。但能用来区分好坏的信息只多了一点：AUC 只提高 0.01–0.014。
   - **约束不够硬。** bayesrisk 会在短语中间、只要该处足够确定就提交。v3 的提交卫生（至少 3 字或 4 词）在 bayesrisk 里换成了有限的碎块代价：zh→en 的 P 配置为 0，A 配置为 0.5。所以内容提交得更早、更准，但切点落在短语中间的比例从 25% 升到 40–44%，小句边界从 21% 降到 10%。
   - **dev 指标测不出这类停顿。** dev 上的模拟时间轴只统计 ≥1 s 的空隙，统计不到这类短而突兀的停顿，所以 dev 选出的配置在这一点上没有受到约束。

## 1. 实现

| 部件 | 文件 | 说明 |
|---|---|---|
| 决策 | `evaluation/si_bayesrisk.py` | 草稿禁止输出等待标记，取 top-20 logprobs；8 个统计量（bias, abc, forced, content, agree, pause, pos, start）；用 MC 对 θ 积分得到逐单位存活概率；对损失取 argmin；复读的动作代价为 ∞ |
| 入口 | `evaluation/si_thinker_stream.py --policy bayesrisk` | `--br-*` 参数；默认关闭，v3 行为不变 |
| 拟合 | `data_clean/fit_bayesrisk_posterior.py` | Laplace 后验、2 折交叉验证（按句，加盐哈希）、过度离散校正、Ψ 用经验 Bayes 估计 |
| dev 评估 | `evaluation/si_bayesrisk_dev_eval.py` | 文本 BLEU、模拟时间轴上的 LAAL、单字块、≥1 s 空隙 |

**实现时发现并修正、需要回写到模型文档的三点（已写入模型文档 §11）：**

1. **按事件计的损失在全局 argmin 下会退化。** 论文中的写法是“一次修改只计一次代价”，此时全局最优动作会把含可疑单位的长草稿整段说出去（dev 上 LAAL 0.5–1.3 s，BLEU 大幅下降）。
   - 改为按单位计的损失：$R(a)=C_\mathrm{err}\,\mathbb E[(a-S)^+]+C_\mathrm{lat}D\,\mathbb E[(\min(S,K)-a)^+]$。
   - 它的 argmin 等价于对边际存活概率取阈值：$P(S\ge a)>1/(1+C_\mathrm{lat}D)$，因此是单调的。
   - 先验下它就是 ABC（命题 1 仍然成立）。
2. **动作集合必须限制在 token 边界上。** 拟合后验曾在多字 token 内部提交，例如“作”|“​​品外”，导致 Thinker 续写出零宽字符和断词，en→zh BLEU 下降 3–5。限制后问题消失。
3. **token 内部的单位没有 ABC 证据。** 为此新增 `forced` 统计量，其先验均值为 ABC 的上限 15，保证“只用先验”时与 ABC 完全一致。

**过度离散（近似 A4）比预想严重。** 同一句的多次读取高度相关，Pearson 离散度为 6.1（en→zh）和 7.3（zh→en）。因此 Σ 乘以离散度，在线更新的似然权重取 1/离散度。

### 3.4 在线后验做了什么

- **zh→en 在线更新把每场的 bias 下调。** 10 场全部低于 dev 的 1.14，变为 0.84–1.28。也就是说，模型认为 RealSI 上的草稿比训练域更容易被改，因此更谨慎。
- **增益来自这次下调。** 延迟只增加 0.13 s（P b0 → PO b0），ASR-BLEU 提高 1.0。这是 PO 优于 P 的来源，与“场效应”假设一致。
- **en→zh 的 Ψ 由经验 Bayes 估为 0.01。** 各场后验几乎不动，所以 PFO 与 PF 没有差别。

## 4. 对照“ASR-BLEU 不降”的硬门槛

| 方向 | 配置 | ASR-BLEU 门槛 | 流畅度 | 结论 |
|---|---|---|---|---|
| en→zh | A / PF / PFO | 低延迟段通过（不显著）；LAAL ≥ 2.5 s 全部略低 | 突兀停顿 ×1.4–1.8，UTMOS 显著下降 | **不采用** |
| zh→en | A | 通过（±0.4，不显著） | 与 v3 相当，单字块略多 | 不优于 v3，**不采用** |
| zh→en | PO | 通过，b0 显著 +1.22 | 突兀停顿 ×2.5–3，单字块 ×3 | **只在“内容优先、可接受碎片化”的场景下作为备选**，不替代 v3 |

## 5. 下一步建议（都只用训练域 dev 选择，不再在 RealSI 上调参）

1. **把 v3 的提交卫生作为硬约束放回 bayesrisk。** 按命题 2，这相当于碎块代价取 ∞ 的极限。同时把切点代价改为按切点类型计：短语中间 ≫ 小句 ≈ 0。PO 的 BLEU 增益来自“更准地扣”，而不是来自碎片化，两者应当可以分开。
2. **dev 评估补上切点类型统计。** 现在的 dev 时间轴只看 ≥1 s 空隙，看不到这次真正变差的“短语中间停顿”和单字块，导致 dev 选择偏向碎片化。
3. **en→zh 不再继续这条线。** 校准提升没有转化为排序提升（AUC 只 +0.014），v3 的 SDR 已经吸收了大部分可得的收益。
4. **如果按第 1 点做出新的 PO 版本，RealSI 只测一次。** 判定标准为：同等延迟下 ASR-BLEU ≥ v3，且突兀停顿 ≤ v3 的 1.2 倍。
