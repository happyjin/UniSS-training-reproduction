## 2. 指标定义（先定义，后计算）

**参考单元**：与 v7 tcpBLEU 相同。同一说话人间隔 <1 s 的已评分发言连成一个单元，输出片段按 v7 的规则分配到单元。

**重叠标记**：某个参考单元的时长里，如果 ≥20% 与其他说话人的已标注语音重叠（hesitation 也算），记为"重叠单元"(ov)，否则记为 1spk。

**新增规则**：一个输出片段跨两个单元时，v7 的做法是整段只算给重叠最多的那个单元。v8 改为按时间比例拆分文本（按字符或词），分别算入两个单元。主结果用新规则，v7 规则作为敏感性分析同时报告。

**指标**：
- **tcpBLEU-ov / tcpBLEU-1spk**：只在重叠单元或只在非重叠单元上计算的 corpus BLEU。插入片段按所在时间判定区域：时间和其他说话人语音重叠的，算入 ov。
- **并发说话人召回 CR**：取两个不同说话人、彼此重叠 ≥0.5 s 的参考发言对。一对算"召回"的条件是：两人各自都有输出片段，且输出片段归属到各自匹配的说话人、和发言在 1 s 容差内有时间交集。CR = 召回的对数 / 总对数。
- **塌缩率**：上述发言对中，两人的内容落进了同一个输出说话人。**重复率**：同一个参考单元被两个不同输出片段重复翻译，判定标准是两个片段之间的 chrF ≥50。
- **短插话召回**：≤0.5 s、0.5–1 s 两档，各分"有重叠 / 无重叠"。
- **tcpSem**：沿用 tcpBLEU 的单元配对，按单元计算 LaBSE 余弦相似度，再按参考长度加权平均。
- **延迟**：
  - 文本完成延迟：输出片段的提交时刻减去源片段结束时刻；
  - 听众端完成延迟：在 v7 的定义上加入读取排队递推，即每次读取开始 = max(计划时刻, 上一次读取结束)，读取耗时用 v6 实测的单流中位数；
  - 两者都按 ov 和 1spk 分开报告。
- **"说完之前就提交"的比例**：在源发言结束之前已经提交的输出字符或词占全部输出的比例。

**参考集**：与 v7 Table 2 相同。En→Zh 如果完成了 B1（为未评分语音补 MT 参考），扩展参考集上的结果作为次要结果报告；**主检验用 v7 的参考集**。

## 3. 因果重标规则（Relabel，先定死）

每个输出片段在提交时刻 t 只能看到截至 t − 1.04 s 的分离器后验。规则：
1. 在片段的源时间区间 [a, b] 内，计算每个说话人位置的平均后验，取最大的那个；
2. 没有可用帧时，取 [a − 2 s, t − 1.04 s] 区间内最活跃的说话人位置；
3. 仍然没有，就标为"未知"，在评分中当作一个未匹配的输出说话人。

不允许使用整场会议的说话人映射，也不允许看未来的帧。

## 4. 确认性检验（统一做 Holm 校正，共 12 项）

统计方法：按会议做精确符号翻转置换检验（会议数为 16 或 20）；同时报 10k 次会议重抽样 bootstrap 区间，每次重抽样叠加一次解码噪声 N(0, σ_dec(n)²)，取分位数作为区间。σ_dec 沿用 v7 的定义。判为"成立"必须同时满足 p_Holm < 0.05 且区间不含 0（E-lat 用其非劣界）。

| 编号 | 集合 | 假设（方向） |
|---|---|---|
| E-ov1-{en2zh, zh2en, ali} | 3 个 | tcpBLEU-ov(Simul) − tcpBLEU-ov(Relabel) > 0 |
| E-ov2-{en2zh, zh2en, ali} | 3 个 | CR(Simul) − CR(Relabel) > 0 |
| E-lat-{en2zh, zh2en, ali} | 3 个 | 非劣：Simul 的文本完成延迟中位数，ov 减 1spk 的差 < 0.5 s（单侧，对 0.5 s 界做检验） |
| E-pol-{en2zh, zh2en, ali} | 3 个 | Simul 的文本完成延迟中位数低于 PLA2（单侧）；同时报 tcpBLEU 差的双侧区间 |

## 5. 失败或持平时怎么写（先定死）

- **E-ov1、E-ov2 不成立**：不声称"speaker 流在重叠语音上有效"。贡献改为"联合窗口翻译 + 在线身份管理 + 结构化输出"，与 Relabel 持平如实写出。
- **E-ov1 成立，E-ov2 不成立**：只说重叠区的翻译质量更好，不说更不容易漏人。
- **E-lat 不成立**：不写"重叠下延迟不增加"，报告实际增量。
- **E-pol 不成立**：不写"学到的策略更省延迟"；质量也持平时，写成"格式统一的工程选择"。
- **墙钟回放 RTF ≥ 1**：不写"约 2 s 的实时延迟"，系统改称"模拟实时输入的研究原型"。
- 短插话修复（C2）只在 dev 上选方案，测试集只跑一次。不论成败，结果都报告。
