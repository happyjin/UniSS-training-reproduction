## 0. 总原则（所有新增实验共同遵守）

1. **RealSI / ACL60/60 只做测试。** 新变体（逐单位队列、全局 argmin、重校准等）的超参数一律在 dev（805 条 held-out 训练域话语 + 已有 dev 选择集）上定；测试集只跑一次，结果不回头改设置。
2. **ASR-BLEU 硬门槛。** 新变体只有在 dev 上 ASR-BLEU 不低于当前 QABC 时才进入测试；进入测试后不管好坏都报告，但只有不降 ASR-BLEU 的变体才能替换主系统，否则只作为消融。
3. **先注册再运行。** 多 adapter seed 重跑、按 talk 的簇 bootstrap 等新的确认性分析，先写 `prereg_v5`（端点、seed 列表、统计单位、判定规则）并 commit，commit 时间戳就是可核验的注册工件，然后才跑。
4. 所有新代码、新脚本只新增文件，不覆盖已有实验目录；每个可用改动单独 commit。

## 1. 逐条判断与改进

记号：**[写]** 只改文字；**[算]** 用已有输出重新计算，不需要新解码；**[跑]** 需要新的 GPU 解码或训练。

### M1 理论只覆盖逐单位 myopic 代理，不覆盖整段前缀动作（高）

- **判断：成立。** Remark 1、附录 Table 4（9.4–22.0% 的 read 顺序停止点 ≠ 全局最优）、Theorem 2 不覆盖过早停止的后续延期成本，都是我们自己写的；问题在于摘要和贡献的措辞比定理强。
- **改进：**
  1. [写] 摘要、引言、贡献统一改成「对给定单步条件损失的 myopic Bayes 动作」；Theorem 2 改称「逐单位决策 regret 上界」，明确不覆盖整段动作、FR、队列动态。
  2. [跑] **端到端比较顺序规则与全局 argmin。** 同一个后验、队列、FR 下实现 `a* = argmin_a L(a)`：对适配后 Thinker 的完整草稿做一次 teacher-forced 前向，拿到每个位置的 ⟨wait⟩ 概率 → ρ(u) 全序列 → 计算每个 a 的总风险取最小。成本约等于一次额外前向。在 RealSI 15 窗（1 个 talker seed）和 ACL 15 窗上比 BLEU / ASR-BLEU / word-aligned LAAL，并报告整段动作 regret（用全上下文标签算的实际损失之差）和错误/延迟分解，按队列状态（q=0、0<q<Δ、q≥Δ）分层。
  3. [跑，可选] 一步 look-ahead（比较「现在提交 a」和「等一轮再决定」的期望损失，用当前后验近似下一轮）。实现复杂度高，P2，时间不够就在局限里写明。
- **回答 Q1：** 直接用 2 的结果。若全局 argmin 不更好，说明 9–22% 的分歧在实际中损失小；若更好，就把它作为改进变体（过 ASR-BLEU 门槛后）。

### M2 RealSI 语音 E1 显著，而提交文本 E1 不显著，收益来源不清（高）

- **判断：成立，而且是最要紧的一条。** 文本 E1 +0.57/+0.19（单侧 p=0.057/0.240）是我们在 prereg 修正里自己登记的结果。word-aligned LAAL 已有（Table 32），但没有和 BLEU 同表、同预算报告。
- **改进：**
  1. [算] 每个主预算同一张表报告：word-aligned LAAL、text BLEU、ASR-BLEU、块级 TTS 误读率、平均块长、单单位块比例。
  2. [算] **分解。** 对每个策略算「语音相对自身提交文本的保真度」（ASR 转写对提交文本的 BLEU/CER），把 ASR-BLEU 差拆成「文本差」+「实现差（TTS+ASR）」；再按句做回归：ΔASR-BLEU ~ Δtext BLEU + Δ块数 + Δ误读率 + Δ静音时长，报告各项贡献。
  3. [跑] **同文本重合成对照。** 把 QABC 的最终提交文本按 LA2 的块边界重新切块、再用同一 Talker 合成（反之亦然），2×2 拆出「提交内容」与「块划分」各自的效应。只需 Talker + ASR，不需要 Thinker。
  4. [写] 结论按结果如实写：若收益主要来自块划分/实现，就把论点改为「QABC 产生更易于语音实现的提交」，而不是「提交的词更好」。
  5. [需要你安排] **人工评测。** 双语 AB 偏好 + 忠实度（每方向约 50 对，2–3 名评审），以及断句不自然率。这需要人工，不能由我完成；在评测完成前，用 UTMOS/自动断句指标作为代理并在局限里写明。

### M4 队列损失不是块内单位真实的听觉延迟（高）

- **判断：成立。** 审稿人的反例对：同一次提交里的第 4 个单位本来就要排在前 3 个单位之后，等一轮的增量延迟应接近 max(0, Δ − q_k − 3r)，而不是统一 D_k。这是本文最有特色的部分，值得修好而不只是承认。
- **改进：**
  1. [写 + 跑] **块内队列版本。** 把 D_k 改为逐单位 D_k(u) = max(0, Δ − q_k − r·(u−1))，阈值 τ(q_k + r(u−1)) 随位置下降；推导只改一行，Theorem 1 仍对新损失精确成立。实现上是按位置变化的 ⟨wait⟩ bias。在 dev 上过 ASR-BLEU 门槛后再进测试；不管是否替换主系统，都作为消融报告。
  2. [算] **实测延迟对照。** 用 `si_talk_timeline` 已记录的块起播时间，算每个单位真实的「推迟一轮的增量等待」，与模型中的 D_k、D_k(u) 比较（偏差、相关系数、按队列分层）。
  3. [跑，可选] 用实际音频时长替代平均速率 r 更新队列；含速度调整的播放器下重算。
  4. [写] 「exact」只对抽象损失成立；τ_max = 0.9975 的截断明确列为工程处理。

### M5 缺少同等监督的学习型基线；简单 queue gate 没被稳定超过（高）

- **判断：部分成立。** 需要说清楚：QABC 的 adapter 本身就是用 235k 个标签训练的二元 stable/wait 分类器，Table 11 的 constant-risk 就是「同一分类器 + 常数阈值」，Table 10 的 binary gate 就是「同一 hazard + 简单队列门」。这两项其实已覆盖审稿人的 (i)(iii)，但正文没有这样命名，而且 binary gate 的比较不显著。
- **改进：**
  1. [写] 把 Table 10/11 的对照重新命名为「学习型分类器 + 常数阈值」「学习型分类器 + 二值队列门」，在正文主表中出现；明确本文增量是「由损失导出的连续队列阈值」，不是分类器本身。
  2. [跑] **binary gate 加大检验力度。** 现有比较只在部分窗口；在完整 15 窗、3 个 talker seed 上比较「导出阈值」与「二值门」，并按队列状态分层。若仍不显著，就如实写「连续阈值与简单门相当，优势集中在 0<q<Δ 区间」（以结果为准）。
  3. [跑] **学习型停止网络。** 在 Thinker 隐状态上训练小头直接回归稳定长度（同样 235k 标签、同样 roll-in），按 dev 上选定的余量提交；与 QABC 同参数量级比较。比 RL 基线便宜得多。
  4. [写] 策略梯度/模仿学习基线成本高，不做；在局限里说明，并引用已发表的学习型同传策略作为未来对比。
