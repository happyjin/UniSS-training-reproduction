## 2. 中文 AMI（zh→en 数据）：复用现成的中文语音，不重新合成

不跑 TTS。英→中数据里每句话都已有中文语音，直接反过来用：中文语音作源，AMI 英文转写作目标文本，AMI 英文原声作目标语音参考。
唯一要新做的是把单句中文语音按时间轴拼成多人会议音轨（CPU 混音），因为 MIST 的输入是整段多人单声道音频。
下文的“合成会议”都指这种拼接，不是重新合成。

### 2.1 材料

| 内容 | 来源 |
|---|---|
| 中文语音 | 翻译链里每句 AMI 话语的中文合成语音（VoxCPM2，克隆该句原说话人的音色），可用 126,732 / 128,911 句 |
| 时间、说话人 | AMI 原始话语的起止时间和说话人，与英→中完全相同 |
| 参考译文 | AMI 英文人工转写（经 §2.4 规范化），所以 zh→en 方向的参考是人写的 |
| 切窗 | 沿用英→中的参考窗口（话语组）；分离器窗口按合成音频重新切 |

### 2.2 放回时间轴

| 步骤 | 做法 |
|---|---|
| 1. 去首尾静音 | 合成语音按能量（峰值以下 40 dB）裁掉首尾静音，保留 50 ms 余量 |
| 2. 对齐时长 | 先用最简单的做法：去静音后按原起点放置，不变速，统计重叠比例变化（§2.3）。只有超出判据时才启用：<br>• 1 < ratio ≤ 1.3（ratio = 中文时长 / 英文原时长）：用 tempo 变速（不变调）压到原时长；<br>• ratio > 1.3：先压到 1.3 倍，剩余部分顺延 |
| 3. 处理顺延 | 顺延只推后同一说话人后面的话语，不同说话人之间的重叠关系保持不变 |
| 4. 语气词 | 纯语气词（UM、UH 等）没有中文，放静音 |
| 5. 背景 | 从同场 IHM-mix 的无人说话片段取底噪，以原始电平叠加，避免“干净录音”过于简单 |
| 6. 产出 | 每场会议一个 16 kHz 单声道 wav，以及新的话语时间表（起止、说话人、中文文本、英文参考）。两者都是新文件，不覆盖英→中数据 |

### 2.3 质量控制

- 统计改动前后的重叠比例、多人窗口比例和窗口时长，要求和英文 AMI 相差不超过 ±20%，超出就调整变速上限；
- 音色一致性：同一说话人各句合成语音的 ECAPA 相似度太低的（例如短句 "OKAY" 只有 0.19）照样放入，但做标记，并统计它们对分离器的影响；
- 抽 20 段人工试听（做一个试听页）。

### 2.4 英文参考规范化

- AMI 转写是全大写、无标点，还有填充词。
- 用文本 LLM 做“只加大小写和标点，删除填充词和口吃重复，不改其他词”的规范化，再自动核对：规范化前后去掉标点和大小写的词序列，编辑距离只允许来自填充词。
- 评测用 sacreBLEU 13a 分词，区分大小写；同时报告不区分大小写的分数。

### 2.5 分离器后验

- 合成会议 171 场 × 两种预设（离线 / 1.04 s 前瞻），8 卡约 1 小时；
- 用 `build_ami_gstar_si_rows.py` 重新建槽位映射（式 9）和窗口，输出到 `e2e_gstar_zh2en_v1/`。

## 3. 多说话人读写时机：ABC 标签

### 3.1 和现有 MIST-Simul 的区别

| | 现有 MIST-Simul（v2 论文） | 本方案（ABC 式） |
|---|---|---|
| 目标内容 | 参考译文按标点切块 | 模型自己的贪心输出（不改变翻译风格） |
| 提交时机 | 固定“对应源词结束 + 1 s” | 草稿和整窗续写的最长公共前缀，内容稳定就提交 |
| 需要词级对齐 | 需要（中文合成源没有） | 不需要 |
| 读取间隔 | 只有 Δ = 1 s（0.5 s 时失效） | Δ ∈ {0.5, 1, 2, 4} s 混合 |
| 延迟调节 | 无 | ⟨wait⟩ 偏置 b，以及 SDR |

### 3.2 标签怎么生成（每个训练窗口）

1. 用 O2（双向离线 MIST，§4）对窗口做读取，随机选一个 Δ ∈ {0.5, 1, 2, 4} s，读取时刻 t_r = min(rΔ, T)。
2. 第 r 次读取：
   - **草稿 d_r**：在 x≤t_r 和因果后验（低延迟预设，t_r − 1.04 s 之后置零）上，从已提交前缀 c_r 续写到结束；
   - **oracle y*_r**：同一模型在整窗音频和离线后验上，从同一个 c_r 续写到结束；
   - **稳定长度** S_r = lcp(d_r, y*_r)，按 token 计，说话人 token 和时间 token 都算在内；
   - **目标** = d_r 的前 S_r 个 token，再接 ⟨wait⟩；最后一次读取为“剩余部分 + ⟨eos⟩”；
   - 下一次读取的已提交前缀 c_{r+1} = c_r 加上本次的稳定前缀（和单人 ABC 一样滚动生成）。
3. 句子未说完时，草稿在截断处写出的结束时间 token 和 oracle 对不上，lcp 自然停在文字中间，下一次读取再接着写同一段。在线解析器已经支持未闭合的段，Talker 按块播放。
4. 起始读取：按单人 fluency v3 的起始 oracle（`build_start_oracle.py`）思路，前两次读取若草稿语序和 oracle 不同，目标为 ⟨wait⟩。这条做成可选开关，在开发集上比较有无。

### 3.3 规模与成本

- 抽训练窗口：英→中 6,000 个 + 中→英 6,000 个（只抽通过审查的窗口；多人窗口按 1.5 倍过采样）；
- 每个窗口平均约 6–12 次读取，每次读取两遍解码（草稿 + oracle）。vLLM 不支持交错嵌入，只能用 HF 批量解码；
- 估计 8 卡约 7–9 小时。先用 200 个窗口试跑，测出实际速度后再定规模；
- 另加 20% 整窗离线行、15% 单人行（取自现有 `si_thinker_selfdistill_v2`，两个方向都有）；
- 代码改动：`gstar_si_stream_online.py` 新增 `--dump-oracle` 模式（同一批窗口一次给出草稿和整窗续写）；新增 `build_ami_gstar_abc_rows.py`。

## 5. 推理：ABC + SDR + FR

| 部件 | 多说话人下的做法 |
|---|---|
| ABC 阈值 | 第 u 个 token 处的 ⟨wait⟩ 概率加偏置 b 后与阈值比较（同 v3 论文式 8）。扫 b ∈ {−1, 0, 1, 2} 得到延迟–质量曲线 |
| SDR | 队列 q 是唯一的译员声道，所有说话人共用，换人时加 0.2 s。τ_k = 1 − (1 − τ0)·max(0, Δ − q_k)/Δ；单位时长：中文 0.19 s/字，英文 0.34 s/词 |
| FR | 块不得以虚词或单字结尾；Talker 空闲时，中文至少 3 字、英文至少 4 词，除非块以从句结束；清掉填充词和重复。全部按段执行，一段结束（遇到结束时间 token）时不受最短长度限制 |
| Talker | 不变（UniSS T1c）；中→英时用英文输出、中文源音色 |

代码：`gstar_si_stream_online.py` 新增 `--policy abc`（偏置、SDR 队列、FR 卫生规则），复用 `si_thinker_stream.py` 里已有的 hygiene 和 clean 函数。

## 9. 风险和对策

| 风险 | 对策 |
|---|---|
| 合成中文语音变速后重叠结构失真 | §2.3 的统计判据；超标就降低变速上限、改为顺延 |
| 短句合成音色偏离原说话人，分离器把同一人分成多个槽位 | 统计分离器在合成会议上的 DER 和槽位数；必要时短句用该说话人长句的音色重新合成（需要再跑 VoxCPM2，作为后备） |
| ABC 标签生成太慢 | 先试 200 窗口测速，按速度调整窗口数；Δ = 4 s 的读取少，占比可以调低 |
| 双向训练伤害英→中 | O2 和 O-G1 在英→中上对比（判据：cpBLEU_sess 下降不超过 0.5）；必要时调整两个方向的比例 |
| 说话人 token 被过早提交而出错 | lcp 本身会推迟不确定的说话人；另报告“已提交说话人被证明错误”的比例 |

### 11.1 拼接中文会议（CPU，171 场会议多进程并行，约 10–20 分钟）

脚本：`data_clean/build_ami_zh_mix.py`。只新建 `session_audio/zh_mix/` 和 `zh_mix_v1/`，不改任何已有文件。

1. 从 `index/chain_en_zh_ihm` 取每句的会议、说话人、起止时间，以及中文 wav 在 tar 包里的位置；
2. 裁掉首尾静音（峰值以下 40 dB，保留 50 ms）；
3. 每句按该说话人在 IHM 原声里的平均响度做 RMS 归一；
4. 按原 `begin_time` 叠加到整场会议长度的空音轨上；
5. 同一说话人的相邻句如果重叠，把后一句顺延（一个人不可能同时说两句）；
6. 写出整场 wav 和新的话语表（`zh_mix_v1/utts.jsonl`：新起止、说话人、中文文本、英文参考、各项质量标记）。

| # | 检查项 | 判据 | 不过时怎么修 |
|---|---|---|---|
| A1 | 覆盖率：有中文语音的非语气词话语占比（整体和逐场） | 每场 ≥ 95% | 缺语音的话语所在窗口剔除（同英→中的审查规则） |
| A2 | 裁剪后时长比（中文 / 英文原句） | 统计 >2 倍的句子，抽查是否 TTS 失败或句内长静音 | 句内静音压到 ≤0.3 s；仍超长且中文 ASR 也错的视为坏样本，剔除 |
| A3 | 重叠统计（话语重叠时长占比、多人窗口比例、重叠窗口比例），和英文对比 | 相对差 ≤ 20%（整体和逐场） | 超标就启用 tempo 变速（≤1.3 倍）后重拼 |
| A4 | 同一说话人自重叠 | 0 | 顺延（11.1 第 5 步） |
| A5 | 削波：叠加后峰值 | 峰值 < 0.99 的样本占比 > 99.9% | 整场按比例缩放 |
| A6 | 可懂度：沿用翻译链的 Whisper CER，加 Paraformer 抽查 | CER > 0.3 的句子打标记，所在窗口不进严格子集 | 不进测试集 |
| A7 | 同一说话人音色一致性（WavLM：每句与该人全部句子平均嵌入的余弦） | 统计分布，最低 5% 打标记 | 测试集报告时单列；训练照用 |
| A8 | 分离器（11.3 之后）：Nemotron 在中文会议上的 DER、每场检测到的槽位数和真实人数 | DER 不比英文 IHM-mix（27.7%）高 10 个点以上；槽位数 ≈ 真实人数 | 查看是不是 A7 的音色问题导致一人分成多个槽位；必要时对低一致性句子换成该说话人另一句的音色重合成（后备，需 VoxCPM2） |
| A9 | 人工试听：4 场测试会议各前 3 分钟，左声道英文原声、右声道中文拼接音轨，做一个试听页 | 你听后确认 | 按反馈修改 |

全部审核结果写进 `zh_mix_v1/audit.json` 和一份中文报告；修过的问题在报告里逐条记录“问题 → 修改 → 复查结果”。

### 11.4 并行排期（8×H200；CPU、写代码、GPU 三条线并行）

| 时段 | GPU 线 | CPU 线 | 代码线 |
|---|---|---|---|
| 第 1 天上午 | 2 卡：英文转写规范化；4 卡（如选做）：SDM 后验导出和零样本评测 | 11.0 脚本入库；11.1 拼接；11.2 A1–A7 审核和修复 | `--dump-oracle`、`--policy abc`（ABC 阈值 + SDR + FR）、ABC 读取行构造器、因果音色参考 |
| 第 1 天下午 | 8 卡：中文会议后验导出（约 1 小时）→ A8 → 构造 zh2en 窗口和训练行 → 训练 O2（约 80 分钟） | A9 试听页 | 2 卡冒烟测试新代码 |
| 第 1 天夜间 | 训练 O2-nosd（约 80 分钟），然后 8 卡生成 ABC 标签（先试 200 窗口测速，再全量约 7–9 小时） | 汇总审核报告 | — |
| 第 2 天 | 离线评测矩阵（两个方向 × 6 个系统，排队跑满 8 卡，约 3 小时）；训练 S2（约 2 小时） | 打分、bootstrap、表格脚本 | 论文 v3 的方法部分先写 |
| 第 3 天 | 同传矩阵（偏置扫描、Δ、SDR/FR 消融，约 8 小时）；语音合成和听感指标；单人 RealSI 回归 | 打分、显著性检验 | 论文 v3 的结果部分 |
| 第 3.5 天 | 选做：第二个随机种子 | — | 论文 v3 编译、严格审稿、修改 |

并行原则：
- GPU 任务统一走 gpuq6 队列，卡一空就补上；vLLM 启动间隔不少于 60 秒；
- 训练要独占 8 卡，所以排在评测空档；
- 所有任务用 `setsid nohup` 后台运行；
- 写代码和写论文不等 GPU。

按这个排法，原计划 4–5 天可以压到约 3–3.5 天。
