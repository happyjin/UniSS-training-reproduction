# 同传 Bayesian 提交策略 v2：实现与 RealSI 结果

- 模型与方案：[m2_bayesrisk_v2_model.zh-CN.md](m2_bayesrisk_v2_model.zh-CN.md)
- 上一版：[m2_bayesrisk_results_v1.zh-CN.md](m2_bayesrisk_results_v1.zh-CN.md)
- 数据与命令：`reports/uniss_m2_bayesrisk_v2/`
  - `dev/`：各轮 dev 结果；`dev_matched.py` 把各系统放到同 LAAL 的 v3 dev 曲线上对比
  - `models/`：hazard 后验
  - `jobs/`：作业清单
  - `final_*.json`：RealSI 全部系统
  - `pair_*.json`：每个系统与 LAAL 最近的 v3 点做配对 bootstrap
  - `matched.md`：各系统插值到同 LAAL 的 v3 曲线上对比
  - `abrupt/`、`utmos/`：逐系统的连续时间轴突兀停顿分析与 UTMOS

所有配置都只在训练域 dev（UniST 805 句）上选择和拟合。RealSI 按事先固定的 8 个系统只测了一次；ACL 没有使用。基线 v3 与 v1 报告相同：ABC + SDR + 提交卫生 + 清洗 + SQ Talker + 播放 s1b1.2q。

## 结论

1. **en→zh：v2 是 v3 的一个较弱的帕累托改进，建议作为新的 en→zh 配置。** 配置为 ABC 先验 + 按单位计的损失 + 播放模型 + 硬卫生约束（trim 模式）。在三个延迟点上：
   - **ASR-BLEU 不低于 v3**：−0.03、**+0.64 [0.00, 1.25]**、+0.06；
   - **UTMOS 持平**：−0.006、+0.013、+0.022，都不显著；
   - **突兀停顿更少**：分别是同等延迟下 v3 的 0.95、0.79、0.94 倍；
   - **多余停顿更短**：每 100 个单位少 0.58–0.94 秒；≥1 秒的停顿也更少。
   
   三个点都通过了“BLEU 不降、突兀停顿 ≤ 1.2 倍、UTMOS 不降”的全部门槛。但 BLEU 的提升只有 b1.5 这一个点达到边缘显著，所以属于较弱的改进。
2. **zh→en：只有硬卫生约束这一个配置通过门槛；用 λ 做软约束在 RealSI 上没有通过。**
   - **硬约束 + trim（P h4t，LAAL 3.18）**：BLEU +0.47 [−0.39, 1.36]，突兀停顿 ×0.79，UTMOS −0.027（不显著），单字块 12.6%（v3 为 7.2%）。门槛通过，但 BLEU 增益不显著，而且只覆盖了高延迟段。
   - **拟合后验 + λ=0.75**：BLEU +0.36 和 −0.30（均不显著），突兀停顿 ×1.75–2.19，**未通过流畅度门槛**。加在线后验后 BLEU 为 +0.42 和 +0.85（均不显著），突兀停顿 ×1.85–2.70，同样未通过。
   - **与 v1 相比**：v1 P 在同等延迟下的突兀停顿是 v3 的 2.7–3.4 倍，λ 把它降低了约 35–40%，但还不够。
3. **zh→en 的 λ 配置失败，原因已经查清。**
   - **偏离了模型文档。** v2 模型（§2.2、§2.4）规定：词内切点（W）和虚词后切点（P-fw）由动作集合直接排除，代价为 ∞。但做“只用 λ”的实验时，我把整个卫生规则都去掉了，这一条也一起去掉了。结果在 RealSI 上，虚词后切点占全部停顿的 20%（v3 为 1%，硬约束版本为 1%）。
   - **dev 的建模时间轴低估了真实停顿。** dev 是单句，只能用固定语速和模拟时间轴，所以低估了连续演讲里切点之后的真实停顿。λ 在 dev 上的突兀停顿是 v3 的 0.76–1.06 倍，到 RealSI 上变成了 1.75–2.19 倍。对于 λ 这样依赖“停顿概率”的软约束，这种偏差会直接传导到结果。
   - 相比之下，硬约束不依赖停顿的概率估计，所以从 dev 迁移到 RealSI 时没有出现这个问题。

## 1. 实现（相对 v1 的新增部分）

| 部件 | 文件 | 说明 |
|---|---|---|
| dev 听感指标 | `evaluation/si_bayesrisk_dev_eval.py --timeline full` | 统计 ≥0.5 s 停顿、切点类型、源语 VAD、突兀停顿/分钟，口径与 RealSI 的 `abrupt.py` 一致；能在 dev 上复现 RealSI 的排序 |
| 硬动作集合 | `si_bayesrisk.py --br-hyg-min m --br-hyg-mode trim` | 候选块必须原样通过 v3 的 `hygiene()` 检查，并且不长于无约束的 Bayes 动作（规则只能延后，不能提前） |
| 下一次提交 hazard | `data_clean/fit_next_commit_hazard.py` | 带删失的离散时间生存似然；句随机截距用 Gauss–Hermite 积掉；τ_c 用经验 Bayes 估计；后验用 Laplace 近似。数据中没有变化的协变量会被固定排除（标准的策略迭代） |
| 突兀停顿代价 | `si_bayesrisk.py --br-next ... --br-abrupt λ` | 计入 λ · 1[源语在说话] · 1[切在短语中间] · P(G ≥ g0)，其中 G 由 hazard 的后验预测得到 |

**hazard 后验**（2 折交叉验证）：zh→en 第 0 轮 AUC 0.706、第 1 轮 0.724；en→zh 为 0.754。只用截距和步数的模型约为 0.55–0.58。λ 的系数是 −0.21 ± 0.01（λ 越大，下一次提交越晚）。

## 2. dev 上的过程（与同 LAAL 的 v3 dev 曲线比较，v3 共 10 个 bias 点）

| 轮次 | 配置 | 结果 |
|---|---|---|
| 0 | 拟合后验 + 硬约束，取全局 argmin | zh→en BLEU −0.7～−1.9：全局 argmin 会跳过自信的前缀 → 引入 trim 模式 |
| 0b | trim 模式 | zh→en A：+0.30 / −0.12；en→zh A：+0.15～+1.01，突兀停顿 ×0.75～0.78 |
| 1 | 去掉硬约束，λ ∈ {0.5, 1, 2, 4} | λ 单调地用 BLEU 换取流畅度；λ=1 时 +1.20 / +0.87，突兀停顿 ×0.73 / ×0.99 |
| 2 | 用第 1 轮数据重新拟合 hazard，λ ∈ {0.75, 1, 1.5} | λ=0.75 时 +1.56 / +0.64，突兀停顿 ×0.76 / ×1.06；单个 dev 点的波动约 ±0.5 BLEU |

## 4. 下一步建议

1. **zh→en 按文档实现 λ：只排除 W 和 P-fw 切点（保留 `trim_dangling`），不加最短长度规则。** 在 dev 上重新选 λ，然后在 RealSI 上测。需要说明：这会是 zh→en 在 RealSI 上的第二次测试，报告时要明确标注。
2. **改进 dev 的时间轴。** 把 dev 句子按录音串成连续的“伪演讲”，并用 Talker 的实测时长表代替固定语速（对应模型文档的 A10）。目标是缩小 λ 从 dev 迁移到 RealSI 时的偏差。
3. **en→zh 可以采用 v2 A h3t。** 它在三个延迟点上都不低于 v3，而且更流畅。

## 5. 按建议的后续：伪演讲 dev 时间轴，以及 zh→en 的第二次 RealSI 测试

**dev 时间轴的改进**（`si_bayesrisk_dev_eval.py --timeline talk`）：
- **做法**：dev 句子按 id 每 8 句串成一场“伪演讲”，句间留 0.3 秒；播放规则直接沿用 RealSI 分析中的 `si_talk_timeline.schedule`（s1b1.2q），只是改为按时长计算。
- **校准**：用已经测过 RealSI 的系统核对，新指标的突兀停顿倍数基本能复现 RealSI；而旧的单句时间轴完全复现不了。

| 系统 | 旧 dev 指标 | 新 dev 指标 | RealSI |
|---|---|---|---|
| v1 P b0 | ×4.78 | ×2.72 | ×2.73 |
| P λ0.75 b0 | ×1.06 | ×1.65 | ×1.75 |
| P h4t b0 | ×0.51 | ×0.52 | ×0.79 |
| en→zh A h3t | ×0.76～0.78 | ×0.72～0.77 | ×0.79～0.95 |

**按文档补上“排除虚词后切点”**（`--br-dangle`）：
- **做法**：排除 W 和 P-fw 切点，不加最短长度规则，并沿用 trim 语义（约束只能让模型少说）。
- **dev 结果**：
  - 只加排除时，突兀停顿为 ×1.3～1.8，仍不够；
  - 再加 λ=1，在 b0 / b0.5 上，两轮策略迭代（第 3、4 轮）都满足 ≤1.2 倍：+0.51～+0.69 / +0.38～+0.44 BLEU，×1.05～1.15；
  - b−0.5 不稳定（×1.20 / ×1.39），所以没有送测。

**zh→en 第二次 RealSI 测试**：
- 这是对 RealSI 的第二次查看，结论需要相应打折扣。
- 只测了两个点：λ=1，b0 / b0.5；hazard 用第 3 轮数据拟合的版本。
- 结果见 `matched_r2.md`、`final_r2_zh2en.json`。

| 系统 | LAAL | ΔASR-BLEU（配对） | ΔUTMOS | 突兀停顿 ×v3 | 虚词后切点占停顿 | 门槛 |
|---|---|---|---|---|---|---|
| Pd λ1 b0 | 2.65 | +0.88 [−0.15, 1.90] | **−0.042 [−0.082, −0.006]** | 1.02 | 0% | 未通过（UTMOS 显著下降） |
| Pd λ1 b0.5 | 3.32 | −0.23 [−1.16, 0.63] | −0.037 | 1.11 | 1% | 未通过（BLEU 低于 v3） |

**结论：**
1. **流畅度问题解决了。** 排除虚词后切点把这类停顿从 20% 降到 0–1%；突兀停顿从第一次测试的 ×1.75～2.19 降到 ×1.02～1.11，通过了 1.2 倍门槛。这验证了第一次失败的原因判断是对的。
2. **zh→en 仍然不是对 v3 的帕累托改进。** BLEU 的增益在 RealSI 上不显著（+0.88）或为负（−0.23），UTMOS 小幅下降（约 −0.04）；每 100 个单位的多余停顿比 v3 多约 0.8 秒。
3. **推荐配置不变**：zh→en 仍用 v3，en→zh 采用 v2 A h3t（§3）。
4. **zh→en 剩下的空间。** dev 上的 BLEU 增益（+0.4～+0.7）比单点噪声（±0.5）大不了多少，迁移到 RealSI 后就看不出来了。想继续提升，需要能提高排序能力的新统计量，即模型文档 §2.7 的门槛，而不是继续调整代价参数。

## 6. 两个方向必须用同一个版本时：选 v3

**结论：两个方向统一用 v3（ABC + SDR + 提交卫生 + 清洗 + SQ Talker + s1b1.2q）。** v3 本身就是 Bayesian 方法（ABC 摊销后验 + SDR 的 Bayes 风险提交，见 [m2_fluency_bayes_v3cfg.zh-CN.md](m2_fluency_bayes_v3cfg.zh-CN.md)），而且 v3 是 v2 的特例（模型文档 §2.8）。所以这个选择的含义是：保留 v3 的 Bayesian 核心，不加 v1/v2 在它之上叠加的 Bayesian 层。

**为什么不选 v2：v2 只在 en→zh 有弱提升，在 zh→en 有系统性的小损失。**

| 方向 | v2 在 RealSI 上测过的系统 | ΔASR-BLEU | ΔUTMOS | 单字块（与同 LAAL 的 v3 之差） | 突兀停顿 ×v3 |
|---|---|---|---|---|---|
| en→zh | 3 个（A h3t） | −0.03 / **+0.64** / +0.06，均值 +0.22 | −0.006 / +0.013 / +0.022 | +0.3～+0.7 pt | 0.79～0.95 |
| zh→en | 7 个（两轮全部配置） | −0.30～+0.88，**没有一个显著** | **7 个全部为负**：−0.023～−0.042（Pd λ1 b0 显著） | **7 个全部更高**：+2.1～+5.7 pt | 0.79～2.70 |

- **en→zh 选 v3 的损失很小。** 三个点中只有 b1.5 的 +0.64 达到边缘显著（CI 下界 0.00），另外两个点打平；放弃的主要是 5–21% 的突兀停顿。
- **zh→en 选 v2 的风险是结构性的。** v2 在 zh→en 把句子切成更多块（P h4t b0 每句 3.31 块，同等延迟的 v3 b1.5 为 2.52 块），单字块从 7.1% 升到 12.6%，Talker 读错从 3.3% 升到 4.1%，UTMOS 随之下降。这在两轮共 7 个配置上方向完全一致，不是噪声。
- **zh→en 的低延迟段没有 v2 的 RealSI 证据，而 dev 上那里更差。** v3 推荐的 zh→en 工作点是 b−1（LAAL 1.68 s）。唯一通过门槛的 v2 配置（P h4t）只在 LAAL 3.18 s 测过。dev 上硬卫生 v2 在 b−1 比同 LAAL 的 v3 低 1.15（P）/ 1.31（A）BLEU。如果再到 RealSI 补测，就是对 zh→en 的第三次查看，不应再做。
- **决策规则。** 统一版本要求两个方向都不比对方差。v3 是参照，没有任何方向未过门槛；v2 在 zh→en 不满足“UTMOS 不降”，在低延迟段 BLEU 也有风险。按最坏方向比较，选 v3。

**Bayesian 在 v3 上是否有效：核心部件有效，再叠加的 Bayesian 层无效。**
- **Bayes 风险部件（SDR）是 v3 质量的来源。** 去掉 SDR、只留 ABC：en→zh −0.90 BLEU（显著）；zh→en −2.54（去掉一句失控复读后仍为 −0.5）。
- **与非 Bayesian 的 LocalAgreement-2（加同样的 v3 规则）相比：**
  - zh→en 低延迟段 +1.33 / +1.60 BLEU，p = 0.029 / 0.013；
  - en→zh 打平（±0.9 以内，不显著）。
- **在 v3 之上再加 Bayesian，没有稳健收益。** 试过的有：SDR 按实测语速校准、按场 Beta 自适应、v1 测试时后验、v2 Bayes 风险（后验重拟合、hazard、λ）。原因见模型文档 §0：
  - 新统计量只提高 AUC 约 0.01，bias 扫描已经覆盖了同一族阈值策略；
  - 场级自适应的净上限只有 +0.35～+0.5；
  - zh→en 在 dev 上的增益（+0.4～+0.7）与单点噪声（±0.5）同量级。

**v3 的工作点。**
- 默认：en→zh b1（LAAL 2.01 s，ASR-BLEU 28.83，UTMOS 3.349）；zh→en b−1（LAAL 1.68 s，21.43，3.229）。
- 可以接受更高延迟时，沿 v3 曲线调高 bias：
  - en→zh b2：+1.28 BLEU，LAAL +0.66 s；
  - zh→en b0.5：+1.39 BLEU，LAAL +0.70 s。

v2 的代码保留。在 θ=m0、λ=0、硬动作集合下，v2 与 v3 逐决策一致，所以统一用 v3 不需要改代码。
