LLM×VITS 流式试听

手册的全部方案都在 LJSpeech test 集上实现并评测完毕。文字逐词到达，流式系统只能看到已经到达的词，已经说出的内容不能修改。所有流式系统共用同一个冻结的 VITS backbone。

结论

  • 最好的方案：S6-future + T5 + S5 解码器。它是唯一一个所有指标都不输主 baseline E1 k=1 的系统：平均等待少 43%，词时长误差和停顿误差都显著更低，WER、UTMOS、F0 持平，每个单元的计算量更小。
  • 按角色看各自最好的方案。何时提交：T5 优于 T3、熵门控和 T1/T2。谁来发声：S5 小幅改善音质，其余替换都让音质变差。时长规划：S6-future 仍然最好，S1 的扩散先验反而更差。
  • 引入大模型的两个方案没有成功。S4（Qwen3-TTS token）的音质略低于 vits。S3（VoxCPM2 AudioVAE）的编解码器本身很好，重建 UTMOS 有 4.31，但只靠文本条件的潜变量先验生成不出可用的潜变量，合成 UTMOS 只有约 1.5。
  • “卡顿”的原因已经查清：来自渲染时的拼接边界，与等待无关。backbone 的解码器是按整句离线训练的，流式时却逐词渲染，而且在词边界处看不到后面的帧。所以每个词边界的频谱跳变比自然语音大约高 20%（边界跳变比 1.30，录音为 1.11），听起来就是每 0.3 秒左右卡一下。
  • 修复方法：给解码器加右前瞻。每次只播放到已提交帧之前 R 帧，剩下的 R 帧留作右上下文，等下一个词提交后再播。时长和潜变量都不变，只改渲染：R=8（+93 ms）时 UTMOS 从 3.86 升到 4.04，R=16（+186 ms）时升到 4.18，基本追平离线的 4.21，边界跳变比回到 1.11。最佳组合加上 R=16 后 UTMOS 为 4.20。
