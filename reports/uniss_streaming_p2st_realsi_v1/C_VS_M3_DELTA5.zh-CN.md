# C 对 m3(δ=5)—— 延迟上 C 输,内容上 C 赢

## 先纠正上一份报告的配置错误

上两份报告拿 C 去比的 m3 是 **δ=0**,那是 m3 的**门禁**配置。m3 自己的文档
(`streaming_demos_delta5/FINDINGS.zh-CN.md`)把 **δ=5**(`CONTINUE_WRITE_BIAS=5`)
称为"**全项目最好的流式 S2ST 配置**",门禁 5/6 对 δ=0 的 3/6,因为它把
`WRITE_MT/事件` 从 0.168 抬到 0.789。**拿 δ=0 比,是拿 m3 作者自己弃用的配置比。**

δ=5 用 `install_bias(0, 5)` 在运行时装(只给 `_choice` 加偏置,`self.logits` 不动),
不改 m3 任何文件。复现验证:我在 80 条上测得 `WRITE_MT/事件 = 0.774`,
m3 文档在它的 16 条上是 0.789 —— 装对了。

## δ=5 在 RealSI 上是免费的,在内部数据上不是

| | 内部面板 MT BLEU | RealSI ASR-BLEU |
|---|---|---|
| m3 δ=0 | 24 / 20 | 1.73 / 0.80 |
| m3 δ=5 | 18 / 14(**−6 / −6**) | 1.36 / 0.50(**≈ 不变**) |

在内部数据上 δ=5 花 6 BLEU 换 2.5 倍延迟;在 RealSI 上它一分没花,
**因为 m3 的 RealSI 质量本来就在地板上(BLEU ≈ 1),没有可掉的了**。
所以"δ=5 免费提速"这个结论只在质量已经崩掉的地方成立。

## 顺带修正:oracle 分段的作用在 ASR,不在延迟

上一份报告撤回了"gold 时刻表让延迟变小"。现在能说清它真正的作用:

| m3,同 80 条 | gold 时刻表 | 均匀 160 ms |
|---|---:|---:|
| ASR 错误 en2zh | **0.248** | **1.708** |
| ASR 错误 zh2en | **0.157** | **0.849** |
| MT 文本 BLEU | 24 / 20 | 3.1 / 2.7 |
| LAAL | 3466 | 3221 |

**换成盲网格,m3 的延迟没变(略好),但 ASR 错误率涨了 6.9 倍、MT BLEU 掉到 1/8。**
oracle 分段买的是**识别质量**,不是延迟。m3 在盲网格上被要求每 160 ms 就写一次
ASR,而它只在 gold 词边界上训练过,于是吐出大量插入(WER > 1)。

# C 目前还有什么问题,以及怎么解决

## 问题 1(主要):开口延迟 = 两级一致性提交器串联

**关键测量:`首次开口 == MT 首次提交`,80/80 = 100%,三个 holdback 下都是。**
TTS 一点都不多等 —— C 一拿到目标文本就说。所以开口延迟**全部**在 ASR→MT 提交链上。

拆开(80 条内部样本,160 ms 读步):

| holdback | ASR 首次提交 | MT 首次提交 | 首次开口 | ASR 错误 en/zh | MT BLEU en/zh | 提交冲突 |
|---|---:|---:|---:|---|---|---:|
| 0 | 400 | 1120 | **1120** | 0.245 / 0.127 | 26.89 / 21.90 | 0 |
| **1(默认)** | 960 | 2080 | **2080** | **0.164 / 0.099** | **38.82 / 33.43** | 0 |
| 2 | 1440 | 2880 | **2880** | 0.168 / 0.093 | 39.39 / 33.11 | 0 |

**2080 ms 里,ASR 提交器占 960 ms,MT 提交器又占 1120 ms —— MT 那一半更长。**
而且**三个设置下提交冲突全是 0**:holdback 纯粹是保守,不是在避免冲突。
hb=2 多花 800 ms 只换 +0.6 BLEU,所以对称 hb=1 已经是对的(印证了之前 hb1 胜 hb2)。

### 解法 A(立即可用,无需训练):只放开 MT 那一层

既然源前缀只增不改、零冲突,MT 那一级的一致性检验很可能是多余的。测了
`source_holdback=1, target_holdback=0`(之前只试过 s0t1 和 s2t1,**没试过 s1t0**):

| s:t | 首次开口 | ASR 错误 en/zh | MT BLEU en/zh | 片段数 |
|---|---:|---|---|---:|
| s0t0 | **1120**(−960) | 0.245 / 0.127 | 26.89 / 21.90(**−11.9 / −11.5**) | 6.0 |
| **s1t0** | **1600**(−480) | **0.164 / 0.099**(不变) | **36.59 / 29.05**(−2.2 / −4.4) | 6.0 |
| s1t1 默认 | 2080 | 0.164 / 0.099 | 38.82 / 33.43 | 4.0 |
| s2t0 | 1980 | 0.168 / 0.093 | 37.49 / 30.32 | 5.0 |

**s1t0 用 2.2 / 4.4 BLEU 买 480 ms,兑换率是 s0t0 的 2.7 倍**(4.6 vs 12.4 BLEU/秒,
En→Zh),ASR 错误率一字不变,零冲突,片段数 4 → 6(更细)。
**结论:要买延迟就放开目标提交器,不要动源提交器。** 别去 s0t0(−12 BLEU)。

### 解法 B(真正的修法,需要训练):把 ASR 在均匀细读步上训

四条证据指向同一处:

1. **C 的中文源 ASR 在细读步上崩塌** —— CER 0.250(整段)/ 0.264(k25)→ **0.804(k1)**;
   英文几乎不动(0.363 / 0.390 / 0.421)。C 的训练切在 gold 事件/词边界上,
   **从没见过固定的 160 ms 读网格**。
2. **m3 在同一个切换上错误率涨 6.9 倍**(0.248 → 1.708)—— 同一个病根,更严重。
3. **第三方 ASR 读 RealSI 源只有 0.141 WER / 0.159 CER** —— 音频本身没问题。
4. **开口被 ASR 提交器绑住** —— 一个更好的 ASR 会**更早达成一致**,
   于是延迟和质量一起改善,而不是互相交换。这是唯一能同时买到两者的杠杆。

具体做法:在纯 CE 配方(C 的胜因)上加一个**均匀 160 ms 读网格的 ASR family**,
并且**中文源要单独加量**(崩塌是中文特有的)。这也正好是 §6 那条不对称质量代价
(k25→k1 时 Zh→En 掉 4.04 BLEU 而 En→Zh 只掉 2.67)的根。

### 什么办法一定不行:照搬 δ 式的无条件写

m3 δ=5 已经把这条路走到头了:开口 347 ms,**ASR-BLEU 1.36**。
它靠"不管有没有把握都写"换延迟,代价是 WER 1.75、文本超生成 1.8 倍。
C 如果照搬,会从"慢但对"变成"快但错"。**δ 不是 C 缺的那个旋钮。**

## 问题 2:内部静音 0.30,m3 是 0.08–0.14

C 的语音更碎(RealSI 上内部静音 0.302 / 0.309,内部面板 0.276)。这和问题 1 同源 ——
开口晚了 2 秒,后面就得追,于是块与块之间留空。s1t0 把片段数从 4 提到 6,
是往正确方向走。**开口修好之后再单独评估这一项**,不要现在单独调。

## 问题 3:欠生成

简短惩罚 0.805 / 0.819,文本长度比 0.86,语音时长/源 0.71–0.76。终止率是 1.000,
所以不是片段内提前停,而是**整体提交的文本偏少** —— 同样是提交器保守的下游表现。

## 建议的下一步顺序

1. **先把 s1t0 在 RealSI 777 条上跑一遍**(纯配置,无训练),确认 480 ms / −2~4 BLEU
   这个兑换率在公开数据上成立。如果成立,这是免费的 0.5 秒。
2. **然后开一个新训练:纯 CE + 均匀 160 ms 读网格的 ASR family,中文源加量。**
   目标是把 k1 的中文 CER 从 0.804 压回 k25 的 0.264 附近。这一项做成了,
   RealSI 的 10.37 和开口的 2544 ms 会一起改善。
3. 不要动 TTS,不要加 δ,不要动 pacer(margin 1200↔2000 的对照已证明它不影响这些量)。
