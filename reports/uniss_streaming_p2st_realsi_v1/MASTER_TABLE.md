# RealSI 总表:C 与 m3 的全部指标并列

同一份冻结的 **777 条 RealSI 句级片段**(346 条 En→Zh + 431 条 Zh→En,总 90.9 分钟),
同一套代码算的全部指标,六个操作点并列。

## 口径

* **ASR-BLEU** 是论文口径:英文目标过 Whisper-large-v3,中文目标过 Paraformer-zh,
  归一化英文 NFKC+小写+13a、中文 OpenCC t2s + 字符插空格 + `zh`。
  `placed` 是发声时间线音频(系统没准备好的地方是静音,SimulEval 的惯例),
  `concat` 是片段背靠背拼接;两者都报,好看出插入静音对 ASR 的影响。
  空假设一律计分(`--score-empty-hypotheses`),不然会虚高。
* **延迟**用 SimulEval 1.1.0 自己注册的 scorer(`latency_scorer.py` sha256
  `2fbb749de96a0d361e673ce1b2c476dfc5f19a25c9a082bb71bed33e37d5e1fa`),
  delay 轴是**每个语音块一个点**。延迟单位按论文:→中文 char,→英文 word。
  句级数据上 **StreamLAAL 退化为 LAAL**(它多出的 mwerSegmenter 对齐步在每条已是
  一句时是恒等)。
* **两个不同的"开口"量,不要混用**:`首次发音` 是首个语音块的发出时刻
  (= SimulEval 的 StartOffset,聚合均值;`首次发音 中位` 是同一量的中位,
  用来和下一行同口径对读);`真实可听起始` 是 `audio_quality.leading_silence_ms`,
  发声时间线音频上**第一个有声帧**的能量口径,已含放置产生的前导静音。
* **AL 在超生成时会变负**(m3 δ=5 的 −433 / −3730),这是 AL 公式在
  假设单元数远超参考时的已知病态;LAAL 正是为此设计的,所以只读 LAAL。
* **AP 在本配置下不可用**,故未列入:SimulEval 的 AP 假设
  `len(delays)` 与 `reference_length` 同量纲,而我们的 delay 是每语音块一个
  (5–36 个),参考长度是几十个字/词,差一个量级。
* **δ** 是 m3 的 `CONTINUE_WRITE_BIAS`,加在续写决策 logit 上。m3 自己的文档把
  **δ=5** 称为"全项目最好的流式 S2ST 配置";δ=0 是它的门禁配置。
  C 的级联不生成决策 token,**结构上没有这个旋钮**。
* `m3 δ=0 m2000` 是把 m3 的配速 margin 从它门禁的 1200 换成 C 的 2000 的对照臂,
  用来证明配速器不是差异来源。
