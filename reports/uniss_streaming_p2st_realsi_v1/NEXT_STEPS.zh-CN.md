# m3 与 C 能不能比、谁更好、C 差在哪、下一步做什么

## 一、能比吗:能,但只在"操作点"这个层面

**已核实共享的**:同一份冻结的 777 条 RealSI 片段;同一个 160 ms 读步网格;
同一个 WhisperVQ 前端和**逐行相同**的 GLM 嵌入数学(`p2st_cascade.py:352-357`
与 `persistent_runtime._speech_embeddings`);同一个流式 BiCodec 解码器
(`decode_fragments` 与 `run_worker._decode_semantic_fragments` 实现相同);
同一套发声时间线放置;同一批 SimulEval scorer(sha256 固定);同一条 ASR-BLEU 链;
同一个祖先检查点(`endmargin_epoch23_15shard` iter_0002264)。

**不同的三处,必须声明**:

1. **运行时架构**:C 是三段隔离级联 + 任务前缀(`TASK_STREAMING_ASR` /
   `TASK_T2T_TRANSLATION` / `TASK_TTS`)+ 外部 switch rule;m3 是单会话、单 KV cache
   的交织事件语法 + 决策 token(WAIT / WRITE_GENERATE + family 选择)。
2. **训练分布**:m3 训在切于 gold 事件边界的交织序列上;C 训在 P2ST 级联格式
   + phase3 replay 上。**两者都没在固定的 160 ms 均匀读网格上训练过。**
3. **旋钮空间不对称**:m3 有 δ(`CONTINUE_WRITE_BIAS`),因为它**有**决策 token;
   **C 结构上没有决策 token,所以没有 δ**,它的对应旋钮是提交器 holdback。
   所以"m3 的最好"和"C 的最好"是在**不同的旋钮空间**里各自调出来的。

**结论:作为"公开基准上的操作点对比"是有效的 —— 这正是论文做的那种对比。
但它不是"训练配方谁更好"的干净对比**,因为两者都在分布外被评测,而且退化幅度
不同:换到均匀网格后 m3 的 ASR 错误率 0.248 → 1.708(6.9 倍),
C 的中文 CER 0.264 → 0.804(3.0 倍)。

## 二、谁更好:在 RealSI 上是 C,而且不接近

| RealSI 777 条 | C k1 | C k1_s1t0 | C k25 | m3 δ=0 | m3 δ=5 | 论文 m=4 |
|---|---:|---:|---:|---:|---:|---:|
| **ASR-BLEU** En→Zh | 14.66 | 14.01 | **17.33** | 1.73 | 1.36 | 25.54 |
| **ASR-BLEU** Zh→En | 10.37 | 10.05 | **14.41** | 0.80 | 0.50 | 22.47 |
| LAAL En→Zh | 4437 | 3686 | 7313 | 4364 | **566** | — |
| LAAL Zh→En | 3681 | 2997 | 6677 | 3615 | **778** | — |
| 首次发音 | 2544/2573 | 1573/1743 | 7238/6656 | 2818/2999 | **347/805** | — |

**m3 在 RealSI 上无论 δ 取 0 还是 5,ASR-BLEU 都在 0.5–1.9。BLEU ≈ 1 的输出不是
译文,而"不是译文"的低延迟不构成延迟成绩。** 所以在这个公开基准上,
**C 是两者中唯一产出可用输出的**,差距是 8–20 倍。

**但要说准确:这是关于 RealSI 的判断,不是关于 m3 的普遍判断。**
在 m3 自己的内部域 + gold 时刻表上,m3 δ=5 是一个**真实的 Pareto 点**
(MT 文本 BLEU 18/14 @ LAAL 1401,对 C 的 39/33 @ LAAL 3667)—— 质量差、延迟好得多。
**同一个问题在两个数据集上答案不同**,而对外发表要看公开基准那一个。

## 三、C 相对 m3 差在哪,以及怎么解决

### 问题 1:延迟 —— 已定位,已部分解决

已测清:**`首次开口 == MT 提交器首次释放`,80/80 = 100%,TTS 一点都不多等**。
2080 ms 里 ASR 提交器占 960、MT 提交器再占 1120,而**三档 holdback 下提交冲突全是 0**,
说明 holdback 纯属保守。

**已做的修:`s1t0`(源 holdback 保持 1,目标 holdback 放到 0)。RealSI 777 条实测:**

| | k1 | **k1_s1t0** | 变化 |
|---|---:|---:|---|
| 首次发音 | 2544 / 2573 | **1573 / 1743** | **−971 / −830 ms** |
| 真实可听起始 | 2480 / 2520 | **1640 / 1880** | −840 / −640 |
| LAAL | 4437 / 3681 | **3686 / 2997** | −751 / −684 |
| ASR-BLEU | 14.66 / 10.37 | **14.01 / 10.05** | **−0.65 / −0.32** |
| 语音块数 | 5.86 / 5.53 | 7.38 / 6.44 | 更细 |

**不到 0.7 BLEU 换回接近 1 秒。建议把 s1t0 设为默认。** 兑换率比内部面板预测的
还好(内部面板是 480 ms / −2.2~4.4 MT 文本 BLEU)。

### 问题 2:卡顿 / 内部静音

C 内部静音 0.302 / 0.309(s1t0 后 0.347 / 0.334),m3 δ=5 是 0.144 / 0.080;
有声段中位 C 是 630 / 580 ms,m3 δ=0 是 1200 / 1720;接缝跳变 C 是 11.4 / 10.0,
m3 δ=0 是 7.0 / 2.9。**C 的语音更碎。**

但注意 **C 的 k25 内部静音只有 0.039 / 0.021** —— 同一个 TTS、同一个解码器。
**所以碎不是 TTS 的问题,是细读步下"每步只提交一点文本"的结果。**
不要单独去调 TTS;它会随问题 1 和 3 一起改善。

### 问题 3(主要):源 ASR —— 而且这里有个决定性的数

按源 ASR 错误率给样本分桶,同一批 777 条:

| 源 ASR 错误率 | C k25 En→Zh | C k25 Zh→En | n(En/Zh) |
|---|---:|---:|---|
| **< 0.15** | **25.66** | **21.12** | 73 / 177 |
| 0.15–0.30 | 19.99 | 12.27 | 100 / 132 |
| 0.30–0.50 | 14.51 | 7.98 | 96 / 77 |
| 0.50–0.80 | 3.77 | 1.93 | 62 / 37 |
| 全体 | 17.33 | 14.41 | 346 / 431 |
| **论文 m=4** | **25.54** | **22.47** | |

**在识别正确的样本上,C 的 En→Zh 是 25.66,已经超过论文 m=4 的 25.54;
Zh→En 是 21.12,逼近它的 22.47。** 也就是说:

> **C 的翻译与合成能力本身不比论文差。它与论文之间的整个差距,是源 ASR 的错误率
> 分布。**

而且 ASR 是同一个瓶颈的两个出口:它既决定质量上限,**又决定开口时刻**
(问题 1 已证明开口被提交器绑住,而提交器要等 ASR 达成一致)。
**修 ASR 是唯一能同时买到延迟和质量的杠杆**,其它一切都是取舍。

### 问题 4:欠生成

简短惩罚 0.805 / 0.819(k25 是 0.773 / 0.918),文本长度比 0.79 / 0.89。
终止率已经是 1.000,所以不是片段内提前停,而是**整体提交的文本偏少**。
若长度完全匹配(bp = 1),同样的精度会给出:

| | 实测 | bp=1 上界 | 可回收 |
|---|---:|---:|---:|
| k1 En→Zh | 14.66 | **18.22** | +3.56 |
| k1 Zh→En | 10.37 | **12.66** | +2.29 |
| k25 En→Zh | 17.33 | **22.40** | +5.07 |
| k25 Zh→En | 14.41 | **15.70** | +1.29 |

## 四、下一步(按优先级)

1. **已完成 —— 把 s1t0 设为默认。** 纯配置,无训练,RealSI 上实测 −971/−830 ms
   开口、−0.65/−0.32 BLEU。
2. **唯一值得开的训练:纯 CE 配方 + 均匀 160 ms 读网格的 ASR family,中文源加量。**
   * 目标:把 k1 的中文 CER 从 **0.804** 压回 k25 的 **0.264** 附近。
   * 依据:① C 的中文 CER 0.250(整段)/ 0.264(k25)/ **0.804(k1)**,英文几乎不动
     (0.363 / 0.390 / 0.421);② m3 在同一切换上更严重(0.248 → 1.708);
     ③ 第三方 ASR 读同样音频只要 0.141 / 0.159,**音频本身没问题**;
     ④ C 的训练切在 gold 事件/词边界上,**从没见过固定细网格**。
   * 预期收益:分桶表说把整批推进 <0.15 桶值 **+8.3 / +6.7 BLEU**,
     并且开口会同时变短。
3. **然后处理长度**(bp 0.79–0.83),值 **+3.6 / +2.3**。终止率已满,所以要动的是
   提交文本的量,不是 END 的时机。
4. **明确不做**:① δ 式无条件写 —— m3 δ=5 已把这条路走到头(347 ms / BLEU 1.36);
   ② 调 pacer —— margin 1200↔2000 的对照证明它对这些量无影响;
   ③ 单独修 TTS —— 已测得它对开口贡献为 0,且 C 的峰值 0.776–0.859、
   >4kHz 能量 0.003 已与 m3 同级或更好。
