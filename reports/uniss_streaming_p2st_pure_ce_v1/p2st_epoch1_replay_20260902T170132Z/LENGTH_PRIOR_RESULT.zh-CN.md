# 长度先验:结果

## 0. 为什么做这个 —— 上一轮算出来的

洞不是调度问题。抖动缓冲被证明**恒等无效**:常数延迟同时平移源到达时刻和播放
游标,洞里的 D 相消,

```
gap_k = 源到达_k − 源到达_{k-1} − 片段_{k-1}的长度        ← 与 D 无关
```

离线扫 D = 0…4000 ms,内部静音全是 26.4%,一动不动。而实测

| | 语音时长/源 | 1 − 时长/源 | 实测内部静音 |
|---|---:|---:|---:|
| C 长音频(配速后) | 0.539 | 46.1% | 50.1% |
| m3 长音频 | 0.838 | 16.2% | 19.6% |

**洞 = 生成的语音不够填满时间轴。是欠生成,不是调度。**

## 1. 做了什么

`log P(N ≤ n | 文本长度, 目标语言)` 加到 `END_SEMANTIC` 的 logit 上 ——
"文本这么长的片段到第 n 个码为止已经说完"的先验概率。这是一维讨厌参数上的精确
贝叶斯:

```
log p(在 n 停 | codes_{<n}, 文本) = log p_model(END | ·) + log P(N ≤ n | 文本)
```

先验从 110,436 条训练轨迹拟合(`data/LENGTH_PRIOR.json`),文本长度用**和训练
prompt 完全同一个** `_split_target_text` 的输出来量:

| 中文 文本长 | n | 码中位 | 码/字 | sd/中位 |
|---:|---:|---:|---:|---:|
| 1 | 53,318 | 20 | 20.00 | 0.98 |
| 4 | 22,633 | 52 | 13.00 | 0.41 |
| 10 | 3,308 | 128 | 12.80 | **0.24** |
| 20 | 236 | 244 | 12.20 | **0.19** |

**中文稳定在 12–13 码/字,相对宽度从 0.98 收窄到 0.19** —— 对多字片段,码数在模型
生成之前就已经基本确定。英文约 3 码/字符,但相对宽度 0.58–1.13,**先验明显更弱**。

**它的界是 log(概率) ≤ 0,所以只压抑过早的 END,永远不能强制停止。** 这是故意的:
过生成已经有配速预算和重复惩罚两个机制且都实测有效,欠生成一个都没有。

**它和失败过的 δ 不是同一个东西。** δ 是全run 一个常数加在一个 logit 上,响应是
阶跃(δ=1 翻转 0/181、δ=2 翻转 58/218、3/4/5 逐位相同)。这个偏置**每一步都变、
且依赖片段携带的文本**,没有单一阈值可以跨过去。

初稿用的是教科书形式的危险率 `p(N=n)/P(N≥n)`,但存储的支撑是子采样、密度全是空
桶,危险率噪声大到会在合理区间中段压抑 END。CDF 没有这个洞。

## 3. 判断

**短音频已经追平并在一项上超过 m3:** 语音时长/源 **0.989** vs m3 的 0.853
(带 [0.9,1.2] 正中),内部静音 **19.9%** vs 16.0%,语义覆盖 0.810 vs 0.844。

**长音频还差:** 内部静音 40.9% vs 19.6%。按恒等式,时长比 0.710 只能解释 29% 的
静音,余下 12 个点来自事件到达的结构 —— **那要靠更密的提交,不是先验。**

**scale 1.5 只在长音频再拿 2.7 个点(40.9% → 38.2%),短音频反而退 0.2。** 而
0 → 1.0 拿了 9.2 个点。收益递减明显,**默认保留 scale=1.0** —— 它是未经调参的
贝叶斯原值,1.5 是硬调。

**内容指标一个都没动**(ASR 0.104/0.128/0.140,MT chrF 64.19/53.22/23.81)——
这是预期的,先验只改 TTS 的停止时刻。

## 4. 剩下的差距,以及它属于哪一类

| 差距 | 数值 | 归属 | 有闭式解法吗 |
|---|---|---|---|
| 长音频内部静音 | 40.9% vs 19.6% | 提交器放行太稀 | 无,holdback 是启发式 |
| 首次可听 | 3360/3020 vs 883/978 ms | 提交器 holdback=2 | 无 |
| LAAL 长 | 5423 vs 2184 ms | 同上 | 无 |
| 中文 ASR | 0.104/0.128 vs 0.072 | 权重,吃数据 | 无 |

**三项里有三项都指向同一处:提交器。** 这是下一个该动的东西,而且它没有闭式解 ——
属于我之前分的"难修"那一类,正是贝叶斯方案 A(风险受控提交)和 B(anytime-valid
e-value)要打的地方。
