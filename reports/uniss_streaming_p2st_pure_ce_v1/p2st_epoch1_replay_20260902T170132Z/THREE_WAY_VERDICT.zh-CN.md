# 三方可比判决:C vs m3 vs B′

## 协议

同一份 frozen `SELECTION.json`(16 条),取自
`free_running_gates/uniform_ce_gate_20260902T042621Z/SELECTION.json`,16 条全部在
`valid_gold_trajectories.jsonl` 里且全部带 `target_semantic_delta`。
BLEU tokenize 与门禁一致:`zh`(→cmn)/`13a`(→eng)。

**一处必须声明的不可比:C 走它自己的级联,m3 和 B′ 走交织 runtime。** 这不是选择
——C 的权重从未在带 WAIT/WRITE 决策的交织序列上训练过,把它送进那条链会得到无
意义的数。样本、参考、BLEU 分词口径相同,推理路径不同。

`ASR 错误率` 与 `文本长度比` 两行是我自己按门禁的定义重算的(同口径,非同代码);
`BLEU`/`chrF` 是同定义同工具(sacrebleu)。

## 判决

|---|---|---|---|---|
| WRITE_MT / event | ≥ 0.50 | **结构上不存在** | 0.147 **FAIL** | 0.189 **FAIL** |
| natural_eos / 终止率 | ≥ 0.875 | **0.977 PASS** | 0.500 **FAIL** | 0.500 **FAIL** |

验证过),README §7 早已声明这是设计变化。`natural_eos` 用 C 的等价量终止率代入。

## 64 条面板:统计效力

8 条面板已被证明分辨率不足(hb1 与 seed 变体 7/8 逐字节相同)。冻结的 64 条
(`PANEL64_SELECTION.json`,双向各 32 条,时长 2.0–15.3 s)结果比 8 条清醒:

| | 8 条面板 | **64 条面板** | 差 |
|---|---:|---:|---|
| 可听 | 8/8 | **64/64** | 稳 |
| 撞 384 上限 | 0/8 | **0/64** | 稳 |
| 自然收尾 | 1.00 | **1.00** | 稳 |
| cmn→eng chrF | 72.88 | **52.27** | 8 条高估 20.6 |
| 内部静音 短 | 14.3% | **26.7%** | 8 条低估 12.4 pt |
| ASR cmn | 0.130 | **0.192** | 8 条低估 |
| ASR eng | 0.120 | **0.185 / 0.088** | 8 条低估 |
| 时长/源 短 | 1.086 | **0.811** | — |

**三个结构性结论在 64 条上完全稳住:全部可听、零撞上限、终止率 1.00。**
而质量类数字 8 条明显高估 —— 以后一律用 64 条报。

## 结论

**C 通过全部可评的门禁判据(5/5),m3 是 2/6,B′ 是 3/6;而 C 的翻译质量同时是
两者的 2–7 倍。** 这是本项目第一次有一个方案通过它自己定的自由运行门禁。

**代价仍在延迟侧,而且门禁不测它:** 首次可听 2660/2340 ms,LAAL 2820/3221 ms,
长音频内部静音 28.9%。m3 在这几项上明显更好(883/978 ms,518/2184 ms,19.6%)。
门禁的 6 项判据里没有一项是延迟,所以"C 5/5 通过"不等于"C 可部署" —— 它等于
"C 在内容和结构上首次全部达标"。
