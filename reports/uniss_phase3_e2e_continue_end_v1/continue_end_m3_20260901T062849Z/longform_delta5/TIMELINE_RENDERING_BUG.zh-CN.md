# "提前发声 / 提前翻译完" 是 demo 渲染 bug,不是模型行为

## 1. 结论

`build_stereo_demos` 把译音写进 `stereo[:len(translation), 1]` —— **从 0 开始**,
而它读的 mono 译音是 `np.concatenate(chunks)`,**所有片段从零紧密拼接**。
**每个片段实际的发出时刻被完全丢弃。**

后果:19.38 秒源上产出的 13.16 秒语音被压进前 13.16 秒播放,听起来就是
**译音一路超前、并且提前 6.2 秒结束**。

## 2. 排除抢跑:模型没有翻译没听到的内容

逐事件核对 `emilia_zh_0003980703`(模型 MT 增量 vs 当时已听源):

| 事件 | 源已听 | 模型输出 | 对应源内容 | 判定 |
|---|---:|---|---|---|
| 3 | 640ms | `In this` | 那在这个 | ✓ 已听 |
| 5 | 1120ms | `case he` | 当中他 | ✓ 已听 |
| 7 | 1920ms | `safety` | 安全 | ✓ 已听 |
| 9 | 2560ms | `to satisfy` | 来满足 | ✓ 已听 |
| 12 | 3680ms | `needs` | 需求 | ✓ 已听 |

**全部翻译已听内容。** 看起来"超前"是因为 **gold 的对齐是爆发式的** ——
它把 `its security is meant to meet these needs` 一次性放在事件 22
(`target_support_end_ms` 6320ms),而模型把等价内容均匀分布在事件 5–24。
这是分布差异,不是抢跑。

## 3. 修复:`evaluation/timeline_stereo.py`

片段 k 在其事件的 `source_end_ms` 时刻可用,播放起点取
`max(source_end_ms, 前一片段结束)` —— 单个扬声器不能同时放两段。
中间没有内容准备好的地方保持静音,这才是真实听感。

| 样本 | 源时长 | **拼接渲染(旧)** | **时间轴渲染(正确)** | 排队延迟 均值/最大 |
|---|---:|---:|---:|---:|
| `emilia_zh_0003980703` | 19.38s | **13.16s** | **19.44s** | 169 / 1360 ms |
| `emilia_zh_0003929091` | 16.78s | 16.16s | **17.40s** | 577 / 1220 ms |
| `LibriSpeech_0000174311` | 16.56s | 14.14s | **16.56s** | 273 / 880 ms |
| `LibriSpeech_0000213211` | 16.84s | 11.62s | **17.22s** | 149 / 560 ms |

**时间轴渲染后译音时长与源几乎完全匹配。**

## 4. 被这个 bug 污染的指标

| 渲染 | 可听起始中位 | 译音时长/源 |
|---|---:|---:|
| 长 rp1.1 **拼接(旧,错)** | **418 ms** | **0.766** |
| 长 rp1.1 **时间轴(正确)** | **978 ms** | **0.972** |
| 长 greedy 拼接(旧,错) | 954 ms | 1.022 |
| 长 greedy 时间轴(正确) | 1664 ms | 1.083 |
| 短 rp1.1 拼接(旧,错) | 643 ms | 0.850 |
| 短 rp1.1 时间轴(正确) | 883 ms | 1.117 |

**此前所有报告过的"可听起始"都偏乐观 2.0–2.3 倍**,因为它测的是拼接音频的
前导静音,而不是真实的首次可听时刻。**`first_emission_ms`(来自事件时间线)
不受影响,仍然正确。**

## 5. 新的诚实指标:排队延迟

时间轴渲染顺带给出一个此前没有的量:**排队延迟** —— 一个片段因为上一段还在播
而必须等待的时间。

| 样本 | 均值 | 最大 |
|---|---:|---:|
| `emilia_zh_0003980703` | 169 ms | 1360 ms |
| `emilia_zh_0003929091` | **577 ms** | 1220 ms |
| `LibriSpeech_0000174311` | 273 ms | 880 ms |
| `LibriSpeech_0000213211` | 149 ms | 560 ms |
| `emilia_zh_0005215832`(短) | **1350 ms** | — |

排队延迟大 = 模型说得比源快,后面的片段被堵住。这是**过度生成的直接听感代价**,
比"音频/源"比更贴近用户体验。
