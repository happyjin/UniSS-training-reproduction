# 探针那 64 条上的正确对照线

探针用的是 CVSS-T **test**，两个方向各 64 条，取法是
`rows.sort(key=id); rows[:64]` —— id 排序后的前 64 条，不是随机抽样。
Phase B 级联公布的 27.68 / 34.14 是**全量 4,897 条/方向**，两者不可直接比。

把 Phase B 的全量结果抠出同样这 64 条重新打分（协议自检：全量复现
27.68 / 34.14 精确一致，所以下面的偏差可信）：

| | zh→en | en→zh | mean |
|---|---|---|---|
| Phase B 级联，**这 64 条** | **32.22** | **36.21** | **34.21** |
| Phase B 级联，全量 4,897 | 27.68 | 34.14 | 30.91 |
| 偏差 | +4.54 | +2.07 | +3.30 |

**和 Phase E 探针比，要用 32.22 / 36.21。**

+3.30 的偏差和 Stage 2 当年发现的 +3.29 几乎相同，同一个病根：
id 排序的前 N 条不是随机样本。探针之间互比不受影响（每次同一批），
只有跨实验比较需要这张表。

## Phase E 的进度（按正确对照线）

| | zh→en | en→zh | mean | 占目标 |
|---|---|---|---|---|
| Phase D 端到端（Talker 没见过音频条件状态） | — | — | 0.15 | 0% |
| Phase E iter 4,000，两次调用 | 7.89 | 18.30 | 13.10 | **38%** |
| Phase E iter 4,000，一次调用 | 5.96 | 17.00 | 11.48 | 34% |
| 目标（Phase B 级联，同 64 条） | 32.22 | 36.21 | 34.21 | 100% |

## 为什么判断是「没训练好」而不是「坏了」

同一个 Talker 在 TTS 模式（喂参考译文）下：

    Phase D iter 14,000   zh→en 63.55   en→zh 73.91

英语不是结构性坏的。差的是「读音频条件状态」这条路，而这正是
Phase E 在训的东西。

训练量对比：

    Stage 1   40,000 x 384  = 15.36M
    Phase D   14,000 x 1024 = 14.34M
    Phase E    4,000 x 512  =  2.05M   ← Phase D 的 14%
    Phase E   15,000 x 512  =  7.68M   ← 计划总量也只有 Phase D 的 54%

计划预算只有 Phase D 的一半，而任务更难。编排器在增益 >= 1.5 时
自动延长到 25,000（12.8M），刚好补到相当水平。
