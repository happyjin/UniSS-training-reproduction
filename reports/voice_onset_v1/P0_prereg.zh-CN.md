# 新论文 voice_onset_v1：隐马尔可夫开口（身份证据驱动的开口时机 + 后验 MBR 音色）
# P0 预登记：带噪时"多听一会儿"能否明显增加身份证据（2026-11-21 17:34 CET，写在任何 P0 数字之前）

## 背景与总计划
- **用户决定（2026-11-21）：** 这是一篇全新论文，不属于 MIST；"开始验证"。
- **约束：** 严格不用 QABC，内容的提交仍由 LA2 决定；一个模型同时做两个方向；不做 teacher-student 蒸馏；只用开放数据训练；RealSI / OBSI 只作测试；验证阶段每个方法只用一个设置、单种子。
- **方法：**
  1. 端到端可训练的小模块：每段音频的噪声不确定性网络 Σ_t = f_θ、嵌入投影头、开口转移网络 p_φ；
  2. 可微的闭式 Kalman 层，累积说话人后验；
  3. 用前向算法对开口时刻求边缘的 HMM（隐事件 = 在 LA2 首次准备好写出之后的第几段开口）；
  4. 损失 = −log Σ_g p_φ(g) · N(y_ref; m_g, P_g + Σ_ref) + λ · E[g − τ]，其中 y_ref 是同一说话人的另一句录音（同说话人最大似然，不是蒸馏）；
  5. 推断时：开口后用后验 MBR 版的 AbS 选 32 个全局音色 token。
  - TitaNet 主干、BiCodec、Thinker、Talker 全部冻结。
- **步骤：** P0（本文件）→ P1（训练 + 留出说话人上的校准检查，另立预登记）→ P2（S1 dev 上的 Talker 评测）→ P3（测试集，只跑一次）。

## P0 设计（只用 CPU，不训练，只看前提）
- **数据：** S1 dev（`eval_outputs/mist_w3po_v1/wave2_S1/data`），两个方向，干净 / 带噪孪生对；主分析用 a、b 两组，b_noxt 只报告。
- **开口时刻 τ：** 每条用底座 LA2 Thinker（`wave2_S1/thinker_<d>/blocks_<d>_w1.jsonl`）第一个块的 write_ms，与部署完全相同：提示 = 源音频的前 max(τ, 1000 ms)。
- **提示长度：** L(Δ) = max(τ, 1000) + Δ，Δ ∈ {0, 500, 1000, 1500, 2000} ms。主分析只用两个孪生都满足"时长 ≥ L(2000)"的对（不截断）；全部条目另报。
- **身份：** cos(TitaNet-large(提示), TitaNet-large(干净孪生整句))，fp32，L2 归一化，与 `wave3_v_spksim` 相同。
  - 带噪提示得 s_n(Δ)，干净提示得 s_c(Δ)。
  - 这个参照对干净条件有利：干净提示本身就是参照的一部分，所以 s_c 会平凡地趋近参照。这一偏差不利于本假设，检验是保守的。
- **增益：** g_n = s_n(1000) − s_n(0)，g_c = s_c(1000) − s_c(0)。
- **判定（写定；两个方向都满足才算通过）：**
  1. 主子集上 g_n 的均值 ≥ 0.02；
  2. g_n − g_c 的配对均值，95% bootstrap CI 下界 > 0（单位 = stream，2000 次，种子 0）。
- **只报告：** 各 Δ 的曲线；噪声缺口在多听 Δ 后被收回的比例 (s_n(Δ) − s_n(0)) / (s_c(0) − s_n(0))；τ 的分布；被截断的比例。
- **不通过：** "多听一会儿"这个前提不成立，方法里去掉开口部分，停下向用户报告。
- **代码：** `experiments/voice_onset_v1/p0_prompt_length.py`（nemo_diar，只用 CPU），输出 `eval_outputs/voice_onset_v1/p0/`。

## 变更 1（17:50 CET，写在正式运行之前；冒烟测试在 CPU 上看过 2 对 4 条的数字）
- **问题：** 参照是"干净孪生整句"时，干净提示本身就是参照的前缀，相似度平凡地趋近 1（冒烟测试中一条为 0.94 → 1.0）。这会让干净与带噪的比较失真，而且偏差方向不确定（干净一开始就接近饱和）。
- **修正：** 参照改为干净孪生里**与所有提示都不重叠**的尾段。
  - 主判定（Δ = 1000）：参照 = 干净孪生 [L1, 句尾]，L1 = max(τ_干净, τ_带噪, 1000) + 1000，要求尾段 ≥ 1000 ms（英→中 294 对、中→英 413 对）；干净提示和带噪提示都对同一尾段计算 Δ ∈ {0, 500, 1000}。
  - 只报告：Δ 到 2000 的曲线，参照 = [L1 + 1000, 句尾]，同样要求尾段 ≥ 1000 ms。
- 判定规则的两条不变（g_n 均值 ≥ 0.02；g_n − g_c 的 CI 下界 > 0），只是换成这个参照和这个子集。

## 结果（2026-11-21 18:00 CET，只追加）
运行：CPU，32 个进程，约 3 min，1643 对；输出 `eval_outputs/voice_onset_v1/p0/{rows,summary}.json*`。

- 只报告，Δ 到 2 s 的曲线（参照 [L1 + 1 s, 句尾]）：英→中 177 对，增益 带噪 +0.037 / 干净 +0.044，差 −0.007 [−0.013, −0.001]；中→英 268 对，+0.042 / +0.040，差 +0.002 [−0.003, +0.007]。b_noxt 两方向的差都约为 0。
- τ 的中位数：干净和带噪都是 3000 ms。
- **判定：不通过。** 第 1 条通过（带噪多听 1 s 增益 +0.045 ≥ 0.02），第 2 条不通过（带噪与干净的增益差约为 0，CI 包含 0）。
- **解读：**
  1. 多听 1 s 对身份证据的提升在干净和带噪下**一样大**（约 +0.045 / s），所以"只在带噪时多等"没有依据。按事先写定的规则，方法里去掉开口部分。
  2. 在提示层面，噪声只让 TitaNet 身份低约 0.025，相当于少听约 0.5 s 的语音。而 Talker 输出端的噪声身份损失是 0.07–0.10。这说明身份信息大多还在提示里（TitaNet 对噪声近似不变，与 D0 一致），损失主要发生在 BiCodec 编码器和量化这一环。这正是 AbS 针对的瓶颈，而不是证据不够。
  3. 不分噪声、统一加长提示对身份有利（每秒约 +0.045）。不增加延迟的做法是跨句累积同一说话人的语音，但这与噪声鲁棒无关，且与 voicecond 线的 Idea 6 / CA-Kalman 重叠。
- 按规则停下，向用户报告；P1–P3 不启动。
