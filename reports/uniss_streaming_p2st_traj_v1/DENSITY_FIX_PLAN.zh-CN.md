# 卡顿与突然停止:根因确认,以及为什么必须回训练侧修

2026-09-07。承接 `WHY_IT_STOPS_ROOT_CAUSE.zh-CN.md`,补上最后两项测量。

## 根因:两个独立的原因,不是一个

### 原因 A — 码密度中位数系统性偏低 19%(内容层)

每个词块需要多少语义码,模型系统性给少了:

| | 每片段 codes/char 中位(对 gold) |
|---|---:|
| prior off | **0.81** |
| prior 2.0 | 0.83 |
| prior 4.0 | 0.91 |
| prior 8.0 | 1.03 |

**关键是:这不是方差问题。** 训练目标自己的离散度就很大 ——
全池扫描(en2zh 34.7 万词块 / zh2en 29.0 万词块,`target_text_delta` 对
`target_semantic_delta`):

| | 中位 codes/char | 归一化 p10 | 归一化 p90 | 离散度 p90/p10 |
|---|---:|---:|---:|---:|
| GOLD en2zh | 11.80 | 0.68 | 1.69 | **2.50×** |
| GOLD zh2en | 3.76 | 0.63 | 2.66 | **4.22×** |
| 我们 prior4(合并方向) | — | 0.68 | 2.05 | **3.01×** |

我们的离散度落在 gold 的区间内。**一个词要多少码,在真实语音里本来就浮动
2.5–4.2 倍**(取决于韵律、重音、句中位置),所以这个量**不可能**由文本唯一确定。
模型学到的方差是对的,**只有中位数偏了**。

### 原因 B — 流式放置本身(调度层)

gold 的码放到我们的流式时间线上,静音也到 **30.2%**(gold 自己打包时是 8.6%)。
17 s 的语音铺在约 20 s 的时间线上,差额必然表现为静音,任何调度都填不满。
播放缓冲只能动这一层:≥500ms 的洞 4.38 → 3.75 个/条。

## 为什么长度先验修不好

长度先验是**乘法旋钮**:它给 `END_SEMANTIC` 加一个全局 logit 偏置,
所以它把整条分布一起平移,而不是只抬短的那一端。

| | 中位 | p10 | p90 | **< 0.5 gold 的片段** | 长音频内部静音 |
|---|---:|---:|---:|---:|---:|
| prior off | 0.81 | 0.55 | 1.76 | **7.3%** | 9.3% |
| prior 2.0 | 0.83 | 0.59 | 1.83 | 2.7% | 10.7% |
| prior 4.0 | 0.91 | 0.68 | 2.05 | **0.5%** | 13.4% |
| prior 8.0 | 1.03 | 0.79 | 2.45 | 0.2% | — |

两种听感对应两端:

* **prior off**:7.3% 的片段密度不到 gold 一半 → 词被切掉 → **突然停止**;
* **prior 4.0**:切断基本消失(0.5%),但 p90 被拉到 gold 的 **2.05 倍** ——
  那 10% 本来就偏长的片段被继续拉长,多出来的码渲染成停顿 → **卡顿**。

**所以推理侧无解:全局乘法偏置只能平移分布,不能既抬中位数又不动尾部。**
777 条上文本 100% 逐字节相同、文本 BLEU 恒为 18.28 / 11.07,而 ASR-BLEU
从 18.75/13.71 掉到 16.61/12.61 —— 差距全部是声学可懂度,不是翻译。

## 解决方案

### 方案 1(首选):把码数变成显式预测目标,写在文本流里

**做法**:每个写事件在语义码之前,先在文本流里用数字写出这一块要多少码。
数据里已经有精确值 —— `micro_write_events` 的 `semantic_start/end` 之差。

```
... <text delta> "16" <BOS_SEMANTIC> c1 c2 ... c16 <END_SEMANTIC> ...
```

**为什么这个能同时修好 A 和 A′**:预算是**每片段**的,抬短的不动长的,
正是先验做不到的事。推理时用预测值作为语义阶段的硬上下界,
**完全取消长度先验**。

**为什么不动词表**:数字用现有文本 token 写,不新增 embedding、不改输出头 ——
这是本项目一贯的最小侵入路径(IDLE 当初也是这么落地的)。

**已知代价**:该量有 2.5–4.2 倍的自然浮动,模型只能预测条件均值,
韵律会被轻微压平。对可懂度是正确取舍,对表现力是损失。

**落地位置**(全部新建,不动既有代码):
* `data/uniform_chunk_tasks.py` 加一个 `--emit-duration` 开关(我自己的文件);
* `training/build_traj_pools.py` 透传;
* 推理侧新建 `runtime/duration_budget.py`,在 `p2st_cascade.py` 之外包一层,
  不改 cascade 本体。

**工作量**:一次建池(约 200 GB,纯 CPU)+ 一次训练(约 13.6 h)。

### 方案 2(便宜,可与 1 并行):END_SEMANTIC 的 CE 按长度误差加权

不改数据格式,只在目标函数里给终止符的 CE 乘一个与
`|已生成码数 − gold 码数| / gold 码数` 相关的权重 ——
早停 30% 的代价远大于早停 3%。新增损失项默认权重 0,既有配方不受影响。

比方案 1 弱(仍然是单个决策,没有显式预算),但改动小一个数量级,
适合作为方案 1 的对照臂。

### 方案 3(纯 CPU,当天可做):按密度重加权训练池

模型中位数 0.81 有可能是池里存在一个"偏快"子群、模型回归到它。
先扫一遍池里每条轨迹的密度分位,再按密度分桶重采样 ——
直接复用步骤 1 的 `nir_stratify.py` 机制。
最便宜,但预期只是部分修复,应当作为方案 1 的数据前置而不是替代。

### 方案 4(调度层,已完成一半):播放缓冲 + 速度 token

* 1000 ms 播放缓冲:片段间静音 0.287 → **0.101**(优于 NaturalFlow 的 0.13/0.21),
  ASR-BLEU 不变,代价是 playout 轴上 LAAL 4852 → 5364;
* 速度 token 0.8:均匀放慢,内部静音 13.3% → 9.2%,但只买到 +11% 的码就饱和。

这两条与方案 1 **互补**,不是替代 —— 方案 1 之后应当用
「每片段预算 + speed 0.8 + 1000 ms 缓冲」重跑一次完整评测。

## 不该做的

* **把先验调到 8.0**:中位数到 1.03 但 p90 到 2.45,停顿更多;
* **填静音 / comfort noise**:是掩盖不是修复,实测无 BLEU 收益;
* **换架构(步骤 5)**:当前瓶颈是密度监督缺失,不是模型容量 ——
  0.52B 已经在同架构下打平论文 3B 的 Dec-only 基线。

## 验证判据(指标链已全部就绪)

| 指标 | 当前(prior 4.0) | 目标 |
|---|---:|---:|
| 每片段 codes/char 中位 | 0.91 | **1.00** |
| 同 p90 | 2.05 | **≤ 1.80** |
| < 0.5 gold 的片段 | 0.5% | ≤ 1% |
| 长音频内部静音 | 13.4% | **≤ 10%**(gold 8.6%) |
| ASR-BLEU(无先验) | 16.61 / 12.61 | **≥ 18.75 / 13.71** |
| 文本 BLEU | 18.28 / 11.07 | 不退化 |
| RTF | 1.49 | 不退化 |

关键判据是**最后两行加第一行**:如果取消先验后 ASR-BLEU 还能持平,
就证明先验的收益确实来自密度,而预算把它拿回来了。
