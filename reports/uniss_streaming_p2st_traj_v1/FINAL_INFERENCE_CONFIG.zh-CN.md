## 二、明确不采用的

**"说完音节"overrun**(`--semantic-end-min-margin`)。它拿到了全场最好的边界指标
(mid_voice 40.2% → **17.3%**,尾部比 0.77 → 0.20,比训练 600 步的 21.8% 还好),
但它靠**强制多吐码**做到,c/char 冲到 **1.20**(超 gold 20%),听感是**元音被拉长**。
代码保留、默认关闭,因为它的边界数字有独立价值,但不进部署配置。

## 四、采样 + 重排序:8 条上判错了,777 条上它有效

> **本节已于 2026-09-09 更正。** 先前版本根据 8 条长音频写了"静音轴没有可挖空间,
> 因此 HPO 的 RL 版本也被否定"。**那个结论是错的**,777 条推翻了它。原文的错误保留在
> 下面的对照表里,因为它正是 §五 那条测量纪律的又一个实例。

按 HPO 的分层奖励(质量/延迟**分别**组内归一化、质量不过门就把延迟罚满、`q̄ − λl̄`)
对采样候选重排序。

### 8 条长音频(16 个候选)—— 看起来无望

| | 静音 | 句级 BLEU |
|---|---:|---:|
| 贪心 | 0.230 | 32.63 |
| HPO 采样设置,16 个均值 | 0.508 | 18.97 |
| 中档 t=0.7/p=0.90,16 个均值 | 0.391 | 31.16 |
| 中档 + 重排序 λ=2.0 | 0.247 | 36.64 |
| **组内 oracle** | **0.212** | — |

oracle 只比贪心好 8%,于是我判"没有空间"。

### RealSI 777(8 个候选)—— 相反

| | 静音 | 95% CI | 文本 BLEU en2zh | zh2en |
|---|---:|---:|---:|---:|
| **贪心基线** | **0.198** | [0.185, 0.209] | 18.17 | 11.17 |
| 8 个候选,各 arm 均值 | 0.213 | | | |
| **重排序 无参考 λ=0.5** | **0.135** | [0.125, 0.145] | **19.88** | **12.56** |
| **重排序 无参考 λ=1.0** | **0.114** | [0.105, 0.124] | 19.67 | 12.23 |
| **重排序 无参考 λ=2.0** | **0.095** | [0.086, 0.105] | 19.07 | 12.11 |
| 重排序 有参考 λ=0.5(上界) | 0.156 | [0.145, 0.167] | 23.07 | 17.38 |
| **组内 oracle** | **0.074** | | | |
| **GOLD** | **0.084** | | | |

**组内 oracle 是 0.074 —— 低于 gold 的 0.084。** 采样分布里确实存在连续语音的样本,
贪心解码只是永远选不到它们。

**无参考重排序把静音从 0.198 减半到 0.095,区间完全不重叠,而文本 BLEU 还涨了
(+1.71 / +1.39 在 λ=0.5)** —— 因为分层门控把质量差的候选挡在了外面。

### 为什么两组数据相反

8 条是长篇多句音频,难得多:候选组均值静音 0.391 对 777 条的 0.213,
而 8 条上这个指标的区间是 ±13pp。**这是同一条测量纪律第三次咬人。**

### 对 RL 的含义

先前版本据此否定了方案 B,理由是"policy gradient 只能强化分布里已有的东西"。
那个推理本身没错,**但前提数据是错的**:777 条上分布里**有** oracle 0.074 的样本,
所以 GRPO 有可以搬运概率质量的目标。**方案 B 重新成为有依据的选项。**

而重排序的代价是 **8 倍推理开销**(8 个候选)。RL 的价值正在于把这个收益烘进权重,
推理时只跑一遍 —— 这也是 HPO 论文在推理时用 beam=4 而不采样的原因。

必须说明:HPO 论文**推理时不采样**,那 16 条采样是 RL rollout 用的,
所以本节测的是"它的奖励形状值多少",不是复现它。
另外我之前一次候选筛选失败的原因也在这里找到:当时用 SimulS2ST-Omni 的
`top_p 0.8 / top_k 20`,**16 个候选几乎逐字节相同**,分位数规则无从分层;
论文的 `0.999 / 10000` 给出 16/16 个不同文本。

## 五、测量纪律(适用于后续所有结论)

777 条上 hole share 的 95% 自助区间是 **±1.3pp** → 8 条上是 **±13pp**。

| 对比类型 | 例子 | 可信 |
|---|---|---|
| **配对**(同一份片段,只改时间/包络) | 缓冲、淡化、底噪、切点吸附 | **是**,区间 ±0.2–0.6pp |
| **非配对**(不同权重 → 不同内容) | 各检查点之间 | **8 条上不可信** |
| 边界分类(每 arm 97–99 个边界) | mid_voice、尾部比 | **是**,效应量 ≫ σ≈5% |

我曾用 8 条上的 hole share 写过"训练目标达成但听感变差"的结论,那个结论已作废。

## 六、剩下的差距,以及为什么停在这里

定案配置的静音是 **13.4%**,gold 是 8.4%、offline 8.0%。

**但 §四 表明这个差距是可以关掉的**:无参考重排序在 777 条上到 **0.095**,
比 gold 的 0.084 只差 1.1pp,而组内 oracle 已经是 0.074。所以本轮定案的
13.4% **不是能力上限,是单次贪心解码的上限**。

两条继续的路,都有了依据:

1. **重排序上线**(立刻可做):静音减半、文本 BLEU 还涨,代价是 **8 倍推理开销**;
2. **HPO 式 RL**(方案 B):把同样的收益烘进权重,推理时只跑一遍。
   §四 的更正恢复了它的前提 —— 分布里确实有可强化的目标。

先决条件是 ASR-BLEU:文本 BLEU 涨了,但本项目的正式指标是声学的,必须单独确认。
