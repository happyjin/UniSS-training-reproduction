# 流式语音停顿这条线的完整记录:8 个被否证的假设,和 3 个有效的手段

2026-09-11。本文记录为解决"发音突然停止 / 卡顿"所做的全部尝试。
**重点不是最终配置,而是那 8 个否证** —— 每一个都附带证据和样本量,
因为下一个做这件事的人最需要知道的是"哪些路已经走过、为什么不通"。

## 零、测量纪律(先读这条,否则下面的数字会被误读)

RealSI 777 条上 hole share 的 95% 自助区间是 **±1.3pp**;
**8 条长音频上是 ±13pp**(√(777/8) ≈ 9.9)。

| 对比类型 | 例子 | 8 条上可信? |
|---|---|---|
| **配对**(同一份片段音频,只改时间或包络) | 播放缓冲、淡化、舒适噪声、切点吸附 | **可信**,区间 ±0.2–0.6pp |
| **非配对**(不同权重 → 不同内容) | 不同检查点之间 | **不可信** |
| 边界分类(每 arm 97–99 个边界) | mid_voice、尾部比 | 可信,效应量 ≫ σ≈5% |

**这条纪律在本轮咬了三次**:我曾据 8 条数据写过"边界训练达成但听感变差"、
"静音轴没有可挖空间因此 RL 也被否定",两条都被 777 推翻并已更正。

## 一、根因:三件事叠加

### 事实 1 — 片段的切口落在**一个音的正中间**

`cut_placement` 在 97 个内部边界上:**40.2% 是 mid_voice**(两侧同为满幅发音),
**40.0% 的片段未衰减就结束**(尾部比中位 0.77)。

而且切口确实在**同一个音内部**。30 ms 窗的频谱距离:

| | n | 中位 |
|---|---:|---:|
| A 片段接缝(mid_voice) | 39 | **0.198** |
| B 同段音频往前挪 30 ms(音内部对照) | 39 | **0.198** |
| C 真实音素过渡(有声区 p90) | 8 | **0.740** |

**接缝 / 音内部 = 1.00×,接缝 / 音素过渡 = 0.27×。**

### 事实 2 — 接缝本身**不是爆音**

接缝采样跳变 0.0084,片段内部 p99 是 0.0942 —— **只有 0.09×**,比正常语音起伏还平滑。

### 事实 3 — 致命的是切口**之后插入的真空**

39 个音内切口里 6 个后面跟 ≥300 ms 空白,而这些空白 **39% 是精确的零**、
边缘落差 **11×**(offline 和 gold 都是 0% / 4–5×)。

**机制:元音发到一半被切 → 没有收尾 → 0.3–2.9 秒真空 → 后半段太晚,听不出是同一个音。**

### offline 为什么免疫

**一个片段,零个内部边界** —— 结构上没有可切的地方。
代价是要等 **16.8–19.4 秒**才开口,而且只说 12.9–16.4 秒(流式说 18.4–23.8 秒的同一段译文)。
**offline 不是更好的模型,是同一个模型把等待挪到开头并且少说了内容。**

## 二、8 个被否证的假设

| # | 假设 | 证据 | 样本量 |
|---|---|---|---|
| 1 | 模型生成静音码 | 四档先验下 ≥500ms 静音码串 **0.000–0.003 个/条**,gold 是 0;全量训练池 20 万条同为 0.01 | 777 + 池 |
| 2 | 退化重复 | 我们最长同码连续 **1.1**,gold 是 **2.0** —— 比 gold 更不重复 | 8 条 × 98 边界 |
| 3 | 声码器接缝 | 接缝跳变 **0.09×** 片段内部 p99 | 39 个接缝 |
| 4 | 码**密度**不足 | prior 4.0 已把密度分布复现到 gold 的 6% 以内(中位 1.01/1.00,p10 0.68/0.66,p90 2.06/1.94),内部静音仍是 **1.5 倍** | 777 |
| 5 | 密度**离散度**过大 | 硬预算把离散度从 3.0× 收紧到 **1.3×**,BLEU 反而 **18.75 → 15.82** | 777 |
| 6 | 提交截止(尾部倾泻) | 目标侧 cap 16 **完全不触发**(无积压);源侧净退步(片段 13.1→9.9、首次发音 2560→2880) | 8 条 |
| 7 | **边界落点**可训练且有效 | mid_voice **40.2% → 21.8%** 训得动,但 777 上静音 18.6% [17.5,19.9] 与当前最好 19.8% [18.6,21.1] **区间重叠** | 777 |
| 8 | **RFT** 把重排序的收益蒸馏进权重 | 见第四节 | 777 + 8 条 |

另有两个**我自己判断错误**并已更正的:

* **3 秒缓冲是必需的** —— 错。777 条上 **500–1000 ms 就到膝点**;3 秒那个数来自 8 条的噪声。
* **需要实现 X2Streaming-TTS 的 speech-state inheritance** —— 不需要。
  `StreamingBiCodecDecoder` 已带 **50 token 左上下文**、5 token holdback、80 ms overlap,
  远强于论文的 H=4。所以 `translation_concat` **本身就是连续的**,切口纯粹由放置造成。

## 三、3 个有效的手段(定案配置)

```
模型   checkpoints/uniss_streaming_p2st_traj_v1/rollin_soft_20260908T190728Z/iter_0000050
HF     checkpoints/exported_hf/uniss_streaming_p2st_traj_v1_rollin_soft_20260908T190728Z_iter_0000050_hf
推理   --read-stride 4 --source-holdback 1 --target-holdback 0
       --length-prior-scale 4.0 --min-fragment-tokens 16 --min-final-chunk-ms 320
渲染   snap_cuts --window-ms 200
       deploy_render --buffer-ms 1000 --taper-ms 40 --gap-ms 120
```

| 组件 | 效果 | 样本量 | 延迟 |
|---|---|---|---|
| **切点吸附** — 把断点挪到边界前最近的能量低谷 | 未衰减结束 **40.0% → 19.0%** | 98 边界 | **0**(内容逐字节不变) |
| **淡化 + 舒适噪声** — 40 ms 升余弦收尾 + 按译音停顿电平填底噪 | 精确零 **39% → 0%**,落差 **11× → 5×** | 8 条配对 | **0** |
| **播放缓冲 1000 ms** | 静音 **−5.22pp**,95% CI [4.79, 5.65] | **777 配对** | 1 s |

**RealSI 777:静音 19.8% → 13.4%,ASR-BLEU 18.57 / 14.36(合计 32.46 → 32.93),RTF 1.41。**

**切点吸附的依据**是事实 2:模型自己的音频没有切口,空档必须插在某处但不必插在片段边界。
往前挪永远合法(延迟播出),往后不合法(会播出尚未被源证成的语音)。

### 明确不采用的

**"说完音节"overrun**(`--semantic-end-min-margin`):拿到全场最好的边界指标
(mid_voice **17.3%**、尾部比 0.20,优于训练 600 步的 21.8%),
但靠强制多吐码做到,c/char 冲到 **1.20**,**听感是元音被拉长**。代码保留、默认关闭。

## 四、RFT 的完整失败记录

### 前提全部验证通过

在 20,000 条训练切片上,每条采 8 个候选(t=0.7/p=0.90/k=100),
用 HPO 的分层奖励(质量/延迟分别组内归一化、质量门控、`q̄−λl̄`,λ=2.0)选赢家:

| | 值 |
|---|---:|
| 组均值 → 选中 | 0.347 → **0.219** |
| 组内 oracle | 0.191 |
| 捕获余量 | **82%** |
| 赢家文本 BLEU | en2zh **45.62** / zh2en **29.14** |
| 赢家分布 | 最高 **12.7%**、最低 12.3%,8 个种子全用上 —— 学的是**行为**不是幸运种子 |
| 轨迹重建完整性 | 文本 **0/4000 不一致**,码 98.6%,事件 97.8% |

### 第一次尝试:崩溃

把 gold 和赢家轨迹拼进同一个 jsonl,五个 family 全混。180 步后:

| | 字数 | ASR-BLEU 合计 |
|---|---:|---:|
| 父检查点 | **60** | **32.93** |
| RFT @50 | 36 | 14.56 |
| RFT @100 | 9 | 1.60 |
| RFT @180 | **7** | **1.10** |

**原因**:gold 和赢家对"何时提交文本"的监督完全相反 ——

| 同一批 3000 条源音频 | 事件数 | 字/事件 | 空 delta 比例 |
|---|---:|---:|---:|
| **GOLD** | 34.6 | **1.4** | **70.8%** |
| **赢家** | 5.6 | **8.0** | **0.0%** |

gold 教"边听边等、一次 1.4 字";赢家教"成块输出、从不等待"。等量混进同一 family,
模型学出的折中就是提前终止。**这是我的设计错误** ——
我提案时写的是"新增独立 RFT family",实际建池时两者进了同样的五个 family。

### 第二次尝试:修好了崩溃,但没有改善

写了 `graft_pool.py` 做 family 级拼接:MT/ASR/replay 保持**纯 gold**,
只有 `p2st_streaming_tts` 来自赢家(赢家的价值在声学行为,不在提交策略)。

| 8 条长音频 | 字数 | mid_voice | 未衰减 | ≥500ms | 最长 | 静音% |
|---|---:|---:|---:|---:|---:|---:|
| **父检查点** | **156** | 40.2% | 40.0% | 4.62 | **2850** | **23.0%** |
| 混合 family @100 | **68** | 37.5% | 44.8% | 1.00 | 13125 | 30.3% |
| 嫁接 @50 | **156** | 43.9% | 40.0% | 3.62 | 4425 | 29.5% |
| 嫁接 @100 | **157** | 47.1% | **33.7%** | 4.00 | 4395 | 28.2% |
| 嫁接 @150 | **157** | 46.1% | 44.3% | 4.00 | 4635 | **25.7%** |

**字数完全保住(156/157/157)—— 诊断被证实。**
**但静音始终没回到基线(25.7% 对 23.0%),最长静音 2.85 s → 4.6 s。**

**赢家的低静音行为没有通过 TTS family 传给模型。**

### 推理侧重排序本身是有效的

| RealSI 777 | 静音(95% CI) | ASR-BLEU 合计 | 开销 |
|---|---:|---:|---:|
| 贪心 | 0.198 [0.185, 0.209] | **32.93** | 1× |
| **重排序 λ=2.0(无参考)** | **0.095** [0.087, 0.104] | 32.74 | **8×** |
| 组内 oracle | 0.074 | | |
| GOLD | 0.084 | | |

**静音减半、区间不重叠、BLEU 持平,而且组内 oracle 0.074 已低于 gold 的 0.084。**

**所以结论是:重排序在推理时有效,但它的收益蒸馏不进权重。**
而 RFT 和 GRPO 用的是同一个信号(一个单步、一个迭代),单步都传不进去,
迭代没有理由更好 —— 这也是对 RL 路线的一个(非决定性的)负面证据。

## 五、方法出处:严格说,本轮跑的方案**不属于任何一篇论文**

| 组件 | 出处 | 忠实度 |
|---|---|---|
| 分层奖励(质量/延迟分别归一化、质量门控、`q̄−λl̄`) | **HPO** arXiv 2604.21045,ACL 2026 Oral | 形状忠实,但 HPO 用它做 **GRPO 的 RL 奖励**,**推理时用 beam=4 不采样** |
| 采样参数(16 候选,top_p 0.999/top_k 10000) | HPO | 参数忠实,但那是 **RL rollout** 用的 |
| 按静音选候选 | **NaturalFlow** arXiv 2606.13121 | **不忠实** —— 它取**第二个五分位**并明确警告压到最低会毁质量,我取了 **argmax** |
| **拒绝采样微调(RFT)** | **两篇都没有** | 我提出的"比 RL 便宜的替代",标准技术,不是任何论文的做法 |

一个顺带的发现:我更早一次候选筛选失败的原因也在这里找到 ——
当时用 SimulS2ST-Omni 的 `top_p 0.8 / top_k 20`,**16 个候选几乎逐字节相同**;
HPO 的 `0.999 / 10000` 给出 16/16 个不同文本。
