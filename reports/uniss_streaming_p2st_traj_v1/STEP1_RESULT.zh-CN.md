## 一、结论:有效,而且效果落点与论文预测完全一致

论文 §4.5 说 NIR 过滤是"低延迟鲁棒性的首要驱动"。实测正是如此 ——
**增益集中在低延迟档,且集中在源 ASR 上**:

### k1 + s1t0(低延迟工作点,这一条是干预的目标)

| | C | **NIR** | 变化 |
|---|---:|---:|---|
| **ASR-BLEU** En→Zh | 14.01 | **14.83** | **+0.82 (+5.8%)** |
| **ASR-BLEU** Zh→En | 10.05 | **10.85** | **+0.81 (+8.0%)** |
| **源 ASR 错误** En→Zh (WER) | 0.421 | **0.315** | **−25.1%** |
| **源 ASR 错误** Zh→En (CER) | 0.804 | **0.546** | **−32.0%** |
| MT 文本 BLEU | 16.81 / 10.76 | 16.65 / 10.36 | −0.16 / −0.41 |
| 简短惩罚 | 0.790 / 0.834 | **0.803 / 0.915** | 改善 |
| 首次发音 | 1573 / 1743 ms | 1603 / 1795 ms | +30 / +52 ms |
| LAAL | 3686 / 2997 | 3703 / 3003 | 持平 |

### k25(质量工作点,ASR 本来就没坏)

| | C | **NIR** | 变化 |
|---|---:|---:|---|
| ASR-BLEU En→Zh | 17.33 | **18.14** | +0.81 (+4.7%) |
| ASR-BLEU Zh→En | 14.41 | **14.66** | +0.25 (+1.7%) |
| 源 ASR 错误 | 0.390 / 0.264 | 0.396 / 0.253 | **+1.6% / −4.3%(基本不动)** |
| MT 文本 BLEU | 16.59 / 10.46 | **17.03 / 10.64** | +0.44 / +0.17 |

**这个对比本身就是机制证据**:k1 上源 ASR 改善 25–32%,k25 上纹丝不动(1.6% / 4.3%)。
NIR 分层修的正是"细读步下的识别鲁棒性",不是通用能力。
反过来 MT 文本在 k1 上略降、在 k25 上略升,说明**它没有改善翻译本身**。

## 三、没有解决的问题

**卡顿完全没有改善**(8 条域内长音频,与 C 同口径):

| | C | NIR |
|---|---:|---:|
| 首次发音 | 1120 ms | 1200 ms |
| 空档/条 | 5.2 | 4.9 |
| 最长空档 | 3140 ms | 3720 ms |
| 内部静音 | 0.360 | 0.350 |
| **切在有声段中间** | 74% | **77%** |

**这是预期之内的**:步骤 1 只改数据组成,没有改读取时刻表、没有教模型"什么时候闭嘴"。
空档来自"模型当时没有可说的文本",而 NIR 分层不改变这一点。
**这正是步骤 2 的目标。**

论文自己的 demo 样本(zh2en/414)上,NIR 的源 ASR 略好(少了一个游离的"啊"),
译文质量相当,但**仍然把"于是你才要注意到"听成"医生已经注意到"** ——
那个幻觉出来的 "the doctor" 还在。

## 四、下一步

**建议按计划进入步骤 2+3(固定 640 ms chunk 网格 + 显式 IDLE 监督)。** 三条理由:

1. **步骤 1 的效果形态验证了移植方法本身**:论文说它修低延迟档的识别鲁棒性,
   实测就是修了那里(k1 −25%/−32%,k25 不动)。说明按论文改是有效的。
2. **剩下的问题恰好是步骤 2 的靶心**:77% 的切口在词中间、每条 4.9 个空档、
   内部静音 0.35 —— 步骤 1 结构上碰不到这些,步骤 2 直接针对。
3. **MT 与 TTS 没有改善**,而步骤 2 改的是写策略(什么时候写、写多少),
   正是这两项的上游。
