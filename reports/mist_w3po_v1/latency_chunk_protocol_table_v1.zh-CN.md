# 多说话人延迟：现行协议与 chunk 协议并列重算表 v1（2026-11-12 布拉格 14:40）

- 用户决定（14:05 前后，经协调者转达）：以后所有多说话人系统的延迟统一按 **chunk 协议**报告，新旧两种协议并列给出。本文件按这个决定，把存有输出的系统全部重算一遍。
- 只用 CPU，只读已有输出，只用 dev。没有训练、调参或重新解码，也没有用 GPU。
- chunk 协议是**记账更正**，不是方法收益。它对所有系统用同一个规则，系统之间的比较必须在同一协议下做。

## 1. 结论

1. 所有系统在 chunk 协议下都变快，每条流语音 LAAL 降 0.10–0.30 s。A′ 系列和 T2 系列都是 −0.19 s，VE1 系列 −0.16 到 −0.17 s，PMC −0.105 s，T1 −0.30 s。
2. **系统排名在两种协议下完全相同**：语音 LAAL（12 个系统）和文本 LAAL（6 个文本系统）都一样。
3. 系统之间的差大多几乎不变：
   - A′ 系列和 T2 系列内部，各系统对 A′rl + PL-EM 的差变化不超过 0.005 s；
   - VE1 系列对 A′rl + PL-EM 的优势缩小 0.02–0.04 s；
   - PMC 的优势缩小 0.09 s（−1.081 → −0.993）；T1 的劣势缩小 0.105 s（+2.300 → +2.194）。
4. 平移量不同的原因很简单：chunk 协议几乎只是让**关窗**提前（平均早 0.40 s），而开窗提前对 LAAL 几乎没有作用（≤ 0.006 s）。所以一个系统在最终读写出的词越多，平移越大：
   - PMC 只有 17.8% 的词在最终读写出，平移最小；
   - T1 有 83.8%，平移最大；
   - A′ 50.9%，T2 55.8%，VE1 42.8%，VE1-s2 39.7%，在中间。
   - 这不是哪个系统"占了便宜"，而是旧协议对最终读写得多的系统多算了检测器等待。
5. 已有的 ref_chunk 数字逐字节复现（第 2 节）。旧协议的重算与所有已存 latency json 的每个字段完全相同。

## 2. 做法与复现检查

- 开窗 = T(st)，gap / cap 关窗 = T(j − 1)，会议末尾不变。
- 窗口、后验、解码、talker 块都不变，只改时间戳。最终读在更早的 chunk 关窗时刻也能看到窗口内所有帧的 P，所以解码不变。
