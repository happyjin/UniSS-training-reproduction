# 鲁棒线：AbS / AbS-C 的 ASR-BLEU 下降是不是"Talker 没训练过这些 token"造成的（2026-11-21 13:56 CET）

只是分析，用已有的 S1 dev 输出（两个 TTS 种子；oracle 只有种子 1），只用 CPU，没有新的运行。
脚本 `experiments/mist_w3po_v1/voicecond/talker_asr_drop.py`、`talker_asr_drop_tail.py`，输出 `eval_outputs/mist_w3po_v1/talker_asr_drop/summary.json`。

## 方法
- **Talker 内容错误率（TER）：** ASR 转写对 **Thinker 文本**（Talker 被要求说的那段话）的编辑距离错误率。英→中按字，中→英按词，先用 `normalize_for_bleu` 规范化。各臂的 Thinker 文本逐条相同（核对过：100%），所以 TER 只反映 Talker 和 ASR，不含翻译质量。
- **剂量–反应：** 按 AbS 相对 V1 翻转的 FSQ 维度数分三档；另按提示重合成 STOI 的变化（AbS − V1）分三档。
- **长尾：** 在两个下降格里逐条看 AbS 的多余编辑数。

### 2. 剂量–反应：按翻转维度数分档（带噪行，ΔTER = AbS − V1）
| 方向 | 低档 | 中档 | 高档 |
|---|---|---|---|
| 英→中（2–24 / 25–29 / 30–41 维） | +0.88 | +0.70 | **−0.72** |
| 中→英（3–24 / 25–29 / 30–42 维） | −1.11 | −3.54 | +5.60 |

- 两个方向的趋势相反，不是单调关系；各档 V1 自身两种子的 TER 差为 0.3–6.5。
- 按提示重合成 STOI 分档：中→英 STOI 下降最多的一档 ΔTER 为 −4.4（反而更好），英→中各档在 +0.1 到 +0.6 之间。**提示层面的 STOI 不能预测 Talker 的可懂度。**

### 3. 长尾
- **中→英 a 带噪：** 种子 1 的 AbS 比 V1 多 170 次编辑，其中 220 次来自同一条：Thinker 文本只有 3 个词，Talker 失控，输出 221 次编辑。这一条在种子 2 正常（1 次）。种子 2 的 AbS 反而比 V1 少 60 次编辑。
- **英→中 b 带噪：** 种子 1 / 种子 2 的 AbS 比 V1 多 25 / 40 次编辑，占参考的 0.5–0.8%。用干净 token 的 oracle 比 V1 多 49 次编辑（种子 1）。
- 两格中，**没有一条**在两个种子上都比 V1 差 ≥ 5 次编辑。一个种子里变差的有 7 / 13 条；V1 自己在两种子间相差 ≥ 5 次编辑的有 9 / 5 条。

## 结论：不是"Talker 没训练过这些 token"
1. **用真实编码器 token 的 oracle 也低于 V1。** oracle 是 Talker 训练时见过的那种分布，它的 ASR-BLEU 和 TER 也不比 V1 好：TER 在 8 格中有 7 格高于 V1。AbS 与 oracle、B 同一水平。所以"在分布内"并不能带来更高的 ASR。
2. **D1 已经证明翻转本身无害：** 翻转约 42% 的 token、d-vector 不变时，ASR 不变。
3. **没有剂量–反应关系：** 翻转越多并不越差，英→中翻转最多的一档反而最好。
4. **没有系统性坏条目：** 下降来自单个种子上的随机失控条目。中→英 a 带噪的下降几乎全部来自一条失控。
5. **参照偏高：** V1 在多数格子上的 ASR 高于 B 和 oracle。V1 的"平均化"音色对 ASR 更友好（v5：MMSE 向平均音色收缩）。AbS 把身份拉回真实说话人，ASR 也回到 B / oracle 的水平。所以"AbS − V1"的一部分是 V1 的偏高，不是 AbS 的损失。

## 影响
- **重训 Talker 预计无益：** 上限是 oracle 的水平，而 oracle 不比 AbS 好。
- **AbS-C 的机制不成立：** 提示 STOI 不能预测 Talker 的可懂度。AbS-C 在带噪格的"修复"和在干净格的下降，都与运行噪声一致。如果只选一个方法，选 AbS：身份收益更大，延迟更短（0.28 s 对 0.42 s）。
- **判定规则的问题：** "每格 ASR-BLEU ≥ V1 − 0.3"的门槛小于单种子的运行波动（V1 0.8、B 1.07 BLEU），参照本身又偏高。原判定（not_established）不改。之后的测试预登记应事先改为：对 B（必要时对 oracle）做非劣性检验，用置信区间判定；并对 Talker 失控做稳健处理，例如另报去掉失控条目后的结果，失控条目要事先定义。
