# 鲁棒 R4：由一致性见证决定是否启用鲁棒适配器 预登记

2026-11-20 约 21:55 CET，写于任何 R4 数字之前。方案出处：`robust_analysis_and_ideas_v3_20261120.zh-CN.md` 第 3 节 R4；用户同意开跑 R1–R4。卡位见文末的变更 1。一个设置，不扫参；先看点估计（用户要求），不做 bootstrap。

## 规则
- **提交：** LA2 w1 不变，即提交原始音频 v0 草稿的 LCP(d_{t−1}, d_t)。不加视角见证，所以不增加提交延迟。
- **路由信号：** 每次读，被选中的模型同批计算两个草稿：v0 和 DeepFilterNet3 增强视角 v1（同第十五波，因果，逐读窗只用已读到的音频）。
- **路由：** 第 t 次读用哪个模型起草，由第 t−1 次读的信号决定：
  - v1 草稿 = v0 草稿（两个视角一致）→ 底座（α = 0）；
  - 不一致 → 鲁棒适配器。
- **第一次读：** 没有信号，固定用底座。理由：
  - 目的是保护干净输入；
  - LA2 第一次读从不提交，所以这个选择只影响第二次读的 LCP。
- **终稿：** 末次读用第 t−1 次读选中的模型，末次读不算 v1。
- **实现：** `voicecond/r4_si_thinker.py`。
  - 两个 vLLM 引擎在两个 spawn 出来的工作进程里，每个进程一张卡：一张放底座，另一张放适配器的合并副本。每个进程在 import vllm 之前设置 CUDA_VISIBLE_DEVICES。
  - 编码器 LoRA（enc_wise05）没有 vLLM 的 LoRA 路径，只有合并权重，所以两个臂统一用"两个合并模型实例"的方式。
  - 解码参数同 si_thinker_stream：贪心，最多 160 个 token，prompt base，seed 20261021。

## 臂
- **R4e：** 适配器为 `wave17/merged_enc_wise05`（UniST 编码器 LoRA，WiSE 0.5）。
- **R4w：** 适配器为 `wave14/merged_unist_wise05`（UniST 文本层 LoRA，WiSE 0.5）。

## 自检（在 R4e / R4w 之前，必须通过）
- `--route base`（永远选底座）在 D-U 上与 si_thinker_stream la2 w1 底座在 D-U 上的运行比较，看逐条 blocks 完全一致的比例。
- 门槛沿用第十五波和组合方案的口径：英→中 ≥ 0.9035，中→英 ≥ 0.9095（三次底座运行两两一致率的最小值）。
- 不通过就停，不跑 R4e / R4w。

## 评测
- **数据：**
  - UniST 同域 dev（`devU/data`，set u，干净 / 带噪各 300 句 × 2 个方向）；
  - bench_dev (b)（`wave2_S1/data` 中 set b，干净 / 带噪，另报无串音子集）。
  - 合并后的 items 在 `eval_outputs/mist_w3po_v1/r4/data/`。
- **视角：** D-U 的增强视角新生成在 `r4/views/<dir>`；(b) 复用 `wave15/views/<dir>`。
- **只跑 Thinker。** 对照（都是 LA2 w1）：
  - D-U 上新跑 si_thinker_stream：底座、enc_wise05、unist_wise05；
  - (b) 上复用：底座 wave2_S1、`wave17/eval_enc_wise05`、`wave14/eval_unist_wise05`。
- **指标（点估计）：**
  - 论文口径 text BLEU（去标点，t2s，英→中按字切分）；
  - 带噪 − 干净的差距；
  - 长度比（系统长度 / 参考长度）；
  - 重复率（译文长度 > 3 倍参考的句子比例）；
  - text D1 LAAL（按块的写出时间计算）；
  - 读次中路由到适配器的比例，干净 / 带噪分开。

## 判断规则（点估计，写定）
R4 对某个适配器"有效"，需要同时满足：
1. 相对该适配器本身（LA2）：D-U 和 (b) 的干净 text BLEU 不降（≥ −0.3），带噪 − 干净的差距不明显变差（变差不超过 0.5）；
2. 相对底座：至少一个带噪单元（D-U 或 (b)）text BLEU 提升；
3. 相对底座：text D1 增加不超过 0.1 s。

## 变更 1（21:58 CET，协调者转达用户要求，写于任何 R4 数字之前）
- **卡位：** 不用卡 1、7（改给 R1），改为叠在 R2（卡 4、5）和 R3（卡 0、6）的训练卡上：
  - 英→中：底座在卡 4，适配器在卡 0；
  - 中→英：底座在卡 5，适配器在卡 6；
  - 对照和自检是单引擎作业，每轮 4 个，分在卡 4、0、5、6 上。
- **显存：** 先等四张卡上都有训练进程（非 gpu_load、≥ 20 GiB），连续 180 s 采样它们的峰值显存。每张卡的 vLLM 显存比例 = (总量 − 训练峰值 − 10 GiB) / 总量。
  - Thinker 权重就要 59.4 GiB（test_robust 的日志：Model loading took 59.36 GiB），加上 CUDA graph 约 0.7 GiB 和至少 4 GiB 的 KV，一个引擎至少需要约 66 GiB。
  - 任何一张卡的可用量不足 66 GiB，就写 `r4/NOFIT` 并退出，先汇报，不硬上。
- **其余不变：** 评测指标、对照和判断规则都不变。不再等 UE / UW 的 DONE。
- **watcher：** 只停 scripts/gpu_load/ 下的占位进程，不碰 R2 / R3 的训练进程。

## 变更 2（21:48 CET，协调者转达用户要求，写于任何 R4 数字之前）：不叠卡，变更 1 作废
- **卡位：** R4 不再叠在训练卡上。等 R2（卡 4、5）或 R3（卡 0、6）任一组的整条链跑完、把卡交还 guard 后，才用那一组的两张卡（先完成的那组）。
  - 完成标记：R2 是 `r2/DONE` 或 `FAILED`；R3 是 `r3/CHAIN_DONE` 或 `CHAIN_FAILED`。
  - 同时要求：没有存活的 r2_* / r3_* 进程，且两张卡上除 scripts/gpu_load/ 的占位外没有任何计算进程（间隔 30 s 连查 3 次）。
  - 卡 1、2、3、7 归 R1，绝不碰。
- **显存：** --gpu-mem 用正常值 0.85。变更 1 的峰值采样和 NOFIT 规则都取消。
- **编排：** `r4_wait.sh`（脱离会话的等待脚本）→ `r4_orch.sh CA=<卡 a> CB=<卡 b>`。
  - 对照和自检：英→中在卡 a、中→英在卡 b，每轮两个单引擎作业，共 4 轮；
  - R4e / R4w：底座在卡 a、适配器在卡 b，按英→中、中→英依次跑；
  - 最后打分，写 `r4/DONE`。
- **其余不变：** 规则、对照、指标、判断规则、自检门槛都不变。
- **CPU 逻辑测试（不是结果）：** `R4_FAKE=1` 用假草稿在 6 条上跑通了路由和提交逻辑。视角一致时下一次读用底座，不一致时切换到适配器，提交仍是 LA2。真实运行不设这个变量。
