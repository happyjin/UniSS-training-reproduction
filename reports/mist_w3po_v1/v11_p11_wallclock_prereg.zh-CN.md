# v11 P1-1 登记：最终系统整场计算实时性测量（2026-11-15，任何测量之前写）

- 目的：回应模拟审稿 M5（v10 只有旧单向模型、且在资源竞争下的 Appendix G 测量）。
- 系统：B+PA（严格基线 Thinker = joint s6000 identity + PA Talker）与 M（stage 2 s3500 + δ_w=−1 + PA Talker）。
- 会议（事先按规则固定，不看任何结果）：AMI 测试 16 场按 zh→en 在线跨度排序取中位附近第 7–9 名 IS1009b、TS3003b、EN2002a（两个方向同用）；AliMeeting 20 场取第 10–11 名 R8008_M8014、R8005_M8008。
- 测量：
  - Thinker：与测试解码相同的参数，--batch 1，每个 Engine.read 调用前后 cuda 同步计时（含每次 read 的前缀重编码、所有包装器）。
  - Talker：PA Talker + CTC 打分器同卡，现有测试 talker 输入限制到上述会议；vLLM generate 拆成每块单独调用计时（两个候选），轮次的候选打分（BiCodec 解码 + CTC HTTP）单独计时，前端与最终解码用 si_infer 自身的 timing。
  - 独占：每个作业一张卡，启动前按 PID 停掉该卡的占位训练；作业进程预留显存只留 16 GiB，避免别的作业叠上来；nvidia-smi 每 5 s 采样，作业期间出现其他 >1 GiB 进程即判为"有竞争"并重跑（最多 3 次，全部保留）。
- 回放模型（evaluation/wallclock_v11.py）：单解码流排队（到期时刻按 chunk 协议的窗口打开 / 结束检测钳位）；单 Talker 工作者 FIFO，同一 item 的块按顺序；播放按"每说话人一通道"和"单通道"两种布局；与不计算的时间线逐块相减。
- 报告：Thinker / Talker 实时率（计算时间 / 会议跨度）、读队列长度与排队等待、超过 1 s 节拍的读比例、计算感知减去不计算的块结束延迟和开口延迟 p50/p90、随会议时间的斜率（s/分钟，>0 表示越跑越落后）、播放积压。
- 判定（事先写定）：Thinker 与 Talker 实时率都 < 1 且延迟差斜率 ≈ 0（|斜率| < 0.05 s/分钟）→ "单卡串行即可跟上会议"；任一实时率 ≥ 1 → "按当前实现跟不上"，如实写。
- 不做：任何调参；不在测试集上做选择（输出的文本只用来计时）。
