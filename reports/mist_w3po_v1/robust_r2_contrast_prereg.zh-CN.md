# R2：不看译文的编码器不变性适配（对比式）预登记

2026-11-20 21:50 CET（布拉格）写，早于本方法的任何数字。方案来源：`robust_analysis_and_ideas_v3_20261120.zh-CN.md` 第 3 节 R2；用户已同意开跑 R1–R4。

## 动机（一句话）
第十七波的编码器 LoRA 用翻译交叉熵训练，学到了 UniST 的译文风格：训练集里从未被抽到的句子也 +12.49，RealSI 上长度比 1.09，还出现了退化重复。R2 让适配完全接触不到目标分布，只学"对声学干扰的不变性"。

## 方法（一个设置，不扫参）
- **LoRA 的位置和优化：** 与第十七波逐项相同。
  - LoRA 加在 Qwen3-Omni Thinker 音频编码器 32 层自注意力的 q_proj / k_proj / v_proj / out_proj 上，rank 16，alpha 32，b 初始化为 0，fp32；
  - AdamW，lr 1e-4，betas (0.9, 0.999)，wd 0，cosine 到 0，不裁剪梯度；
  - 2300 步，全局批量 64，seed 20261119；
  - world 2（卡 4、5），每个 rank 32 条，微批量按冒烟取最大（只影响梯度累积）。
- **数据：** 第十四波的 UniST 数据（`eval_outputs/mist_w3po_v1/wave14/data`），8 个环境，Sampler 规则同第十四、十七波：
  - 第 s 步第 j 个槽位取 row = sha1("20261119|w5m|row|s|j")；
  - 带噪环境的槽位，噪声与第十七波完全相同（同一个 mix 键、同一个训练噪声池，即 Idea 2 背景索引的 train 划分）；
  - 干净环境的槽位，另用 sha1("20261119|r2|type|s|j") mod 3 选一种噪声类型（music / crowd / sfx），用 sha1("20261119|r2|mix|s|j") 采样噪声；
  - 每个槽位都产生一对：干净版就是原音频，带噪版是混噪后的音频。
- **目标（InfoNCE，对称）：**
  - 干净版和带噪版各过一次同一个带 LoRA 的编码器；
  - 取编码器输出（送进大模型的那层，即 proj2 之后），按帧做均值池化，再 L2 归一化；
  - 全局 64 对（跨 rank all_gather，带梯度），相似度矩阵 = z_cleanᵀ z_noisy / 0.1；
  - 损失 = 行、列两个方向交叉熵的平均，正例在对角线上，批内其他句子作负例（两个方向的句子混在一起）。
- **大模型完全不参与前向，不使用任何参考译文。**
- **不是蒸馏：** 没有教师模型，也没有伪标签；两路是对称的对比学习，由同一个编码器（同一套 LoRA）同时编码。
- **防塌缩检查（只记录，不调参）：** 每 10 步记录正例对平均余弦、负例对平均余弦、z 每维跨批次标准差的均值。
- **最终系统：** r2_wise05，即 WiSE α = 0.5（LoRA alpha 减半为 16），按第十七波的方式合并进完整模型（`wave17_merge.py`，不改）。

## 评测（只跑 Thinker，点估计，不做 bootstrap）
- **数据：**
  - UniST 同域 dev（`eval_outputs/mist_w3po_v1/devU/data`，每个方向干净 300 句 + 带噪 300 句）；
  - bench_dev (b)（`wave2_S1/data` 中 set = b 的条目，干净和带噪）。
- **系统：** 都用 `combo_si_thinker.py --second-view none`（等于 la2 w1），同一份 items，在同一次链里各跑一遍：
  - base（原始 Qwen3-Omni）；
  - enc_wise05（第十七波，`wave17/merged_enc_wise05`）；
  - r2_wise05。
- **指标**（论文口径：去标点、t2s、中文按字切分；英文 13a），按方向 × {u, b} × {干净, 带噪} 分别算：
  - text BLEU；
  - 带噪 − 干净的差距；
  - 长度比（规范化后的系统长度 / 参考长度）；
  - 重复率：规范化后的译文长度超过参考 3 倍的句子比例；
  - text LAAL：按块的写出时间，以字或词为单位计算。
- **判断规则（点估计，写定）：**
  1. 相对 enc_wise05：两个方向的 u 和 b 上，差距都不变差（容差 0.3）；干净 BLEU 不降（≥ −0.3）；长度比更接近 1；重复率不升。
  2. 相对 base：至少一个方向的 u 或 b 带噪 BLEU 提升（> +0.3）。
  - 两条都满足，记为"有效"，之后再补 bootstrap 和 Talker 链。

## 实现说明 / 变更 1（2026-11-20 21:50 CET，写在任何数字之前）
- **协调者变更：** R4 的 vLLM 推理会叠在卡 4、5 上，所以训练的峰值显存要控制在每卡约 70 GB 以内，全局批量仍为 64。
- **实现方式：梯度缓存**（Gao et al. 2021, GradCache）。
  1. 先在无计算图的情况下算出全部 64 对的嵌入；
  2. 在缓存的嵌入上计算全局 InfoNCE，得到对嵌入的梯度；
  3. 按微批量重新编码，并回传缓存的梯度。
  - 这样损失与"整批一次计算"在数学上相同，而显存只取决于微批量的大小。
- **微批量的选取：** 冒烟时依次试 32、16、8，取 rank 0 的峰值显存（max_memory_allocated）≤ 60 GiB 的最大值，为分配器的保留量留出余量。微批量只影响显存，不影响损失。
- **评测时的等待：** 每个 Thinker（vLLM 0.85）启动前，先等这张卡上非占位进程占用的显存降到能放下它为止（剩余 ≥ 122000 MiB，最多等 6 h），以免与 R4 冲突。
- **watcher：** 只停 scripts/gpu_load/ 的占位进程，不碰 R4 的 vLLM 进程。
- **代码：** `r2_contrast_train.py`（只加载音频编码器）、`r2_chain.sh`、`r2_noplaceholder.sh`、`r2_score.py`。合并用 `wave17_merge.py`，未修改。

### 原因分析
1. **对比任务太容易，学到的是"均匀性"而不是"不变性"。** 第 0 步：正例余弦已有 0.89，批内 top-1 已 0.94；到第 100 步 top-1 = 1.0。整个训练里正例余弦只从 0.89 升到 0.985，负例余弦却从 0.45 降到 0.008。InfoNCE 的大部分下降来自把不同句子的池化嵌入推开（去掉公共方向），这是对编码器输出几何的改动，本身就是一种表示分布的偏移，与噪声无关。
2. **句级均值池化抹掉了噪声真正伤害的位置。** 噪声伤的是局部帧（掩蔽、插入），整句均值对它们不敏感；正例在池化后几乎已经对齐，帧级的不变性没有学习信号。
3. **规则本身的一个教训：** D-U 与训练数据同域，enc_wise05 在 D-U 干净上的大幅提升（中→英 +8.1）正是 v3 发现 C 所说的"风格偏移"。以"不低于 enc_wise05 的 D-U 干净 BLEU"为门槛，会惩罚不学风格的方法。判定照写定规则执行（无效），但之后的新方案的规则改为以底座为参照衡量"干净不退化"，再报告相对 ERM 的对比。
4. 积极的一面：在不同域的 (b) 上，r2 把中→英带噪提高 +1.43、差距从 −2.69 缩到 −0.20，说明"不看译文"的适配确实能学到一部分不变性；但 (b) 干净中→英 −1.06，英→中 u 差距反而变差，不满足三轴。
