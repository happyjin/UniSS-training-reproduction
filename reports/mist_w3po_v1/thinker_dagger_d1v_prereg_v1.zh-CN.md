## 0. 为什么做

- **VE1 仍然像 A′ 一样等**（dev5 速查，`thinker_crf_t_results_v1` 的 VE1 一节）：
  - ≥ 6 s 窗口里"一直不起步"（A 类）占 12.9%（A′ 14%，T5 0%）；
  - B 类（写一段后停住）平均连续空读 2.15 次（A′ 1.99，T5 0.29）；
  - 最终读写出的词占比 41.3%（A′ 49.7%）。
- **而 VE1 的质量最接近 A′**：dev 全集文本 28.07 / 23.70，VE1rl + PL-EM 语音 23.64、每条流语音 LAAL 3.756 s。写得更早的 T4 / T5 / RC5 文本掉约 1 分（RC5 说明碎片不是主因，更像是"证据没听够就写"）。
- **D1 只纠正时机**：roll-in 时学习者只决定何时写，内容固定为参考条目；在学习者**自己走到的**逾期状态上，用专家动作"立刻写出全部已到期的条目"打标签。与 DART 的随机扰动不同，D1 的状态来自学习者自身（DAgger, Ross et al., AISTATS 2011）。
- **要回答的问题**：在 VE1 的配方上，加上学习者自身逾期状态的专家行，能否在文本和语音 BLEU 不降的前提下，把语音 LAAL 降到 VE1 以下。
- **为什么不怕 T5 式的掉分**：D1 行的专家目标只包含**已到期**（e_i ≤ r）的条目，e 是 VE1 的证据时刻标签（merge3 粒度，每块约 6 词）。D1 不把写出往标签之前推，只把"晚于标签一读以上还没写"的状态拉回标签。VE1 的格本身已允许 [e, e+1]，所以逾期（e_i ≤ r − 1 还没写）的条目在 VE1 的格里正好是"到了上界必须写"的状态。

### 1.2 roll-in（GPU，只做前向，评测类，可以叠在非训练卡上）

与 D1 §1.2 相同，只改学习者和数据：
- 对计划里用到的每个训练窗口（VE1 的计划用到全部 22,671 个窗口），按读的顺序模拟学习者。状态 H_r 是每个说话人 κ 顺序的前缀，初值为空。
- 第 r 读（非最终读）：一次教师强制前向，输入与训练行相同（音频到 t_r；说话人后验到 t_r − 1.04 s；历史 κ(H_{r−1})；输出部分强制为"剩余全部条目按 κ 顺序"）。在输出部分的每个条目边界 j = 0, 1, …，取全词表 argmax：第一个 argmax 为 `<wait>` 的边界就是本读停下的地方，否则写完。最终读写完全部条目。
- 输出：每个条目的写出读 ρ̃_i。
- **打分器换成修好的 v2**（见 §2 的 R0）：右侧补齐（与训练的 `collate` 相同）、显式的 position_ids（每行从 0 起）、同一读的音频嵌入在一次性前向与逐边界前向之间共享，两条路径都固定用同一个 SDPA 后端（EFFICIENT_ATTENTION）。原打分器 v1（左侧补齐、不给 position_ids）保留不动，是默认值。

### 1.3 D1 行（与 D1 §1.3 完全相同）

- 在学习者轨迹的每一读 r 上，若逾期集合 O_r = {i ∉ H_{r−1} : e_i ≤ r − 1} 非空，加一行：历史 κ(H_{r−1})，目标 W*_r = {i ∉ H_{r−1} : e_i ≤ r}（κ 顺序）接 e_r（非最终读 `<wait>`，最终读 `<eos>`）。
- 超前状态不加行，只报告。
- 权重与 DART 行相同（目标 token h_t / D，结束 token 1 / D）；D1 行只进第 2 遍，不影响后验。
- 每步上限：D1 行超过该步正常读行的 25% 时，用 `numpy.random.default_rng([20261112, 步])` 均匀抽到 25%。

### 1.4 训练（DAgger 的数据聚合，与 D1 §1.4 相同的形式）

- π₂ 从头训练（v8 merged 初始化），数据 D₁ ∪ D₂：
  - D₁ = VE1 的训练目标与数据原样（v2p 隐写时 CRF 的正常行 + VE1 的 DART 行）；
  - D₂ = §1.3 的 D1 行（清单 `crf/d1_ve1_w10_v1`）。
- **与 VE1 只差一处**：多了 D₂。
- 命令：`run_crf_v2p.sh` + `EXTRA="--sched crf/sched_t5_merge3_w10_v1 --objective latent_write --lw-mode v2p --dart crf/ve1_dart_merge3_w10_v1 --d1 crf/d1_ve1_w10_v1"`；其余参数是 VE1 的（τ 0.5、`--final-read-full-post 1`、3000 步、学习率 1e-4 → 1e-5 余弦、warm-up 50、AdamW (0.9, 0.95)、梯度裁剪 1.0、扰动 p 0.2、LoRA r32 / α64 + 投影器 + 259 个新 token 行、`--feat-per-row 1 --fast-moe-bwd 1 --prefetch 1 --empty-cache 0 --tok-budget 32000 --mem-cap-gib 120`），训练种子 20261109。
- 4 卡（卡由协调者排，默认 0–3 号卡），只评 step_03000。

## 2. 预检

### 2.1 CPU（训练和 roll-in 之前；任何一项不过就不跑 GPU，修好后重做）

- **R0 自检失败的原因与修复**（新，本登记专有）：
  - (a) **原因核实**：在 CPU 上用真实的 HF `Qwen3OmniMoeThinkerTextModel`（同一份 transformers 代码，缩小的随机配置，bf16）、真实的 Prompter 和真实的 VE1 训练窗口，加一个让 `<wait>` 与内容 token 接近打平的判决头（专门放大数值差），比较三种打分：原 v1（左侧补齐、不给 position_ids）、"左侧补齐 + 正确的 position_ids"、v2（右侧补齐 + position_ids + 共享音频嵌入）。每种都与逐边界前缀前向的字面贪心循环比 ρ̃ 是否相同，并报告判决位置上 logit 的最大差。
  - (b) **GO**：v2 与字面循环在全部测试窗口上 ρ̃ **100% 相同**（≥ 60 个窗口）；并且 (a) 的结果能说明 v1 的不一致来自左侧补齐时的位置偏移（v1 有不一致、加上正确 position_ids 后不一致消失或显著减少）。若 (a) 说明原因另有所在，照实写，按新原因修。
  - 照实说明：CPU 的核函数与 GPU 不同，CPU 上 100% 相同不保证 GPU 上也 100% 相同。所以 §2.2 的 GPU 自检仍是硬门槛。
- **R1–R3**：D1 的 `test_d1` 4/4 原样重跑（roll-in 驱动、D1 行、训练器 `--d1`），加 VE1 数据与 v2p 格上的同类检查：
  - R1：在 VE1 的真实训练窗口上，批量驱动与字面循环一致；
  - R2：VE1 数据上 D1 行的定义检查（与 `aug_requests` 在扰动轨迹上逐字段相同；学习者轨迹上的行只出现在有逾期条目的读）；
  - R3：`--d1` 配 `--lw-mode v2p --dart`：不给 `--d1` 时与 VE1 的训练步逐位相同，给了时基线行不变、loss = 基线 + D1 行的 loss；prefetch 1 与 0 相同。
  - 回归：`test_dart_aug`、`test_latent_write_crf`、`test_train_crf_sft`、`test_pmc`、`test_pmc_noc` 全过。
- **默认路径逐位不变**：新代码只做加法；`d1_rollin` 不给 `--scorer` 时用原打分器 v1，原有命令行行为不变。

### 2.2 GPU 自检（每个 roll-in 分片开头，硬门槛）

- 每个分片在 roll-in 之前，取本分片前 20 个"至少 3 读、至少 2 个条目"的窗口，用逐边界前缀前向（字面贪心循环）复核一次性前向的决策。**必须 20/20 相同**，否则该分片退出，不生成清单，报告协调者。
- 自检同时记录每个不一致处的判决余量（两条路径上 argmax 与 `<wait>` / 下一个内容 token 的 logit 差），供协调者判断。容差（`--selfcheck-tol` > 0）只有协调者明确决定才能用，用了就记为有记录的偏离。

### 2.3 roll-in 之后（训练之前）

- **R4 有没有对象**：计划窗口里，学习者至少有一次逾期（O_r 非空）的窗口占比 **≥ 5%**。不到 5%：**不训练**，报告协调者。
- 附带报告（与 D1 §4.2 相同）：逾期读占比与分布、超前条目占比、ρ̃ − e 的中位数和 p90、每步 D1 行数（抽取前后）、训练窗口上的停顿分类（用 ρ̃）。
