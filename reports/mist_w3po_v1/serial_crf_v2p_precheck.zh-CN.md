**怎么读这个 GO**
1. **失败机制在 teacher forcing 下复现了（S2′b 远高于门槛）。**
   - 在 newfirst 上下文里写完其他说话人的新条目、m 仍待写时，非最终读 p(`<wait>`) 的均值是 0.32（中位数 0.19）。
   - 40% 的上下文里，p(`<wait>`) 大于打开 m 的说话人 token 的概率。
   - 这与 v2 预检中"下一读开头打开 m"的情形（p(e) 0.006）完全不同：同一个被推迟的 m，排在第一时几乎总被打开，排在新条目之后就常被放弃。这直接支持 `serial_crf_precheck.zh-CN.md` §12.5–§12.6 推断的链。
   - 模型确实能区分"还有待写"与"写完了"：标签路径读末 p(e) 0.85，配对差中位数 −0.64。但区分得不够。

2. **但顺序隐变量的后验质量很薄，GO 很勉强。**
   - S2′a = 0.066，只比停止线高 0.016；中位数 0.008，信号集中在少数读上。

   - 原因：只有约 19% 的后验质量走到有真选择的边（先要发生推迟），这些边上 newfirst 又只占约 35%（τ = 0.5）。
   - 整个 dev 样本（300 个窗口）上，newfirst 的期望路径数合计约 7.8（τ = 0.5）、5.3（τ = 1）。
3. **在线覆盖率够**：最终读因果 P 解码中，25.9% 的重叠短漏译走完整条链（推迟 → 下一读写了别人 → u 再没出现），占 DEFERRAL 的 56%。另有 41 个 DEFERRAL（34%）是"下一读什么段都没提交"，v2′ 的顺序隐变量不针对这一类。
4. **事后诊断（不是预登记，只作参考）**：
   - 后验并没有系统地避开 p(`<wait>`) 高的上下文：dev 上按 q(newfirst) 加权的 p(e) 为 0.18（不加权 0.27），train 为 0.34（不加权 0.25）；Spearman 相关 −0.14（dev）/ +0.08（train）。
   - 所以在边际似然训练中，"写完 N 后补写 m"这一步的梯度会落到真正出问题的上下文上，但总权重很小。

## 1. 预登记（在任何 S1′ / S2′ 结果之前提交）

代码：`experiments/mist_w3po_v1/crf/precheck_serial_v2p.py`（新文件；`import` v2 的 `precheck_serial_v2.py`，v2 文件一字未改），测试 `crf/test_precheck_serial_v2p.py`（10 个 CPU 测试，`__main__` 运行器）。判定常数写死在脚本里：`TAU = 0.5`，`S1P_STOP = 0.15`，`S2A_STOP = 0.05`，`S2B_STOP = 0.02`。

### 1.1 缺口

v2 的读内顺序固定为规范顺序：先写上一读推迟下来的条目，再写本读按时的 D_r。所以被推迟的 m 在下一读**总排第一**，而这正是 v8 已经会补写的情形。在线失败链（`serial_crf_precheck.zh-CN.md` §12.5–§12.6 推断）是另一种顺序：下一读先写新到期的条目，然后在 m 之前发 `<wait>`，m 就丢了。"新条目已写、m 仍待写"这种上下文在 v2 的格里不存在，所以在 v2 上训练学不到"写完新条目后还要补写 m"。

### 1.2 v2′ 的格（只改一处）

条目、松弛 1 读、集合状态、κ 历史、kap 写出顺序、最终读 P 协议、τ = 0.5、样本窗口，全部与 v2 相同（v2 报告 §1.1–§1.3）。唯一的改动：

- **读内顺序隐变量** o_r ∈ {canon, newfirst}，每读一个。
  - **canon**：v2 的顺序，即 kap 序的"待补写 ⊕ D_r"。
  - **newfirst**：先写 N_r，再按 kap 序写其余条目（待补写的，然后 D_r \ N_r）。N_r 是 D_r 中说话人（slot）与任何待补写条目都不同的那些条目，按 kap 序。这样每个说话人内的标签顺序不变。
  - 只有待补写集合和 N_r **都非空**时，o_r 才是真选择。否则 newfirst = canon，这一读只算一次，不重复计数。
- **边势函数**：ψ_r(D_{r−1}→D_r) = logsumexp_o log p_θ(按 o 排列的 W_r ⊕ e_r | x≤t_r, κ(A_{r−1}))，o 取遍不同的顺序。
- **退火（澄清，结果之前写定）**：q_τ(ρ, o) ∝ exp(τ Σ_r ψ_{r,o_r})，即在**联合**隐变量 (ρ, o) 上退火。这就是暴力枚举 (ρ 赋值 × 顺序) 所定义的后验。前向的边项因此是 logsumexp_o(τ ψ_{r,o})。τ = 1 时它就等于上面的 ψ_r（训练用的边际似然不受这个选择影响）。另一种"先 logsumexp 再退火"（q ∝ exp(τ Σ_r ψ_r)，顺序条件分布不退火）只报告。
- **为什么仍是精确 CRF**：
  - κ 只依赖集合，o_r 只进入第 r 读自己的项，前向递推与 v2 相同，只是每条边多一个 logsumexp。
  - 这个隐变量是合法的：打分器给一读内所有条目打同一个写出时刻，评测对读内顺序不变。
- **标签路径**：所有 D_r = B_r，且 o_r = canon。标签路径上没有待补写条目，所以没有顺序选择，仍与 S（v8 / C0 的训练目标）在每一读逐 token 相等。

### 1.3 前向的组织

- canon 的单元格完全沿用 v2 的计划（`plan_window(old_final=False)`）。每个（读，上下文）一次完整续写前向，加上非前缀写集的补充前向。测试核对：v2′ 计划的前一段请求与 v2 计划逐项相同。
- newfirst：每个上下文、每个有真选择的写集 D 一条序列 N ⊕ 其余。如果一条序列是同一上下文里另一条更长序列的条目前缀，就共用那条前向，在边界处读 log p(e_r)。
- 在 newfirst 前向中，"写完 N 之后"这个位置上读三样：log p(e_r)、m（第一个待补写条目）的说话人 token 的 log p、起始时间 token 的 log p。
- 只打新协议（最终读 P 完整可见，dev 用 `final_cut_ms` 规则，同 v2 §1.3）。v2 打过的旧协议最终读这次不打。
- 引擎路径、批处理、`<wait>` 屏蔽都是 v2 的 `score_reqs_v2`（未改）。

### 1.4 判定规则

**S3′ 精确性（CPU）。不通过 → 先修代码，不上 GPU。**
- (a) v2 的标签路径检验（历史 ids = S 前缀，写集 ids = S 片段，状态 0 = 标签 B_r，v1 的 κ 测试），覆盖 sched_v1 与 sched_dev_v1 **全部**窗口的每一次读。另外检查标签路径上没有任何顺序选择。每个打分进程在加载模型前对自己的窗口再查一遍。
- (b) 格的结果与**独立于格**构造的暴力枚举对拍，容差 1e-9。比较的量：log Z（τ = 0.5 和 1；全部读打分，以及跳过无选择读后加回常数），每条 (ρ, o) 路径的分数和质量，每读状态边际，每个条目的推迟边际，每读的顺序边际 q(o_r = newfirst) 和 q(o_r 是真选择)，路径数。
  - 暴力枚举：枚举所有 ρ 赋值（同 v2），对每个赋值的每一读，直接由写集构造顺序。canon 按 kap 键排序；newfirst 用稳定排序，把"ρ_lab = r、且 slot 不属于任何 ρ_lab = r − 1 条目"的条目排在前面。
  - 用于随机合成实例，以及样本中可推迟条目 ≤ 10 的真实窗口（假 log 概率，是整个前缀的确定性函数）。(ρ × o) 路径超过 40 万条的窗口跳过并计数。
  - 合成实例和真实窗口中，都必须有含真选择的实例。
- (c) newfirst 写出序列的联合分词 = 块 ids 的拼接（全部样本窗口）。
- **反例（必须全部抓到）**，在含真选择的真实窗口上：
  1. 去掉顺序隐变量（即 v2 的格），log Z ≠ 暴力枚举；
  2. 错的 newfirst（第一个待补写条目放在 N 之前），对拍不通过；
  3. newfirst 单元格的边界错一个 token，log Z ≠ 暴力枚举。
  - 另报告（不计入判定）：忽略 slot 条件、把整个 D 都放前面的 newfirst。它在 N = D 时与正确定义相同，所以不一定被抓到。

**S1′ 覆盖率（CPU，在线轨迹）。**
- 人群：v2 S1 的人群，即 dev 所有 ≤1 s、ov50、没被召回的单元。
  - 主要：最终读因果 P 解码 `dev_v8_ctx0_guard_finalpost_s8`。v2 在这上面得到 263 个，其中 DEFERRAL 121 个。
  - 只报告：`dev_v8_ctx0_guard_s8`。
- 代码路径：v2 的 S1（`diag_order_attr.run_scorer`，断言复现 `score_text.json` 的短单元召回）。另外断言：本次算出的 v2 字段与 v2 已存的 `s1_rows_*.jsonl` 逐行相同。
- **CHAIN(u) 当且仅当**同时满足：
  - (a) v2 的 DEFERRAL 在 t_due 成立；
  - (b) w 的下一读 t_due + 1 提交了至少一个文本非空、且不是 u 的段（write_ms = 下一读时刻，与 v2 的"在 t_due 提交"同一口径）；
  - (c) u 没有在 t_due + 1 写出，也没有在 w 之后的任何一读写出。"写出"用 v2 S1 的文本匹配规则，不论说话人标签。
- **S1′ = CHAIN 数 / 人群数。S1′ < 0.15 → 停止。**
- 其余 DEFERRAL 分类报告：
  - U_WRITTEN_NEXT_{SAME,OTHER}_LABEL：u 在 t_due + 1 写出，按段所映射的说话人是否等于 u 的说话人分；
  - U_WRITTEN_LATER_{SAME,OTHER}_LABEL：u 在更晚的读写出；
  - NOTHING_ELSE_WRITTEN_AT_NEXT：u 之后没写，t_due + 1 也没写别的。
- 对 CHAIN 另报告：t_due + 1 是否最终读（那时 e = `<eos>`）、t_due + 1 写了几段、u 是否在别的窗口被写出。
- **读内写出顺序在轨迹里可得**（数据性质，结果之前已核对）：
  - `dev_v8_ctx0_guard_finalpost_s8` 的 3,050 个窗口，各读 `read_log.new` 拼起来都等于 `raw`；
  - `segments` 按 Parser 的写出顺序排列，write_ms 不降。
  - 脚本对两个解码都重查这两点并写进输出。
  - 由于 CHAIN 要求 u 之后一直没写，"新条目先写"在 CHAIN 中自然成立，不需要再判顺序。

**S2′ 信号量（GPU，dev 为准，train 参考）。**
- **S2′a**：
  - 人群：dev 上 o_r 是真选择的读，即格中至少一条边有两种顺序的读。
  - 量：每读的 q_{τ=0.5}(o_r = newfirst)，在整个格上边际化（包括该读没有选择的那些路径，它们贡献 0）。对读取平均。
  - **S2′a < 0.05 → 停止**（顺序隐变量对 v2 没有增加任何东西）。
  - 只报告：条件量 q(o_r = newfirst | o_r 是真选择)，以及 q(o_r 是真选择) 本身。
- **S2′b**：
  - 人群：dev 上每个 newfirst 上下文，按（窗口，读，上一状态，N_r）去重。同一前缀的 p(e) 相同，只算一次。

  - **S2′b < 0.02 → 停止**：在 teacher forcing 下复现不了丢弃，格训练够不着，这是暴露偏差 / on-policy 问题。
  - 同时报告：中位数；同一窗口同一读在标签路径上读末（没有待补写条目）的 p(e_r)，以及配对差。
- **GO 当且仅当** S3′ 通过、S1′ ≥ 0.15、S2′a ≥ 0.05、S2′b ≥ 0.02。每项一个设置，不扫参数。
