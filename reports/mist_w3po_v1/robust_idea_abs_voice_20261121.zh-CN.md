# 候选主方法：分析–合成式音色 token 搜索（AbS-Voice）（2026-11-21 09:20 布拉格，只是方案）

## 针对的瓶颈（来自 v6 分解与 oracle 诊断）
- 噪声造成的身份损失，几乎全部经由 32 个全局音色 token 进入；用干净 token（oracle）可以收回 92–119%。
- 现有估计器 V1、K3、K4 都是"先在连续空间估计，再取整"：连续码已接近干净码（余弦约 0.93），但取整后只有约 20% 的位置正确。即使输入是干净提示，也只有 45–55%。
- **根本原因：** 身份是 token 经过解码器之后才体现出来的属性。在码空间里做 MSE 或 CE，等于用 Hamming 或 ℓ2 损失去优化一个其实由解码器决定的目标；取整边界附近，一位的翻转就会改变身份。

## 思路
不在码空间里猜 token，而是在身份空间里检验 token，借用语音编码里分析–合成（analysis-by-synthesis）的思想：
1. **候选：** 从 V1 的连续码出发，对最靠近量化边界的 k 个维度枚举另一侧的等级（比如 k = 4，得到 16 个候选）。k 事先写定为一个值，不扫。
2. **合成：** 每个候选只经过 BiCodec 解码器端的说话人条件（d-vector 路径）得到条件向量。如果需要，再合成一段固定的短参考句（离线缓存的文本，与本句无关）。
3. **分析：** 用一个与评测指标不同的说话人编码器（比如 ECAPA 或 WavLM-SV；评测用 TitaNet，以免钻指标的空子），计算候选合成音和本句源音频的说话人相似度。源音频可以用原始带噪版，也可以用增强版，看预检结果。
4. **决策：** 取相似度最高的候选。等价于在离散 token 上做最小贝叶斯风险（MBR）决策，效用函数是"身份一致性"，而不是码距离。

## novelty
- 分析–合成是经典的语音编码思想（CELP），MBR 是机器翻译里的解码方法。把两者结合起来，在 codec 语言模型的离散音色条件上做"身份效用"的决策，用来解决带噪提示的音色克隆，没有看到先例。
- 配合 oracle 诊断，可以写成一个有理论陈述的论点："在离散音色条件下，先估计连续码再取整不是贝叶斯最优；在身份效用下的 MBR 决策才是。"
- 免训练，可以叠加在任何连续估计器（V1、K3）之上。

## 会不会 work：风险与预检（先做，不花 Talker 卡时）
- **风险 1：** 说话人编码器在带噪源音频上不可靠，搜索可能对准"带噪的身份"。
- **风险 2：** 候选集合里根本不包含接近 oracle 的 token：只翻转 4 个维度，而 V1 有约 25 个位置是错的。
- **风险 3：** 首次写出时增加的计算延迟。
- **预检 P0（GPU 轻量，几分钟）：** 在 S1 dev 的带噪条目上，对每条比较三种 token 与 oracle token 的 d-vector 余弦：V1 token、AbS 选出的 token、候选集合中的最佳 token（这是集合的上限）。
- **停止规则（事先写定）：**
  - 集合上限比 V1 高不到 0.02，就说明候选集合不够，停止；
  - AbS 选出的 token 收回的集合增益不到一半，就说明效用函数不可靠，停止。
- 预检通过后，再跑 Talker 评测：S1 dev，比较 B、V1、oracle、AbS，看身份收回比例、ASR-BLEU、PESQ（相对干净提示），以及首次写出的额外耗时。
