## 1. 模型与目标（唯一设置）

### 1.1 符号

一个训练窗口 x，读 r = 0..R−1，读入时刻 t_r（1.0 s 一读，再加窗口终点）。

**条目**：≤ 4 词的块（piece）i，说话人 k_i，词数 W_i，源端终点 τ_i。每个条目有：
- 标签读 e_i，以及基线格的上界 h_i，由第 3 节选定的基线决定：
  - T4：格模式 t2，h_i = min(R−1, max(u_i+1, e_i+1))；
  - T5：格模式 t5，h_i = min(R−1, max(u_i, e_i))。

### 1.2 隐变量：写出计划 = 块的分段

- **写出计划** ρ：每个条目在哪一读写出，ρ_i ∈ [e_i, h_i]，并且在每个说话人内按 κ 顺序前缀闭合（即 T2 / T5 的集合状态链 A_r）。
- **块**：对每个说话人 k，ρ 把他的条目序列切成若干连续段 B_{k,r} = {i : k_i = k, ρ_i = r}（非空时）。每段对应 talker 的一块，段的标号是写出读 r，段与段之间的读严格递增。
  - 所以 ρ 等价于每个说话人的一个**半马尔可夫分段**（Sarawagi & Cohen, NeurIPS 2004）。
  - 各说话人的分段在读上同步，因为 Thinker 在一次读里一次生成所有说话人的新条目。
- **读内顺序** o_r ∈ {canon, newfirst}（v2′ / T2 原样）。
- **talker 语速类**：每个非空块一个 v_{k,r} ∈ {0, +2}（PL-EM 候选格的两个语速档，即 T3 的设定）。

### 1.3 势函数

**Thinker 读势**（T2 原样）：

ψ^T_{r,o}(A_{r−1}→A_r) = log p_θ(W_r^o ⊕ e_r | x_{≤t_r}, κ(A_{r−1}))，按 τ = 0.5 退火。

**块势**（语音时间线；PL-EM 播放格的段势，T3 的定义原样）：

$$\phi_{k,r}(B, v, b'_k) = \log\pi(v\mid \mathrm{bin}(b'_k)) - \lambda\, l_{k,r},\qquad
l_{k,r} = \sum_{i\in B} W_i\,(t_r-\tau_i) + W_B\, b'_k + \tfrac{W_B+1}{2}\, D(B,v)$$

单位是秒 × 词：每个词"说完的时刻 − 源端终点"，块内的词在播放期间均匀展开，与 `speech_latency_lit` 相同。

- **时长** D(B, v) = a_v · chars(B) + c_v，用 T3 已拟合的 `eval_outputs/mist_w3po_v1/crf/t3_talker_model_v1.json`，不重拟：
  - a_0 = 56.1 ms/字符，c_0 = 336 ms；a_2 = 54.2，c_2 = 345。
  - **截距 c_v 就是每块开销**：一个块拆成两块，要多付约 0.34 s 的播放时间，这段时间也会推迟同一条流后面所有块。碎片的代价就是这样进入目标的。
- **积压**（每个说话人一条流，确定性转移，T3 原样）：
  - b′_k = max(0, b_k − (t_r − t_{r−1}))；
  - 写入块时 E_k ← ⌊t_r + b′_k + D⌉_{80 ms}，b_k = min(8 s, E_k − t_r)；
  - 空读不取整。

**联合后验**：

$$q_\lambda(\rho, o, v) \propto \exp\Big(\sum_r \big[\tau\psi^T_{r,o_r} + \sum_k \phi_{k,r}\big]\Big)$$

**跨流排队**：只在单通道指标里存在。主指标是每条流，所以登记的块势只含同一条流的积压，不含跨流排队；单通道 LAAL 只报告。依据是第 0 节第 2 条，这是与协调者原始描述的一处有意偏离。

### 1.4 精确推断

增广链的状态是（Thinker 集合状态 A_r，积压向量 b⃗_r）。给定（A_{r−1}→A_r，v⃗_r），转移是确定的。前向-后向就是 q_λ 的精确和积（T3 的 `joint_speech_crf.augment` / `forward_backward`，原样）。
- 每读的状态数上限 4096；超过时，该窗口的网格加粗为 160 / 320 … ms。这样仍是精确推断，并计数报告。
- Thinker 的边-顺序边际 = 增广边际对（b⃗, v⃗）求和，再乘以读内顺序的条件概率，得到 cend，交给 `serial_v2p_train.set_coefs`。

### 1.5 λ：后验正则的对偶（Ganchev et al., JMLR 2010）

按步求：Σ_w E_{q_λ}[l] = Σ_w E_{q_T1}[l]，其中 q_T1 是同一联合模型在 T1 子格上 λ = 0 的后验。T1 子格指满足 c_k ≥ #{e_i ≤ r−1} 的状态，按基线的格模式定义。
- 约束不绑定时 λ = 0。
- 从 1 开始倍增括区间（上限 1e3，到上限时标记），再二分 50 次。
- 这与 T2 / T3 / T4 / T5 是同一原则。所以 J1 与所选基线的训练目标**只差一处**：延迟算在语音时间线上（含块开销、积压和 talker 语速隐变量），而不是文本时间线。

### 1.6 M 步

- **后验加权交叉熵**：v2′ 的 `set_coefs`，q 不回传梯度。
- **DART 增广行**（Laskey et al., CoRL 2017；思路来自 DAgger, Ross et al., AISTATS 2011）：用所选基线的清单原样加入（T4 / T5 的设置：0.5 的窗口，每块 p = 0.3，推迟 k ∈ {1,2,3} 读，额外交叉熵行，权重同正常行，不进 pass 1 的打分）。

### 1.7 推理

- **Thinker**：照常逐 token 流式生成，1.0 s 一读，`decode_crf_ckpt_finalpost --final-read-post close_detect`，其余同 A′。
- **talker 的输入：读级块**（新，属于登记的系统）。每条流里，同一读写出的连续段在送进 talker 之前用空格拼成一段（`crf/merge_read_segments.py`，新）。这样推理时的块就是训练目标里的 B_{k,r}。T3 的近似 A6 在训练路径上有 41% 的块是多条目块，推理时会被拆成多块播放；读级块把这个不一致去掉了。
  - 文本的 tcpBLEU 和文本延迟在原始解码上算；
  - talker → ASR → 语音 tcpBLEU → `speech_latency_lit` 的整条语音链，在合并后的解码上算（`thinker_t_eval_orch --speech-from <name>_rl`）。
- **talker 不训练**：用 A′ 的 c1+b1+s2，与 T 系列相同。

### 1.8 与已有工作的关系（文献检查：本执行者委托的检索，未发现直接先例；不是穷尽检索）

- **最接近的**：
  - 潜在分段加期望延迟约束：Seg2Seg（Zhang & Feng, NeurIPS 2023）、HMT（Zhang & Feng, ICLR 2023）。延迟按源 token 计，分段在源侧。
  - 自适应分段 / 意义单元：Zhang et al., EMNLP 2020。
  - 用 DP 优化分段：Oda et al., ACL 2014。
- **训练中已用过语音时间信号**：
  - Seed LiveInterpret 2.0（2025）的 RL 奖励含语音时长和 lagging；
  - Hibiki（Labiausse et al., ICML 2025）在构造数据时用对齐感知 TTS 惩罚滞后（contextual alignment）。
  - 所以"首个按语音延迟训练提交策略"**不能**这么说。
- **播放队列只出现在评测或指标里**：SimulEval 的 FIFO 时间线、ATD（Kano et al., Interspeech 2023）、Sudoh et al. 2020、Liu et al. Interspeech 2022、Zheng et al. Findings EMNLP 2020（按语速调整译文长度）。
- **J1 主张的新颖之处只限于**：
  1. 输出侧的 TTS 块边界作为隐变量；
  2. 块势是含每块开销和积压的播放队列延迟（状态里带离散积压，不是标准的段内局部势，推断在增广链上精确完成）；
  3. 多说话人、每条流各自的播放；
  4. 用后验正则的对偶 EM 训练。

## 3. 用哪个基线的标签：决策规则（现在定下，不依赖任何结果）

- **语音 LAAL 目标**：每条流语音 LAAL（all，两种子平均）≤ 3.85 s，即 A′ 4.151 − 0.30。
- **"J1 有效"的判定**：门槛通过并且达到语音 LAAL 目标。门槛通过但没达到目标，记为"质量保住、延迟收益不足"。
- **主报告**：每条流语音 LAAL（all / ov / 1spk）；另报文本 LAAL、EndOffset、单通道 LAAL、延迟分解（模型滞后、检测器等待、排队、最后一块、最终读）、talker 块大小、语音总秒数。
- **消融（报告，不判定）**：J1 的同一个解码，用逐段输入（不合并）再跑一次语音链，两个种子，把读级块的作用和训练目标的作用分开。
- **与基线的配对比较**（只有基线自己有 dev 全集解码时才做）：
  - 基线的解码也用读级块再跑一次语音链（只多 TTS / ASR，不重新解码），这样两者只差训练目标；
  - 判定规则与 T2 对 T1 相同：只有当 J1 的语音 LAAL 不比基线高 0.1 s 以上，并且文本 all 与语音的配对差都 ≥ 0 时，才说 J1 更好；
  - 否则只在质量-延迟平面上并列。

中性分数，前 200 步，每个后验用自己的 λ*：

| 数据 | 后验 | E[语音 l] / 词 | E[文本延迟] / 词 | E[块数] | λ 均值 |

- **(ii) 不过**：J1 的块反而略多。
- **(iii) 过**：文本延迟只高 0.06 / 0.008 s，在 0.25 s 的余量之内。

**PC4 判定：NOT GO（两套数据）。** 按第 5 节，由协调者（用户）决定是否照常训练。

**诊断（事后做的，不是登记的线）**：把 J1 的 λ 目标改成"基线后验自己的 E[语音 l]"，即让两者的语音延迟期望相同，结果 J1 仍然块更多、文本更晚：

| 数据 | J1 块数 | 基线块数 | J1 文本延迟 / 词 | 基线 |
|---|---|---|---|---|
| T4 | 6571.8 | 6449.0 | 2.488 | 2.440 |
| T5 | 8431.2 | 8419.4 | 0.885 | 0.877 |

输出在 `eval_outputs/mist_w3po_v1/crf/j1_precheck_v1_diag_pc4_matched.json`，脚本是 `crf/j1_diag_pc4_matched.py`。

**解读**：
1. "目标 = T1 子格期望延迟"这个原则对 J1 不利。基线在文本时间线上用 T1 的水平收紧时，它在语音时间线上已经低于 T1 的语音水平；J1 只要求到 T1 的语音水平，所以收得更松（λ 0.105 vs 0.157），写得略晚。
2. 在这两套格上，"少分块"主要来自"集中在标签路径上"：同一读到期的条目本来就成组。推迟一读更常把组拆开，而不是把组合并。每块开销约 0.34 s，在宽度只有 1–2 读的格里不足以让语音势偏向合并。这与 (a) 的结论一致：合并本身的上界很小，降语音 LAAL 要靠更早写。
3. 这是在中性分数下的结构性结论。用真实的模型分数，后验会集中到模型偏好的路径上，结果可能不同，但没有理由预期 J1 会比基线更早写。
