## 1. 结论

1. **在同一个公式下，多说话人比单说话人慢 0.6–1.3 s。** 单说话人取同样每步读 1 s 的点（QABC b0=1，Δ=1）：
   - D1：VE1-s2rl + PL-EM 3.04 s，对 2.18–2.25 s，差 0.8 s；A′rl + PL-EM 3.50 s，差 1.3 s。
   - D2：差 0.6 s 和 1.0 s。
   - 以前常拿来比的是"多说话人 D2 4.05 对论文 D1 1.77"（Δ=0.5 的点），差 2.3 s。这个数既混了两个定义，又混了两种读窗。
2. **窗口检测器占这个差距的一半到九成。** 检测器在每个定义下都贡献 0.54–0.72 s（第 4 节）。去掉检测器以后：
   - VE1-s2rl + PL-EM 比单说话人只慢 0.27 s（D1）和 0.06 s（D2）；
   - A′rl + PL-EM 慢 0.61 s 和 0.37 s。
3. **字面上的 SimulEval 默认 LAAL（D0）不适合跨系统比较。**
   - 它对每个语音段记一个延迟，而参考长度按词数算。所以语音切得越粗，数值越大；切得越细，数值越小，细到一定程度甚至比按词计的还小。
   - 同一个单说话人点（En→Zh m2），按整块算是 3.69 s；按 320 ms 音频块算是 2.08 s；按 80 ms 音频块算是 1.26 s。D1 是 1.77 s，正好落在这个范围中间。
   - 按整块算的 D0 把多说话人和单说话人的差距抹平了：单说话人句子更长（7 s 对 3.5 s），每句的段也更多，所以被罚得更重。
4. **幻灯片上和 SimulS2ST-Omni 的比较是否保守，取决于 Omni 的语音段有多细，而 Omni 的文中没有写。**
   - 如果 Omni 实际上按输出词计时（D0w，等价于每个词一个段），我们的 D1 比 D0w 高 0.08–0.13 s，幻灯片上的数字略偏严，大约保守 0.1 s。
   - 如果 Omni 按音频块切段：块长 ≤ 160 ms（En→Zh）或 ≤ 320 ms（Zh→En）时我们的 D1 偏严；块更长时我们的 D1 偏宽。
   - 如果按整个提交切段（与我们 D0 的切法一样），我们的数会高 1.3–2.1 s，幻灯片偏宽。但 Omni 自己的 m1 = 1.18 s（每步读 1 s）与这种粗切法对不上，见第 2 节，所以这种情形不大可能。
   - 结论：不能说幻灯片"肯定保守"。只能说它在 Omni 的两种可能的细粒度做法下大体持平或略保守，而且 Omni 的计算方式本身没有公开。

## 2. 三个定义（以及两个辅助量）

三个定义用的是同一个 LAAL 公式（Papi et al., 2022）：

$$\mathrm{LAAL}=\frac1\tau\sum_{i=1}^{\tau}\Bigl(d_i-(i-1)\frac{|X|}{\max(|Y|,|Y^*|)}\Bigr),\qquad \tau=\min\{i:d_i\ge|X|\}$$

如果没有任何 $d_i\ge|X|$，就对全部 $i$ 求平均。三个定义的区别只在于"一个 $i$ 是什么"以及"它在什么时刻计时"。

| | 一个 i 是 | $d_i$ | $\|Y\|$ | 排队 | 用在哪里 |
|---|---|---|---|---|---|
| **D0** SimulEval 默认 | 一个发出的非空**语音段** | 发出时已经读到的源时长（`step_to_delay`），**不是**开始播放的时刻 | 段数 | 不计（排队只进 EndOffset / RTF / Discontinuity） | SimulEval `LAAL`，不计算耗时；假定 Omni 用的是这个 |
| **D1** 段 LAAL | 一个输出单位（英文词 / 中文字） | 承载该单位的语音块**开始播放**的时刻 | 输出单位数 | 计 | 单说话人论文（appendix "Latency metric"）、幻灯片 |
| **D2** speech_laal_online | 一个输出单位 | 该单位**说完**的时刻（块内各单位按播放时长均分，取第 k 个的 (k+1)/n 处） | 输出单位数 | 计 | 多说话人报告（`speech_latency_lit`） |
| D0w（敏感性） | 一个输出单位 | 所在块的发出时刻（与 D0 相同） | 输出单位数 | 不计 | = 每个词单独成段时的 D0；= SimulEval 文本输出的 LAAL；多说话人里就是报告中的 text LAAL（`text_laal_online`） |
| -raw / -rec（多说话人） | 同上 | 用 Thinker 的原始写出时刻，不经过窗口检测器；D1-rec / D2-rec 用 talker 自己记录的时间线（排队建立在原始写出时刻上） | | | 用来量检测器的份额 |

D0 的细节（SimulEval 1.1.4，`latency_scorer.py` / `instance.py`）：
- $|Y^*|$ = 参考长度。`latency_unit word` 时是 `len(reference.split(" "))`。中文目标这里用 `si_metrics.units` 的字数，与 D1 相同。SimulEval 的 `char` 会把标点也算进去（`len(reference.strip())`），对 En→Zh 的 D0 只多 0.01–0.07 s（`D0_char`）。
- 如果 $d_1>|X|$，直接取 LAAL = $d_1$。
- 段按发出顺序排列。
- SimulEval 还有 `LAAL_SpeechAlign_{BOW,COW,EOW}`：用 MFA 把输出 wav 对齐到词，延迟 = 第一段的发出时刻 + 该词在输出 wav（含等待的静音，也就是播放队列）里的时刻。其中 EOW 就是 D2 的强制对齐版本。Omni 写的是 "LAAL"，不是这一组。

各系统的口径：
- **多说话人**：
  - 源 = 一个计分的参考单元（同一说话人间隔 < 1 s 的句子，与 tcpBLEU 相同），$|X|$ = 单元时长（dev 均值 3.5 s，中位数 2.1 s），$|Y^*|$ = 单元的参考词数（均值 10.8）。
  - 一个 D0 段 = 官方分配给该单元的一个 talker 块（读级块 run 里一个块就是合并后的一段），延迟 = 块的**在线**提交时刻（经过窗口检测器：≥ open_detect；最终读的块 ≥ close_detect）减去单元起点。
  - 延迟**不截断**到 $|X|$，因为单元结束以后会议还在继续。
  - 单元集合与报告里的 speech_laal_online 完全相同（有分配到的块，并且有说出的词）。
- **单说话人**：
  - 用的就是论文的 run 和筛选（`paper/bayes_simul_s2st_v11/scripts/collect_results.py` 的 `realsi_points`）。源 = 一个 RealSI 句子（均值 En→Zh 7.4 s、Zh→En 6.7 s），$|Y^*|$ = 参考的字数或词数（均值 30.1 / 16.5）。
  - D0 段 = 有语音（`dur_ms > 0`）的块，延迟 = `min(write_ms, |X|)`。SimulEval 读不到源结束以后；实际上没有块越界。
  - 没有检测器，所以 D0-raw = D0。

**SimulS2ST-Omni 写了什么**（arXiv 2607.19810，正文 4.1 节、附录 D.3、F）：
- 只写了 "SimulEval-style latency metrics"，句级 S2TT/S2ST 用 "LAAL (Papi et al., 2022) and computation-aware LAAL (LAAL_CA)"，长音频用 StreamLAAL。
- 没写 latency unit，没写语音段怎么切，也没写是否做词对齐。附录 F 说 LiveInterpret 被"重新实现为一个 SimulEval agent"，所以可以推断他们自己的系统也是用 SimulEval agent 评测的。
- 因此本文把 Omni 的数字标为"报告值，假定为 D0"。但段的粒度无从得知。

**一个可检验的推断**：Omni 的 m1 每步读 1 s 源（附录：one second per step at m=1）。
- 如果每个读步最多发一个语音段，那么第 i 段的延迟至少是 i 秒，于是每句的 D0 ≥ 1 + (1 − |X|/|Y*|)(τ − 1)/2 秒。
- RealSI 的 |X|/|Y*| 约为 0.25 s/字（En→Zh）和 0.44 s/词（Zh→En）。要让均值等于 1.18 s，τ 平均只能有 1.5–1.6 段。对 7 s 的句子来说，这几乎等于不同传。
- 所以 Omni 的段必然比"每步一段"细（例如每个 flow-matching 音频块一段），或者它是按词计时的。这正是 D0 最依赖粒度的区间（见第 5 节）。

## 7. 注意事项

- D2 是均分的近似，不是真正的词对齐。论文 `tab_wordlaal` 里强制对齐的 word LAAL 是：QABC Δ=1 为 3.20 / 3.31（一个种子），b0=0、Δ=0.5 为 2.08 / 2.32；这里的 D2 分别是 3.04 / 3.01 和 2.00 / 2.10，低 0.1–0.3 s。
- 多说话人有 0.4–0.7% 的单元，第一个块在单元起点之前就提交了（延迟为负；分配有 2 s 的容差）。这里照原样计入，与报告的口径一致。
- 单说话人的 D0 里，只有标点的块（En→Zh 每个 run 约 30–90 个）也算作一个语音段，因为它们有语音；只算含字词的块（`D0_unitblocks`）时，变化不超过 0.04 s。
- 顺带看到但没有核实：Omni 附录 D 写的是 En→Zh 431 句、Zh→En 347 句；我们的 RealSI 文件是 en2zh 346 句、zh2en 431 句。方向标注可能对调了。
