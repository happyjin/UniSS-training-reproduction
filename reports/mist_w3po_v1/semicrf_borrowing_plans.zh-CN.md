## 1. 论文方法精读

**任务。** 一段语音里只有部分区间被伪造，要判断"有没有伪造"以及"在哪里"。输出是 20 ms 网格上的真/假标签。

**问题设定。** 已有方法都是逐帧分类，再把连续的同类帧拼成区域。区域只是间接得到的，它的内容、边界和时长从来没有被直接打分。

**方法要点。**

1. **输出单位从"帧"改成"带标签的区段"。** 一个切分 z = ((i_m, j_m, c_m))，把 T 个位置无缝隙、无重叠地分成 M 段，每段长度不超过 L（4 s），段的类别 c ∈ {真, 假}。
2. **区段打分由四部分组成。**
   s(i,j,c) = 段内内容势的**均值** + 左边界势 ℓ_i^c + 右边界势 r_j^c + **时长势** d^c_{j−i+1}
   - 用均值而不是求和，是为了不让长段的分数自动变大。
   - 时长势是一个可学习的表，直接给"多长的段"建模。
3. **全局归一化。** 整个切分的分数 = 起始分 + 各段得分之和 + 相邻段转移分 A_{c,c'} + 结束分。概率 p(z|x) ∝ exp S(z,x)，归一化是对**所有合法切分**求和。每个区段都在全局一致的切分里被评估，不会各判各的。
4. **用帧标签训练，内部边界作为隐变量。** 帧标签只决定"类别在哪里切换"，同类连续段内部怎么再切，标签并不知道。损失定义为
   L = (log Z(x) − log Z_y(x)) / T
   其中 Z_y 是所有与标签相容的切分之和。这样不会强加一个人为的内部切法，两个配分函数都用半马尔可夫前向算法精确计算。
5. **后验解码。** 用前向-后向算法得到每个候选区段的出现后验 γ_{i,j}^c。帧级后验 = 覆盖该帧的所有"假"区段后验之和，大于 0.5 就判为假。没有用 Viterbi 选单一路径，阈值也不需要调。
6. **对照设计很干净。** 共享 WavLM-Large、2 层 Conformer 和同一套训练协议，只换输出层：Softmax 或线性链 CRF，各自配二元、BIO、TIO 三种标注，再加 semi-CRF。
   - 结论一：边界感知的标注（BIO/TIO）只有在 CRF 建模了相邻依赖时才明显有用。逐帧独立分类时，标注再丰富，收益也很小。
   - 结论二：从"帧标签 + CRF"换成"区段 + semi-CRF"还有进一步提升（20 ms 处 EER 相对下降约 25%）。最大的收益在**完整区域的定位**上（IoU-F1）。
7. **评测设计。**
   - 指标：帧级 EER/F1 之外，加了**区域级 IoU-F1**（时间 IoU ≥ 0.5 的一对一匹配）。
   - 时长分析：画**预测区段与参考区段的时长分布（CDF）**。逐帧方法把完整区域切成碎片，表现为短段过多；semi-CRF 的时长分布更接近参考。
   - 种子：每个配置跑 **3 个随机种子**，报告均值 ± 标准差。
   - 基线：所有对照尽量从公开 checkpoint 统一重算。
8. **数据增强的贡献最大。** RawBoost 去掉后 EER 相对上升 32%；跨片段拼接（CSM，20% 的批）贡献小一些但稳定。跨域测试（LlamaPartialSpoof）所有系统都大幅退化，semi-CRF 的优势主要保留在区域级指标上。

**局限。** 和我们相关的局限有三点：
- 离线：整句可见，不是流式；
- 只有二分类：没有多说话人、重叠；
- 判别式：不涉及生成。

## 2. 论文的观察与 MIST 现象的对应

| 论文的观察 | MIST 中对应的现象 | 我们已有的证据 |
|---|---|---|
| 逐帧决策把一个区域切成碎片，时长分布偏短 | 输出段碎片化、重复；短片段的语音质量差 | 每条轨迹约 4 段；重复率 5–6%；≤2 词的段合成后再识别 BLEU 2.85，WER 38–44%（`diag_speech_drop.json`） |
| 短区域最难定位；区段建模 + 时长势有帮助 | 短插话（≤1 s）漏译 | ≤0.5 s 召回约 57–59%；漏掉的短插话里 66.6% 是 8 条 rollout 全部漏掉（ECF 预检） |
| 说话人/类别信息来自逐帧后验，区域是间接得到的 | 说话人信息来自冻结 diarizer 的逐帧 8 槽后验（`post/lowlat`，80 ms/帧，形状 T×8），错误向下游传（方案文档 P10） | 错标 2.2–2.9%（dev 窗口级）；collapse 0.16–0.20 |
| 只加边界标签、没有结构依赖时收益很小 | 给 who token 加独立的逐 token 信用（w3dia/w3dia2/EA），只是在"敢拆分"和"标得准"之间来回挪 | 三次实验都没有净增益 |
| 内部边界没被标注时，对所有相容切分求边际，而不是强加人为切分 | `<wait>` 策略由**启发式截止时间标签**监督（`docs/mist_grpo_plan.zh-CN.md` 第 34 行），译文切成几块是人为定的 | GRPO 推不动提交时机；W³PO 的延迟奖励导致切碎 |
| 区域级指标 + 时长 CDF 比帧级指标更能揭示结构差异 | 语音门槛被 TTS 抽样噪声主导，判不出 0.5 BLEU 级别的差别 | TTS 噪声约占语音分数方差的 60%（ICC 约 0.40） |
| 多种子报告均值 ± 标准差，所有对照统一重算 | 每个系统的语音分数只是一次 TTS 抽签 | 同一份 TTS 输入，两次运行 WER 19.6% 对 15.1% |
| 跨片段拼接增强 | 短插话和重叠样本太少，RL 得不到对比信号 | 时长 < 1 s 的流只占 7.3% |

## 3. 能借鉴什么，不能借鉴什么

**能直接借鉴的**
- 在 diarizer 后验（逐帧、80 ms、8 槽）之上，把"说话人轮次"建模成带时长的区段。这和论文是同构问题：论文对"真/假"做切分，我们对"某个槽在说/没说"做切分。
- 区域级指标、时长 CDF、多种子报告。
- 后验解码：用 0.5 阈值，不调参，正好符合"验证期不扫超参"的规则。
- 跨片段拼接增强。

**需要改造的**
- **流式。** 论文整句可见，我们只能用当前时刻 t 加固定延迟 D 之内的帧做前向-后向，即 fixed-lag 平滑。D 会给说话人判断增加延迟，必须预先固定。
- **重叠。** 论文是单标签切分，我们有多说话人重叠。可行做法：每个槽各做一条二元 semi-CRF 轨道（在说 / 没说），参数共享，重叠自然允许。
- **槽位置换。** diarizer 的槽编号在每个窗口内是局部的。训练标签要先用匈牙利匹配，把参考说话人映射到 diarizer 槽。

**不能借鉴的**
- 生成部分（翻译内容）不是判别式切分，semi-CRF 不能直接替代 LLM 的输出。
- 它能提供的是**结构信息**（什么时候、哪个槽有一个多长的轮次），不能提升译文质量本身。
- 如果 diarizer 把两个人合并到同一个槽（collapse 的一部分来源），逐槽精修也分不开。

## 4. 方案

所有方案都遵守现有约束：
- 只用 AMI 训练集训练；RealSI、ACL 60/60、AliMeeting 只做测试，dev 只做选择；
- 正式门槛不变：文本 all、文本 ov、语音三项，点估计 ≥ ref − 0.2，配对 bootstrap P(diff≤0) < 0.95；
- 每个方案只跑一个预先登记的设置，不扫参数；单种子训练；
- 代码只做增量修改，默认行为逐位不变，配单元测试。

### 方案 A：结构化评测与诊断（纯 CPU，现在就能做）

**动机。** 现在判不出方法好坏，最大的障碍是测量噪声：语音分数约 60% 的方差来自 TTS 抽签。论文用区域级 IoU-F1 和时长 CDF，揭示了帧级指标看不到的结构差异。我们需要一组**不经过 TTS、只看结构**的指标，作为门槛之外的方向信号。

**做法**

1. **说话人归属区域 F1（SA-IoU-F1）。**
   - 输出段 {spk, a, b} 和参考单元 {spk, a, b} 按时间 IoU 做一对一匈牙利匹配，IoU ≥ 0.5 算命中。说话人用 STAMP 的窗口级映射 π*，映射一致才算正确。
   - 分三档报告 P/R/F1：全体、重叠区、≤1 s 单元。
   - 这个指标不看译文、不经过 TTS，所以没有抽样噪声。
2. **时长 CDF 和碎片率。**
   - 输出段时长与参考单元时长的 CDF 对比图；
   - 碎片率 = 输出段数 / 匹配上的单元数；
   - ≤2 词段的比例。
3. **语音评测去噪。**
   - TTS 种子改由内容哈希决定：同样的文本得到同样的语音，系统之间的差别只来自文本；
   - 再用两个种子取平均。
   - 已写好的 `evaluation/gate_2seed.py` 可以直接复用。
4. 用 1–3 对已有的解码结果重算：v8、dia 20/50/100、w3dia 50/100、w3dia2 20/50、EA 20/50。
   - 第 1、2 项是纯 CPU；第 3 项需要重跑 TTS 和 ASR。

**产出与用途**
- 回答"EA 和 dia 在结构上到底差在哪"；
- 给论文的分析章节提供图表；
- 后续每个方案都用这组指标看方向。

**风险。** 无。这一方案不改门槛，只增加次要指标。

### 方案 B：半马尔可夫说话人轨迹精修（SCT）

**动机**
- 说话人信息完全来自冻结 diarizer 的逐帧后验。
- 逐帧后验正是论文批评的形式：区域是间接拼出来的，没有时长和边界建模，容易碎片化、漏掉短区域、在槽之间抖动。
- 错标、collapse 和短插话检测，都受这一层的质量限制（方案文档 P10）。
- GRPO 从输出端去修说话人，三次都失败了；更合理的做法是在输入端把结构做对。

**做法**

1. **模型：每槽一条二元 semi-CRF 轨道，8 条轨道共享参数。**
   - 每帧特征：logit(p_k)、max_{j≠k} p_j、Σ_j p_j、Δp_k（相邻帧差），可选加帧能量。
   - 一个两层 MLP 输出内容势 u、左边界势 ℓ、右边界势 r。
   - 时长势 d_q^c 的 q 取 1…L，L = 50 帧（4 s）；超过 L 的同类长段由多个段相接表示，和论文一样。
   - 另有转移分、起始分和结束分。
2. **标签。** 取 AMI 训练集 23,742 个窗口（`windows_train_diar.jsonl`）里的 `utts`（说话人和起止时间），按 80 ms 栅格化，再用匈牙利匹配（按与后验的重叠）把参考说话人映射到槽，得到每槽的帧标签。
3. **训练。** 用论文式的边际似然：同类段内部的切分作为隐变量，−log Z + log Z_y，精确的半马尔可夫前向计算。参数只有几万个，用 CPU 就能训练。
4. **流式推理。** 在时刻 t，对 [窗口起点, t + D] 做前向-后向，取帧 t 的边际后验作为精修后的后验。D = 6 帧（0.48 s），预先登记。得到的区段后验 γ_{i,j} 同时给出"一个时长 ≤1 s 的轮次刚刚结束"这类事件，供方案 C 使用。
5. **三种用法，按成本从低到高。**
   - **B1，事后重标（CPU，不训练 MIST）。** 输出段的槽 := 精修后验在该段源区间上均值的 argmax，只有当它 > 0.5 且与模型给出的槽不同时才改，否则保留模型的标签。
   - **B2，作为 MIST 的输入。** 用精修后验替换 `lowlat`。分布会变，需要短 SFT 适配，放到后面做。
   - **B3，作为方案 C 的事件检测器。**

**预检（纯 CPU）**
- 在 dev 上比较精修后验和原始 lowlat：帧级 F1、轮次级 IoU-F1、≤1 s 轮次召回、槽抖动次数（每分钟槽切换数）。
- **关键问题：** dev 上被漏掉的 ≤1 s 单元，diarizer 原始后验有没有在正确的槽上升起来？
  - 升起来了但模型没翻：问题在策略，做方案 C。
  - 根本没升起来：问题在检测，做方案 B 加方案 E。

**判定**
- B1 通过正式门槛，且错标和 SA-IoU-F1 不比模型自己的标签差，才算有效。
- 注意：过去"因果重标"在 dev 和 AliMeeting 上结果不一，模型自己的标签有时更好（34.56 对 31.94）。B1 必须正面胜过模型自己的标签，否则只作为检测器使用。

**风险**
- 分不开被合并的槽；
- D = 0.48 s 给说话人判断增加延迟；
- AMI 训练出来的时长分布迁移到 AliMeeting 时可能变化。好在论文显示结构化模型跨域时在区域级指标上仍保留优势。

**相近工作和新意**
- VBx（Landini et al., 2022）用 HMM 平滑说话人，但 HMM 的停留时间隐含几何分布；
- EEND 系的后处理大多是中值滤波；
- 新意：在**流式多槽 diarizer 后验**上做**可学习时长势**的 fixed-lag semi-CRF，并把区段后验作为同传策略的事件信号。
- 这是一个组件级创新，单独撑不起顶会论文，要和方案 C、D 合在一起讲。

### 方案 C：事件触发的强制输出（推理期，不训练）

**动机**
- 66.6% 的短插话漏译发生在 8 条 rollout 全部漏掉的情况，GRPO 在原理上学不到。
- ECF 预检显示，在部分覆盖的单元上，输出了插话的成员 z(cpBLEU) 平均高 0.42，59% 的单元为正。也就是说，"听完插话就输出"整体上对奖励有利。
- ECF 训练时用参考时间轴决定在哪里分支，推理时没有参考。方案 B 的检测器正好在推理时提供这个触发信号，而且不需要训练。

**做法**
- 推理时，如果方案 B 的区段后验显示"槽 k 上一个时长 ≤1 s 的轮次在最近一次读之前结束"，即 Σ γ_{i,j}^{在说} > 0.5，其中 j − i + 1 ≤ 13 帧且 j 落在上一次读的区间内；
- 并且 k 不是当前正在输出的说话人；
- 而模型在这次读选择了 `<wait>`，那么下一次读设置 `bar_wait`。引擎已经支持，ECF 用的就是同一个机制。
- 每个事件最多强制一次。
- 预登记设置：τ = 0.5（后验解码的自然阈值）、≤1 s、每事件 1 次，不调参。

**预检（纯 CPU，用已有的 dev 解码）**
- 漏掉的 ≤1 s 单元中，有多少会被检测器触发（覆盖率）？
- 非插话位置的误触发率是多少？
- 覆盖率 < 30% 或误触发率 > 50% 时，不上 GPU。

**GPU 评测。** 只需要解码，不训练。分别在 v8 和 dia 100 上加触发规则，跑 guarded dev，看门槛、≤0.5 s 和 0.5–1 s 召回、碎片率和重复率。

**判定**
- 门槛通过；
- 短插话召回高于不加触发的同一系统；
- 碎片率、重复率不升，或者升了但语音不降。

**风险**
- 强制输出会产生很短的片段，而 ≤2 词片段的语音 WER 约 40%，语音门槛可能先受损。这正是要用门槛来检验的地方，不靠调参挽救。
- 误触发会造成提前、不完整的翻译和重复。

**如果有效**
1. 得到一个推理期立即可用的改进。
2. 用同一个检测器替换 ECF 的参考时间轴触发，训练和推理就一致了（ECF-det），策略可以学会自己做到，最后去掉规则。

### 方案 D：潜在提交点的边际似然 SFT（不再强加人为切分）

**动机**
- 论文第 4 点：标签没有确定的内部边界，应该对所有相容切分求边际，而不是强加一种切法。
- MIST 的 `<wait>` 由启发式截止时间标签监督：一个参考单元在哪一次读提交、切成几块，是人为规则定的。
- 规则和模型自己的倾向不一致时，SFT 学到的就是噪声。这可能是碎片化、重复和提交时机不稳的来源之一。
- GRPO 在同一个奖励上调信用，推不动这一点。

**做法（硬 EM 近似，可在 GPU 上实现）**
1. 对每个参考单元 u，相容的提交读集合 R_u = {读 r : t_r ∈ [b_u, b_u + D_max]}，预登记 D_max = 2 s，一般 3–4 个候选。暂不做单元内再切块，保持简单。
2. **E 步。** 固定其他单元的金标前缀，用当前模型给每个候选算控制 token 序列（若干 `<wait>` 后接写出）的对数似然，取最大者 r_u*。候选可以批处理，每个窗口约 K × |U| 次前向，可接受。
3. **M 步。** 用重标后的序列做 SFT（LoRA，从 v8 起步），然后再做一轮 E/M。
4. 软版本，留作后续：按后验对 K 个序列加权，即论文式的 Z_y 求和。
- 预登记：D_max = 2 s，EM 2 轮，其余超参同 v8 的 SFT。

**判定**
- 门槛通过；
- 碎片率和重复率下降（方案 A 的指标）；
- 延迟不变差（ov 延迟 p50）。

**风险**
- 模型可能把自己"偏晚"的倾向固化下来，延迟变差。所以把延迟列入判定。

**相近工作和新意**
- HMT（Zhang & Feng, ICLR 2023）用隐马尔可夫建模"何时开始翻译"并求边际；
- MILk/MMA（Arivazhagan et al., 2019；Ma et al., 2020）对读写路径求期望。
- 这些都是单说话人、非 LLM。
- 新意：多说话人交错输出（`<spk_k>` 槽）的 LLM 同传上的潜在提交点边际训练。需要文献核查确认。

### 方案 E：跨片段拼接增强（插话和重叠合成数据）加定向 SFT/RFT

**动机**
- 论文里增强的贡献最大：RawBoost 相对 32%，CSM 稳定有收益。
- 我们的短插话和重叠样本太少（时长 < 1 s 的流占 7.3%），而且大多被全组漏掉，SFT 和 RL 都得不到信号。
- 方案 B 的预检如果显示 diarizer 根本检测不到短插话，问题就在"感知"，只能靠数据解决。

**做法**
1. 只用 AMI 训练集。截取说话人 B 的 ≤1 s 话语（附和、打断、插话），以及对应的参考译文。
2. 把它拼进说话人 A 的窗口，有两种方式：放在 A 的停顿处，或与 A 重叠（交叉淡化 50 ms，增益在 [−6, 0] dB 内均匀抽）。
   - 论文提到检测器会依赖拼接边界的伪影，所以必须做交叉淡化，并抽查听感。
3. 在拼接后的音频上重新跑因果 diarizer，得到 `lowlat` 后验。标签里加入 B 的单元和译文，按 v8 的格式生成 SFT 目标。
4. 从 v8 起步做短 SFT（LoRA）。预登记：合成样本占 20%（同论文 CSM），1 个 epoch。可选：再在合成窗口上做 RFT（best-of-8 选优后做 SFT）。

**预检**
- diarizer 在拼接样本上对 B 的检出率；
- 人工抽听 20 条。

**判定**
- 门槛通过；
- ≤0.5 s 和 0.5–1 s 召回提升；
- 错标不升。

**风险**
- 合成数据与真实会议有分布差距；
- 可能学到拼接伪影；
- 需要 GPU 跑 diarizer 和 SFT。

## 5. 推荐顺序

| 顺序 | 方案 | 资源 | 主要回答的问题 |
|---|---|---|---|
| 1 | A：结构化评测（1、2 项） | CPU，现在 | 已有方法在结构上到底差在哪；给论文分析章节出图 |
| 2 | B：训练 SCT 加两个关键预检 | CPU，现在 | 短插话漏在"感知"还是"策略"；精修能不能降错标 |
| 3 | C：事件触发输出 | GPU，只解码 | 最便宜的短插话召回改进；如果有效，就是 ECF-det 的基础 |
| 4a | 预检表明问题在"策略"：C 有效后做 ECF-det 训练，或做 D | GPU，训练 | 让策略自己学会，并去掉规则 |
| 4b | 预检表明问题在"感知"：做 E（可接 RFT） | GPU，训练 | 补数据 |

**和上一轮建议的关系**
- 上一轮建议的"语音评测去噪"已并入方案 A 第 3 项。RFT 和"前瞻老师蒸馏"仍然有效，可以和方案 E 共用数据管线。
- 论文主线可以讲成"**事件结构化的多说话人同传**"：
  - 用结构化检测器（B）把源语音整理成带时长的说话人事件；
  - 推理时用事件触发输出（C）；
  - 训练时用事件触发的反事实分支（ECF-det），以及潜在提交点边际训练（D）；
  - 再配上区域级评测（A）。
