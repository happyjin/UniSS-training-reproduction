# 鲁棒线 v6：瓶颈分解：噪声到底伤在哪里，下一步该在哪里提升（2026-11-21 09:10 布拉格）

只是分析，用已有的输出。文本 BLEU 一律用论文口径（去标点，t2s，按字切分）。

## 1. 内容（翻译）的损失分解：底座 Thinker，CoVoST dev (a)
| 方向 | 离线（整句读完）干净 | 离线带噪 | LA2 流式干净 | LA2 流式带噪 |
|---|---|---|---|---|
| 英→中 | 42.19 | 41.03（噪声 −1.16） | 38.28（流式 −3.91） | 38.00（流式下噪声只 −0.28） |
| 中→英 | 35.43 | 34.27（噪声 −1.16） | 33.16（流式 −2.27） | 30.07（流式下噪声 −3.09） |

- **英→中：** 最大的损失是流式策略本身（−3.9），与噪声无关。流式下噪声只伤 0.3，抗噪方法在这里没有空间。这也解释了为什么 RealSI 英→中上所有方法都只能持平或略降。
- **中→英：** 流式下噪声伤 3.1。其中约 1.2 是感知（离线时也会掉），约 1.9 来自"噪声 × 流式提交"的交互：前缀不稳定，提交了被后来推翻的内容。这与第三波"约 71% 来自提交"一致。
- **说明 Thinker 训练失败的原因：** Thinker 训练（ERM、R1–R13）改的是感知和翻译，能碰到的只有约 1.2 的感知部分。而这部分又和参考译文的风格纠缠，所以净效果很小。
- **从文本到语音的内容损失很小：** RealSI 上 ASR-BLEU 与文本 BLEU 相差 −1.3（英→中）和 +0.7（中→英），Talker 不是内容的瓶颈。

## 2. 语音输出的损失分解（测试 / S1 dev）
| 指标 | 干净 → 带噪（底座） | V1 之后 | 上限（干净 token 的 oracle） |
|---|---|---|---|
| PESQ | 3.2–3.75 → 1.9–2.4（−1.3 到 −1.4，最大的相对损失） | 3.6–4.0（超过干净，是过度平滑） | 回到干净水平 3.2–3.45 |
| 说话人相似度 | −0.07 到 −0.10（约 −20%） | 只收回 13–63%（中→英最差） | 收回 92–119% |

- **音质已经解决，并且 PESQ 被高估：** V1 生成的是"比真人更干净"的平均化声音。
- **身份是剩下的最大缺口，而且可以救：** oracle 证明，只要 32 个全局 token 对了，身份就能完全回来。
- **瓶颈已经定位到全局 token 的估计和量化：**
  - 噪声只从全局 token 进入，GLM 语音 token 通道的影响可以忽略；
  - V1 / K3 / K4 的连续码与干净码余弦约 0.93，但量化后只有约 20% 的位置正确；
  - 即使输入是干净提示，也只能复现 45–55% 的位置。
