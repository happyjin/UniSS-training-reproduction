# 鲁棒第七波：任务驱动伪干净目标的因果前端 预登记

2026-11-19 深夜（布拉格），写于任何第七波数字之前。用户已确认用 Thinker 梯度构造的伪目标"不算"蒸馏。约束同 memory `robust-paper-constraints`：
- 一个前端服务两个方向；
- 提交策略仍是 LA2；
- 不碰 QABC；
- 训练只用开源非测试数据；
- 一个设置，不扫参。

来源：Rethinking Image Restoration for Object Detection（NeurIPS 2022）：用定向的、降低下游损失的扰动，在干净图上构造"对下游友好"的伪真值，再训练复原网络去逼近它。

## 动机（已测）
- 英→中的噪声损失在感知层面：oracle 提交下，(b) 无串音子集上仍掉 4.28 [2.00, 6.88]。
- 中→英 LA2 的 3.22 中，约 30% 是感知损失（oracle 0.94）。
- 免训练的输入侧方法失败（K3 / K7 / K8），HDemucs 替换输入还伤了干净输入。普通去噪的目标是"听起来干净"，不是"Thinker 好懂"。

## 方法（一个设置）
- **伪目标：** x* = PGD_L∞(x_clean)，沿降低 CE(Thinker(x), y_ref) 的方向走。
  - y_ref 为参考译文；Thinker 冻结；梯度经可微的 log-mel 前端回传到波形；
  - 3 步，ε = 0.1 × 该句 RMS，步长 ε/3。
  - x* 离线预先算好（每方向 5000 句 CoVoST 2 train，共 1 万句，排除留出说话人）。
- **前端 f_φ：** 因果的 STFT 掩蔽网络，帧长 32 ms / 帧移 16 ms，不向前看，因果 conv + GRU，约 3M 参数。算法延迟 ≤ 32 ms。只接在 Thinker 输入上（音色侧仍用 C）。
- **输入：** x_noisy = x_clean + 背景，配方与第五波主线相同（Idea 2 背景 train 划分、bench_build、BVR 分布）。另有 20% 干净样本，学恒等映射，保护干净输入。
- **损失：** 多分辨率 STFT 幅度 L1，加波形 L1，在 f_φ(x_noisy) 与 x* 之间计算。
- **训练：** 20k 步，lr 3e-4，batch 16。前端很小，Thinker 只用于离线生成 x*。

## 对照（同数据、同步数、同结构）
- **FE-clean：** 目标换成 x_clean（标准增强）。用于分清"伪目标"本身的贡献。
- 底座：直接用 S1 的数字（不加前端）。

## 评测
- LA2 流式（si_thinker_stream la2 w1，底座 Thinker）。音频先过前端：前端是因果的，对整段音频处理后再截取，与流式处理等价。
- S1 的 items：(a) 两个方向；(b) 无串音子集；干净和带噪都跑。文本 BLEU 用 S1 口径。

## 门槛（FE-pseudo）
1. 英→中 (b) 无串音带噪 BLEU ≥ FE-clean + 1.0，且 ≥ 底座 + 1.0。
2. 中→英 (a) 带噪 BLEU ≥ 底座 + 1.0。
3. 两个方向 (a) 干净 BLEU ≥ 底座 − 0.3。
4. 实时性：算法延迟 ≤ 32 ms；前端 RTF < 0.05（单卡实测）。

## 变更：统一判定标准（2026-11-19 深夜布拉格，写于本波任何评测数字之前）
用户："指标只需要关注 bleu 值不退化，laal 不要太差，音质有提升就可以"。主判定改为下面三条同时满足，原门槛降为次要结论照列：
1. **BLEU 不退化：** 两个方向、干净和带噪，对比底座（或本波对照）：
   - 文本 BLEU：点估计 ≥ −0.3，且配对 bootstrap CI 上界 ≥ 0（不显著变差）；
   - ASR-BLEU（如测了）：同样要求。
2. **LAAL 不太差：** D2 语音 LAAL 均值差 ≤ +0.10 s。
3. **有提升：**
   - 改语音通路的方法（Talker、音色）：带噪 PESQ 配对中位差 > 0，且 CI 下界 > 0；
   - 只改 Thinker 或前端的方法：至少一个带噪单元的文本 BLEU 显著提升（CI 下界 > 0）。

## 变更 2：LAAL 改为辅助（2026-11-19 深夜布拉格，写于本波任何评测数字之前）
- 用户："语音 LAAL 最多慢 0.1 s 也不一定，这个当辅助，主要还是 bleu 值和语音 pesq 提升就可以"。
- 统一判定中的第 2 条（D2 LAAL ≤ +0.10 s）**不再作为门槛**，只作为辅助指标照列。
- 主判定 = 第 1 条（BLEU 不退化）加第 3 条（语音通路看 PESQ 显著提升，Thinker / 前端看带噪 BLEU 显著提升）。

## 实现细节（执行者追加，2026-11-19 23:05 布拉格，写于任何评测数字之前；只追加）
- **脚本：**
  - 公共部件：`voicecond/wave7_fe_common.py`（可微 log-mel、前端、损失、混合）；
  - 训练句清单：`wave7_fe_data.py`；伪目标：`wave7_fe_pseudo.py`；
  - 前端训练：`wave7_fe_train.py`；评测：`wave7_fe_eval.py`（process / rtf / score）；
  - 启动器：`wave7_fe_run.sh`；占位进程 watcher：`wave7_fe_noplaceholder.sh`。
  - 输出 `eval_outputs/mist_w3po_v1/wave7/FE/`，日志 `logs/mist_w3po_v1/wave7/`。
- **训练句：**
  - 取第五波主线已裁好的 CoVoST 2 train 句（`wave5/M/data/rows_<dir>.jsonl`：已排除 HELDOUT 说话人，经 trim_norm），按 sha1("20261119|w7fe|sel|<dir>|<id>") 排序，每方向取前 5000 句；HELDOUT 说话人在本脚本里再断言一次。
  - 中→英 5000 句来自 7004 句、22 位说话人（CoVoST zh-CN train 只有这么多说话人），6.66 h；英→中 5000 句、2296 位说话人，6.53 h。
- **可微 log-mel：**
  - 按 `WhisperFeatureExtractor._torch_extract_fbank_features` 逐步重写，不做 detach，padding 方式与处理器一致（padding=True，补零到 batch 最长，丢最后一帧）。
  - 与处理器的 `input_features` 对比：CPU 上 3 个 batch 和 2 个单句，最大差 **0.0**，attention mask 逐位相同；GPU 冒烟最大差 ≤ **6.7e-5**（GPU 与 CPU 的 STFT 数值差）。
  - 运行时每个 microbatch 都会把这个差写进记录。
- **伪目标（与预登记一致）：**
  - ε = 0.1 × 整句 RMS，步长 ε/3，3 步 signed gradient，起点就是 x_clean，投影到 ε 球并限幅到 ±0.99。
  - 一个 microbatch 的损失 = 各句平均 CE 之和，所以每句的梯度符号只由它自己决定。
  - HF bf16，参考译文教师强制，提示同 si_thinker_stream 的基础提示。
  - 先按时长排序，再每 8 句组成一个 microbatch（mb = 8，影响的只有 padding）。
  - 以 float32 wav 保存。16 个分片 / 方向，用 O_EXCL 认领。
  - 冒烟（GPU，2 句 / 方向）：扰动最大值恰好等于 ε；CE 变化 0.956 → 0.870、1.894 → 1.889、0.178 → 0.125、2.985 → **3.164**（固定步长的 signed 步可能越过最低点，这是预登记的设置，不改）。正式运行会统计 CE 上升的句子比例。
- **前端：**
  - 共 2.61 M 参数，输出层零初始化，所以初始时 mask ≡ 1，内部重建误差 9e-8。
  - 因果性检验：在第 20000 个样本处改动输入，最早受影响的输出在第 19715 个样本（向前看 285 个样本，不超过一帧 512 个样本 = 32 ms）。
- **训练（两臂相同）：**
  - 每步 batch 16，从两个方向合并的 1 万句中按 sha1 抽句，再按同一哈希取 4 s 片段（不足 4 s 的补零，补零部分不计损失）；
  - 0.2 的概率为干净样本（目标 = x_clean），其余从 {music, crowd, sfx} 均匀选一种（第五波的单层配方，随机数为 w7fe）；
  - 目标与混合信号乘同一个限幅增益；
  - Adam lr 3e-4（恒定），梯度范数裁剪 5，fp32，20000 步；只存最终权重。
  - CPU 冒烟 3 步通过。
- **评测：**
  - 前端处理 S1 的全部 items → `si_thinker_stream la2 w1`（vLLM，gpu-mem 0.85）→ 文本 BLEU，与 S1 的底座 blocks 对比，也做两臂互比。
  - 再把该臂的 blocks 配上**原始** items（音色提示是原始音频，用第三波 V1 的 C token 表），跑 si_infer：4 个 shard、种子 20261021，与第三波 V1 完全相同 → ASR-BLEU 与 D2 / D1 LAAL 和 V1 配对比较。
  - 主判定按变更 1、变更 2：BLEU 不退化，且至少一个带噪单元的文本 BLEU 显著提升；LAAL 照列，不作门槛。
  - 判定单元为 (a) 与 (b) 无串音子集（无串音 = 同一对的干净和带噪都没有串音，与 S1 相同），两个方向，干净和带噪。
- **RTF：** 在一张卡上实测离线 RTF，以及逐帧流式（每 256 个样本调用一次，卷积上下文和 GRU 状态延续）的单帧耗时。
- **卡：** 只用卡 6–7（协调方分配）。卡 0–5 不碰。
- **实现修正（2026-11-20 00:20 布拉格，在任何评测数字之前）：** 第一次 Talker 运行（编排器在 00:17 停下）里，8 个作业都在音色覆盖的 sha1 核对处报错退出。
  - 原因：si_infer 的音色提示 = 原始音频截到 max(首次写出, 1 s)，而首次写出时刻取决于本臂自己的文本，所以第三波 V1 的 token 表（按 S1 的首次写出生成）对不上。
  - 改正：`wave7_fe_v1tokens.py` 按各臂自己的首次写出重算 V1 token。计算与 `wave3_v_tokens.py` 的 V1 完全相同（同样读取、截取、sf.write，C 编码器 → FSQ）。音色方法仍是 V1，提示长度跟随本臂的文本时序。
  - 失败输出改名为 `*.superseded_v0_v1tablesha`，日志同样改名。续跑由 `wave7_fe_orch2.sh` 负责（v1tok → talker → asr → score）。
  - 语音指标仍与第三波 V1 运行配对。两者的差别包括文本（及其首次写出），这正是前端带来的变化。

## 结果（2026-11-20 01:00 布拉格，只追加）：两臂前端都没有学到东西（近似恒等），方法未被检验
- **运行：** 卡 6–7。
  - 伪目标：23:03–00:00，共 1 万句。
  - 两臂训练：00:00–00:09，2 万步。
  - 处理与 RTF → Thinker：至 00:16。
  - Talker：第一次运行因 V1 token 表 sha1 不匹配失败（见实现修正），续跑 00:20–00:35。
  - ASR 至 00:53，打分完成 00:53。
  - 汇总：`eval_outputs/mist_w3po_v1/wave7/FE/summary.json`，日志 `logs/mist_w3po_v1/wave7/`。watcher 已用 stop 文件停掉，卡 6–7 交还 guard。
- **伪目标本身符合预期：**
  - 1 万句的平均 CE 1.080 → 1.022（逐句相对变化中位数 −10.4%）；27.5% 的句子 CE 上升（固定步长的 signed 步越过最低点）。
  - 可微 log-mel 与处理器的最大差 1.2e-4。
- **前端没有学到东西（关键）：**
  - 处理后的音频与输入几乎相同：中→英 (a) 相对变化中位数 0.1–0.2%，带噪 SNR 14.0 → 14.0 dB；
  - 训练好的 mask 在 [0.995, 1.003] 之间；
  - 训练损失从第 100 步起就是平的（pseudo 0.137–0.138，clean 0.102–0.103）。
- **原因（看数后的诊断，不改判定）：** 在预登记的损失（多分辨率 STFT 幅度 L1 + 波形 L1）下，对训练 batch 比较三种做法：

  | 做法 | pseudo 臂损失 | clean 臂损失 |
  |---|---|---|
  | 恒等映射 | 0.1586 | 0.1223 |
  | 训练后的前端 | 0.1574 | 0.1212 |
  | 理想幅度掩蔽（|目标| / |输入|，保留带噪相位） | 0.226 | 0.134 |

  - 连理想掩蔽都比恒等差。所以"保留带噪相位的幅度掩蔽 + 波形 L1"在 BVR 中位约 −14 dB 的条件下，最优解就是近似恒等，模型正确地收敛到了恒等。
  - 伪目标的扰动（约 −20 dB、逐样本符号）也不是幅度掩蔽能表示的。
  - 这是预登记设计本身的缺陷，不是训练 bug。
- **判定：** 主判定（变更 1、2）不通过：
  - 中→英 (a) 干净文本 −0.53 [−1.41, 0.41]、ASR-BLEU −1.49 [−5.38, 0.48]；(b) 无串音干净文本 −0.78 [−1.66, 0.10]（点估计低于 −0.3）；
  - 没有任何带噪单元显著提升。
  - 原门槛 1–3 不通过；4（算法延迟 32 ms，流式 RTF 0.045）通过。
  - **但由于前端近似恒等，这一结论不能说明"任务驱动伪目标"这个想法无效，只说明本设计没有检验到它。**
- **附带价值：同一 vLLM Thinker 重跑的噪声底。** 两个恒等前端相对底座，文本 BLEU 的差在 −0.85 到 +1.51 之间（例如中→英 (a) 带噪：clean 臂 +1.24 [−0.29, 2.47]；英→中 (b) 无串音带噪：+1.51 [−0.62, 3.98]）。
  - 这些差全部来自重跑的不确定性（输入的微小变化，以及 FLOAT 与 PCM16 写盘差异，让 greedy 解码走偏），说明 dev 上单次比较的噪声底约 ±1.5 BLEU。
  - 后续比较应当在同一次运行内配对，或者多跑几次。
- 按预登记，不改设置重试。
- 若要真正检验这个想法，需要新写一份预登记，例如：直接在波形 / 复数谱上输出、不用幅度掩蔽，并用 Thinker 侧任务损失的伪目标校验。是否重开由协调方决定。
