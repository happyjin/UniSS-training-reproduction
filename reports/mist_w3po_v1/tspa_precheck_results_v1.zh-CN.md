# TS-PA CPU 预检 P1 / P2：结果（2026-11-16）

## 概况

- 预登记：`tspa_precheck_prereg_v1.zh-CN.md`（e22805af4，先于任何数字提交）。
- 代码：
  - `talker/tspa_precheck_p1.py`、`tspa_precheck_p2.py`；
  - 测试 `test_tspa_precheck.py`：60/60 与暴力枚举一致；

**判定：P1 GO（三套数据全过），P2 NOT GO（两个方向的新增 AUC 都 < 0.03）→ 按登记总体 NOT GO：不上 GPU，不改阈值重算。**

- **四条 GO 线**，(a)、(b)、(c) 都满足：
  1. 可行。λ/κ 分别为：(a) 0.99/23.6，(b) 1.02/22.8，(c) 0.70/50.6；PL-EM 的 λ\* 为 0.80 / 0.70 / 0.50。
  2. 句内停顿：−41% (a)，−29% (b)，−32% (c)。
  3. 延迟代理：+0.010 / +0.011 / +0.019 s。
  4. CTC f：−0.016 / −0.028 / −0.018。
- **读法**：
  - 在已知真实到达时刻的上界下，TS-PA 把停顿降回规则路径的水平（甚至更低），同时保住了 PL-EM 的延迟和 CTC 保真度。
  - 语速几乎不变（3.69 → 3.65），说明靠的不是整体放慢，而是把快慢在块之间重新分配。
- **填不上的停顿**：在 PL-EM Viterbi 路径上，约 80% 的停顿（dev5 是 654/817，已独立复算；train 两套恰好也约 80%）无法靠"在同一积压下给该块换候选"填上。所以 TS-PA 的收益主要来自调整前面块的快慢、改变积压，而不是单块放慢。这也意味着补采更慢的候选帮助有限。

## P2：到达的可预测性（因果）—— NOT GO

- 两个方向的全部特征 AUC 都 ≥ 0.75，但新增值都 < 0.03，按登记判 NOT GO。
- 说明：
  - 在有后继块的样本里，final 和 closed 恒为 0（最终读写出的块必然是流里最后一块），这两个特征实际上没有信息。登记时没有预见到，不改判定。
  - 有信息的新特征是 pend（说话人之后又说了多少）和 debt（源端终点之后过了多久），在 En→Zh 上的系数合理（−0.72 / +0.47），但增益小。
- **含义**：PA Talker 现在已经能看到的信息（积压、块长、句末）对"下一块会不会及时到"已经有 0.75 左右的判别力；diarizer 提供的到达预测几乎没有新东西。

## 结论与需要用户决定的事

1. **按登记总体 NOT GO**：TS-PA（带到达预测 token 的版本）不上 GPU。
2. **值得用户知道的事（登记之外，只作描述）**：
   - P1 说明"双边代价"的训练目标本身很有效（上界下句内停顿 −29% 到 −41%，延迟 +0.01 s）。
   - P2 失败的是"需要新输入"这个前提，而不是双边目标。基线组 AUC 已有约 0.75，意味着不加新输入的 TS-PA（只把空隙项加进势里，Talker 的输入不变）也可能学到一部分。
   - 这是看过 P1/P2 结果之后才形成的新假设，如果要做，需要**重新登记**：
     - 先做一个 CPU 因果回放：用基线组特征拟合"模仿 TS-PA 选择"的策略，在格上回放，估计可实现的停顿降幅；
     - 再决定是否上 GPU。
   - 是否走这一步由用户决定。

## 追加：不加新输入的 TS-PA 因果回放 —— NOT GO（2026-11-16 傍晚）

- 预登记：`tspa_causal_replay_prereg_v1.zh-CN.md`（d89fa5f9e，事后假设，先于数字提交）。
- 代码：`talker/tspa_causal_replay.py`（精确前向 + CTC 二选一，与逐路径枚举 40/40 一致；拟合在人造数据上能完全恢复设定的参数）。
- 3 个作业并行，每个 60 进程，约 2.5 分钟。

| 设置 | 回放：句内停顿/分钟 PL → TS | 相对变化 [95% 会议 bootstrap] | 已知到达时刻的上界（q_PL → q_TS） | 延迟代理 Δ | CTC f Δ | 判定 |
|---|---|---|---|---|---|---|
| Zh→En：train16 拟合 → dev5 回放 | 1.575 → 1.549 | **−1.7%** [−2.0, −1.5] | −39.8% | +0.002 s | −0.006 | NOT GO |
| En→Zh：偶数折拟合 → 奇数折回放 | 7.970 → 7.908 | **−0.8%** [−0.9, −0.6] | −24.3% | +0.004 s | −0.009 | NOT GO |
| En→Zh：奇数折拟合 → 偶数折回放 | 7.183 → 7.109 | **−1.0%** [−1.4, −0.8] | −26.5% | +0.004 s | −0.013 | NOT GO |

- **GO 线 1**（句内停顿降 ≥ 15%）三个设置都远远没到；GO 线 2、3 都满足。**按登记 NOT GO，TS-PA 这条线结束。**
- **原因**：
  - 已知到达时刻时，TS-PA 能把句内停顿降 24–40%。但只用 Talker 推理时能看到的信息（积压 token、文本长度、句末、首块）去模仿，只能实现其中的 3–5%（例如 Zh→En：−1.7% 对 −39.8%）。
  - 因果策略对 TS-PA 目标的拟合也明显比对 PL-EM 目标差：argmax 一致率 0.79 对 0.84（Zh→En），0.72–0.75 对 0.77–0.78（En→Zh）。说明 TS-PA 的选择主要取决于"下一块何时到"这一未来信息。
  - 这与 P2 一致：因果信号里关于到达时刻的信息很少。
- **结论**：停顿的根源是 Thinker 的文本"何时到"不可预知。只改 Talker 的训练目标无法在因果推理中消除停顿。
- **可能的方向**（只作记录，不建议现在做）：
  - (i) 播放端加小的前瞻缓冲（等 Δ 秒看下一块是否到来），用延迟换流畅，代价是 LAAL 至少增加 Δ；
  - (ii) 让 Thinker 写得更均匀。
  这两条都超出了"只改 Talker"的范围。
- **论文**：维持 v11 的写法，停顿作为写明的局限。可以补一句：即使训练目标里加入停顿代价，在已知到达时刻的上界下可降 24–40%，但因果 Talker 只能实现 1–2%，停顿主要由文本到达时刻决定。这一句是否写入由用户决定。
