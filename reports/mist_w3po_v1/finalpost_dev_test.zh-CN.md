# 最终读因果 P 推理测试（dev，v8 ctx0 guard）

2026-11-09 19:43–23:19 UTC。只做推理和打分，没有训练。数据只用 dev 在线窗口：3,050 个窗口，15 个会议。背景见 `sched_precheck_v8.zh-CN.md` §8 和 LOG 2026-11-09 19:35 UTC 条目。

## 结论

- **正式闸门通过。** 对照官方参考 `dev_v8_ctx0_guard_s8`，语音用两个 TTS 种子：
  - 文本 all +0.69，ov +0.88，都显著；
  - 语音 +0.10，不显著，但没有下降。ASR-BLEU 硬闸门满足。
- **孤立短插话的错标大幅下降。**
  - ≤1 s 孤立单元：错标率 18.0% → 6.7%，漏译率 32.3% → 17.4%。
  - ≤0.5 s 单人召回：0.579 → 0.766。
- **延迟不变。** ov p50 1.690 → 1.674 s，平均滞后 1.779 → 1.769 s。塌缩和重复也都略降。
- **噪声地板。**
  - 开关关闭的重跑与参考逐位相同（3,050 个窗口），所以文本噪声地板是 0。
  - 但开关打开后，bf16 MoE 的批次耦合会扰动同批其他窗口的非最终读，涉及 1,170 个窗口。
  - 只看"非最终读完全相同、仅最终读不同"的 1,166 个窗口，干净效应是 all +0.39 [0.27, 0.54]、1spk +0.47、ov +0.19。短单元召回的提升几乎都来自这部分（见 §5）。

## 1. 改动（提交 2aec87d1）

- **新模块** `experiments/mist_w3po_v1/evaluation/online_decode_finalpost.py`，没有修改任何现有文件。
  - 选项 `--final-read-post {off,close_detect}`，默认 `off`。`off` 时直接调用 `online_decode.main`，不打补丁，参数原样传入。
  - `close_detect` 时包装 `Engine.read`：对 final=True 的读项，把 P 从第 cut // 80 帧起置零，并设 full=True，引擎不再做第二次掩码。
  - cut = max(t − 1040, min(t, close_detect_ms − 1040))，t 为窗口时长。下标规则和引擎自己的 `max(0, t − 1040) // 80` 相同，只改截止点。
  - 非最终读、音频、提示 id 和其他参数都不变。
- **因果性。** 打分器把最终读的输出记在 max(write, close_detect)（`overlap_score.py:141-144`），而 lowlat P 帧在其结束 1.04 s 后可得，所以不增加延迟。
- **窗口末端。** 按要求截到窗口末（min(t, …)）。跨越窗口末端的最后一个不完整 80 ms 帧仍然被掩掉，这是保守取法。
  - dev 上 3,049 / 3,050 个窗口的最终读能多看到 P；2,855 个（93.6%）能看到窗口内全部帧。
- **单元测试** `test_online_decode_finalpost.py`（CPU，真实 Prompter 和特征提取器，假 Thinker 记录模型输入）：
  - `off`：参数不变，`Engine.read` 未被打补丁。
  - `close_detect` 且 close_detect = t（截止点与默认相同）：提示 id、inputs_embeds、attention mask 和说话人流输入都逐位相同。
  - 扩展 P：只有最终读项的说话人行变化，其他位置不变。
  - 全部通过。

## 3. 正式闸门

规则：点估计 ≥ 参考 − 0.2，且按会议配对 bootstrap（10k）P(diff ≤ 0) < 0.95。三项都过才算通过。语音为两个种子在每个会议上合并 BLEU 统计量（`gate_2seed.py`）。

| 对比 | 文本 all | 文本 ov | 语音 all（2 种子） | 闸门 |
|---|---|---|---|---|
| CAND vs 官方参考 | 27.05 → 27.75，**+0.69** [0.44, 0.96]，P = 0.000 | 21.94 → 22.82，**+0.88** [0.41, 1.24]，P = 0.0003 | 19.07 → 19.17，**+0.10** [−0.84, 1.04]，P = 0.43 | **通过** |
| CAND vs OFF 重跑 | +0.69 [0.44, 0.96]，P = 0.000 | +0.88 [0.41, 1.24]，P = 0.0003 | 19.16 → 19.17，+0.01 [−1.17, 1.11]，P = 0.49 | **通过** |
| OFF vs 官方参考（噪声地板） | 0.00（逐位相同） | 0.00 | +0.09 [−1.09, 1.34]，P = 0.46 | —（脚本因 diff = 0、P = 1 判"不过"，不是退步） |

- **语音分种子**（CAND vs 参考）：
  - all：种子 1 为 +0.56 [−0.64, 1.75]，种子 2 为 −0.37 [−1.87, 1.14]；
  - 两种子合并：ov +0.42 [−1.27, 1.94]，1spk −0.13 [−1.21, 1.04]。
- **语音噪声。** 参考与 OFF 文本相同、种子也相同，语音 all 却差 −0.81（种子 1）和 +0.64（种子 2），来自 vLLM talker 和 ASR 的不确定性。单次抽取的语音噪声约 ±0.8。

## 5. 改变的窗口和归因

- **最终读的 P 被扩展：** 3,049 / 3,050 个窗口。
- **CAND vs 参考：**
  - 输出改变 2,334 个窗口；
  - 最终读改变 2,027 个；
  - 某个更早的非最终读也改变 1,170 个；
  - 说话人序列改变 1,285 个。
- **OFF vs 参考：** 0。
- **非最终读为什么会变。** 开关只改最终读。但同一批里别的窗口在做最终读，或已经提前分叉，它的输入变了，bf16 MoE 的数值随之变化，贪心解码可能翻转。
- **证伪检查**（`finalpost_batchcheck.py`）。按 ctx0 的确定性调度重建每一步的批次（3,050 个窗口的读数全部对上）：
  - 1,170 个分叉窗口中，首次分叉那一步的同批里都有输入不同的窗口（在做最终读，或已分叉）。
  - 无法解释的个数为 0。
  - 所以没有迹象表明开关泄漏到了非最终读。
- **归因**（`finalpost_attrib.py`）：混合假设，用原打分器对参考做配对 bootstrap。

| 混合 | 窗口数 | all | ov | 1spk | ≤0.5 s 召回 1spk / ov |
|---|---|---|---|---|---|
| 参考 + 仅最终读不同的窗口用 CAND | 1,166 | +0.39 [0.27, 0.54] | +0.19 [0.02, 0.33] | +0.47 [0.31, 0.66] | 0.751 / 0.732 |
| 参考 + 早期读也被扰动的窗口用 CAND | 1,170 | +0.31 [0.08, 0.54] | +0.69 [0.30, 0.97] | +0.14 [−0.17, 0.45] | 0.594 / 0.721 |

- **干净效应。** 第一行只含开关本身的效应：1spk 和短单元召回的提升基本都在这里。
- **扰动窗口。** 第二行既有这些窗口自己最终读的效应，也有批次噪声，分不开。ov 的提升有一部分来自这里。
- **噪声幅度。** §8.5 记录过不同分片间 ov 约 ±0.3 的波动，可作参考。

## 7. 注意事项

- **噪声地板不完整。** 开关关闭的重跑与参考批次组成完全相同，所以逐位相同，测不到开关带来的批次耦合噪声。干净效应应以 §5 第一行为准（下界）。
- **语音提升不显著。** 文本 +0.69 在语音上只剩 +0.10，与种子间约 ±0.8 的噪声同量级。语音的漏译和短单元召回改善与文本同向。
- **训练与推理不一致。** v8 训练时最终读也做了 t − 1.04 s 掩码，从没见过扩展的 P；未经再训练直接生效。若要在训练行里对最终读同样放宽掩码，需另行决定。
- **数据范围。** 只用了 dev。没有读取或评测 RealSI、ACL 60/60、AliMeeting。
