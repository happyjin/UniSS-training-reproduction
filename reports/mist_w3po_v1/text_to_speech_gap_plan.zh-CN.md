## 0. 结论（逐条回答用户的四个问题）

**问题 1：延迟"与 Seamless / Hibiki 同量级"有没有数据支持？只支持"同为秒级"，不支持"相当"（§3）。**

- **最接近文献定义的数**是逐话语的语音 EndOffset（Hibiki 的 End Offset 是逐话语的），按在线协议计算。C0-fp 上：**均值 4.78 s，p50 4.32 s，p90 7.70 s**。
- 文献数字：
  - Hibiki：短音频 2.9 s，长音频 2.7 s；
  - Seamless X→eng：2.79 s；
  - Hibiki-Zero：2.1–2.3 s；
  - 只有 Seamless eng→X（4.64 s）与我们相当。
- **以前引用的"语音 EndOffset p50 2.2 s"低估了延迟**，原因有三：
  1. 它是中位数，而文献（SimulEval）报的是均值；
  2. 它按"窗口×说话人"流计算，参照点是窗口终点，不是话语终点；
  3. talker 的时间线没有按在线窗口检测器对齐：最终读提交的块本应在窗口关闭后 +1.7 s 才能开始，实际却提前播放了。
- **还缺的测量**：
  - 计算感知延迟（CA / RTF）；
  - 质量-延迟曲线；
  - 可比的数据集。文献用的是 CVSS / Fleurs 单说话人朗读语料，我们是 AMI 会议的中文配音。

**问题 2：为什么多说话人的缺口这么大，单说话人却很小？大约 55% 是测量口径造成的；口径对齐后，两者的相对损失相同（§1、§2）。**

- **单说话人"语音不低于文本"的印象来自口径不一致。**
  - "文本 BLEU 18.17 / 11.17"（`FINAL_INFERENCE_CONFIG`）没有做 repo 归一化（这是推断，见 §1.3）；
  - "ASR-BLEU 18.57 / 14.36"是 repo 归一化后的（小写、去标点）；
  - 同一个贪心系统在 repo 口径下的文本 BLEU 是 **21.69 / 16.26**（`MBR_RESULT`）。
  - 所以单说话人真实的缺口是 **−3.12 / −1.90，相对 −14% / −12%**。
- **多说话人的官方 tcpBLEU 用 raw 13a**：区分大小写，标点也算 token。Whisper 的大小写和标点习惯与 Thinker 的文本不同，这一项就让语音少了 3.2 BLEU。
- **体现缺口的指标**是 raw 口径下的 tcpASR-BLEU 对 tcpBLEU：all 28.00 → 19.91（−8.09），ov 22.87 → 12.97（−9.90）。

**分解（C0-fp，两种子平均，all / ov / 1spk）：**

| # | 来源 | all | ov | 1spk | 性质 |
|---|---|---|---|---|---|
| — | 官方缺口（raw） | **−8.09** | **−9.90** | −6.68 | — |
| 1 | 表面形式（大小写、标点；两侧做 repo 归一化） | −3.18 | −3.66 | −2.42 | 测量 |
| 2 | 打分粒度（语音按流整条打分；把 ASR 词投影回各段后消除） | −1.38 | −2.30 | −0.90 | 测量 |
| 3 | **真实的 TTS→ASR 保真度损失**（repo 口径，段级） | **−3.53** | **−3.94** | **−3.36** | 系统 |
| 3a | 　其中：删词（talker 没说出来，或说得听不清） | −1.84 | −1.75 | −1.79 | 系统 |
| 3b | 　其中：替换 | −1.45 | −1.44 | −1.54 | 系统 |
| 3c | 　其中：插入（包括原来的"幻听长尾"） | ≈0（repo）；raw 口径下 −0.61 | — | — | 主要是测量，见 4 |
| 4 | "幻听长尾" | raw −1.29；repo −0.19 | raw −2.33；repo −0.31 | — | **测量**：这是评测时把 Whisper 按 8 条一批解码造成的标点循环（"……"），不是 TTS 多说了话，也不是 Whisper 对单条音频固有的幻听（§2.4）。全部音频按 batch 1 重转写后，raw 口径下 +1.15 / ov +2.17，种子差从 0.70 降到 0.15；repo 口径下只有 +0.05（§5.1） |

- **口径对齐后**（repo 口径、段级），多说话人的损失是 −3.53 / 29.16 = **−12.1%**，与单说话人 zh→en 的 −11.7% 相同；1spk 为 −10.7%。
- **只有 ov 明显更差（−16.7%）。** 这一部分是多说话人特有的，主要由三件事驱动（§2.5）：
  - **碎片化**：每段词数少；
  - **talker 失控块**：一直说到长度保护上限、没有自己收尾的块。在 3 流以上的窗口里，这类块的比例是单流窗口的 7 倍；
  - **语音拖长**。
  - 已经排除的原因：**源语音混合导致的内容串流**（串流词率 2.4–2.8%，低于随机基线的 3.1–3.3%）、不可读符号、填充词、截断、音色提示长度。
- **真实损失大部分是随机采样失败，不是系统性的。**
  - 两个种子的流级 WER 相关系数只有 0.66；
  - 每条流取两个种子中 WER 较低的那个，WER 从 12.7% 降到 5.6%。
  - **用独立 ASR（CTC）在两个种子之间二选一**，repo 口径下语音 all **+1.24**、ov +1.29，raw 口径下 +1.28。这已经超过语音的噪声地板（约 1.1）。

**问题 3：文献检索与方案（§4、§5）。** 下表按"可补齐的上界 × 现实收益 ÷ 成本"排序：

| 线 | 方案 | 目标 | 预期 / 上界 |
|---|---|---|---|
| A | 双口径（raw + repo，另加 Whisper 归一化）；段级语音打分；ASR 按 batch 1 解码；按文献定义报语音延迟 | 测量 | 不改模型，语音 all +5.7（raw→repo 段级）；缺口从 −8.1 降到 −3.5 |
| B1 | talker 的 ASR 一致性 best-of-k，用独立 ASR 打分（`select_k` 已有接口） | 真实损失 3.5 | k=2 实测 +1.2；k=4–8 估计 +1.5–2.0（上界：WER 能减半） |
| B2 | 失控块检测后重采样 | 失控块 | 上界 +0.66 / ov +0.85，现实 +0.3–0.5 |
| B3 | 按说话人掩蔽 talker 的源语音条件 | 多流窗口 | 上界 +2.2，现实 +0.5–1.0。**最有新意**，需要 GPU 小实验验证 |
| B4 | 以 ASR 为奖励、带语速约束的 talker 偏好训练 | 真实损失 | +1–2（参照 Koel-TTS、Seed-TTS RL） |
| C1 | 语速：talker 每秒 2.34 词，源语音 3.20 词，输出时长是源语音的 1.43 倍 | EndOffset | 最后一块的时长（均值 2.28 s）是 EndOffset 最大的一项，预计 −0.5 至 −1.0 s |
| C2 | 窗口关闭检测的 +1.7 s | EndOffset | 55% 的话语的最后一块受影响，均值 0.93 s，预计 −0.4 至 −0.9 s |

**问题 4：§6 的"新方向"有没有对上这些问题？部分对上了，需要重排（§6）。**
- **方向 1（MS-SimulEval）**：测量部分比原先估计的更大，有 4.6 BLEU，不是 3.1。原先漏了大小写和标点（3.2），还把"幻听长尾"错归给了 Whisper / TTS，其实是批处理伪差。**仍是第一位。**
- **方向 2（"说你写的"）**：对上真实损失，但应该先做最便宜的 B1、B2。
- **方向 4（输出时间线调度）**：对上延迟，但必须和语速控制（C1）一起做。输出总时长是源语音的 1.43 倍，单靠调度消不掉积压。
- **方向 3、5（覆盖、说话人路由注意力）**：只作用于文本，对语音缺口没有直接作用。
- **新增 B3（按说话人掩蔽源条件）**：它是多说话人特有损失唯一直接的抓手。

## 1. 指标定义与两种设置的口径差异

### 1.1 多说话人（本项目，`reports/gstar_si_v8/overlap_score.py`）

| 项 | 文本 tcpBLEU | 语音 tcpASR-BLEU |
|---|---|---|
| 假设 | Thinker 的文本段（说话人、源时间 start_s / end_s、提交时刻 write_ms） | 每个"窗口×说话人"流的 speech-only wav（talker 各块拼接、去掉静音），由 Whisper 转写（`asr_hyp.py`）。整条流作为**一个段**：时间取该说话人各段的 min(start) 到 max(end)，write_ms 取最大值 |
| ASR | — | whisper-large-v3，fp16，transformers pipeline，language=english，greedy。>2 s 的短音频**按 8 条一批**解码（带 attention mask），≤2 s 的单条解码。可疑重试只在"每秒词数 >12 且总词数 >64"时触发（`evaluation/asr_transcribe.py`） |
| 参考 | AMI 英文原文（英式拼写，数字写成单词，有 "yeah" 等回应词），按会议取话语；同一说话人间隔 <1 s 的话语合成一个单元 | 同左 |
| 归一化 | **无**：区分大小写，标点保留，13a 把标点切成独立 token | **无**（同左）。两侧规则相同，但 Whisper 的标点和大小写习惯与 Thinker 不同，所以这条规则在效果上并不对称 |
| 说话人 / 时间 | 每个会议用 chrF 匈牙利匹配说话人；collar 2 s；一段与同一说话人的两个以上单元各重叠 ≥20% 时，按时间比例把词切开 | 同左。但合并后的一整条流跨度长，更容易被按时间比例切错 |
| 计分 | 13a corpus BLEU；插入作为 (hyp, "") 计入 | 同左 |
| 区域 | 单元时长中 ≥20% 与其他说话人的标注语音重叠，记为 ov，否则 1spk。三个区域各自算 corpus BLEU（不可加） | 同左 |

### 1.2 单说话人（旧报告，RealSI 777，只引用）

| 项 | 文本 BLEU | ASR-BLEU |
|---|---|---|
| 假设 | 整句译文 | "placed"音频：按时间线放置、含等待的整句，由 Whisper-large-v3 转写（中文用 Paraformer） |
| 归一化 | `FINAL_INFERENCE_CONFIG` 表中的 18.17 / 11.17 **不是 repo 口径**（推断，见 §1.3）；`MBR_RESULT` 明确用 repo 口径，同一系统为 21.69 / 16.26 | **repo**（`evaluation/text_metrics.normalize_for_bleu`）：英文做 NFKC、小写、去掉除撇号外的标点；中文转简体、去标点、按字切分。然后 sacreBLEU 13a / zh。另有 raw 口径 16.03 / 11.74 |
| 粒度 | 整句一个单元，没有说话人匹配，也没有时间约束 | 同左 |

### 1.3 能解释"单说话人没有缺口、多说话人有缺口"的口径差异

| # | 差异 | 实测作用 |
|---|---|---|
| D1 | **归一化。** 单说话人：ASR 侧用 repo 归一化，文本侧（18.17 / 11.17）没有。多说话人：两侧都是 raw | 单说话人：同一系统在 repo 口径下文本是 21.69 / 16.26，**真实缺口 −3.12 / −1.90**。多说话人：仅表面形式一项就 −3.18 / ov −3.66 |
| D2 | **粒度。** 单说话人整句计分；多说话人语音按"窗口×说话人"整条流计分，再按时间比例切分 | −1.38 / ov −2.30（ASR 投影回段之后） |
| D3 | **ASR 的批处理。** 多说话人中 >2 s 的音频 8 条一批解码 | 产生标点或词的循环，即"幻听长尾"（§2.4） |
| D4 | **音频长度。** 多说话人流很短：34% 的流 ≤4 个词，22% 只有 1–2 个词；单说话人是整句 | 1–2 词的流 WER 27%，>32 词的流 10% |
| D5 | **参考的写法。** AMI 用英式拼写、数字写成单词；Whisper 用美式拼写和阿拉伯数字 | 9.8% 的替换在 Whisper 归一化下相等（colour/color、nineties/90s、fifty/50）。Whisper 归一化让文本和语音各 +2.6，对缺口几乎没有影响 |
| D6 | **talker 的条件。** 多说话人时，源语音是整个窗口的混合，块也更碎；单说话人是干净的单人源 | 见 §2.5 |

"18.17 / 11.17 不是 repo 口径"的依据：
- 同一系统（dpo_base 贪心，ASR-BLEU 18.57 / 14.36），`MBR_RESULT` 在 repo 口径下给出 21.69 / 16.26；
- 两者相差 3.5 / 5.1，与 raw 对 repo 在 ASR 侧约 2.5 分的差距同向，且 zh→en（英文输出，标点计分）差得更多；
- 计算 18.17 / 11.17 的脚本没有保留。**这是推断**，写进论文前，应在旧输出上用两种口径各重算一次文本 BLEU（RealSI 只读旧输出，不跑模型）。这需要用户批准。

**同一个打分器里，文本和 ASR 输出的归一化方式相同吗？** 相同，都不做归一化。但正因为这样，raw 口径惩罚的是两个来源之间不同的书写习惯：
- Whisper 输出 "So..." 时，13a 切出 4 个 token；
- Thinker 学的是 AMI 的风格，写成 "So."。

## 2. 用数据分解真实的 TTS→ASR 损失

各个"补回"操作都是上界：把该类流或该类词换回 talker 的输入文本。表中数字是 C0-fp 两种子平均，v8+finalpost 结论一致，见 `fp_s{1,2}.json`。

### 2.1 三种口径、四种粒度（all / ov / 1spk）

| 假设 | raw（官方） | repo（单说话人口径） | Whisper 归一化（Seamless / Hibiki 口径） |
|---|---|---|---|
| 文本，段级（= tcpBLEU） | 28.00 / 22.87 / 30.26 | 29.16 / 23.63 / 31.42 | 31.72 / 26.00 / 34.09 |
| 文本，按流合并 | 26.12 / 19.59 / 29.13 | 27.50 / 20.62 / 30.42 | 29.92 / 22.76 / 32.99 |
| 语音，按流（= tcpASR-BLEU） | 19.91 / 12.97 / 23.58 | 24.25 / 17.39 / 27.16 | 26.86 / 19.62 / 29.96 |
| **语音，段级**（ASR 词投影回段） | 21.16 / 14.93 / 24.27 | **25.63 / 19.69 / 28.06** | 28.41 / 22.27 / 30.96 |
| v8+fp 文本，段级 | 27.75 / 22.82 / 29.93 | 28.78 / 23.59 / 30.90 | 31.26 / 25.81 / 33.51 |
| v8+fp 语音，按流 | 19.17 / 13.96 / 21.48 | 23.80 / 17.21 / 26.61 | 26.37 / 19.31 / 29.41 |
| v8+fp 语音，段级 | 20.07 / 15.60 / 22.02 | 25.17 / 19.58 / 27.48 | 27.91 / 21.96 / 30.40 |

**段级投影的做法。**
- 把 ASR 的词与 talker 自己的输入文本做 Levenshtein 对齐。比较键用 repo 归一化后的词。
- 每个 ASR 词继承它所对齐的输入词所属的段。插入词跟随前一个词所在的段。
- 全程**不看参考**。
- 自检：用 talker 输入文本投影回自身，结果与 tcpBLEU 逐位相同（`text_seg_selfproj`）。

| 语音（基线） | 24.25 | 17.39 | 27.16 |

| + 表面形式 | 27.50（repo 口径下为 0） | — | — |

- 19.91 → 去插入 20.52（+0.61）→ 补删词 20.58（+0.06）→ 换回替换词 23.49（+2.91）→ 表面形式 26.12（**+2.63**）；

| 多流窗口（≥2 条流）的流 | 3,619 | 69.5% | 12–18% | **+2.20** | **+3.13** | 多说话人特有，见 §2.5 |
| 单流窗口的流 | 1,618 | 30.5% | **7.3–8.3%** | +0.83 | 0.00 | — |
| ov 流（流跨度内 ≥20% 有两人以上同时说话） | 1,919 | 29.7% | 18–19% | +0.87 | **+2.69** | — |
| 由 ≥2 段合并成的流 | 2,807 | 77.7% | — | +2.44 | — | 合并本身不是损失来源，见 §2.5 |

**音色提示的长度。** 97% 的流有 ≥6 s 的因果提示，按长度分箱没有单调趋势，排除。

**语速与保真度。** 按"每词语音秒数"（spt）分箱：

| spt（秒 / 词） | 占词 | WER |
|---|---|---|
| < 0.4 | 57% | 6.7–7.4% |
| 0.4–0.6 | 30% | 15.7% |
| ≥ 0.6 | 12.5% | **34%** |

**拖长的语音是失败的症状，不是"说得清楚"。** 这对延迟方案 C1 很关键：加快语速不一定损害保真度。

**两个种子的一致性**（`best_of_seeds2_c0fp.json`）：
- 流级 WER 的 Pearson 相关 0.66；
- 两种子 WER 都 > 0.5 的流只承担 11% 的错误，只有一个种子 > 0.5 的流承担 42%；
- 每条流取两种子 WER 的较小值，WER 从 12.7% 降到 **5.6%**。
- **真实损失多半是一次采样的失败，换一次采样就能好。**

### 2.4 "幻听长尾"的来源：评测流水线的批处理伪差

用第二个独立 ASR 区分来源：wav2vec2-large-960h-lv60-self，greedy CTC，没有语言模型，所以无法"续写"它没听到的内容。这也是 StreamSpeech 计算 ASR-BLEU 时用的英文模型。在 CPU 上转写了两种子全部 10,474 条音频。

| | 尾部流（种子 1 / 种子 2） | 其余流 |
|---|---|---|
| 条数 | 194 / 188 | 5,043 / 5,049 |
| Whisper 词数 / 输入词数 | **2.12 / 2.13** | 0.94 / 0.93 |
| CTC 词数 / 输入词数 | **0.62 / 0.70** | 0.93 / 0.93 |
| 只有 Whisper 写多（CTC ≤ 1.2×） | **183 / 183（94% / 97%）** | — |
| 两个 ASR 都写多（CTC > 1.5×，TTS 真的多说） | 6 / 2 | — |

**所以尾部不是 TTS 多说了话。**

再用 batch 1 单条解码重新转写尾部音频：先在 CPU 上跑了前 51 条，GPU 上的全量见 §5 A3。
- 51 条里，Whisper 词数 / 输入词数为 **0.91**，原评测结果是 2.79。
- 例子："Yiiiight…………"（原评测）对 "Yikes."（batch 1）；"and the pain…………" 对 "and the pen"。
- 加上 Whisper 论文的回退启发式（温度回退、压缩比、无语音阈值）后，51 条中只有 3 条与单条贪心解码不同。

**结论。**
- 尾部主要来自两件事：
  1. 评测脚本把 >2 s 的音频 8 条一批解码，padding 让解码器陷入 "." 或词的循环；
  2. raw 口径下，"……" 被 13a 切成多个 token 计分。
- 它们分别对应论文里常见的 Whisper 幻听（Careless Whisper 2402.08021；非语音诱发幻听 2501.11378）的两个机制：**解码设置**，以及**非语音或低可懂度片段**（尾部流的 spt 中位数 1.04 s / 词，其余为 0.48）。
- 尾部流里的输入词，只有 33–43% 被两个 ASR 都听到（其余流是 79%）：**这些片段本身的可懂度就低**。

### 2.5 多说话人特有的损失：碎片化、失控块、语音拖长（`strata_c0fp.json`）

流级 WER（两种子合计）按"每段词数"分层，再比较窗口内的流数：

| 每段词数 | 1 流 | 2 流 | 3 流以上 | 去掉失控块后：1 / 2 / 3+ |
|---|---|---|---|---|
| ≤ 2 | 25.0% | 28.0% | 26.7% | 24.7 / 23.8 / 24.6 |
| 2–5 | 13.4% | 16.6% | 20.2% | 11.8 / 14.4 / 14.7 |
| 5–10 | 7.9% | 9.9% | 14.5% | 6.5 / 8.1 / 9.7 |
| > 10 | 4.1% | 7.5% | 8.5% | 3.9 / 5.8 / 7.4 |

| | 1 流 | 2 流 | 3 流以上 |
|---|---|---|---|
| 含失控块的流 | **1.1%** | 5.0% | **8.1%** |
| spt 中位数（秒 / 词） | 0.41 | 0.51 | 0.54 |

加权最小二乘（流级 WER）：

| 因子 | 系数 |
|---|---|
| 失控块 | +0.47 |
| log(每段词数) | −0.067 |
| ov 流 | +0.026 |
| 2 流 / 3 流以上（控制以上各项后） | +0.002 / +0.009 |

**解读。**
1. **碎片化是最大的因素。** 每段 ≤2 个词时，WER 约 25%；>10 个词时为 4–8%。多流窗口里各说话人的段更短。
2. **失控块集中在多流窗口。** 控制其他因素后，"流数"本身的效应几乎为零。也就是说，多流窗口损失更大，是因为段更碎、失控更多、语音更拖，而不是流数本身。
3. **一个可检验的机制假设：talker 的源条件是整个窗口的混合语音。**
   - 现状（`si_infer_cont.py`）：同一窗口各说话人的 `src/*.wav` 逐字节相同，都是窗口混合音；talker 每块都会读到截至该块的源 GLM token。
   - 在多人说话的窗口里，"源上应该对齐到哪里"是模糊的，这可能导致不收尾和拖长。
   - **但没有词汇层面的串流**：错误词出现在同窗口其他流输入里的比例，Whisper 为 2.4–2.8%，CTC 为 2.5%；随机换成另一个会议的窗口作基线，比例是 3.1–3.3% / 2.7–2.8%。
   - 这个假设需要 B3 的 GPU 小实验来验证。
4. **"把同一说话人的几段合成一条 TTS 流"本身不伤保真度。**
   - talker 已经在一个序列里续写前面各块，有上下文；
   - 在长度 ≥9 词的流里，段数多的流 WER 更高（1 段 6.8%，2 段 9.2%，3 段以上 13.3%），但这是每段词数变少的结果；
   - 它造成的是打分粒度伪差（§2.1），A2 可以消除。

### 2.6 语义指标（tcpSemER 的翻译版；需要用户批准才能进入正式指标）

做法与 Tawara et al.（arXiv 2603.22709，Eq. 2）相同：
- 在我们的 tcp 对齐单元对上计算；
- 用 all-MiniLM-L12-v2 的平均池化余弦；
- 每对的误差：参考为空时取 |H|，假设为空时取 |R|，否则取 (1 − cos)·|R|；
- 总和除以参考词数。**越低越好。**

| | 文本段级 | 文本按流 | 语音按流 | 语音段级 |
|---|---|---|---|---|
| C0-fp all | 0.290 | 0.327 | 0.382 | 0.349 |
| C0-fp ov / 1spk | 0.408 / 0.236 | 0.485 / 0.256 | 0.546 / 0.307 | 0.475 / 0.292 |
| v8+fp all | 0.307 | 0.344 | 0.390 | 0.359 |

**文本 → 语音（段级）的语义误差增加 +0.059，相对 +20%。** 对照其他口径的相对降幅：

| 口径 | 段级相对降幅 |
|---|---|
| raw BLEU | −24% |
| repo BLEU | −12% |

**按 Tawara 的可加分解**（E^ν / N_ref；ov 单元占参考词的 31%）：
- 文本：ov 0.127 + 1spk 0.163。**ov 占误差的 44%，而只占参考词的 31%**，与该文"重叠段占少数、错误占多数"的发现同向。
- 语音段级：0.148 + 0.200。从文本到语音增加的误差里，1spk 占 2/3。

**结论。** 表面形式和数字写法在 BLEU 里占了将近一半的缺口，语义指标不受它们影响。剩下的真实损失在语义上也看得到，并不只是表面差异。

### 3.4 还缺的测量

1. **单流计时的 CA 延迟和 RTF。** 现在 Thinker 以 batch 16 解码，talker 按轮批处理，给不出 CA。需要单流、逐读计时：Thinker 每读的耗时、talker 每块首包耗时、vocoder 耗时。
2. **质量-延迟曲线**（方向 6）。至少要扫窗口关闭检测的时延、talker 语速档位、读步长三项。
3. **可比的数据集。**
   - 单说话人 SimulS2ST 常用的测试集是 RealSI 和 CVSS。RealSI 是本项目的测试集，跑它需要用户批准。
   - 本机有 CVSS-T zh→en 测试集（`/opt/dlami/nvme/jasonleeeli/CVSS/canonical_16k/cvss_t_zh_en_test`），SimulS2ST-Omni 报过它的离线 ASR-BLEU（25.18）。它不在项目规定的测试专用集之列，可以作单说话人的可比集，用来测 Offset 和 CA。
   - 是否使用由用户决定。
4. 逐话语 Offset 应该用词级时间：语音一侧用 Whisper 词时间戳或 MFA，与 Hibiki 一致。现在用的是块的边界，偏保守（偏大）的程度不超过一个块内的尾部静音。

## 5. 方案

**硬规则不变。** ASR-BLEU 与文本 tcpBLEU 都不能降。协议改动后：
- 旧口径一律照报；
- 参考系统（v8 参考、finalpost、C0-fp）要在新口径下重测；
- 噪声地板（种子差、MDE）要在新口径下重新估计。

### A. 只改测量（不改模型）

**结论。**
1. **raw 口径下，batch 1 让语音 all +1.15、ov +2.17，并让种子差从 0.70 降到 ≤0.15。** "幻听长尾"在 raw 口径下就是这一项。
2. **repo 口径下 batch 1 几乎不起作用**（+0.05）：去掉标点之后，"……"循环本来就不计分。所以 A1（归一化）已经包含了 A3 在 BLEU 上的效果。
3. **batch 1 并不更"干净"。** 它多出一些词级插入：按 repo 词计，插入率从 2.0% 升到 4.3%，WER 从 12.7% 升到 14.9%。官方流水线会把可疑的超长输出改成单条重试或拒绝，这一步替它挡掉了一部分。回退启发式的作用很小。
4. **建议的协议。**
   - 主口径用 repo 归一化，对标点循环免疫；
   - ASR 一律按 batch 1 解码（或修好 padding），把它当作卫生措施；
   - 同时报插入率；
   - raw 口径照报，但注明它对 ASR 批处理敏感，而且种子差约 0.7（ov）。
5. **噪声地板。** batch 1 + raw 时种子差 ≤0.15；repo 口径下 ≤0.2。语音闸门的 MDE 可以从约 1.1 重新估计。两个种子只能给出粗估，正式估计要用会议级自助法。

## 7. 局限

- 所有"补回"都是**上界**：把 talker 的输入文本当作理想语音的转写。
- "18.17 / 11.17 不是 repo 口径"是推断，没有重算（RealSI 是测试集）。
- CTC 模型在这批 TTS 语音上的 WER 是 Whisper 的 2 倍，只用于"词数是否虚高"和"选择器"，**不作为评测 ASR**。
- 串流检验只检了词面；语义层面的串流没有检。
- 延迟用块的边界，没有用词级时间；也没有 CA。
- 第一次运行时，`speech_gap_decomp` 的等待条件写错了，以为进程已结束，又重复启动了一次。重复的那批（`r2_*` 前缀）已按 PID 停止，留下的部分文件没有删除。CPU 上的 `whisper_guard_check` 只跑完 51 条尾部音频就停了（太慢），由 GPU 的 `whisper_b1` 取代。`ctc_compare_c0fp_*.json` 与 `best_of_seeds_c0fp.json` 是第一版：talker 输入用的是 `translated_text`，块与块之间没有空格，会多算错误。以 `*2_*` 版本为准；第一版保留，没有删除。
