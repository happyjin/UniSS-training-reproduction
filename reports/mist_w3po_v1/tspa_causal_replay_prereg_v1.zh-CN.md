# TS-PA（不加新输入）CPU 因果回放：预登记 v1

- 写于 2026-11-16 傍晚，**早于任何回放数字**。用户已批准做这一步。
- 这是看过 P1 / P2（`tspa_precheck_results_v1.zh-CN.md`）之后才形成的新假设，**照实标为事后假设**。
- 只用 CPU，只用 train / dev 数据；测试集、AliMeeting、ACL、RealSI 都不碰。
- 一个设置，不扫参。

## 问题

TS-PA 在训练目标里加入空隙（断粮）代价，Talker 的输入不变：仍然只有积压 token、文本和历史。用这样的 Talker 做因果推理，能实现多少停顿下降？

对照是同样做因果模仿的 PL-EM，也就是现在 PA Talker 的训练目标。两边都是"用同一组因果特征去模仿各自的 CRF 目标"，**唯一的差别是目标里有没有空隙项**。

## 两个设置

| | Zh→En | En→Zh |
|---|---|---|
| 拟合集 | train16 Zh→En 候选（`train16_crf_v2p_s3000_finalpost_c2g06`），全部会议 | train16 En→Zh 候选，按会议名排序后**奇偶两折**：拟合一折，回放另一折，两个方向都做，结果合并 |
| 回放集 | dev5 Zh→En 候选（`plcrf_dev5_cands`，留出会议） | 另一折 |

- 拟合时，λ\*（PL-EM）和 (λ, κ)（TS-PA）**只在拟合集上**求解，方法与 P1 相同：预算 = 规则路径 − 0.3 s，空隙目标 = 0.75 × PL-EM。

## 模仿目标（与现在 PA 的训练配方相同）

- 块 n 的目标是 q(c | b_n = 规则路径的积压状态)，用 `Stream.conditional` 计算，PL-EM 和 TS-PA 各算一份。
- 这与 `talker_rows` 的 plem 行构造相同。没有引入积压边缘化，因为那是另一项改动。

## 因果策略（条件 logit）

`π(c | ctx) ∝ exp(θ·φ(c, ctx))`，块内对候选做 softmax，只用 Talker 推理时能看到的信息。

- **上下文**：
  - 积压 token 对应的秒数，b = 0.5 × min(7, ⌊backlog_ms / 500⌋)，与 si_infer 的分档相同；
  - log W_n；
  - 句末标志；
  - 是否为流里的第一块。
- **候选特征**：
  - x1 = 每单位时长（D_c / W_n，秒）；
  - x2 = 是否为快两档的候选；
  - x3 = CTC f；
  - x4 = ℓ̄。
- **φ（共 12 维）**：x1、x2、x3、x4，以及 x1、x2 分别与 b、句末、log W、首块相乘。
- **拟合**：最大化 Σ_n Σ_c q(c) log π(c)，L2 系数 1e-3，用 scipy L-BFGS。

## 回放（精确期望，不抽样）

- 在回放集的每条流上，对积压状态分布做精确前向：`α_{n+1}(s′) = Σ_{s,c: next(s,c)=s′} α_n(s) · π₂(c | s)`。
- **π₂ 是 π 加上 CTC 二选一**（模拟 MIST 推理时的"采 2 个、CTC 取优"）：
  `π₂(c) = π(c) · [π(c) + 2·Σ_{f(c′)<f(c)} π(c′) + Σ_{c′≠c, f(c′)=f(c)} π(c′)]`。
- 累计以下量的期望：延迟代理 Σl/ΣW、停顿（全部、句内）/分钟、CTC f、ℓ̄、语速。
- 按会议汇总，用 2,000 次会议 bootstrap 估计句内停顿相对变化的 95% 区间。

## GO 条件

Zh→En、En→Zh 各自满足下面三条，才进入 GPU 阶段的登记：

1. 句内停顿/分钟：回放 TS-PA ≤ 0.85 × 回放 PL-EM（降 ≥ 15%）；
2. 延迟代理：回放 TS-PA ≤ 回放 PL-EM + 0.10 s；
3. CTC f：回放 TS-PA ≥ 回放 PL-EM − 0.05。

**另外报告**（不参与判定）：
- 用 P1 方式算的回放集 oracle（已知到达时刻）上界；
- 不加二选一时的回放；
- 策略对目标的交叉熵；
- bootstrap 区间。

## 正确性检查

精确前向得到的期望，在小流上（≤ 4 块、≤ 3 个候选）与逐路径枚举（路径概率 = Π π₂）一致，容差 1e-9。测试不过就不运行。
