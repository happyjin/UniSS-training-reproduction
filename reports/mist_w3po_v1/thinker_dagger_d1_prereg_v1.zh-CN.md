## 0. 为什么做，以及与协调者原话的一处差别

T1 和 T2 的 dev5 诊断显示，主要的失败是暴露偏差：
- 错过第一次该写的读之后就一直等（A 类）；
- 写一段后停住，追不回来（B 类）。T2 停住后平均连续空读 8.8 次，A′ 只有 2.0 次。
- 但只要在写，写得是及时的。

T4 用随机扰动的逾期状态（DART）补这一点。D1 改成在**模型自己的轨迹**上取状态（DAgger, Ross et al., AISTATS 2011）：用 T4 或 T5 训好的模型在 train 窗口上 roll-in，在它实际走到的状态上，用专家动作"立刻写出全部已到期的块"打标签，再训一轮。

**与协调者原话的差别：roll-in 只让模型决定"何时写"，写的内容固定为参考条目。** 协调者原话是"自己解码"，即自由生成文本。这一点在登记时就写明。理由：
1. 自由生成的轨迹要用一个"覆盖判定"把模型的历史映射回参考条目，才能定义"哪些块已到期而还没写"。
2. 本项目 11-10 已对这个判定做过两次预登记检查（`crf_dynamic_oracle_precheck.zh-CN.md` §6、§8），人工一致率都不到 0.95：v2 不到 0.948，v3 不到 0.949，v1 只有 0.865。两次都按规则 STOP。主要原因是这个任务的输出里有大量误译、拷贝和循环。
3. 自由解码的 DAgger 会再撞到同一个问题。
4. 只控制时机、内容取参考，状态可以精确定义：已写集合是每个说话人 κ 顺序的前缀。专家动作也可以精确定义。而 T1/T2 的失败恰恰出在时机这一侧。
5. 代价：D1 不处理"内容错了导致的停住"。这一点作为局限照实写。

这种"策略 roll-in、参考内容、专家补写"的做法，与同传的模仿学习工作同属一类，例如 Zheng et al., EMNLP 2019 的 oracle 动作训练，以及 Arthur et al., EACL 2021 的耦合策略模仿学习。这两条引文凭记忆写出，未逐篇核对，正式写作前要核对。

## 1. 定义（唯一设置）

### 1.1 学习者与数据

- **学习者 π₁**：第 2 节规则选出的 T4 或 T5 的 step_03000。不作任何改动，与它的 dev 解码用同一套合并方式。
- **数据**：与所选基线完全相同的训练数据和训练计划。
  - T4：`sched_piece_t0_g1000_v1`，3000 步的 `plan_steps`（seed 20261109，约 64 个读行 / 步），1.0 s 读；
  - T5：`sched_t5_pieces4_w10_v1`，同上。

### 1.2 roll-in（GPU，只做前向，可以叠卡）

对计划里每个用到的训练窗口，按读的顺序 r = 0..R−1 模拟学习者：
- **状态**：已写集合 H_r，是每个说话人 κ 顺序的前缀，初值为空。
- **第 r 读**：一次教师强制前向。
  - 输入与训练行完全相同：音频到 t_r；说话人后验到 t_r − 1.04 s（最终读按 `--final-read-full-post 1`）；历史为 κ(H_{r−1})；输出部分强制为"剩余全部条目按 κ 顺序"。
  - 不扰动后验。
- **决策**：在输出部分的每个条目边界 j = 0, 1, 2, …（j = 0 是本读输出的开头），取全词表的 argmax，这就是贪心解码的停止规则。
  - argmax 是 `<wait>`：本读停在第 j 个边界，H_r = H_{r−1} ∪ 输出的前 j 个条目；
  - 否则继续写下一个条目（内容取参考，按 κ 顺序）；
  - 最终读屏蔽 `<wait>`，写完全部条目。
- **输出**：学习者的写出读 ρ̃_i，即条目 i 被写出的那一读。它在每个说话人内单调，可以早于标签 e_i（"超前"），也可以晚于它（"逾期"）。
- 每个窗口串行 R 次前向，窗口之间并行。实现参照 T0 一致数的逐读前向（`t0_agree_labels.py`），加上历史。CPU 测试要证明它与在小模型上逐边界的字面贪心循环完全一致。

### 1.3 D1 行（专家标签，与 T4 的增广目标相同）

- 在学习者轨迹的每一读 r 上，若逾期集合 O_r = {i ∉ H_{r−1} : e_i ≤ r − 1} 非空，加一行：
  - 历史 = κ(H_{r−1})（学习者的实际历史）；
  - 目标 = W*_r = {i ∉ H_{r−1} : e_i ≤ r}，按 κ 顺序，然后接 e_r（非最终读为 `<wait>`，最终读为 `<eos>`）；
  - 输入与同读的正常行相同。
  - 这就是 `dart_aug.aug_requests` 把扰动读换成 ρ̃ 后的行。允许 ρ̃ < e，是新加的、只做加法的入口，有测试。
- **超前状态**（历史里有还没到期的条目，但没有逾期）不加行，只报告数量。
- **权重**：与 DART 行相同，每个目标 token 为 h_t / D，结束 token 为 1 / D，D 是基线的归一化常数。D1 行只进 pass 2，不影响后验和 λ。
- **每步的量**：每个计划中的（步，窗口）都加上该窗口的全部 D1 行。若某一步的 D1 行超过该步正常读行的 25%，用 `numpy.random.default_rng([20261112, 步])` 均匀抽取，保留到 25%。抽取后的行数和被抽掉的比例都报告。

### 1.4 训练（DAgger 的数据聚合）

- π₂ 用 D₁ ∪ D₂ 从头训练（Ross et al. 的原始形式）：
  - D₁ = 所选基线自己的训练目标与数据，包括它的隐写时 CRF 正常行、λ 对偶和 DART 行，原样不变；
  - D₂ = 第 1.3 节的 D1 行。
- **与基线只差一处**：多了 D₂。
- **配方与基线相同**：
  - v8 merged + 新 LoRA r32 / α64 + 投影器 + 259 个新 token 行；
  - 3000 步，学习率 1e-4，warm-up 50，余弦到 1e-5；AdamW (0.9, 0.95)，梯度裁剪 1.0；扰动 p 0.2；
  - `--final-read-full-post 1`、τ 0.5、`--tok-budget 32000`、`--mem-cap-gib 120`，以及 fast-moe / prefetch / feat-per-row；
  - 4 卡，独占一个槽位。
- 只评 step_03000。
- D2 行的读入方式：一个新的清单 `crf/d1_<base>_w10_v1/rollin.jsonl`，每行是（窗口 id，ρ̃）。训练器按清单生成 D1 行，并核对窗口与计划一致。入口是 `train_crf_sft --dart <基线清单> --d1 <roll-in 清单>`，新加，只做加法，默认路径逐位不变。

## 3. D1 什么时候跑，和 J1 谁先

**"停住"的定义**：对 T4、T5 中每个有速查结果的模型，看它的 dev5 速查输出（`go.json` 和 `stall_diag.txt`；后者第 1 行是该模型，第 2 行是同一批窗口上的 A′）。满足下面任一条，就算这个模型"停住"：
- S1：最终读写出的词占比 > 49.7%（A′ dev5 的值，即速查的第 1 条 GO 线没过）；
- S2：≥ 6 s 窗口里 A 类（最终读之前一个词都没写）占比 ≥ 28%（规则 C 的线）；
- S3：B 类停住后的平均空读数（`B_mean_silent_reads`）≥ 同一批窗口上 A′ 的 2 倍。两者都是 1.0 s 读，可以直接比较。

**"碎或质量掉"的定义**：对同样的模型，满足下面任一条就算：
- 文本那条 GO 线没过（文本 all < 28.16 或 ov < 23.92）；
- talker 段的平均词数（`go.json` 的 `talker_blocks.segment.mean`）< 4.0。

**规则**（`crf/j1_decide.py` 一并输出 `logs/mist_w3po_v1/d1/schedule.json`）：
1. **D1 是否跑**：T4、T5 中有任何一个"停住"，或者两个都不 GO，就跑；否则不跑（没有暴露偏差的证据，D1 没有对象）。
2. **谁先**：有任何"停住"时，D1 先占第一个空出来的 4 卡槽，J1 用下一个；否则 J1 先。只是"碎或质量掉"而没有"停住"时，也是 J1 先。
3. 两个都跑时，各占一个 4 卡槽。
4. D1 的 roll-in 是前向作业，可以叠在评测卡上（每卡 ≤ 135 GiB），不叠在训练卡上，不占 4 卡槽。

## 4. 预检

### 4.1 CPU（代码完成后，训练之前）

- **R1 roll-in 正确性**：在小模型、真实窗口上，"一次前向取各边界 argmax"的批量实现，与逐边界做一次前向的字面贪心循环得到的 ρ̃ 完全相同；最终读写完全部条目；ρ̃ 在每个说话人内单调。
- **R2 D1 行**：ρ̃ ≥ e 时，D1 行与 `dart_aug.aug_requests`（delay = ρ̃ − e）逐行相同；允许 ρ̃ < e 时，历史与目标满足 H ∪ W* = {e ≤ r} ∪ H，并且都是 κ 前缀；行只出现在有逾期条目的读上。
- **R3 训练器**：`--d1` 不给时，训练与基线逐位相同（行、loss、梯度）；给了时，基线的行不变，loss 等于基线的 loss 加上 D1 行的 loss，`--prefetch 1` 与 0 逐位相同。
- 任何一项不过：不跑 GPU，修好后重做。

### 4.2 roll-in 之后（训练之前）

- **R4 有没有对象**：计划窗口里，学习者至少有一次逾期（O_r 非空）的窗口占比 ≥ 5%。
  - 不到 5%：学习者在 train 上几乎不落后，D1 没有可学的东西。**不训练**，报告给协调者。
- **附带报告**：
  - 逾期读的占比、逾期读数的分布；
  - 超前条目的占比；
  - 学习者 ρ̃ 与标签 e 的差（中位数、p90）；
  - 每步 D1 行数（抽取前和抽取后）；
  - 在训练窗口上的停顿分类（A / B / C，用 ρ̃ 代替 read_log）。

## 5. 速查与门槛（与 J1 完全相同）

- **dev5 速查 GO 线**（`thinker_joint_crf_prereg_v1` §6，全部满足才 GO）：
  1. 最终读写出的词占比 ≤ 49.7%；
  2. 文本 LAAL < 3.64 s；
  3. 文本 all ≥ 28.16 且 ov ≥ 23.92；
  4. dev5 的 CPU 语音延迟代理（`joint_speech_proxy`，读级块）低于 A′。
- **附带报告**：talker 块大小、停顿分类（同时对比所选基线）。
- **dev 全集**（GO 才做）：评测链与 J1 §7 相同，语音链用读级块输入，逐段输入作为消融；两个 TTS 种子。
  - 门槛对 A′：文本 all、ov、语音 ≥ A′ − 0.2，且 P(差 ≤ 0) < 0.95；
  - 语音 LAAL 目标 ≤ 3.85 s；
  - "D1 有效" = 门槛过并且达到目标。
- **与基线的配对比较**（基线有 dev 全集解码时）：基线的解码也用读级块重跑语音链。解读规则同 T2 对 T1：D1 的语音 LAAL 不比基线高 0.1 s 以上，且文本 all 与语音的配对差都 ≥ 0，才说 D1 更好。
