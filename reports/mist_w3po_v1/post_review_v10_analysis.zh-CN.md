# v10 审稿后补充分析（M5 延迟约定 + M2 合成语音）

- 时间：2026-11-15 布拉格时间 02:00–03:00（CET）。
- 范围：只用已有测试输出做分析；没有新的解码、训练，也没有新的测试集选择。
- 对应审稿意见：`paper/gstar_si_v10/review_v10.md` 的 M5 和 M2。
- 系统（测试集 ami / ali / en，每个都有两个 TTS 种子，`<run>` 和 `<run>_tts2`）：
  - B：严格基线，`jtest_b{s}_joint_v8h6k_20261113T073658Z_s06000__t1c`
  - E2：B + rl + PL-EM，`jtest_b{s}_joint_v8h6k_20261113T073658Z_s06000__rlplem`
  - M0：方法，δ=0，`jtest_m{s}_joint_v2p_20261113T120415Z_s03500__rlplem`
  - M：最终系统，δ=−1，`jtest_m{s}_joint_v2p_20261113T120415Z_s03500_wbzm1em1__rlplem`
- 结果文件：`eval_outputs/mist_w3po_v1/joint/post_review_v10/analysis_v1.json`。所有数字都在这个文件里，保留 4 位小数。
- 没有改任何 `.tex`，也没有改 `make_tables_v10.py`。

## 方法

### 延迟

- 工具：`experiments/mist_w3po_v1/evaluation/lat_units_dump.py`（新增）。
  - 它把 `speech_latency_lit` 复制一份再打补丁，仓库里的原工具不动。参数和 `joint_lib.sh` / `e2_baseline_plem.sh` 的 `lat()` 完全一样：chunk 协议窗口，ami / ali 走 `on_refset`，en 走 `en2zh_lat`。
  - perword：原公式不变，就是论文的逐词 speech LAAL。
  - blockstart：把块内每个词的时刻都记为该块在线播放的起点。这和 v10 块起点表（scratchpad `m2laal.py` 的 online 模式）是同一行补丁。
  - 另外按单元导出数值（`<out>.units.jsonl`），用来做按会议的 bootstrap。
- 复现检查：
  - perword 的 24 个 json 与已存的 `lat_chunk_<run>.json` 逐字段相同。
  - blockstart 中 B / M0 的 12 个 json 与 `paper/gstar_si_v10/generated/v10_inputs/t*_online.json` 逐字段相同。
  - 两种约定下 EndOffset / StartOffset 完全一致。
- 统计方法：
  - 区域取 all 单元。点估计是两个种子单元均值的平均，与论文一致。
  - 配对检验：
    - 每个会议先算单元值之和与单元数，两个种子取平均（与 gate_2seed 合并 BLEU 统计量的做法相同）。
    - 统计量 = 总和 / 总数。
    - 置信区间来自 10,000 次会议 bootstrap，rng 种子 20261114，与 make_tables_v10 相同。
    - p 值是对 2^M 种翻转精确枚举的双侧符号翻转检验：AMI M = 16，最小 p = 3.1e−5；Ali M = 20，最小 p = 1.9e−6。
  - 本报告没有做 Holm 校正；如需校正，与论文 E3 相同，按族处理即可。

### 合成语音

- 输入：`talker/results.jsonl`，统计所有块。
- 计量单位：
  - Zh→En 按英文词计，用 `talker_block_pauses.n_words`。
  - En→Zh 按汉字 / 拉丁词计，用 `zh_units.n_units`。
- 指标：
  - 语速 = 单位数 / 合成语音秒数。
  - 每窗口语音秒数：只统计有输出流的窗口。
  - load：取延迟 json 里的值。
- 配对检验方法同上。

### UTMOS / SIM

- 用现成工具 `experiments/mist_w3po_v1/talker/talker_quality.py`，原样运行，环境是 qwen3omni。
- 模型：
  - UTMOS：`utmos22_strong`，即 SpeechMOS 本地 hub 副本。
  - SIM：WavLM-base-plus-SV，比较对象是 talker 的声音提示，不是原说话人的真实录音。
- 范围：只跑种子 1，数据是全部长度 ≥ 0.5 s 的流，没有抽样。
- 运行环境：单卡（1 号卡），显存约 1.7 GB × 2 个进程。
- 配对差：方法同 `pmc_listen_compare.paired`，即同一条流配对，求和后取比值，再按会议 bootstrap。有两处不同：
  - 会议定义为窗口 id 中 `_on_` 之前的部分。原定义取第一个 `_` 之前的部分，会把 AliMeeting 同一房间的会议合并。
  - 重采样次数改为 10,000。

### 块与停顿

- 用现成工具 `talker_block_pauses.py` 统计。
- “句中停顿”指停顿前的块不以 `. ? !` 结尾，用来近似“突兀停顿”。这个定义只对英文输出有意义，所以 en（中文输出）只报总停顿数。

## 结论

### M5：延迟约定

1. **块起点（常规）LAAL 下，M 相对 B 几乎没有优势。** M − B 的差值和置信区间：
   - AMI：−0.02 s，[−0.04, +0.01]，p = 0.23，不显著。
   - AliMeeting：−0.08 s，[−0.15, −0.02]，p = 0.018。
   - En→Zh：−0.02 s，[−0.04, +0.00]，p = 0.098，不显著。
   
   论文的逐词 LAAL 下，同一组差值是 −0.33 / −0.37 / −0.16 s，CI 都远离 0。可见逐词约定下的收益大部分来自“块说得更快”，与审稿意见 M5 的判断一致。在测试集上，δ=−1 的块起点数字现在补齐了。
2. **E2（B + PL）在两种约定下都比 B 早，而且显著。**
   - 块起点 LAAL：−0.09 / −0.33 / −0.11 s。
   - StartOffset：−0.03 / −0.13 / −0.04 s。
   
   原因是播放更快，队列积压更少，后续块因此更早开始播放。也就是说，块起点约定下 M 那一点点优势来自播放层，不来自写入对齐。
3. **M 比 E2 晚，所有约定都一样。**
   - 块起点、逐词、EndOffset、StartOffset、文本 LAAL 的差值都在 +0.07 到 +0.28 s 之间，CI 全部大于 0。
   - 这些差值和文本 LAAL 的差值（+0.08 / +0.24 / +0.09）基本相等。原因是 δ=−1 之后 M 的文本仍比基线 Thinker 写得晚，这部分直接传到了语音端。
4. **EndOffset 改善很大，CI 远离 0。**
   - M − B：−0.89 / −1.12 / −0.50 s。
   - E2 − B：−0.96 / −1.34 / −0.58 s。
   
   这主要是最后一块变短、队列等待变少的结果，和语速提高一致（见 M2）。
5. **M0（δ=0）在块起点 LAAL 下比 B 晚 +0.27 / +0.73 / +0.26 s**，复现了论文 Table 10 的数字。δ=−1 把这个差缩小了 −0.29 / −0.82 / −0.28 s。
6. **没有覆盖的部分：**
   - τ′ 分布：单元导出里没有逐词序列，需要在补丁里再导出一项。
   - 强制对齐的词时间戳。
   - 计算感知延迟 / RTF。

### M2：合成语音

1. **语速提高约 45%。**
   - Zh→En：B 每秒 2.40 词，E2 / M 为 3.49–3.56 词，约每分钟 210 词。
   - En→Zh：B 每秒 3.90 字，E2 / M 为 5.02–5.04 字。
   
   M − B 的语速差 CI：AMI [+1.03, +1.13]，Ali [+1.05, +1.19]，En [+1.08, +1.16]。同样的文本，合成语音总时长少 31–33%，load 从 1.37 / 1.56 / 1.28 降到 0.95 / 1.06 / 0.99。M 和 E2 之间语速差别很小，不超过 0.04。可见这部分变化完全来自播放层（PL-EM + 队列速率），与 Thinker 无关。
2. **UTMOS 没有因为语速加快而下降，反而略升。** 数据为种子 1、全部流：
   - 同一条流配对的差：M − B 为 +0.12 / +0.19 / +0.12，E2 − B 为 +0.13 / +0.20 / +0.13，CI 都大于 0。
   - M − E2 在 −0.01 左右，AMI 和 Ali 不显著。
   - 注意 AMI 上 UTMOS 的绝对值偏低（约 1.8–1.9），这是流级纯语音 wav 的特点，旧系统也是这个水平。UTMOS 也不直接衡量语速是否自然。
3. **说话人相似度（SIM）基本不变。** B / E2 / M 分别为 0.827 / 0.827 / 0.828（AMI）、0.873 / 0.873 / 0.873（Ali）、0.833 / 0.831 / 0.831（En）。比较对象是 talker 的声音提示，不是原说话人。
4. **E2 / M 的停顿更多。**
   - 每分钟 ≥ 0.5 s 的停顿：AMI 3.3 → 8.3（E2）/ 7.7（M），Ali 4.3 → 11.8 / 11.0，En 4.6 → 9.3 / 8.8。
   - 句中停顿（近似“突兀停顿”）：AMI 0.8 → 2.8 / 2.3，Ali 0.8 → 3.8 / 3.1。
   - 原因：说得快，在等下一块的空档里就留下了静音。这是 UTMOS 看不到的听感风险，审稿要求的人工听测仍有必要做。
   - E2 的强制截断块占比反而下降：Zh→En 从 1.2–1.5% 降到 0.01–0.03%，En→Zh 从 0.2% 降到 0。
