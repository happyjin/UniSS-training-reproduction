# T4 / T5 早写为什么掉文本分：CPU 诊断与文献核查（2026-11-12 布拉格 02:20–03:15）

- **执行者**：方法设计执行者 v2。只用 CPU，没有用 GPU；只用 dev（dev5 的 1092 个窗口），没有用任何测试集，没有用 COMET / MetricX。
- **对象**：
  - A′：`decode/plcrf_dev5_aprule`；
  - T4：`decode/dev5_t4_s3000`；
  - T5：`decode/dev5_t5_s3000`；
  - 三者窗口相同。
- **代码**：`experiments/mist_w3po_v1/evaluation/early_commit_diag.py`。它沿用 `metric_headroom` 对 `overlap_score.score()` 的复现，逐项复现官方 tcpBLEU（28.36 / 27.39 / 27.46），脚本里有断言检查。输出 `eval_outputs/mist_w3po_v1/crf/t45_quality_diag_v1.json`。
- 标注"探索"的数字来自 scratch 里的一次性脚本，没有进仓库，只作旁证。

## 1. 掉的是精度，不是召回

| | 文本 all / ov | BP（all） | sys / ref 长度 | p1 / p2 / p3 / p4 | 不匹配 token | 段数 | 每段词数 |
|---|---|---|---|---|---|---|---|
| A′ | 28.36 / 24.12 | 0.950 | 22867 / 24049 | 62.7 / 36.8 / 23.2 / 14.9 | 8528 | 3818 | 5.38 |
| T4 | 27.39 / 22.34 | 0.991 | 23828 / 24049 | 59.4 / 34.1 / 21.3 / 13.6 | 9675 | 7430 | 2.79 |
| T5 | 27.46 / 22.11 | 1.000 | 24158 / 24049 | 58.8 / 33.9 / 21.2 / 13.5 | 9948 | 7579 | 2.79 |

- T5 多写了 5.6% 的 token，匹配上的反而少约 130 个。BP 从 0.95 升到 1.0，抵掉一部分，但 p1–p4 都下降。
- **多出的不匹配 token**（T5 − A′ = +1420，探索）：
  - 逗号 +452；
  - 一个死循环窗口约 +300；
  - 句号 +75；
  - 其余是一长串功能词，比如 the、a、is、So、I、think。
- 逗号整体上是加分的：去掉所有块末逗号后，A′ 降 1.15，T5 降 1.57（见第 2 节）。所以它们不是可以去掉的原因。

## 2. 单独可去掉的原因：加起来 ≤ 0.25

都是推理期的编辑，同时作用在 A′ 和候选上，再重新打分。表中是 all / ov。

| 编辑 | A′ | T4 | T5 | T5 与 A′ 的差距（原为 −0.90 / −2.01） |
|---|---|---|---|---|
| 去掉 ≥ 2 词的精确边界复写 | 28.31 / 24.11 | 27.35 / 22.34 | 27.56 / 22.12 | −0.75 / −1.99 |
| 只看文本的循环守卫（周期 ≤ 6 词，重复 ≥ 3 次） | 28.34 / 24.06 | 27.39 / 22.35 | 27.61 / 22.11 | −0.73 / −1.95 |
| 去掉块末逗号 | 27.21 / 22.27 | 25.54 / 20.18 | 25.89 / 20.08 | −1.32 / −2.19 |
| 同一读、同一说话人的段合并后再打分 | 28.32 / 24.08 | 27.22 / 22.06 | 27.37 / 22.09 | −0.95 / −1.99 |
| 漏译 oracle（补齐所有未召回单元） | 30.75 / 28.70 | 29.90 / 28.29 | 29.43 / 26.56 | −1.32 / −2.14 |

- **重复与循环**：
  - T5 有 100 处 ≥ 2 词的边界复写（A′ 29 处），其中 76 处来自同一个窗口 `IB4003_on_0111` 的 "it's looking like" 死循环；
  - 把这个窗口换成 A′ 的输出，all +0.25（探索）；
  - 原有的解码期循环守卫是按 token 周期判断的，碎块之间的时间标签每次都不同，打断了周期，所以这个循环没被拦住。
- **漏译**：
  - T5 在 ov 上掉分不是漏译造成的：补齐后差距不缩小（−2.01 → −2.14）；
  - T4 是：ov 差距从 −1.78 缩到 −0.41，与它 0.178 的 ov 漏译率（A′ 0.131）一致。
- **打分器的分配**：同读合并后分数几乎不变，说明不是碎块在单元分配上的伪影。
- **重排**（探索）：按参考话语的 NIR 分桶，差距并不集中在高 NIR 的话语上。例如 1spk 单元中，NIR = 0 的掉 0.83，NIR > 0.3 的反而 +0.19。
- **说话人串话**（探索）：ov 单元的内容词里，属于对方说话人参考的，A′ 6.5%，T5 8.1%，T4 7.2%。有一点影响，但不大。

## 4. 碎块切口

2/3-gram 精度。单元里的 n-gram 按位置分类：

| | 块内 | 跨块：句末之后 | 跨块：同一读 | 跨块：隔读 | 跨块（句中）合计 | 以功能词结尾的非末块 |
|---|---|---|---|---|---|---|
| A′ | 0.311（34.4k） | 0.310（3.7k） | 0.244（1.0k） | 0.216（0.7k） | 0.230（1.7k） | 11.4% |
| T4 | 0.306（26.1k） | 0.284（4.0k） | 0.240（7.1k） | 0.220（4.5k） | 0.232（11.6k） | 38.2% |
| T5 | 0.305（26.3k） | 0.289（3.9k） | 0.237（4.5k） | 0.229（7.4k） | 0.232（11.9k） | 37.9% |

- 块内精度 T5 与 A′ 几乎一样。差在句中切口：T5 有 11.9k 个跨切口 n-gram，A′ 只有 1.7k，而这些位置的精度只有约 0.23。
- 同一读里的切口与隔读的切口一样差，A′ 自己少量的句中切口也一样差。所以切口的代价来自"在这里切开"本身，与写出时间无关。
- 以功能词结尾的块并不更差（探索：0.253 vs 其余 0.219）。所以问题不是切点选得不好，而是切口太多。
- 被另一说话人插断的切口更差（0.19），但只有 710 个 n-gram（探索）。

## 5. 缺口在哪些窗口

把候选模型某一组窗口的输出换成 A′ 的，看 BLEU 回升多少（all / ov）：

| 窗口组 | 窗口数（T5） | T5 ← A′ | T4 ← A′ |
|---|---|---|---|
| 时长 < 2 s | 220 | +0.03 / 0.00 | +0.01 / −0.01 |
| 2–4 s | 260 | +0.15 / +0.38 | 0.00 / +0.24 |
| 4–6 s | 200 | +0.25 / −0.09 | +0.01 / −0.27 |
| 6–10 s | 192 | +0.15 / +0.11 | 0.00 / −0.26 |
| **≥ 10 s** | 220 | **+0.70 / +1.62** | **+0.97 / +2.06** |
| 输出只有 1 个说话人 | 641 | +0.23 / +0.10 | +0.20 / 0.00 |
| **输出有 ≥ 2 个说话人** | 451 | **+0.82 / +1.92** | **+0.79 / +1.79** |

- T5 的总差是 −0.90 / −2.01，T4 是 −0.97 / −1.78。≥ 10 s 的长窗口占了 T5 缺口的约八成，几乎是 T4 的全部。
- 长窗口里写出次数最多、切口最多，与第 4 节一致。
- 在长窗口内部，单元的位置（前、中、后三分之一）与差距没有一致的关系（探索），看不出错误随写出次数累积的迹象。

## 6. 结论

1. **主因**：早写本身没有错，错在文本被切成了太多小块。
   - 块内质量已与 A′ 相当，缺口来自句中切口（约 0.23 vs 块内约 0.31）和多写的功能词。
   - 缺口集中在长的多说话人窗口。
   - 这是一个粒度问题：同读切口不带来任何延迟收益，却同样付出切口的代价。
2. **次要原因**：
   - 一个逃过循环守卫的死循环窗口（约 +0.25）；
   - T4 在 ov 上的漏译（它 ov 缺口的大部分）；
   - ov 中的说话人串话（+1.6 个点的内容词）。
3. **不是原因**：标点（逗号整体加分）、打分器的单元分配、精确重复（除那个循环外）、重排程度。
4. **推理期修复**：增益都 ≤ +0.15（all），ov 没有变化，不值得占 GPU 去评测，所以任务 4 不登记。
   - 对后续所有碎块模型可能有用的一点：循环守卫应只看文本 token、忽略时间标签。这需要改解码器，留给用户决定。
5. **由此登记的方法**：RC5（`thinker_rc5_prereg_v1.zh-CN.md`）。T5 原样，只合并同读的相邻块：标签路径逐词不变，只去掉同读切口（训练数据里占 43%）。
   - VE1 也针对粒度，但它是固定 merge3、标签随之变晚；RC5 的粒度由证据时刻决定，延迟不变。两者互补。

## 7. 文献核查（只读；一个子代理检索，主要来源都是 arXiv 原文）

与"保留早写、找回质量"直接相关的要点：

- **SimulMask**（EMNLP 2024，2405.10443）：wait-k 越小，输出越长；作者归因于上下文不足时的幻觉。这和这里 BP = 1.0、p1 下降的现象一致。另一条要求是训练状态要与推理状态逐 token 等价。
- **HMT**（ICLR 2023，2303.00257）：与隐写时 CRF 最接近。
  - 把边际化换成 Viterbi，AL 从 3.46 降到 1.77，BLEU 从 29.3 降到 24.0；
  - 去掉 state loss（让每个候选写出时刻都对正确 token 做 CE）掉约 1.5 BLEU；
  - λ_lat 从 1.0 到 1.5 是一个陡坎：AL 3.46 → 2.10，BLEU 29.29 → 26.65。
  - 这说明发射一致项是下一个可以候选的目标改动。本次只能登记一种设置，所以没有用。
- **EAST / EASiST**（Findings ACL 2025，2504.09570；AAAI 2026，2504.11809）：用 LLM 切出语义块，把不足 2 词的块并入下一块，并过滤非单调样本。同一个模型只换训练数据，所有延迟档都 +2 BLEU 以上。支持"粒度要按语义和证据定，不要按固定词数定"。
- **SimulS2ST-Omni**（2607.19810）：轨迹构造与 T5 几乎相同。作者的结论是：数据池的过滤（NIR 分层，刻意保留约 10% 的高重排样本）比采样方式重要得多。
- **Agent-SiMT**（2406.06910）：用 wait-k 前缀对做 SFT 会严重退化（BLEU 1.0 vs 31.3）。发射项不应在源端还没覆盖目标块的配对上训练；T5 的证据标签已经满足这一点。
- **Hibiki**（2502.03382）：上下文对齐（似然跳升）加至少 2 s 余量。作者认为比理想对齐更激进的标签会导致幻觉。
- **Restricted Imitation Learning**（ACL 2019）和 **Seg2Seg**（NeurIPS 2023）：在区间内做边际化（多标签写出），等价于隐写时 CRF 的格。
- **Chen et al. 2021**（伪参考）、**Tailored Reference**：用更单调的参考来减少前瞻。这需要另外生成参考，并且要注意 ASR-BLEU 是按原参考打的。
- **多说话人重叠语音下的提前写出**：没有找到一手文献。DiariST / t-SOT 只有序列化方法，没有延迟分析。
- 都不涉及 QABC（ABC 后验、SDR、按排队调阈值）。
