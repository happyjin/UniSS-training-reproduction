# 鲁棒线 v3：有效 idea 的深入分析（RealSI 为什么掉）与只围绕"噪声鲁棒"的新方案（2026-11-20 21:35 布拉格）

只是分析和方案，**什么都没有启动**。数字都是 Thinker 文本 BLEU 的点估计（论文口径：去标点，t2s，按字切分），不做 bootstrap。
系统：
- B：底座 LA2；
- EW：CoVoST 训练的 ERM-WiSE；
- C：EW + CV-LA；
- UE：UniST 训练的编码器 LoRA（WiSE 0.5）+ CV-LA；
- UW：UniST 训练的文本层 LoRA（WiSE 0.5）+ CV-LA。

## 1. 分析

### 1.1 先排除一个口径陷阱
- 用 sacrebleu 原生 zh 分词（保留标点），EW 在 RealSI 英→中干净上比 B **高 +2.4**；用论文口径（去标点）则**低 −0.76**。
- 也就是说，EW 原生口径下的"提升"大部分来自学会了参考译文的标点习惯。内容上，RealSI 英→中确实掉了。以后一律用论文口径。

### 1.2 干净与带噪的差距（噪声真正伤了多少）

| 测试集 | B | EW（CoVoST） | C（CoVoST + CV-LA） | UE（UniST） | UW（UniST） |
|---|---|---|---|---|---|
| RealSI 中→英：带噪 − 干净 | **−1.65** | −1.74 | −1.54 | **+0.13** | −0.22 |
| RealSI 英→中：带噪 − 干净 | +0.15 | +0.46 | +0.79 | +1.81 | −0.22 |
| OBSI 英→中：id2 − clean | −2.39 | −0.56 | −0.12 | −2.47 | −1.95 |
| OBSI 中→英：id2 − clean | −1.34 | +0.17 | −0.49 | +0.65 | −0.58 |

**发现 A：CoVoST 训练学到的鲁棒性不能迁移到真实语音。**
- 在 OBSI 上（源语音来自开源朗读或对话语料，与 CoVoST 接近），EW / C 几乎消除了噪声差距；
- 在 RealSI 中→英（真实讲座，自发语音）上，差距完全没缩小（−1.65 → −1.74 / −1.54）；
- UniST 训练的 UE / UW（Emilia 自发语音）在 RealSI 中→英上把差距消除了（+0.13 / −0.22）。
- 结论：鲁棒性是"噪声 × 说话风格"的联合分布上的，训练语音的风格决定了学到的鲁棒性能不能迁移。

### 1.3 RealSI 上的提升从哪里来
**发现 B：RealSI 中→英的大部分"提升"与噪声无关，是长度校准。**
- B 在中→英上过度生成，长度比 1.10（干净）、1.13（带噪）；
- EW 把它压到 0.97 / 1.04，1-gram 精度从 50.8 升到 55.3；
- 干净和带噪的提升幅度相同（+2.05 / +1.95），说明不是鲁棒性带来的。

### 1.4 RealSI 英→中为什么掉
**发现 C：适配带来了输出分布的偏移，不同的训练数据偏移方式不同。**
- **CoVoST 版（EW）：** 掉分集中在术语多的录音上：tech −3.2、health −2.6、fin −2.6、law −2.7；口语化的录音反而提升：ent +1.6、art +1.0。窄域朗读数据上的 LoRA 覆盖了大模型的领域知识，与第十三波（训练子集 +13.31，离线 −2.77）的机理相同。WiSE α = 0.5 不足以保护。
- **UniST 版（UE / UW）：** 译文变长（长度比 1.07–1.12），因为 UniST 的合成参考译文偏冗长。另外，UE 在 RealSI health 的一句上出现退化重复（"分子。"重复上百次，生成 755 个字），这一段录音因此 −14.4。
- 可见适配同时学到了两件事：
  1. 我们想要的，对声学干扰的不变性；
  2. 我们不想要的，参考译文的风格和长度，以及覆盖原有知识，甚至带来解码退化。
- 两者纠缠在同一个 LoRA 更新里。训练数据换成 CoVoST 或 UniST，只是换了一种纠缠方式（发现 A 与发现 C 互为镜像）。

### 1.5 CV-LA 在测试上的代价
- D1 增加 0.3–1.3 s，RealSI 中→英带噪最多（2.72 → 4.04 s）；
- dev 上的两个对照已证明它的增益来自晚提交。
- 它不是鲁棒性方法，而是延迟和质量的交换，**建议移出主线**。

## 2. 主线（只有一个 motivation）
> **噪声鲁棒适配会把"对声学干扰的不变性"和"输出分布的偏移"纠缠在一起：** 偏移包括参考译文的风格和长度、领域知识被覆盖、解码退化。
> 有效的鲁棒方法应当只学前者。

**评价三轴：**
1. 真实语音上的噪声差距缩小，看 RealSI 带噪 − 干净；
2. 干净输入不退化，看 RealSI 英→中术语录音、长度比、重复率；
3. 延迟不增加。

下面每个方案都是"当前方法 + 一篇顶会论文的思想"，回答同一个问题：**怎样只学不变性、不学偏移**。训练全部用同一批 UniST 数据。

## 3. 方案

### R1. 抵消风格的任务向量差（当前 ERM-WiSE × Task Arithmetic）★
- **文献：** Editing Models with Task Arithmetic（Ilharco et al., ICLR 2023），任务向量的加减与"否定"。
- **当前方法的问题：** ERM 的 LoRA τ_noisy 同时包含不变性和风格偏移（发现 C）。
- **思路：** 在同一批 UniST 数据、同样的参考译文、同样的步数下，再训练一个只用干净输入的 LoRA τ_clean。两者学到的风格和知识偏移相同（目标一样），差别只在声学条件。于是：
  - τ_rob = τ_noisy − τ_clean，近似只剩"对噪声的适应"；
  - 部署 θ = θ_base + τ_rob。
- **为什么 novel：** Task Arithmetic 用任务向量的差去掉一种行为（例如毒性），我们用"同数据、只差干扰条件"的两个任务向量之差，把干扰分量从目标偏移中分离出来。这是"干扰差分"的任务向量构造，没有看到先例。
- **做法：**
  - τ_noisy 用第十四波已有的 unist LoRA，它的 8 个环境里含干净环境；如果需要严格对称，就另训一个只用带噪环境的版本；
  - 新训一个 τ_clean：同数据、同步数、同种子，只是不加噪；
  - 只用一个设置：系数 1，不扫。
- **成本：** 卡 0–3 训练 τ_clean 约 2.5 h，合并和评测约 40 min。
- **预期检验：** 长度比回到约 1.0，RealSI 术语录音不掉，RealSI 中→英差距保持接近 0。

### R2. 不看译文的不变性适配（当前编码器 LoRA × 语音对比不变性学习）★
- **文献：** wav2vec-Switch（ICASSP 2022）、Robust data2vec（ICASSP 2023）：同一句话的干净版和带噪版在表示空间互为正例，做对比学习；SimCLR 的 InfoNCE 目标。
- **当前方法的问题：** 第十七波的编码器 LoRA 用翻译交叉熵训练，学到了 UniST 的译文风格（训练集里从未被抽到的句子也 +12.49），还出现解码退化。
- **思路：** 只训练音频编码器的 LoRA，目标里完全不含译文：同一条 UniST 音频的干净版和带噪版，编码器输出按帧池化后做 InfoNCE，批内其他句子作负例。大模型冻结，也不看任何参考译文，所以风格和知识偏移从源头上无法产生。
- **不是蒸馏：** 没有教师模型，也没有伪标签；两路是对称的对比学习，同一个编码器同时编码两路。写进预登记，请用户确认。
- **为什么 novel：** 对比式抗噪预训练在 ASR 编码器上有，但在"大模型同传、编码器被冻结大模型消费"的场景里，以"不让适配接触目标分布"为目的的无目标鲁棒适配，没有看到先例。它也是 R1 的另一条路：R1 在参数空间做减法，R2 从目标上切断偏移。
- **做法：** UniST 音频，8 个环境，rank 16（同第十七波），2300 步，温度 0.1，不扫；最后 WiSE 0.5。
- **成本：** 卡 4–5，约 2 h。

### R3. 限定在噪声子空间里的适配（当前编码器 LoRA × SEE/SEEN 子空间 × O-LoRA）★
- **文献：**
  - SEE / SEEN（ACL 2026）：用干净和纯噪声的编码器激活做 SVD，得到与语义方向近正交的噪声子空间；
  - O-LoRA（Wang et al., EMNLP 2023 Findings）：把 LoRA 更新约束在指定的正交子空间里，以避免遗忘。
- **当前方法的问题：**
  - SEEN 免训练、硬投影，我们测过拿它替换输入，失败（K7）；
  - 编码器 LoRA 不受约束，学到了风格。
- **思路：** 用 SEEN 的方法估计每层的噪声子空间 Q（UniST 干净 / 带噪对，加上训练噪声池）。训练编码器 LoRA 时，把每层 LoRA 的输出投影到 Q 上：Δh = Q Qᵀ(BA)x。模型只能在噪声方向上改变表示，语义方向完全不动，也就没有通道去学风格。训练目标仍是翻译交叉熵。
- **为什么 novel：** SEEN 用子空间做免训练的删除；O-LoRA 用正交约束防遗忘。两者结合起来，就是"用测得的噪声子空间来定义可学习的范围"：子空间不再是被删除的对象，而是学习发生的位置。没有看到先例。
- **做法：** 子空间估计约 20 min（GPU，一张卡）；训练同第十七波的设置，只多一个投影。
- **成本：** 卡 6–7，约 2.5 h。

### R4. 由一致性见证决定是否启用鲁棒适配器（当前 CV-LA 的副产品 × LoRA 路由）
- **文献：** Towards Modular LLMs by Building and Reusing a Library of LoRAs（Arrow 路由，Ostapenko et al., ICML 2024）：按输入选择 LoRA，免训练。
- **当前方法的问题：** 适配器在干净输入上也会带来偏移（发现 C）；NCWI 用能量比估计噪声，失败了。
- **思路：** ctrl_pool_base 已证明"原始音频与增强音频的草稿是否一致"能可靠地跟踪噪声。用它作路由器：上一次读两个视角一致，就用底座起草；不一致，就用鲁棒适配器。用 vLLM 多 LoRA 按请求切换，不增加前向。
- **为什么 novel：** 路由信号是"对干扰的不变性"，而不是任务相似度或噪声估计；保证干净输入走原模型，从机制上避免干净退化。
- **做法：** 推理期，只跑 Thinker，约 10 min。可以叠加在 R1–R3 任一个适配器上。
- **说明：** 它仍需要增强视角（两路同批计算），但只用于路由，提交规则仍是 LA2，所以不增加延迟。这和 CV-LA 不同。

### R5. 吸收噪声的声学寄存器（当前编码器适配 × Registers）
- **文献：** Vision Transformers Need Registers（Darcet et al., ICLR 2024），以及免训练寄存器（NeurIPS 2025†）。
- **思路：** 在音频编码器输入前加 8 个可训练的寄存器 token，只训练这些 token，编码器和大模型都冻结。容量很小，只够吸收背景，很难学到风格。
- **novelty：中。** 寄存器用于语音大模型抗噪没有看到先例，但它对"不学偏移"的控制不如 R1–R3 直接。
- **成本：** 约 2 h，可以排在 R2 或 R3 之后。

### 不再放进主线的
- CV-LA、见证代数、保形提交、语速追回：都属于延迟和质量的交换，与"鲁棒性"不是同一个 motivation，留到附录或另一篇文章。
- 带噪前缀训练、参数见证：与主线无关。

## 5. 论文形态
- **标题方向：** "Disentangling Acoustic Invariance from Output Shift in Robust Adaptation of Speech LLMs for Simultaneous Translation"。
- **结构：**
  - 第 1 节的分析是 motivation：口径陷阱、发现 A–C；
  - R1–R3 是同一原则的三种实现：参数空间做减法、目标上切断、子空间约束；
  - R4 是推理期的保护。
- **ICLR：** 有一个清晰、可检验的科学问题（不变性与偏移的纠缠），配三种互相印证的方法，比"组件叠加"更有机会。前提是 R1–R3 中至少一个在 RealSI 上同时做到"差距小且干净不掉"。

## 更正（2026-11-20 22:06 布拉格，只追加）
- **"UniST 版译文变长，因为合成参考偏冗长"不成立，撤回。** 在整个测试集上：
  - UE 的长度比与底座相同：中→英 1.023 对 1.023，英→中 0.945 对 0.928；
  - 超过参考 3 倍长的句子比例也与底座相同：中→英 0.5% 对 0.4%；
  - 合成语音的总时长与 C 相同：中→英 25.7 h，英→中 16.9 h。
- **RealSI 中→英上的真实情况：** 底座本身就偏长（1.10）；CoVoST 训练把它压短到 0.97（CoVoST 人工参考比较简洁）；UniST 训练保持了底座的长度（1.11）。所以是"CoVoST 让译文变短"，而不是"UniST 让译文变长"。发现 B（长度校准）仍然成立，只是归因要改成"CoVoST 的参考风格"。
- **退化重复只有 1 例**（UE，RealSI health_003，1/7896）。它单独让该段录音 −14.4，但不能据此推出 UniST 系统普遍存在重复。
- **测试的 ASR 并不比 C 慢：** C 和 EW 的中→英 ASR 也用了约 38 分钟（20:22 → 21:00）。之前说"C 只用 15–20 分钟"，是把 dev 臂（2012 条）的耗时误当成了测试臂（4143 条）的。
