## 0. 诊断依据

dev5，与 A′ 同一批窗口，用 `score_run` 的同一套单元分配逐项复现了官方分数。

1. **掉的是精度，不是召回。**
   - T5：BP 1.000，p1 58.8 / p4 13.5，sys/ref 为 24158/24049；
   - A′：BP 0.950，p1 62.7 / p4 14.9，sys/ref 为 22867/24049；
   - T5 不匹配的 token 多 1420 个。
2. **块内质量已和 A′ 相当，缺口在切口上。**
   - 块内 2/3-gram 精度：T5 0.305，A′ 0.311；
   - 跨块 n-gram：T5 有 15.8k 个，精度 0.22–0.25；A′ 只有 5.4k 个，大多在句末，精度 0.31。
   - 同一次读写出的两块之间，跨块精度 0.237；隔读写出的 0.229，两者一样差。
3. **整单元在最终读写出的 1spk 单元不掉分**（T5 33.15，A′ 32.64）；有提前写出的单元掉 1.3–1.4。
4. **缺口集中在 ≥ 10 s 的窗口**：把这些窗口换成 A′ 的输出，T5 收回 +0.70 / +1.62，总差为 −0.90 / −2.01。输出里有多个说话人的窗口收回 +0.82 / +1.92。
5. **能单独去掉的原因加起来 ≤ 0.25**：重复与循环 ≤ +0.15，标点为负，打分器的分配为 0，重叠漏译对 T5 不是主因。

**结论**：T5 早写本身没有错，错在把文本切成了太多小块。其中约四成切口两侧在同一次读写出（训练数据里 43%，T5 输出里约 26%），它们不带来任何延迟收益，却带来切口的质量代价。

## 1. 定义（唯一设置）

### 与 T5 完全相同的部分

T5 原样，即预登记 `thinker_crf_t_prereg_v1` 的 T5 节、修订 1 与第 4 条豁免：

- OmniAlign 证据时刻标签：support + 200 ms，不加滞后，按说话人取运行最大值；
- NIR > 0.3 的窗口去掉；
- 1.0 s 读（`read_times(dur, 1000)`）；
- 格模式 t5：h = min(R − 1, max(u, e))；
- 隐写时 CRF：`--objective latent_write --lw-mode t5`，λ 对偶的目标是同一步 T1 子格后验的期望延迟；
- DART：0.5 的窗口，每块 p = 0.3，推迟 k ∈ {1, 2, 3} 读，额外交叉熵行，抽样种子与规则相同；
- 配方：v8 merged + 新 LoRA r32 / α64 + 投影器 + 259 个新 token 行；3000 步；`plan_steps` seed 20261109，约 64 个读行 / 步；学习率 1e-4，warm-up 50，余弦到 1e-5；AdamW (0.9, 0.95)，裁剪 1.0，扰动 p 0.2；`--final-read-full-post 1`；τ 0.5；`--tok-budget 32000`、`--mem-cap-gib 120`，以及 fast-moe / prefetch / feat-per-row；4 卡。只评 step_03000。

### 唯一的变化：块的粒度（`--granularity pieces4rc`，只做加法）

1. 先按 T5 的 pieces4 规则切块，即标点块内贪心切成 ≤ 4 词的块。
2. 每块的标签读 e 与 T5 相同，即块末词的 τ 所在的读（1.0 s 网格）。
3. 同一话语里相邻、且 e 相同的块合成一块。块里没有英文词的，并入下一块；话语最后一块没有英文词的，并入上一块。
4. 合并后的块：
   - 文本是原块文本用空格连接；
   - 源端区间取第一块的起点到最后一块的终点，仍是首尾相接的对齐区间；
   - 时间 token 按 80 ms 网格取，规则与 T5 第 8 条相同；
   - u 按合并后的块重新计算，规则与 T5 第 9 条相同，即最后一块的比例终点 + 1.0 s 之后的第一个读。

### 由构造保证、并在预检中核对的性质

- 每个词的标签读不变，所以标签路径的文本延迟与 T5 相同。
- 文本切口只去掉同读切口；不同读之间的切口一个不动。

### 随之而来的差别

照实写明，都由合并直接带来，不另作选择：

- 合并块的格上界取最后一块的 u，前面几块原来的上界因此可能变宽；
- DART 以合并块为单位扰动；
- 训练序列里的标签 token 变少。

## 5. 解读规则（在结果之前定下）

- **RC5 GO 而 T5 NOT GO**：支持"切口太多是 T5 掉分的主因"，而且延迟没有让步。
- **RC5 与 T5 的文本差 < 0.3**（all 和 ov 都是）：同读切口不是主因，要么 RC5 粗化得不够，要么原因不在切口。这时看 VE1（merge3）的结果再定下一步。
- **RC5 的文本 LAAL 比 T5 高 0.3 s 以上**：说明合并改变了写出时机，不能只归因于切口；照实报告。

**v1 → v2 的说明**：
- 第一次预检（`rc5_precheck_v1.json`）里，`test_train_crf_sft` 在无 GPU 环境下 import transformers 失败。原因是 `torch.accelerator.current_accelerator()` 没有设备时报错，`test_dart_aug` 自己打了补丁，这个测试没打。

**R2 中 lat_heur 那一句为什么没过**（登记时的设定错误，照实写明）：
- `lat_heur` 是逐 token 的"读时刻 − 所在块的源端终点"。合并后，前面几块的词用的是合并块（即最后一块）的终点，所以它会因构造而变小，与写出时机无关。
- 登记这一句的本意是"标签路径不变"，这由同一行里逐词标签读的检查直接检验，结果是 99.9984%。
- 训练中隐写时 CRF 的延迟势用同一种块终点定义，λ 对偶的目标（同一步 T1 子格的期望）也在同一定义下算，所以前后一致。
