- 论文 v11 的生成表：`paper/gstar_si_v11/generated/`；
- 析因实验：`eval_outputs/mist_w3po_v1/joint/v11f_analysis/factorial_test_v1.json`；

## 0. 结论摘要

1. **项目里有两个 CRF，结论完全不同。**
   - **PA（Talker 侧播放对齐 CRF，论文主方法）**：相对基线 B 有效，而且幅度大。ASR-BLEU +2.28 / +0.58 / +1.35，Holm 校正后全部显著；锁定测试（AliMeeting Eval，8 场）复现。
     - 但相对**同语速的规则层**（R3′），CRF 训练出的 Talker 只多 +0.11 / +0.05 / +0.23，只有 AliMeeting 显著，延迟差 ≤ 0.003 s。
     - 所以能证明的是"播放层有效，CRF 自动学出了正确的语速和选择策略"；不能证明"CRF 学到了规则做不到的东西"。只有积压最重的 AliMeeting 例外。
   - **WA（Thinker 侧写出对齐 CRF）**：无效。
     - 文本和语音都没有显著提升；听到的时间更晚（LAAL_block +0.07 / +0.09 / +0.24 s）；在 AliMeeting 上三项全差。
     - 同一偏置族下，WA 的质量–延迟曲线没有超出 deadline 基线，低延迟段更差。
2. **比基线差的地方**有四类（§2）：
   - 停顿翻倍以上：所有集，最主要的代价；
   - En→Zh 上学到的 Talker 不比规则好；
   - WA 在 AliMeeting 上更差、整体向晚漂移；
   - 语音起点几乎不动。
   每一类都能在数据里找到具体机制。
3. **与 HMT 的差别**（§3–§5）：
   - **相同之处**：HMT 的 HMM 损失（−log 边缘似然）与我们 WA 的 EM 式自训练，在 τ = 1 时梯度相同。两者都是"用目标序列的似然决定何时写"。
   - **我们缺的**：HMT 有三样东西我们 WA 没有——
     1. 一直开着、绝对尺度的延迟损失；
     2. 让每个状态都学会正确输出的 state loss；
     3. 独立于语言模型输出的读/写置信头。
   - **格的位置**：HMT 的下界很激进（wait-L），候选宽度 K = 4–8；我们的格只能"按时或晚一读"（K = 2，下界就是 deadline）。
   - **HMT 自己也有漂移**：去掉延迟损失后同样向晚漂移，而且掉出自己的前沿（λ_latency = 0：AL 3.46 → 6.66，BLEU 30.07，低于 AL 6.43 时的 30.90）。这正是我们观察到的现象。
4. **HMT 相对自己的 baseline 并非"无条件全面有效"**（§4）：
   - 它的对照是**固定的 wait-k**，以及其他学习式策略。
   - 它的收益依赖延迟损失、state loss、边缘化这三件事，缺任何一件都明显变差：取最大路径时崩到第一个状态，BLEU 24.02；去掉 state loss 掉 1.55 BLEU。
   - 它也依赖 L、K 的选择：同等延迟下不同 (L, K) 能差 1.9 BLEU。
   - 而我们的基线是"词对齐 + 1 s"的 deadline，本身就是自适应的、接近 oracle 的时机，留给隐变量策略的空间小得多。
5. **是否要 Thinker 与 Talker 联合训练一个 CRF**（§6）：**不建议**。
   - J1 和 J1-v2 两次预检都显示：在同样的语音期望下，语音时间线的势相对一个简单延迟预算没有额外作用。
   - 加了播放层以后，排队只剩 0.14 s，联合优化的对象基本不存在了。
   - 剩下的延迟主要是 Thinker 的模型滞后（约 0.7 s）、检测器等待（约 0.4–0.7 s）和最后一块的时长。这些都不需要联合 CRF。
6. **建议**（§7）：
   - ACL 版本不再加训练，按上面的结论如实写，并把 WA 负结果与 HMT 的 λ_latency = 0 结果联系起来。
   - 如果要让 Thinker 侧 CRF 成为真正的贡献，最值得做的一次实验是 **WA-H**（HMT 式改造），只跑一个设置。
   - Talker 侧最值得做的是在势里加"空隙代价"，正面处理停顿。

## 1. 当前两个 CRF 的数学形式与 loss

### 1.1 PA：Talker 侧播放对齐 CRF（论文 §3.5，附录 app:plem）

- **状态**：每条说话人流的块 i = 1..I，状态是 (h_i, c_i)。
  - h_i 是积压（块 i 要等同流前面的语音多久），取 80 ms 网格，上限 8 s；
  - c_i ∈ C_i 是 Talker 的 8 个候选（4 个用规则语速，4 个再快两档）。
- **转移**：确定性的积压递推，ν_i 是块的释放时刻，D(c) 是候选时长：
  `h_{i+1} = g_i(h_i, c_i) = ⌈max(0, ν_i + h_i + D(c_i) − ν_{i+1})⌉`
- **势**：
  `φ_i(h, c) = 0.5·ℓ̄(c) + 5·f(c) − λ·L_i(h, c)`，其中 `L_i = W_i·h + (W_i+1)/2·D(c)`。
  - ℓ̄：Talker 的平均 token 对数概率；
  - f：独立 wav2vec2 CTC 每字符损失的负值（上限 10）；
  - L_i：块内词的总延迟（词·秒）。
  - 权重 0.5 和 5 是事先固定的，没有消融。
- **λ 的来源（后验正则）**：
  `min_q KL(q‖q_0)  s.t.  E_q[Σ L_i] / Σ W_i ≤ b`
  - b 是规则路径自身的延迟减 0.3 s，用二分法求 λ\*；
  - 结果 Zh→En λ\* = 0.50，En→Zh λ\* = 0.70。
- **训练（只做一轮，不是迭代 EM）**：
  - 在规则路径到达的积压 h_i^rule 处计算候选权重：
    `w_{i,c} ∝ exp(φ_i(h_i^rule, c) + ←m_{i+1}(g_i(h_i^rule, c)))`
    其中 ←m 是后向消息，带来后面各块的排队代价；权重 < 0.01 的候选丢弃。
  - Talker 的 loss：
    `Σ w_{i,c}·CE(codes_c | 文本, 声音, 积压 token) + 1.0·CE(语速 token, 后验语速边缘) + 0.5·KL(base ‖ PA)`
    语速共 35 档；KL 只算在语义码和结束符上。
  - Zh→En 用 15 个 AMI 训练会议、19,077 块、111,487 行；
  - Zh→En 的 Talker 是在 WA Thinker 的文本上训练的（论文 §4 已写明）。
- **推理**：
  - 推理时不跑 CRF。PA Talker 以积压 token 为条件采样 2 个候选，用 CTC 取较好的一个。
  - 再加上读级合并（rl），合起来就是播放层。

**本质**：这是"带前瞻排队代价的 best-of-8 选择"，经后验加权蒸馏进 Talker。它更接近奖励加权回归，而不是 HMT 那样在线学习一个隐变量策略。

### 1.2 WA：Thinker 侧写出对齐 CRF（论文 §6，附录 app:crf）

- **状态（写出计划）**：每次读 r（每 1 s 一次）对应已写出的块集合 A_r 和说话人顺序 o_r。格的约束是：
  `{j : r(j) ≤ r−1} ⊆ A_r ⊆ {j : r(j) ≤ r}`
  也就是每个块 j 只能在它的到期读 r(j) 写出，或者晚一读。**换成 HMT 的说法：下界 L = deadline，K = 2，只能推迟。**
- **发射和转移合在一起**：
  `ψ_r = log p_θ(Y_r η_r | E^(r), κ(A_{r−1}))`
  - η_r 是 `<wait>`（最后一读是 eos）。策略（是否写）就是同一个语言模型在 `<wait>` 上的概率，没有独立的策略头。
  - κ 是规范序列化：历史只依赖集合，所以链可以精确分解。
- **后验**：`q_τ(z) ∝ exp(τ Σ_r ψ_r)`，τ = 0.5，float64 前向–后向，不剪枝。
- **M 步**：
  `L_W = −(1/Ω) Σ_e q_τ(e) · log_ω p_θ(Y_r^o η_r | ·)`
  - 每步用当前 θ 重算后验，即对回火后验做 EM 式自训练；
  - 从 deadline 模型出发，新 LoRA，训练 3,500 步。
- **延迟控制**：
  - 主系统训练时没有延迟项。推理时在 wait logit 上加常数偏置 δ_w = −1，在 dev5 上选出。
  - 另一个对照是 E 步预算：`q_μ ∝ exp(τΣψ − μ·Lat(z))`，每个窗口取 μ 使 `E_{q_μ}[Lat] = 0.5 · E_{q_0}[Lat]`。这是相对当前模型的预算。

## 2. 能否证明 CRF 有效？哪里有效、哪里更差

### 2.1 有效的地方：播放层相对 B（测试集）

| | AMI Zh→En | AMI En→Zh | AliMeeting |
|---|---|---|---|
| ASR-BLEU，B → MIST | 18.07 → 20.35 | 31.65 → 32.23 | 16.73 → 18.08 |
| 差（Holm） | +2.28\* | +0.58\* | +1.35\* |
| LAAL_block (s) | −0.09 | −0.11 | −0.33 |
| EndOffset (s) | −0.96 | −0.58 | −1.34 |
| 第二识别器（去循环后） | +1.32\* | +3.74\*（只看符号） | +0.93\* |
| COMET（语音） | +2.58\* | +0.34\* | +1.47\* |
| UTMOS | 1.80 → 1.94 | 3.25 → 3.40 | 3.48 → 3.72 |

- 锁定测试（AliMeeting Eval 8 场，之前从未用过）：ASR-BLEU +2.23 [0.75, 3.37]，LAAL_block −0.37 s，EndOffset −1.43 s，三项 Holm p 都是 0.023（8 场能得到的最小值）。
- **这一层的有效性是可靠的**：显著、换识别器和 COMET 都成立、在新会议上复现。

### 2.2 CRF 本身的贡献：析因实验（全部在 B 的文本上）

| 行 | 内容 | ASR-BLEU Z→E / E→Z / Ali | LAAL_block | 语速 (w/s, AMI) | 停顿 (/min, AMI) |
|---|---|---|---|---|---|
| R0 | B | 18.07 / 31.64 / 16.73 | 3.12 / 2.54 / 3.28 | 2.40 | 3.3 |
| R1 | + 读级合并 | 18.32 / 31.66 / 16.61 | 3.09 / 2.50 / 3.16 | 2.46 | 3.5 |
| R2 | + 积压语速规则 | 19.88 / 31.91 / 17.48 | 3.04 / 2.45 / 3.00 | 3.20 | 6.8 |
| R3 | + CTC 二选一 | 20.27 / 32.26 / 17.81 | 3.04 / 2.45 / 2.99 | 3.21 | 6.9 |
| R3′ | R3，语速对齐 | 20.24 / 32.17 / 17.85 | 3.03 / 2.43 / 2.94 | 3.38 | 7.7 |
| R4 | R2 + PA Talker（1 个样本） | 20.17 / 31.93 / 17.82 | 3.03 / 2.43 / 2.95 | 3.48 | 8.2 |
| R5 | MIST（R4 + 二选一） | 20.35 / 32.23 / 18.08 | 3.03 / 2.43 / 2.95 | 3.49 | 8.3 |

配对差（ASR-BLEU；R5−R3′ 是事先登记的检验，用 p_Holm；其余是探索性检验，给未校正的 sign-flip p）：

| 对比 | 含义 | Z→E | E→Z | Ali |
|---|---|---|---|---|
| R2−R1 | 积压语速规则 | +1.55 | +0.24 | +0.80 |
| R4−R2 | 学到的 Talker vs 规则（都是 1 个样本） | **+0.29** (p 0.002) | +0.02 (0.82) | **+0.33** (0.001) |
| R5−R3 | 同上，都加二选一 | +0.07 (0.48) | −0.03 (0.29) | **+0.27** (<0.001) |
| R5−R3′ | 登记检验：语速对齐的规则 | +0.11 (p_Holm 0.90) | +0.05 (0.90) | **+0.23** (0.007) |
| R5−R4 | 在 PA 上再加二选一 | +0.18 | +0.30 | +0.27 |

**解读**：
1. 收益的大头来自"按积压加快语速"（R2−R1），这是规则就能做到的。
2. 单样本时，学到的 Talker 比规则好约 0.3（AMI Zh→En、AliMeeting）。但两边都加上 CTC 二选一之后，AMI 上的差距消失了。
   原因在 CRF 的势里：势是 `0.5·ℓ̄ + 5·f_CTC − λL`，CTC 保真度的权重最大。PA Talker 蒸馏得到的主要是"选 CTC 好的候选"和"在积压时说快"。这两样在推理时都有便宜的替代：CTC 二选一和积压语速规则。所以规则加二选一能复现大部分收益。
3. CRF 独有的东西，是用后向消息把后续块的排队代价带进当前块的选择（前瞻）。这只有在积压长、排队链长的地方才有价值。
   - AliMeeting 的语音负载最高：合成语音时长与源语音时长之比 B 为 1.56，AMI Zh→En 为 1.37，En→Zh 为 1.28；排队等待 B 为 1.33 s，另外两个集是 0.65 / 0.54 s。
   - 正好只有 AliMeeting 上学到的 Talker 显著优于规则（+0.23 到 +0.33）。
4. **因此**：能证明"CRF 训练的播放层有效"，以及"在积压重的场景下，CRF 的前瞻有可测的额外价值（AliMeeting）"。不能证明"CRF 在所有场景都优于手工规则"。论文 v11 的保底写法与这一点一致。

### 2.3 比基线差的地方及原因

#### (a) 停顿翻倍以上：所有集，最主要的代价

| | AMI Zh→En | AMI En→Zh | AliMeeting | AliMeeting Eval |
|---|---|---|---|---|
| ≥ 0.5 s 停顿/分钟，B → MIST | 3.3 → 8.3 | 4.6 → 9.4 | 4.4 → 11.8 | 4.3 → 11.1 |
| 语速，B → MIST | 2.40 → 3.49 w/s | 3.90 → 5.04 字/s | 2.40 → 3.56 w/s | |
| 排队等待，B → B+PA (s) | 0.65 → 0.14 | 0.54 → 0.14 | 1.33 → 0.33 | |

**机制**（数据链条）：
1. Thinker 每 1 s 读一次，文本是一段一段到的。
2. PA 学会了说快（+45% / +29% / +48%），同样的文本少用 23–48% 的时间，排队几乎被清空（0.14 s）。
3. 排队空了以后，Talker 说完当前块就要等下一块文本，空隙就成了停顿。说话越快越早"断粮"，停顿越多：R2 → R3′ → R5 的语速与停顿同步上升（6.8 → 7.7 → 8.3）。
4. CRF 的目标只有词延迟 L_i，没有任何项衡量空隙：一个块说得再快也不会受罚，反而因为 L_i 变小而受奖励。所以停顿是目标函数里没有的代价，不是训练失败。

**PA-F 的教训**：PA-F 在 CRF 里加了"说话时长预算"，停顿只少了 6–9%（8.3 → 7.6，11.8 → 11.0），却在 AliMeeting 上降低 ASR-BLEU（−0.13 [−0.24, −0.01]），En→Zh dev 也没过门槛。它约束的是说话总时长，对所有块一视同仁，包括积压时本该说快的块，所以伤了质量。对停顿真正有针对性的是"空隙代价"（见 §7 C1）。

UTMOS 反而升高（约 +0.13 到 +0.2），所以 UTMOS 抓不到停顿。这一点论文已经写明。

#### (b) En→Zh：学到的 Talker 不比规则好

- R4−R2 +0.02，R5−R3 −0.03，R5−R3′ +0.05，全都不显著。整个播放层也只 +0.58。
- **原因**：
  - En→Zh 的积压最轻：负载 1.28，排队 0.54 s。中文合成语音相对英文源很紧凑，规则加速以后排队几乎没了，前瞻没有用武之地。
  - En→Zh Talker 的 λ\* = 0.70。PA-F 在 En→Zh dev 上 ASR-BLEU −0.09，P(Δ≤0) = 1.0，说明中文语音对"更快、更短"更敏感，CRF 能调的余地本来就小。
  - 第二识别器上 En→Zh 的大增益（原始 +6.46，去循环后 +3.74）主要来自 Whisper 在 B 的音频上更容易出循环（16% 对 6%），不代表 CRF 在 En→Zh 上更有效。

#### (c) WA（Thinker CRF）：AliMeeting 更差，整体向晚漂移

| MIST+WA − MIST | AMI Zh→En | AMI En→Zh | AliMeeting |
|---|---|---|---|
| 文本 tcpBLEU | +0.32 (n.s.) | +0.59 (n.s.) | **−0.36** (n.s.) |
| ASR-BLEU | +0.10 | +0.11 | **−0.24** |
| 文本 LAAL (s) | +0.08 | +0.10 | **+0.24** |
| LAAL_block (s) | +0.07 | +0.09 | **+0.24** |
| 语音起点 (s) | +0.09 | +0.11 | **+0.28** |

**机制**：
1. **似然奖励等待**：多读一次，同样的译文似然更高。格只能推迟，所以后验只会往晚走。
   - stage 2 期间按时计划的质量从 0.66 降到 0.56；每个窗口期望推迟的块数从 0.60 增到 0.91。
   - 不加偏置时，dev 上的文本 LAAL 晚 0.42 / 0.38 s，句末前写出的词从 39.7% 降到 31.6%。
2. **正反馈**：M 步按后验加权，按时的行被降权，按时状态的预测相对变差，后验就更偏向晚。
   - 加了 E 步预算 ξ = 0.5 以后，无约束后验的期望代价仍在训练中从 2.37 增到 3.37。说明问题出在模型本身，不只是后验。
3. **偏置在 AMI 的 dev5 上选出，AliMeeting 不在域内**：
   - 训练用的是 AMI 加重配音的中文；AliMeeting 是真实普通话会议。
   - δ_w = −1 在 AMI 上把延迟拉回到 +0.08 s，在 AliMeeting 上还剩 +0.24 s。
   - 不加偏置时，AliMeeting 的文本 BLEU 掉到 18.99（−2.44），语音起点晚 1.10 s。
4. **同延迟下不占优**：同一偏置族在 deadline 模型上画出的曲线，与 WA 在 deadline 工作点附近重合（28.25 @ 3.16 s 对 28.11 @ 3.07 s）。低延迟段 WA 更差（14.66 对 19.26 @ 1.95 s）。
5. **两个检查点都选不出优势**：规则选中的 step 4000 在三个集上都不如 step 3500，不存在"换一个检查点就好"的情况。

#### (d) 语音起点几乎不动

- MIST − B 的语音起点只变 −0.03 / −0.04 / −0.13 s。
- 第一块何时能说，由 Thinker 何时写出、检测器何时放行决定。PA 只管块写出之后的事。
- 这不算比基线差，但说明剩下的延迟大头已经不在 Talker 一侧：

| AMI Zh→En（MIST） | 时间 (s) |
|---|---|
| 模型滞后 | 0.68 |
| 检测器等待 | 0.66 |
| 排队 | 0.14 |
| 最后一块时长 | 1.64 |

## 3. 与 HMT 的数学差别（逐项）

| 方面 | HMT（Zhang & Feng, ICLR 2023） | 我们的 WA（Thinker CRF） | 我们的 PA（Talker CRF） |
|---|---|---|---|
| 任务 | 文本→文本 SiMT，读源 token | 语音→文本，1 s 一读，多说话人 | 文本→语音的播放调度 |
| 隐变量 | 每个目标 token 从哪个源前缀开始翻译：z_i ∈ {1..K}，t_{i,k} = L+(i−1)+(k−1) | 每块按时写或晚一读，外加说话人顺序 | 积压 h_i 和候选 c_i |
| 粒度与宽度 | token 级；K = 4–8；下界 wait-L 很激进（L 可以是 −1、2、3） | 标点块级（多个词）；**K = 2，下界 = deadline，只能推迟** | 块级；8 个候选 × 积压网格 |
| 状态表示 | 每个目标 token 复制 K 份，每份的交叉注意力只看自己的源前缀，并行算出 | 每条格边重新用 LLM 打分（规范序列化的历史） | 采样得到的候选（固定） |
| 发射 | p(y_i \| x≤t_{i,k}, y<i) | log p_θ(Y_r η_r \| E^(r), κ(A_{r−1})) | 不是生成概率，是质量势（ℓ̄、CTC） |
| 转移/策略 | **独立的置信头**：c_{i,k} = σ(W[h̄≤t; s_{i,k}])，单调；最后一个状态强制写 | **没有独立策略头**：`<wait>` 是同一个 LM 输出的一部分 | 积压确定性递推；没有学习的转移 |
| 主目标 | L_hmm = −log Σ_z Π p(y_i\|·)p(z_i\|z_{i−1})，前向算法，τ = 1，从头联合训练 | 回火后验（τ = 0.5）的 EM 式自训练；后验不回传梯度；从 deadline 模型出发，只训练 LoRA | 一轮后验加权的交叉熵蒸馏 |
| 延迟项 | **L_latency = E_{p(z)}[1/\|z\| Σ(t_{i,z_i} − t_{i,1})]**：在先验上，绝对尺度（相对 wait-L 下界），权重 1，一直开着，梯度直接作用在置信头上 | 主系统没有；推理时加偏置 δ_w；对照用的是 E 步相对预算 ξ·E_{q0}，是移动的目标 | 有：−λL_i，λ 由后验正则对偶求出，用绝对预算（规则延迟 − 0.3 s） |
| state loss | **L_state = −(1/K) ΣΣ log p(y_i \| x≤t_{i,k})**：每个状态都要学会输出正确的 token，权重 1，label smoothing 0.1 | **没有**：按时的行随后验被降权 | 不适用 |
| 推理 | 阈值 0.5 的贪心：从早到晚，第一个置信度 ≥ 0.5 的状态就写，最后一个状态强制写 | LM 贪心解码，wait logit 加 δ_w | Talker 采样 2 个，CTC 取优；不跑 CRF |
| 基线 | 固定 wait-k 及其他学习式策略 | **词对齐 + 1 s 的 deadline**，本身已经是自适应的 | 规则 Talker |

**关键的数学等价**：

`∇_θ log Σ_z p_θ(y, z) = Σ_z p_θ(z | y) · ∇_θ log p_θ(y, z)`

HMT 的 L_hmm 梯度，等于"用当前精确后验加权的完整数据对数似然梯度"。我们 WA 的 M 步在 τ = 1 时就是这个量。所以两者的核心 HMM 项本质相同，差别全在 HMT 另外加的三样东西，以及格的位置和宽度：
1. 延迟损失；
2. state loss；
3. 独立的置信头。

## 4. HMT 相对自己的 baseline 是否全面有效？

### 4.1 主结果
- 论文写的是 "HMT outperforms strong baselines under all latency"（En→Vi、De→En）。但基线曲线只在图 4 里，正文和附录没有基线的数值表，**无法逐点核对**。
- 附录 C.1 把收益拆成两部分，都是相对固定的 wait-k 推理：
  - HMT 架构（多状态）约 +0.8 BLEU；
  - HMT 推理策略约 +2.8 BLEU，低延迟段收益更大。
- 没有显著性检验，没有多种子，beam = 1。

### 4.2 消融（De→En Base，L = 3，K = 6；已用 PDF 原文核对）

| 消融 | AL | BLEU | 说明 |
|---|---|---|---|
| 完整 HMT | 3.46 | 29.29 | |
| 只优化最可能路径（max 代替 Σ） | 1.77 | 24.02 | 崩到"总选第一个状态"，−5.27 |
| λ_latency = 0 | **6.66** | 30.07 | **向晚漂移到上界附近**；而 (L, K) = (7, 6) 在 AL 6.43 时 BLEU 是 30.90，所以这一点掉出了前沿 |
| λ_latency = 0.5 | 4.12 | 29.80 | 在前沿上 |
| λ_latency = 1.5 / 2.0 | 2.10 / 2.00 | 26.65 / 25.94 | 太大会压到下界，也低于前沿 |
| λ_state = 0 | 3.24 | **27.74** | **−1.55 BLEU** |
| λ_state = 0.5–2.0 | 3.46–3.58 | 29.10–29.29 | 不敏感 |

### 4.3 同一框架下 K = 1（就是 wait-L）对比 K > 1（Table 5）

| 延迟段 | K = 1 | 最好的 K > 1 | 最差的 K > 1 |
|---|---|---|---|
| 低 | (4,1) 25.57 @ 2.57 | (2,4) 27.60 @ 2.20 | (1,6) 25.69 @ 2.28 |
| 中 | (7,1) 28.20 @ 5.86 | (5,6) 30.29 @ 4.74 | (4,8) 29.35 @ 4.69 |
| 高 | (11,1) 30.36 @ 9.71 | (9,8) 31.45 @ 8.36 | (8,10) 31.36 @ 8.27 |

多状态在每个延迟段都优于 K = 1，而且 AL 更低。但 (L, K) 选得不好时，收益会缩到几乎为零：低延迟段 (1,6) 只比 wait-4 高 0.12，比同段最好的配置低 1.9 BLEU。

### 4.4 结论
- HMT 相对**固定策略**在所有延迟段都有效，但这依赖三个条件：
  1. 一直开着、绝对尺度的延迟损失；
  2. state loss；
  3. 边缘化（不能取最大路径）。
  另外还依赖调好的 (L, K)，每个曲线点是一组单独选出的配置。
- **HMT 自己也确认了"纯似然向晚漂移"**：λ_latency = 0 时 AL 3.46 → 6.66，并且掉出前沿。这与我们 WA 的漂移是同一个现象。我们的论文 related.tex 已引用 HMT，也提到了 MILk、MMA 的延迟损失，可以再补一句 HMT Table 3 的直接证据。
- HMT 没有和"按词对齐得到的自适应时机"（相当于我们的 deadline）比较过。它的增益里有多少超过对齐 oracle，论文里没有答案。

### 4.5 代码层面的要点（ictnlp/HMT）
- 总 loss = hmm_loss + state_loss + latency_loss，三个权重都写死为 1，没有命令行参数。label smoothing 只用在 state loss 上，HMM 项不用。
- 延迟损失是在先验上做前向得到的状态占用 × (cands − (L+t))，再按目标位置数归一化，梯度只流到转移头。
- 转移头是 `Linear(2d, 2)`，输入是解码状态拼接源前缀均值，2 路 softmax；最后一个状态的"不写"logit 置为 −inf。
- 从头训练，没有热启动，也没有课程学习。推理时每读一次就重算整个编码器和解码器，batch 必须为 1。

## 5. 我们的 Thinker CRF（WA）为什么没效果：与 HMT 对照的原因

按影响大小排序：

1. **基线强度完全不同**（最根本的原因）。
   - HMT 的对手是 wait-k 这种不看内容的固定策略，自适应时机有大量空间可挖。
   - 我们的 deadline 来自词对齐，再加 1 s 的口译滞后，已经是"每块在源说完后 1 s 写"的近 oracle 时机。
   - 隐变量策略要赢，必须找到比对齐更好的时机。WA 曲线显示在 deadline 工作点附近两者重合，就是这个上界在起作用。
2. **格只能推迟，而且很窄**（K = 2，下界 = deadline）。
   - HMT 的下界很激进，延迟损失把后验往早拉，似然往晚推，两者形成平衡。
   - 我们的格里没有比 deadline 更早的状态，似然只会往晚推，任何漂移都只会更晚。
   - 加了"可早一读"的变体（PMC）又没有对应的质量约束，结果冲过头：语音 LAAL 2.86 对 3.86，但文本 −1.92、ASR-BLEU −1.70。HMT 用 state loss 加延迟损失来平衡这两头。
3. **没有一直开着的绝对延迟损失**。
   - 主系统只在推理时加偏置，训练时不受约束，所以训练过程中一路漂移（按时计划的质量 0.66 → 0.56）。
   - E 步预算 ξ = 0.5 是相对当前模型的：目标等于 0.5 × E_{q0}[Lat]，而 E_{q0} 本身从 2.37 涨到 3.37，目标跟着上移。
   - HMT 的 L_latency 是相对固定下界 wait-L 的绝对量，模型怎么变都不会移动。
4. **没有 state loss，形成正反馈**。
   - 按时的行被后验降权，按时状态的预测能力相对变差，后验就更往晚走。
   - HMT 的 state loss 让每个状态（包括最早的）都始终学习正确输出，缩小早晚之间的似然差，削弱漂移的动力。去掉它掉 1.55 BLEU。
5. **策略和内容耦合在同一个 LM 输出里**。
   - 我们的读/写决定是 `<wait>` token 的概率，在推迟的行上训练内容，也会同时改变 wait 的概率。
   - HMT 用独立的置信头，延迟损失只作用在策略上，不干扰内容。推理时 HMT 调阈值，我们调 δ_w，作用类似；但训练时我们无法单独约束策略。
6. **Thinker 写出时刻只占语音延迟的一小部分**。
   - MIST 的 EndOffset（AMI Zh→En 3.13 s）里，模型滞后只有 0.68 s。
   - T2 实验显示，单纯让 Thinker 更早、更碎地写，会被 Talker 排队抵消：排队 0.50 → 2.04 s，语音 LAAL 反而升高 0.48 s；做读级合并也只挽回一部分。
   - HMT 是纯文本任务，写出时刻就是延迟本身；在 S2ST 里，Thinker 侧的改进会被语音层稀释。
7. **训练方式**。我们是在一个大型预训练 LLM 上，从 deadline 模型热启动，只训练 LoRA，并且用回火的自训练（τ = 0.5，后验不回传）。热启动意味着起点就集中在按时计划上，任何变化都只能是离开它。HMT 是从头联合训练，策略和表示一起成形。
8. **域外**：偏置和检查点都在 AMI dev5 上选，AliMeeting 是真实普通话会议，延迟偏差在那里被放大（+0.24 s）。

### PA（Talker CRF）为什么相对规则提升小

1. **势里最重的两项在推理时都有便宜的替代**：5·f_CTC 可以用 CTC 二选一代替，−λL_i 主要表现为"积压时说快"，可以用积压语速规则代替。CRF 蒸馏学到的，正好就是"规则 + 二选一"能做的事。
2. **前瞻的价值取决于积压链的长度**。播放层把排队压到 0.14 s 以后，前瞻能起作用的地方只剩积压最重的 AliMeeting。
3. **只做一轮**：权重在规则路径的积压上计算，候选来自基础 Talker；没有用微调后的 Talker 重新采样、重新加权，也没有在积压上做边缘化。
4. **目标里没有停顿项**，所以学到的策略在停顿上必然比 B 差（§2.3 (a)）。

## 6. 是否需要 Thinker 和 Talker 联合训练一个 CRF？

**建议：不做完整的联合 CRF。** 依据：

1. **已经做过两次预检，都是 NOT GO**：
   - **J1**（2026-11-11）：联合写出–播放半马尔可夫 CRF。每个说话人的块序列看作半马尔可夫分段，块势是语音时间线延迟，包括每块约 0.34 s 的开销和同流积压。
     - 中性分数下，联合后验的语音延迟反而略高（4.343 对 4.329），块数更多（6570 对 6449）。
     - 原因：在 1–2 读宽的格里，0.34 s 的每块开销不足以让势偏向合并。
   - **J1-v2**（2026-11-12）：改用更严格的语音预算。在同样的语音期望下，块数一样（4963 对 4933），文本更早。
     - 结论：语音时间线的势相对一个简单的延迟预算没有额外作用。
2. **联合要优化的东西已经被播放层吃掉了**。
   - 联合 CRF 的价值在于协调"Thinker 何时写、写多大块"和"Talker 的积压"。
   - 加了播放层以后排队只剩 0.14 s（AliMeeting 0.33 s）。剩下的延迟是模型滞后 0.68 s、检测器 0.66 s、最后一块 1.64 s，都不需要联合建模。
   - CPU 上界也显示，只改分组对语音 LAAL 的影响约 0.1 s。
3. **结构和成本**：
   - 两个模型（Qwen3-Omni Thinker、UniSS Talker）没有共享参数，联合"训练"只能交替优化。
   - 联合状态空间是写出计划 × 积压 × 候选，而候选依赖于分组：每种写出计划会产生不同的块，都要重新采样 Talker 候选。只能用代理时长模型（J1 的 PC2 用的就是代理）。
   - 每一步都要跑 Thinker 的格打分加 Talker 的候选采样，成本比 WA 高一个量级。
4. **如果一定要耦合，更便宜也更合理的方式**（留作后续工作，不建议进 ACL 版本）：
   - **反馈耦合**：把 Talker 的当前积压作为 Thinker 写出置信头的输入特征。积压大时可以晚一点写、写大块；积压空时早写。这是控制问题，不需要联合 CRF。
   - **交替优化**：固定 Talker，在 Thinker 的 WA-H（§7 B）里，用实际 Talker 时长算出的语音时间线延迟作为 L_latency 的代价。

## 7. 建议（按优先级）

### A. ACL 版本（不加训练，只改写法）

1. 维持方案 A 和保底写法：播放层有效；"CRF 学出了与积压相关的语速和候选选择策略，同语速的规则能复现大部分；在积压最重的 AliMeeting 上，CRF 的前瞻有显著的额外收益（+0.23，p_Holm 0.007）"。可以补 §2.2 的机制解释（CTC 项与二选一重叠，前瞻价值随积压增大），作为分析段或放进附录。
2. WA 负结果与 HMT 联系起来（§6 / related 各加一句）：HMT 也观察到 λ_latency = 0 时向晚漂移，并且掉出前沿（AL 3.46 → 6.66）。我们在只能推迟的格、对齐得到的 deadline 这一更强基线下得到同样的结论，并说明 HMT 的两项补救（绝对延迟损失、state loss）是我们没有用的。这能把"负结果"变成"有解释的发现"，回应审稿人"为什么不用已有方法"的质疑。
3. Limitations 补一句：停顿是 CRF 目标之外的代价；说话时长预算（PA-F）去不掉它，需要的是空隙层面的建模。

### B. 如果要让 Thinker 侧 CRF 成为真正的贡献：WA-H（HMT 式改造），只跑一个设置

- **改动**（全部来自 HMT，一次到位，不扫参）：
  1. **独立写出置信头**：c_r = σ(w·[Thinker 最后一层隐状态; 音频前缀均值])，`<wait>` 不再承担策略。推理时阈值 0.5，最后一读强制写。
  2. **目标** = −log 边缘似然（τ = 1，精确前向）+ λ_lat·先验期望延迟 + λ_state·所有格边的 CE。
     - 先验期望延迟用绝对尺度：相对 deadline 减一读的下界；
     - state loss 对所有格边一视同仁，按时、晚一读、早一读都训练；
     - λ_lat = λ_state = 1，沿用 HMT 的默认值。
  3. **格加宽为 K = 3**：每块可以在 deadline 前一读、按时、晚一读写出。下界比 deadline 早，延迟损失把后验往早拉，state loss 保证早状态有能力写对。
- **对照**：deadline 模型用同样的数据和步数继续训练，控制训练量。
- **预检**：dev5 上按时计划的后验质量在训练中不下降，早状态的 CE 不上升。
- **门槛**：匹配到 deadline 的文本 LAAL（±0.05 s）时，文本 tcpBLEU ≥ B + 0.2；语音链上 ASR-BLEU 不降。
- **成本**：4 卡训练 3–5 小时，加 dev 评测 1–2 小时。这是按以往 stage 2 和 D1v 的速度（约 4 s/步）估算的，K = 3 的格打分大约要多 1.5 倍的行。
- **预期**：坦率地说空间小。deadline 已经接近对齐 oracle，§5 第 1 条和第 6 条决定了即使 WA-H 成功，语音层的收益也会被稀释。它最可能带来的是"训练中不漂移、不再需要事后偏置"，这在方法上更干净，但未必有显著的质量收益。是否值得做取决于你是否需要 Thinker 侧的创新点；如果只为 ACL，不建议现在做。

### C. Talker 侧（直接处理最大的代价：停顿）

1. **空隙代价（最推荐）**：在 PA 的势里加
   `−κ · max(0, ν_{i+1} − (ν_i + h_i + D(c_i)))`
   它只惩罚"本块说完时下一块还没到"造成的空隙。积压时（h > 0）这一项为 0，不会妨碍说快；只有将要断粮时才鼓励说慢。
   - 这和 PA-F 的区别：PA-F 约束总时长，误伤了积压时的块。
   - 风险：Talker 推理时不知道下一块何时到达。需要给 Talker 加一个"Thinker 当前是否处于 wait 状态 / 已等了几读"的条件 token，否则学不到。
   - 门槛沿用"流畅性改动不得降低 ASR-BLEU"：ASR-BLEU 差 ≥ −0.2 且 P(Δ≤0) < 0.95，停顿至少降 25%。
   - 成本：一次 PA 训练约 1 小时加评测；用已有候选重新建行即可，CPU 上就能先做预检。
2. **迭代一轮 EM**：用 PA Talker 重新采样候选，并在积压上做边缘化，不再固定在规则路径上。预计能增强前瞻的作用，对 AliMeeting 这类积压重的场景最有希望。
3. **推理时的滚动 CRF（MPC）**：用已知积压加上预测的下一块到达时刻，做 1–2 块前瞻的 Viterbi，替代现在固定的二选一。这样 CRF 在推理时也在工作，与规则的区别会更清楚。

### D. 不建议

- 完整的 Thinker + Talker 联合 CRF（理由见 §6）。
- 在 WA 现有框架上继续调 δ_w、ξ、τ（这是参数扫描，而且 J1、PMC、ξ 都已经说明在现有框架里调不出来）。

## 附：一句话回答

- **CRF 有效吗？** 播放层（PA）相对基线有效，而且稳健。但 CRF 相对同语速规则的独有贡献，只在积压最重的 AliMeeting 上显著；Thinker 侧的 WA 无效。
- **哪里更差？** 停顿翻倍以上，原因是说快以后断粮，而目标里没有空隙项；En→Zh 上学到的 Talker 不比规则好，原因是积压轻；WA 在 AliMeeting 上更晚、更差，原因是向晚漂移加上域外。
- **与 HMT 的差别？** 核心的边缘似然项本质相同。我们缺绝对延迟损失、state loss、独立策略头；格只能推迟（K = 2）；基线是对齐 deadline 而不是 wait-k。
- **HMT 全部有效吗？** 相对固定策略在所有延迟段都有效，但依赖延迟损失、state loss、边缘化，以及调好的 (L, K)。去掉延迟损失后，它也会向晚漂移并掉出前沿。
- **要联合 CRF 吗？** 不要。两次预检 NOT GO，联合要优化的排队已经被播放层吃掉了。
