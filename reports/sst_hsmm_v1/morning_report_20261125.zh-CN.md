# 晨报 2026-11-25（sst_hsmm_v1，夜间自主 6 轮）

**一句话：** 6 轮都没有在同等时延下超过 N。

**最有价值的发现：** 支持验证提交（SVC，第 5、6 轮，无训练），用一个只学"语音支持边界"的 LoRA 当同读验证器。
- 相对 B_b（主对照），两个方向都得到 BLEU 更高、时延更低（SVC），或 BLEU 明显更高、时延与 B_b 相当（SVC-JM）的系统。
- 相对 N，它是用 BLEU 换时延（D2 早 0.3–0.5 s，ASR 低 0.2–0.7）。

## 2. 每轮原因（一句话）

1. **DLA**（惩罚错误一致）：参考 token 级的"错误一致"把分布压平，与 N 打平。
2. **CR-LA**（提交后悔策略梯度）：单参考的改写噪声淹没后悔信号（17% 有害、72% 为零），KL 约 0.01，几乎没学到。
3. **PC-MBR**（最终读 MBR）：T 0.7 采样证据比贪心差，chrF 与 BLEU 不一致，与 N 打平。
4. **SAP**（只输出已支持的参考前缀）：草稿确实停在支持边界，zh2en RealSI ASR +1.7..+2.2。
   - 但 LA2 的 1 s 读取滞后让 D2 +0.3–0.4 s。
   - 最终读的风格漂移（KL 约 1）使 en2zh OBSI 下降。
5. **SVC**（N 起草，SAP 同读验证，内容永远来自 N）：消除了一读滞后，D2 比 B_b 还低。
   - dev 上约 18% 的额外提交后来会被 N 改写（已被支持 ≠ 已确定）。
   - 这个比例在 clean / noisy、提交类型、段内位置之间都一样，门控规则修不了。
6. **SVC-JM**（N 与 SAP 对所选 token 的概率都 > 0.5 才延长）：dev 上 BLEU 损失从 −1.15 / −0.85 降到 −0.31 / −0.26，时延优势保留约 60%。
   - 测试相对 N：ASR −0.24 / −0.51，D2 −0.28 / −0.29。

## 3. 判断

- **"在 N 上训练提交一致性"这条线（DLA / CR-LA）已证伪：** 最终读是已提交前缀的确定函数，训练信号太弱或太噪。
- **"支持边界"是真信号：**
  - SAP 当译者时质量涨（zh2en RealSI），SAP 当验证器时时延降（SVC）。
  - SVC / SVC-JM / N 构成可调的质量–时延曲线，SVC-JM 的置信门槛决定落点。
  - 这是一个干净、无蒸馏、无 QABC 的推理时机制，可以写成方法。
  - 但要声称"同等时延下优于 N"，现在的证据不够：en2zh 略高于 SVC–N 连线，zh2en 略低。
- **主对照改为 B_b 后的可写结论：**
  - 在与 B_b 相同的时延下（zh2en ΔD2 +0.04），SVC-JM 的 ASR-BLEU 比 B_b 高 2.1；en2zh 在 ΔD2 +0.10 下高 1.0。
  - SVC 在时延比 B_b 低 0.15 s 的同时，ASR 仍高 0.6 / 1.9。

## 4. 建议的下一步（需要你点头）

- **(a) 只补对照，不是新方法：** 给 N 画出等时延对照曲线（同一 Thinker 用预算 / 更早提交得到 2–3 个时延点）。用来判断 SVC 曲线是否整体在 N 族之上，这是写论文前必须有的证据。
- **(b) 支持 + 确定性联合验证器：** 把 SAP 目标从"已支持"改为"已支持且此后不会被改写"（用参考对齐 + 离线一致性构造标签，不用教师模型输出）。直接针对 18% 的误提交。
- **(c) 如果只要论文结论：** 以 B_b 为主对照写 SVC / SVC-JM，N 作为高时延参考点。
