# 两个方向 BLEU 都提升的方案（2026-11-28，待批准）

## 0. 目标和约束

- **目标：** en2zh 和 zh2en 的 ASR-BLEU 都超过 p3hk，时延不高于 p3hk。按 change 55 规则：(i) ΔASR ≥ −0.2 且 ΔD2 ≤ −0.10 s，或 (ii) 比 p3hk–p3hk2 连线高 ≥ 0.2。
- **同时报：** 文本 BLEU、COMET、D1、EndOffset、停顿、sim、PESQ，相对 B_b 和 p3hk 都报。
- **约束：**
  - 一个双向模型；不做 teacher-student 蒸馏；一个方法一个设置；预注册在任何数字之前；
  - 测试集只测不调；工作点只在开放开发集上选。

## 1. 为什么已有方法过不了（依据）

已有方法分两类：

- **改用词的**（P2F、E1、HCG 等 adapter 预判）：en2zh 用词偏离参考，BLEU 降（COMET 升）。
- **只调时机的**（θ、提交规则、MBR、K 次采样一致性、HCD）：只在原曲线上移动。

`en2zh_stream_gap_20261128.zh-CN.md` 的分解给出了具体原因：

- **en2zh：** 损失来自语序。参考把后听到的修饰语提前，而 87% 的重排要到最后一读才出现在草稿里，所以 base 的稳定性信号预见不到。
- **zh2en：** 41% 的分歧在提交块的最后一个单位，是局部的提交过早。

所以新方法必须同时满足两点：保留 base 的用词（不训练 adapter）；在提交之前看到"句子说完以后的样子"。

## 2. 方案 1（主推）：TAF-S，对源语音的未来采样并投票，作为 HSMM 提交的否决证据

**文献：** Ouyang et al., "Anticipating Future with Large Language Model for Simultaneous Machine Translation", NAACL 2025。
- 做法：用 LLM 为源语句采样多条可能的后续，MT 模型分别翻译每条完整句，多数投票后提交得票最多的译文前缀。
- 结果：同等时延下最多 +5 BLEU，评测含 En-Zh 和 Zh-En。

**为什么对症：**
- 每条"完整句"的译文都由 base 模型给出，用词就是 base 的，没有 adapter 的语体漂移。
- 采样的未来会让重排提前显形。例：听到 "Osan Station is a large subway station" 时，若采样到 "…located in the city center"，其译文是"Osan站是位于市中心的大型地铁站"，和单调草稿"Osan站是一个大型地铁站"在"一个"处不一致，投票就会否决这次提交。这正好针对 en2zh 的主要损失。
- zh2en 块尾提交过早的单位，同样会在采样未来的译文里分歧，被否决。
- 否决提高了提交精度，开发集网格就能选到更低的 θ，从而换回时延。这是两个方向同时提升 BLEU 的路径。

**做法：** hsc30 = 当前 HSMM 流式模块的副本，加 `--taf`，只改非最后读。
1. **源前缀转写：** 同一个 Thinker（wave17）用 ASR 提示词转写当前音频前缀，逐读增量缓存。
2. **采样未来：** 同一个 Thinker 在纯文本模式下，从转写续写 K = 8 条源语句，到句末为止（T 0.9，top-p 0.95，最多 24 token，种子 sha1(id|t)）。
3. **翻译 8 条完整句：** 同一个 Thinker 在文本翻译模式下贪心翻译，强制以已提交的 healed 前缀开头，和语音草稿同样受约束。
4. **投票：** 语音草稿 d0 在已提交部分之后的第 j 个单位，若有 ≥ 50% 的未来译文与 d0 的公共前缀覆盖到 j，就算"受未来支持"。
5. **提交：** cut = min(HSMM cut, 连续受支持的最远位置)，即只增加否决。θ 照常在开发集网格 {0.60…0.85} 上选。最后一读不变。

**唯一的设置：** K = 8，多数票阈值 0.5。不扫参。

**预检查（开发集 edev / cvdev，两个方向；不过关不跑流式）：**
- **P0 实时性：** 每读墙钟时间 p95 ≤ 1000 ms（与 change 38-0 相同）。不满足时一次性改为 K = 4 重测；仍不满足就停。
- **P1 区分能力：** 在 HSMM 会提交（P ≥ θ）的单位里，比较被否决和未被否决单位"存活到最终"的比例。GO 的条件：两个方向上，被否决单位的存活率都比未被否决的低 ≥ 0.15，且否决率 ≤ 30%。

**风险：**
- 噪声音频上的短前缀转写不准；
- 文本模式和语音模式的用词不一致，导致否决过多（P1 会直接测出来）；
- 每读计算量增加。

**论文定位：** 把 TAF 的思路从文本 SimulMT 搬到语音重翻译加 HSMM。投票被解释为"对源语音的未来做边缘化"的证据，接入 settledness 后验。这和本文主线一致，属于推理期的贝叶斯方法。

## 3. 方案 2（并行）：会话上下文 Thinker

**文献：**
- Koshkin et al., "LLMs Are Zero-Shot Context-Aware Simultaneous Translators", EMNLP 2024：零样本给 LLM 背景信息能提升同传质量，专业内容提升最大。
- Zhang et al., ACL 2021, "Beyond Sentence-Level End-to-End Speech Translation: Context Helps"。

**为什么适用：**
- 测试集本身按会话组织：RealSI 每个方向 10 段会话，每段约 35–48 句；OBSI en2zh 140 段、zh2en 37 段。
- 同一会话里，人名、术语、话题和语体是连贯的。例："Mark"在上一句已译成"马克"；"负载均衡"反复出现。
- 两个方向都受益，而且不改时延机制。上下文让草稿更早稳定，还可能顺带降低时延。

**做法：**
- 每句的所有读取（含最后一读）在提示词里加入同一会话前 3 句**系统自己的最终译文**，不用参考译文。
- 测试按会话顺序跑，会话之间并行。

**唯一的设置：** 前 3 句，固定提示格式。

**预检查：**
- 开放开发集 `bench_dev`（OBSI 开发流，开放数据，已有泄漏检查）按会话内顺序，只取单说话人片段。
- 整句离线 BLEU：带上下文对不带上下文，两个方向都 ≥ +0.3 才跑流式。

**消融：** 同时报 B_b + 上下文，说明增益不只是"任何系统加上下文都会涨"。

**风险：**
- wave17 是在单句提示上微调的，改提示可能退化（预检查会测出来）；
- 自身错误可能沿上下文传播。

## 4. 方案 3（暂不推荐，备选）：针对同传的参考改写训练

**文献：**
- Guo et al., "Simultaneous Machine Translation with Tailored Reference", Findings of EMNLP 2023；
- Zhao et al., EMNLP 2021（译文转口译风格，+2.8 BLEU）；
- Chen et al., EMNLP 2021（少重排的伪参考）。

**不推荐的原因：**
- 这类方法要训练 Thinker。我们已有 6 次训练（B1、B2、C1、SAA、反向配对等），都因为 UniST en2zh 的语体漂移在 G0 掉分。
- 改写参考需要一个 tailor 或 LLM 改写器，接近你排除过的 teacher 设置。

只在方案 1 和 2 都失败，并且你同意更换训练数据或使用改写器时再考虑。
