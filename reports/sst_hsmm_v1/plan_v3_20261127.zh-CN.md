## 1. 已经知道的事实（全部来自已有结果）

### 1.1 时延花在哪里（p3hk，测试集，overnight_diag）

| 方向 / 数据 | 内容稳定滞后 | 确认等待 |
|---|---|---|
| en2zh OBSI / RealSI | 1.08 / 1.48 s | 0.54 / 0.64 s |
| zh2en OBSI / RealSI | 1.33 / 1.30 s | 0.48 / 0.60 s |

- **内容稳定滞后：** 从这个译文单元从此不再变的那一读开始算。这是起草模型（drafter）一侧的问题。
- **确认等待：** 从内容稳定到被提交的时间。这是提交层一侧的问题。
- 大头是内容稳定滞后，约为确认等待的 2～2.5 倍。

### 1.2 17 个尝试按"动了哪一层"分组

| 组 | 方法 | 动的层 | 测试结果（相对 p3hk） |
|---|---|---|---|
| ① 提交判据 / 阈值 | S4、S6、S8、B1、C1、C2 | 提交层（小头） | 都在 ±0.1 s 以内，或者只是沿取舍曲线移动 |
| ② 同一读里的候选选择 | S6、S7、A1、A2、D1、D2 | 草稿的措辞 | 措辞变了，内容什么时候稳定没变；D1 的 zh2en 例外 |
| ③ 预判（改起草模型） | D3、S1、S2、S3、E1 | 内容稳定滞后（大头） | **同一阈值下快 0.3～0.67 s**，但 en2zh 和 OBSI 上 BLEU 损失更大；zh2en 的 S3 / E1 有效 |
| ④ 少看音频 | B2 | 识别 | 质量和延迟都更差 |

**唯一真正动到大头的杠杆是预判（③）。** 同一阈值下，D3 让 en2zh 快 0.67 s、zh2en 快 0.52 s。问题不在"快不起来"，而在"猜错的内容被提交了"。

### 1.3 预判猜错的三个具体原因

1. **可靠性在测试域被高估（F1）。** 预判内容"能不能信"是 HSMM 在 UniST 上学到的，到测试域就偏高：
   - S1：edev 上平均后验 0.76，实际存活率 0.77；zh2en OBSI 上 0.79 对 0.65。
   - S8 的证书：ECE 0.124。
   - D3：edev 上 en2zh BLEU +0.86，到测试变成 −2.5。
2. **预判看得太远（新发现）。**
   - 话说到一半时，P2F 和 E1 的草稿已有最终译文的 0.73～1.15 倍长，相当于把整句都猜出来了。
   - D3 预检查显示：下一秒的源内容可预测性还不错（top-5 en 0.59 / zh 0.38），但再往后的远处内容不可预测。
   - 所有预判训练用的都是"前缀 → 整句译文"，没有限制往前猜多远。
3. **en2zh 要大幅调整语序（F4）。**
   - 中文要把修饰语、状语、从句提前，所以预判要猜的是内容本身，不只是语序。
   - 不去猜、改用顺着源语序的译法（D1）也不行：会被以离线译文为参考的 BLEU 惩罚（en2zh 文本 BLEU −0.81）。

## 2. 错误和问题在哪里

### 2.1 方法设计上的错误（事后看，有些本来可以事先预见）

- **C2 在原理上就不可能有效。** 它对提交分数做单调的重新校准。只要阈值是在 dev 上选的，任何单调变换都等价于换一个阈值，只能沿取舍曲线滑动。能把曲线外推的只有排序能力（AUC），不是校准（ECE）。结果也一样：ECE 0.077 → 0.056，但只是沿曲线移动。
- **B1 新信号和已有信号高度相关，应该先查再跑。** 它的 AUC 是 0.743，已有的跨读一致性是 0.748，信息几乎重合。用已有 rollout 在 CPU 上算一个 AUC 增量就能提前停掉。
- **C1 的错误定义把同义改写也算成错误。** 只要提交的单元不在"影子终稿"的最长公共前缀里就算错。结果允许的错误率门槛 α ≈ 0.5，控制器退化。
- **A1 / A2 / S6 / S7 / D2 的目标层选错了。** 第 1.1 节已经测出主要瓶颈在内容稳定滞后，但同一读里的候选之间只有句尾措辞不同，改不了内容什么时候稳定。
- **E1 只修了"截断还是说完"的问题，没限制预判视野。** 它在 en2zh 上照样把整句结构猜出来并提交了：文本 BLEU 相对 p3hk −3.4，D2 −0.38 s。

### 2.2 流程上的错误（我的问题）

- **上一份方案的第 0 步没做。** 计划先把 1.1～1.5 s 的内容滞后拆成识别、重排、犹豫三部分，再决定方法优先级，但实际直接跑了方法。B2（攻识别滞后）在不知道识别滞后有多大的情况下就跑了。
- **没有便宜的预检查门槛。** B1 的 AUC 增量、C2 的"单调变换不改排序"，都可以在 CPU 上几分钟内判断。结果全部跑完了 rollout、dev 和测试。
- **edev 与训练数据同分布，dev 上的收益不迁移。** D3、S1、S8 都是 dev 上"有效"、到测试无效。加了 cvdev 以后好一些（D1 的 dev 和测试一致），但 cvdev 是朗读语音，和 RealSI 的真实口语仍有差距。

### 2.3 评测本身的约束（不是错误，但决定了方向）

- en2zh 的参考是离线译文。少调整语序的顺句译法会被 BLEU 惩罚。按 BLEU 优先，en2zh 能走的路只有"猜对"，或者"只在猜得对的地方猜"。
- 所以本轮的核心问题定为：**有选择地预判。只在有把握的地方提前，并且这个"有把握"的判断要能迁移到测试域，不能依赖在 UniST 上学到的频率。**

## 3. 本领域和其他领域的相关做法（检索）

- **SiMT 中的预判与参考：**
  - Tailored Reference（Guo et al., EMNLP 2023 Findings）用 RL 训练一个改写器，把参考改成按时延"少预判"的版本。它是一个生成训练目标的模型，接近师生蒸馏，不能照搬，但它说明"训练目标应随时延调整"有效。
  - HMT（Zhang & Feng, ICLR 2023 spotlight）把开始翻译的时刻当隐事件，用 HMM 边际似然训练，和我们的 HSMM 同源。
  - TAF（NAACL 2025）用 LLM 采样多个源语言未来，对每个目标 token 做多数投票，决定写不写。它是文本 SiMT，不涉及不可撤回提交，也不涉及"在所有未来下都成立"的约束。
- **语音同传：**
  - Hibiki（ICML 2025）和 DSM（Kyutai 2025）把对齐放在数据预处理，用延迟条件在推理时控制时延。
  - Seed LiveInterpret 2.0、Hibiki-Zero 用 RL 优化时延。我们自己的 RL 尝试因为流水线对浮点扰动敏感而失败，见 rl_plan_20261126。
- **机器人 / 自动驾驶的应急规划（contingency planning）：**
  - Branch MPC 面对多模态的未来预测时，要求"现在执行的动作在所有分支上相同"（非预判约束，ScePT 2022；Bouzidi et al. 2025），分歧之后的决策推迟。
  - 这正好对应"已经提交的译文前缀，在所有可能的源未来下都必须成立"。
- **流式视频 LLM 的"何时回应"：** VideoLLM-online（CVPR 2024）、Dispider（2025）、StreamBridge（2025）把"何时开口"与"说什么"解耦。我们的 HSMM 提交层已经是这种结构，所以这一支不单独做方法。
- **分布漂移下的选择性预测：** 有研究指出温度缩放这类重新校准只改善校准、不改善排序，而且漂移下的高置信错误无法通过推迟来挽回（Fisch et al. 2022 及其后续）。这和 C2 的失败一致：要的是对测试域可迁移的排序信号。
- **控制标记训练：** Tagged back-translation（Caswell et al. 2019）、CTRL（Keskar et al. 2019）。用数据自带的属性打标签，推理时选标签，不需要改写数据，也不需要教师模型。

另有一个工程项，不算新方法：**zh2en 用 E1 起草 + D1 选择**。这是本轮两个 zh2en 有效方法的叠加，纯推理，单独报告。

### 4.1 每个方法的要点

**H1 限定预判视野（主推）**
- 训练数据：
  - 用 UniST 训练集的强制对齐（D3 预检查用过的 torchaudio 流程）得到源词时间。
  - 用 SimAlign（`venvs/uniss-formal-align-v1`）做源词和目标词的对齐。
  - 对随机截断点 t，目标 = 参考译文的最长前缀，要求其中每个目标词对齐到的源词都在 t + Δ 之前结束（单调闭包）。
- 标记：沿用 E1 的 partial / complete 标记，加一个视野标记 `<h1s>`。最后一读用 complete，目标是整句。
- Δ = 1.0 s 只设这一个值。理由是 D3 预检查测的就是下一秒的可预测性（top-5 en 0.59 / zh 0.38），再往后没有测过、也不可信。
- 预期：
  - E1 在 en2zh 的损失来自"整句结构被提前猜出并提交"。视野限制在 1 s 内时，远处的从句结构不会被猜。
  - zh2en 应保留 E1 / S3 的大部分收益（它们的收益主要来自近处的结构）。
- **预检查（CPU，只报告，不作门槛）：** 在 edev 上统计 Δ = 1 s 时"可达目标比例"，以及 Δ 目标与整句目标的长度比。如果和 Δ = ∞ 几乎一样，说明视野限制没起作用。
- 为什么是 ICLR 级：现有 SiMT 训练目标只有"前缀→前缀"（wait-k、Hibiki 对齐）和"前缀→整句"（P2F、re-translation）两种。把"预判视野"变成一个显式的条件变量，并说明它决定了时延收益与猜错风险之间的取舍，这是新的问题刻画。配合第 1.3 节的实证（预判长度比、存活率），可以构成一篇完整的分析加方法论文。

**H2 非预判提交**
- 每读流程：
  1. wave17 先输出当前源前缀的转写，再续写 K = 4 个源未来（温度 1.0，每个最多 1.5 s 的词数）。
  2. 对 4 个"前缀 + 未来"用 wave17 文本模式翻译。
  3. 草稿中某个单元，只有在 4 个未来译文里按概率加权的一致比例 ≥ 0.8 时，才可以提交。
- 输入 HSMM：上面的一致比例作为第 5 个发射，HSMM 在匹配的 rollout 上重拟合。
- 和 S8 / K 样本一致性的区别：
  - K 样本一致性（change 38-2）是对同一个输入采样。
  - S8 是两个模型对同一个输入的一致。
  - H2 是显式地对不同的源未来做一致检查，看的是"不管后面说什么，这一段译文都成立"。这是新的信息来源。
- **预检查（GPU 约 20 分钟，只报告）：** 在 cvdev 的 200 句 rollout 上，算这个一致比例对"单元最终是否存活"的 AUC 增量（相对现有 HSMM 发射）。增量小于 +0.01 就按登记停下，避免 B1 那样跑完全程才发现没信息。
- 风险：4 个未来来自同一个底座，可能共享同一个错误猜测（S8 的教训）。所以门槛设得高（0.8），而且只比较翻译结果，不比较未来文本本身。

**H3 句法门控的选择性预判**
- 起草：E1 的 LoRA，已有，不重训。
- 源转写：每读复用 E1 / wave17 的转写输出。用 Stanza（en / zh，开源）判断当前源前缀在句末是否有未闭合的依存（中心词在右侧、尚未出现）。
- 门控：未闭合时，对齐到源前缀之后的目标单元（即预判出来的部分）不得提交。用对齐估计 + SAP 的 support 判断。
- **预检查（CPU）：** 在 E1 的 dev rollout 上，算"未闭合"特征对被提交单元存活与否的 AUC 增量。

**H4 自然顺句标记**
- 预检查一（CPU，约 30 分钟）：UniST 两个方向的 Kendall τ 分布。如果最单调的 30% 和其余数据的 τ 差异很小，说明数据里没有"顺句"信号，直接停。
- 预检查二（训练后，GPU 约 20 分钟）：cvdev 上整句离线解码，`<mono>` 对比无标记的 BLEU 下降 ≤ 0.5 才继续。这是为了避免 D1 那种"顺句就掉 BLEU"。

**H5 截断感知识别**
- 第 0 步测出的识别滞后 < 0.3 s 时不跑，空出来的卡给其他方法。

## 5. 第 0 步：先做诊断（CPU 约 2 小时，必须在跑方法之前完成）

1. **时延三分解：** 在 dev（edev + cvdev）上用 p3hk 和 E1 的 rollout，把每个单元的内容稳定滞后拆成三部分：
   - (i) 识别：源词已经说完，但还没有被转写认准的时间；
   - (ii) 重排：目标单元对齐到的最晚源词，比它按语序应在的位置更晚；
   - (iii) 犹豫：证据都齐了，草稿还在改。

   **在 dev 上做，不在测试上做，避免用测试集结果来设计方法。**
2. **视野可达性：** H1 的预检查。
3. **AUC 增量：** H2 / H3 的预检查。

第 0 步的结果决定 H5 跑不跑，并作为论文的分析部分。

- 测试相对 p3hk，每个方向单独判断：
  - (i) ASR-BLEU ≥ p3hk − 0.2，且 D2 ≤ p3hk − 0.10 s；
  - (ii) 在同样延迟下，比 p3hk–p3hk2 连线高 0.2 以上。
- 两个方向都满足才算有效；只满足一个方向的，标为单方向有效。
- 所有指标相对 B_b，并列 N、LA-2、p3hk、p3hk2。zh2en 另外和 D1、E1 比。COMET 作为辅助。
- 只对有效方法做逐组数据的配对 bootstrap。
- dev 筛选：edev 和 cvdev 都要满足，相对 B0 曲线 ΔBLEU ≥ +0.3（同 D2），或 ΔD2 ≤ −0.10 s（同 BLEU）。

## 8. 如果成功，ICLR 的故事

"Anticipation under irrevocability"（不可撤回提交下的预判）：
1. **分析：** 在重翻译式同传里，时延的大头是内容稳定滞后。唯一能动到它的是预判，但预判的收益被猜错吃掉。实证包括 17 个方法的时延分解、预判长度比、跨域存活率。
2. **方法一（H1）：** 预判视野作为显式的条件变量。它统一了 prefix-to-prefix 和 prefix-to-full，并给出视野与"猜错风险 / 时延收益"的关系。
3. **方法二（H2）：** 从应急规划借来的非预判提交。被提交的前缀必须在所有可能的源未来下都成立。它不依赖在训练域学到的可靠性，所以对领域漂移稳健。

H3 和 H4 作为消融或备选。

## 9. 排除的方法与原因

- **测试流上的在线自适应**（TTT、Tent 一类）：你定了"不能在测试集调参"。
- **任何用教师模型生成训练目标的做法**（伪参考、Tailored Reference 的 RL 改写器、GPT 动作参考）：属于师生蒸馏。
- **token 级 RL / ES：** 已证实流水线对浮点扰动混沌，信号被淹没。
- **只做重新校准的方法**（温度缩放、MAP 平移）：第 2.1 节已经说明它们在原理上只是换阈值。
- **同一读里再做候选选择的变体：** 第 2.1 节已经说明改不了内容什么时候稳定。
- **Talker 侧的停顿或语速调整：** 之前已证实 ΔD1 ≈ ΔD2，延迟在 Thinker 一侧，Talker 侧最多只有 1～2% 的空间。

## 11. 你的决定（2026-11-27 CET）与据此的修改

1. **对齐工具：同意。** 查了已有数据，不需要再跑 SimAlign：
   - 之前用到 SimAlign 的只有两处分析脚本：v11 论文统计 RealSI 的语序交叉（测试集，只做分析），以及 gstar 多说话人线在 AMI 上的 deadline 审计。都不是训练数据，也不是 UniST。
   - 训练数据 `data/unist_simul_v1/rows`（107 万行，en 557k、zh 517k）已经包含：
     - `source_words`：Qwen3-ForcedAligner 给出的源词时间；
     - `word_links`：OmniAlign 词对齐；
     - 每个目标词的"证据时刻"，按 4 种规则各算一份（`support_{omni,argmax,suff,hybrid}_ms`），覆盖率 100%。
   - **和 H1 的需要基本一致，只差切法：**
     - 以前 LA-2 / SAP 用的是 hybrid 规则，目标在证据时刻之后（tau = support + 200 ms），不预判。
     - H1 要的是"证据时刻 ≤ t + 1 s"的目标前缀，也就是允许往前预判 1 s。
   - 所以 H1 只需要在 CPU 上按新规则重新切目标，几分钟，不重算对齐。
   - **H1 改用 `support_omni_ms`（只由对齐决定），不用 hybrid。** hybrid 里掺了 Thinker 自己的对数概率，用它做训练目标接近自蒸馏。omni 中没有链接的词（null）按前后单调闭包补齐。
   - **H4 的 Kendall τ 直接用 `word_links` 计算，也不需要 SimAlign。**
2. **H2 的算力：** 只在推理时多，没有训练。每读多两次批量调用：一次生成 4 个源未来，一次翻译这 4 个未来。
   - D2 按读的音频时刻计算，不计算力，所以指标不变。
   - 实验的墙钟时间变长约 2×。
   - 实际部署时，每读的计算要在 1 s 读间隔内完成。所以 H2 的测试会另外报告每读的实际计算时间（RTF）。超过读间隔的话，在报告里标明"需要更多 GPU 才能实时"。
