## 1. 现状问题（p3h8 = wave17 起草 + HSC6 后验 + n2 θ0.75 + N 的 talker）

| 问题 | 证据 | 谁能改 |
|---|---|---|
| 等待未听到的内容 | 被等待的是 wave17 的提前猜测（草稿领先真值支持约 1.3 读），存活 75–80%；后验类内 AUC 0.82 / 0.75；四种加证据的办法（HSC7、SDC、on-policy、K 采样一致性）均无效；oracle 上界 0.55–0.75 s | 只有起草者：让“猜测”变得可被验证，或少依赖猜测 |
| 停顿 | 28–33% 的读入零提交，断流间隙中位 0.8 s；talker 补不上（TS-PA）；即使 oracle 提前提交，停顿数也不降 | 只有起草者：每读都能给出可确认的文本 |
| 句末延迟 | 约一半单元在源结束后才写出 | talker 尾块加速（第 1 步，推理期） |
| BLEU | en2zh OBSI 与纯 LA2 持平，比 N 低 0.5–1.0 | 起草者 + 冻结的末读 |

结论：提交层在现有证据下已到上限；剩余空间在“起草者写什么、何时写成可确认的形式”。监督学习没有合适目标（参考译文是离线风格；用大模型改写参考属于蒸馏，用户不接受），所以用强化学习。

## 2. 调研结论

### 2.1 本项目以前的 12 条 RL / 偏好优化线（详表见调研记录）
- 只有两条被采用：NaturalFlow 式 DPO（静音比偏好对，按论文超参）、PL-EM talker（结构化 best-of-N）。所有 GRPO 线都是 NO-GO、持平或“有效但不支配”。
- 失败原因（必须规避）：
  1. **组内无对比**：4–8 个几乎相同的候选，std 归一化把噪声放大成满幅优势。
  2. **时延奖励被钻空子**：时延项主导时策略漂向过早、碎片化提交并掉 BLEU（W³PO、P4）；不对称惩罚则导致过度等待（Stage 7A）。
  3. **门控 / 饱和奖励没有梯度**（v3、content-first）。
  4. **只训提交头补不了内容**（v4：action policy 不能补回上游没有给出的内容）。
  5. **评测噪声大于 RL 效应**（重复循环、TTS 采样噪声）。
  6. **训练期期望与推理期确定性阈值不一致**（P5 拉格朗日、DLA）。

### 2.2 已发表工作（与本方案的区别）

文献空白（调研确认）：(a) 没有工作在概率提交后验之下训练“可被提交”的生成器；(b) 没有工作把冻结的级联 talker 的时序放进 RL 奖励；(c) 没有 RL 专门针对“提前猜测是否正确”；(d) “整段重起草 + 不可撤回提交到 TTS + 冻结 30B thinker 上的 LoRA”这一设置无人做 RL。

## 3. 方案：Drafter-through-Committer RL（DTC-RL）

### 3.1 形式化
- 起草者 π_θ（wave17 + 一个双向 LoRA，方向只作输入）在每读 t 输出整段草稿 d_t。
- 提交者 = HSC6 后验 q_φ（精确在线滤波）+ n2 阈值规则：位置 i 在 P_t(i) ≥ θ 的最长连续段内被提交，不可撤回。
- talker（冻结，含第 1 步的尾块加速）把提交块变成语音；用播放队列模型 + 实测每单元语速得到逐单元说完时刻（D2 代理）与间隙。
- 目标：max_θ E[Q(最终输出)] − λ·E[L_speech] − μ·E[N_pause]，并以“质量 ≥ 参照 − δ”为约束（拉格朗日对偶，λ 自适应）。

### 3.2 三个新的组成部分（创新点）

**(1) 信息设计奖励（解决“猜测不可分辨”）**
- 借鉴经济学的贝叶斯劝说 / 信息设计（Kamenica & Gentzkow 2011）与 Prover–Verifier Games（可检验性）：起草者是“发信者”，提交者是根据证据行动的“接收者”，双方目标一致。
- 奖励项：S = Σ_{t,i} log q_φ(y_i | 证据_{≤t})，即提交者对每个未提交位置“最终是否存活”的对数评分（严格合适评分规则）。
- 命题（待证，计划给出完整证明）：在提交者为其模型下的贝叶斯后验时，期望对数评分 = −H(Y | E) + 常数；最大化它等价于最大化“证据与存活的互信息”。所以起草者被激励让自己的可观测行为（读间一致、视角一致、SAP 支持、置信）**如实反映**猜测是否可靠：确定时稳定、不确定时不稳定或截短。它无法靠“假装稳定”获益，因为那会让提交者提交错误内容，同时降低 S 和最终质量（激励相容）。
- 这直接针对现在的瓶颈：问题不是提交者不够好，而是起草者的证据里没有“猜对还是猜错”的信息；本项让起草者把这一信息写进证据里。

**(2) 读级反事实分叉 GRPO（解决“组内无对比、稀疏奖励”）**
- 训练时源音频可重放：在随机选的读 t，从 π_θ 采样 K 个草稿（温度 0.8–1.0）；每个草稿经提交者得到不同的提交决定，然后从该状态用确定性策略续跑到句末，得到回报 R_k。
- 优势 A_k = R_k − mean_k(R)，只作用于读 t 的草稿 token。组内差异只来自读 t 的决定，保证有对比；回报是该决定的反事实价值（借鉴 VinePPO 的中间状态蒙特卡洛、RUDDER 的信用重分配）。
- 用真实的确定性提交规则做 rollout，消除训练期期望与推理期阈值不一致（项目内 P5 / DLA 的失败原因）。

**(3) 提交者与起草者共同适应（解决分布漂移）**
- 交替：若干步 RL 更新起草者 → 用新起草者的 rollout 按 HSC6 目标重拟合提交者（似然 + 对数评分）。
- 两者共享同一个对数评分项，构成一个势博弈；在精确最优响应下交替更新单调提升共享势函数（计划给出命题与证明）。借鉴 RL Tango 的验证器共训，但这里的验证器是闭式、精确滤波的贝叶斯模型，而不是另一个 RL 策略。

**附加：语音级时序奖励**——时延与停顿用冻结 talker 的播放队列模型计算（已验证：D2 ≈ 文本到达 LAAL + 固定说话耗时），不需要每个样本都合成语音；最终评测仍用真实合成 + ASR。

### 3.3 防作弊与稳定（对照项目内教训）
| 教训 | 对策 |
|---|---|
| 组内无对比 | 读级分叉：组内差异只来自一个决定；预检查 P0 先量对比度 |
| 时延被钻空子 | 提交由固定的后验 + 阈值把关，起草者只能通过证据影响提交；质量用约束形式（对偶上升），不靠固定权重 |
| 奖励饱和 / 无梯度 | 对数评分项在每个位置都有致密信号 |
| 只训提交头补不了内容 | 训练的是起草者（内容），不是提交头 |
| 评测噪声 | 训练和选择用文本 BLEU + 代理时序；真实语音只在最终测试用 |
| 风格漂移掉 BLEU | 对冻结 wave17 的 KL；句末读入用冻结 wave17（只有句中草稿用 LoRA） |

### 3.4 RL 只针对 thinker 文本吗？
- 被更新的参数只有起草者的 LoRA（thinker 文本）。
- 但奖励经过整条流水线：提交者（每轮重拟合，非 RL）、talker 时序（冻结，语速为推理期参数，第 1 步）。
- talker 不进 RL：今天的拆解显示 talker 不是 D2 / 停顿差距的来源，它的语速已能在推理期调节。

## 8. 补充：流畅度（2026-11-26 下午，用户提问后加入；网页版 rl_plan_20261126.html）

### 8.1 归因（diag_p3h8/decomp2、decomp3、ratesim）
- 句内停顿次数：只用提交时刻 + 固定单元时长重建的 NPrec 与真实合成 NP 相差 ≤0.17 → talker 几乎不贡献停顿；oracle“草稿一稳定就提交”的 NPstab ≈ 实测 → 停顿下限由起草者决定；p3h8 比 B_b 多的 +0.22 / +0.27 次来自提前提交的碎片化（RealSI en2zh 每块单元 4.5–4.7 对 5.1–5.2，零提交读 32–34% 对 30–31%）。
- 停顿时长 PT_in +0.38 / +0.54 s：零提交读 + 门控扣留 → thinker（起草者 + 提交者）。
- 尾部 EndOffset：42–60% 单元在源结束后写出（thinker）；talker 尾块加速可缓解（change 39 U1T3）。
- 碎片韵律 / 断词：talker / 播放通道（旧 SVC-JM 对 N：zh2en 文本 −0.15、ASR −0.88）。NC 与 B_b 基本持平。
- thinker 计算延迟（首次正确→稳定）0.07–0.15 s，远小于稳定→提交 0.5–0.66 s。
- 结论：停顿是 thinker 问题，talker 修不了（TS-PA；全局加速反而 +0.17..+0.21 次停顿）；talker 负责尾巴和碎片韵律。

### 8.2 方案补充
- F1 奖励中用播放队列代理的断流时长 Σ max(0, gap − 0.3 s) 替换停顿次数（对齐 PT_in，致密）。
- F2 均匀到达：惩罚零提交读与过小提交块；起草者可学更顺序的译法。
- F3（推理期）提交终点吸附短语边界（≤1 单元），即 11-25 的 E4，未运行。
- F4（推理期，需工程核查）未提交草稿作为 talker 不念出的韵律上下文。
- F5 尾块加速 U1T3 已完成。
- 目标：BLEU ≥ p3h8 − 0.3 且 ≥ B_b 约束下最小化 D2；断流时长作第二约束（不高于 p3h8），对偶变量自适应。
- 新预检查“P0 流畅度”：同一批分叉上，同 BLEU、同 D2 下最优分叉代理 PT_in −0.1 s 或零提交读 −3 个百分点；不通过则 F1/F2 不进奖励，流畅度只靠 F3/F4。
- 新增用户决定：(4) 流畅度是否作为第二约束进奖励；(5) 是否核查 F4。
