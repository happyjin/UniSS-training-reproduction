# 失败原因分析（2026-11-26 晚，汇总 change 35–44）

> 目的：把今天所有失败放进同一个解释框架，判断还剩哪些方向能移动“质量–时延前沿”。数据全部来自已登记的运行：
> p0rl（e1 500 / 方向）、es1、bi1b、p0r（e1 第 501–1000 行）、p0t（edev 500 / 方向）、diag_p3h8。

## 1. 一个单元从出现到被念出的时间线
对每个目标单元 u：
- **支持时刻**：音频里出现了它所需的内容；
- **首次写对**：起草者第一次在草稿里写出它（wave17 平均比支持早约 1.3 读，即“提前猜”）；
- **稳定时刻**：草稿此后不再改它（事后定义）；
- **提交时刻**：提交者把它交给 talker；之后是播放排队与说话时长。

实测（p3h8）：
| 阶段 | en2zh | zh2en | 来源 |
|---|---|---|---|
| 首次写对 → 稳定 | 0.07–0.15 s | 同 | diag_p3h8 |
| 稳定 → 提交：0 读 / 1 读 / ≥2 读 | 44% / 48% / 8% | 49% / 42% / 9% | p0rl（今天） |
| 平均提交等待 | 0.56 s | 0.52 s | 同上 |
| 最后一读才提交的单元 | 36% | 38% | 同上 |
| talker / 计算 | 不是差距来源 | 同 | diag_p3h8、change 39 |

**可控的时延就是“稳定后多等一读”。**

## 2. 这一读能不能省？——四条路都撞到同一堵墙
| 尝试 | 想省什么 | 结果 | 说明了什么 |
|---|---|---|---|
| 更多证据（change 35–38） | 在稳定当读就认出它 | AU 类（两读一致但 SAP 未支持）内 AUC 0.78–0.82，加证据 ≤ +0.01 | 起草者输出里关于“这次猜得对不对”的信息已用尽 |
| 降低阈值 | 冒险早提交 | 前沿约 0.4 s / BLEU | 只是沿前沿移动 |
| 更密的读取（P0-T） | 把“一读”从 1 s 缩到 0.5 s | D2 −0.95 s，但 BLEU −9..−10 | 确认需要约 1 s 的新音频，等待是信息性的，不是时钟造成的 |
| 按质量后悔提交（P0-R） | 只在改错也无害时早提交 | 未存活单元平均句级 BLEU −6..−8，有害可预测性 AUC 0.69–0.74 | 早提交错的内容代价大，且无法事先分辨哪些错是无害的 |

结论：**在冻结 wave17 下，“提交层”已接近证据上限**。剩下的前沿位置由两件事决定：起草者猜得有多准（存活率 75–80%），以及猜对与猜错能否从它的输出中分辨（AUC ≈ 0.8）。

## 3. 为什么改起草者也没成功
| 尝试 | 结果 | 原因 |
|---|---|---|
| token 级 RL 分叉（change 40） | 最优分叉 ΔD2 只有 −0.03 s / 读 | 一致性提交者下，独立采样两份草稿相同的概率是碰撞概率 Σp·q，分布不变也随熵下降，探索自我惩罚 |
| 参数空间 ES（change 41） | 一步 ES 在留出半上 −0.28 | 扰动不再自我惩罚，但单个成员效应（D2 ±0.05 s，BLEU ±1）低于噪声 |
| 批次不变内核（change 42） | 运行间差异 14–19% → 2–5%，未达 1% | 流水线对浮点扰动是混沌的 |

两点共同原因：
1. **目标对参数是不连续的**：贪心 argmax 草稿 + 逐字一致 + 硬阈值。近似平局的 token 一翻，整条提交轨迹就变。
2. **局部改动的真实效应很小**：在 wave17 附近，无论动作空间还是参数空间，能带来的时延改善只有几十毫秒；要大幅提升“猜得准”，需要新的信息来源，而不是在同一分布附近微调。

## 4. 今天新发现的一个“自损”
| en2zh，强制提交的字本身正确 | 组数 | 最终文本不变 | Δ句级 BLEU |
|---|---|---|---|
| 提交点在 token 边界 | 741 | 87% | −0.35 |
| 提交点在 token 中间 | 895 | 13% | −5.88 |

- 机制：提示词以半个 token 结尾（如“负 | 载均衡”），分词不规范，之后的 d0、d1、SAP 草稿都变差。
- 规模：p3h8 测试集 en2zh 20% 的句子至少有一次这样的提交（e1 上 25%）。zh2en 不受影响。
- 这是唯一一个不需要“猜得更准”就能收回的损失，正在用 P0-K（提交点对齐 / token healing）检验。

## 5. 方法论上的教训
- **比较必须同引擎配对**：同批次克隆之间差异 1.6–2.5%，不同作业之间 14–19%。以后所有变体比较都放进同一个引擎（hsc13 / hsc15 的做法），否则 ±0.05 s 级的差异不可信。
- **廉价的反事实预检查有效**：分叉 / 强制提交 / 多成员同引擎，每次 10–20 分钟就能否决一个方向，今天否决了 5 个，没有浪费训练算力。

## 6. 还剩什么能移动前沿
1. **收回自损**：P0-K（运行中）。工程修复，不是 ICLR 级创新。
2. **给起草者新的预测信息**（提高存活率本身），而不是在旧分布附近优化：例如演讲级上下文、对未听到内容的显式预测。须满足不蒸馏、开放数据。
3. **改变“单元级不可撤回提交”与“token 级模型”之间的接口**（第 4 节的现象说明这个接口本身会造成损失）：例如在字符级上精确地以已提交前缀为条件（对覆盖该前缀的所有 token 序列求和），使任意单元边界的提交都不改变模型分布。
4. 新一轮外部文献调研正在进行，结果将并入新的方案文件。
