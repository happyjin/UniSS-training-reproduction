## 3. 原因

1. **文本 LoRA 被 λ 的混合分布拉偏。** λ_L、λ_P 在 [0.003, 1] 上按对数均匀采样，算术平均约 0.17。LoRA 本身看不到 λ（只有 5 个特征的门控能看到），学到的是这个混合分布下的平均策略：更早、成块写出。
   - 非末块比例：P6 0.59 / 0.48，P5′ 0.36 / 0.32；平均块数 2.0（P5′ 2.5）。
   - 过早承诺导致文本 BLEU 下降：en2zh OBSI −5 到 −7，ASR 随之下降。
2. **成块写出造成语音排队。** 文本延迟 D1 与 N 持平（+0.04），语音延迟 D2 却 +0.2 到 +0.9。一大块文本写出后，语音只能按语速顺序播放；停顿极少也是因为块少。
3. **控制器几乎没起作用。** 控制量是文本滞后 t − W/ρ，看不到语音排队，因而认为已经达到设定点：λ_L 末值中位数 0.068（λ0 为 0.055），只有 5% 打到上限。另外，前 2 s 文本滞后天然低于设定点，控制器会先把 λ 往下调。

## 4. 方案（第二版 P6b，变更 13，已启动）

- 文本 LoRA 冻结在 P5′（测试集 ASR 与 N 持平），只训练 λ 条件门控；
- 控制器改用语音滞后（含播放队列），只在 t > L* 后更新；
- 设定点用 6 个 dev 系统重拟合：R² 0.994 / 0.996，P6 也落在线上。
