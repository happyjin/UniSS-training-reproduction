## HSC4 诊断（2026-11-25 20:30 CET；脚本 reports/sst_hsmm_v1/diag_hsc4/）

1. **HSC4 ≈ SVC-JM。** 每个测试单元的提交结构（块数、块大小、首写时间、尾块单元数、NP_in、PT_in、D2）与 SVC-JM 几乎相同。后验在 N 底座之外多提交的单元 100% 有 SAP 支持，87–99% 超出两读一致前缀，只有 2–13% 超出跨视角前缀。学到的发射以 SAP 支持为主（似然比约 20 倍），所以 θ 只在 SVC-JM 那一点附近移动。
2. **后验严重失准且偏悲观，并随观测读数增加而加重。**
   - 测试集上未提交的位置：P < 0.02 的实际保留率 0.24–0.35；P ≥ 0.9 的只有 0.77–0.83；决策区 P 0.5–1.0 内保留率几乎是平的（0.66–0.85）。
   - 训练集（h1 UniST 展开，h9）同样：P < 0.02 的保留率按观测读数 T = 1 / 2 / 3 / ≥4 为 en2zh 0.20 / 0.36 / 0.44 / 0.52，zh2en 0.21 / 0.37 / 0.48 / 0.68。
   - 原因：a、v、sq、qN 是同一 Thinker 信念的相关读数，同一证据又在每一读重复出现，朴素乘积把它们重复计数。另外，潜在状态 S 要求"以后再也不变"，比提交真正需要的"最终保留"更严格。
   - 后果：长条目（RealSI）每个位置的读数多，后验更悲观，单元被扣得更多，这正是 RealSI 剩余时延和长停顿的来源。
3. **停顿规则基本失效。** θ−0.1 在 74–93% 的读上触发（播放队列几乎总是空的），等于全局 θ = 0.7。en2zh RealSI clean 有 55% 的额外提交发生在队列仍忙时，提交没有带来语音时延收益，却承担了 BLEU 风险。额外单元中 22–62% 在首次出现时就被提交。
4. **证据价值随条件变化。** 同一翻译模型下，zh2en RealSI 的纯 LA2 支配 HSC4（ASR +0.41 / +3.11 对 +0.36 / +3.06，D2 −0.11 / −0.07 对 −0.07 / +0.25）。en2zh RealSI noisy 的门控换来 +1.2 BLEU（+0.19 s）。OBSI 中 HSC4 支配 LA2。
5. **停顿来源。** 次数随非最终块数和小块比例上升；时长来自门控扣留（RealSI en2zh：同一翻译模型的 LA2 PT_in 1.51–1.58，HSC4 2.03–2.09，B_b 1.47–1.49）。最终块占条目单元的 45–60%。
