# 失败原因分析与新方法方案（2026-11-26 晚，草案，未登记、未运行）

> 依据：change 35–42 的结果（iterations_20261125.zh-CN.md）、diag_p3h8、今天的提交滞后统计（p0rl 基线，下文 §1.1）、外部文献检索（§5）。
> 约束沿用：单一双向模型（所有训练部分）、不用蒸馏、只用开放数据训练 / 选择、RealSI / OBSI 只测一次、BLEU 优先其次 speech LAAL、流畅度改动不得降低 ASR-BLEU、对比 B_b 全指标。

## 1. 当前失败原因（逐层）

### 1.1 时延到底花在哪里（今天新算，p3h8 策略，e1 500 条 / 方向）
| 已提交单元：从“草稿在此后不再变”到“被提交”的等待 | en2zh | zh2en |
|---|---|---|
| 0 读（稳定当读就提交） | 44% | 49% |
| 恰好 1 读（多等一次确认） | 48% | 42% |
| ≥ 2 读 | 8% | 9% |
| 平均等待 | 0.56 s | 0.52 s |
| 在最后一读才提交的单元 | 36% | 38% |

- 早先的拆解：talker 不是 D2 / 停顿差距的来源；thinker 计算延迟（首次写对 → 稳定）只有 0.07–0.15 s。
- 结论：**可控的时延几乎全部是“多等一读确认”**，约一半单元为此等了 1 s。

### 1.2 为什么提交层的改进饱和（change 35–38）
- 想消除这一读的等待，提交者就得在单元第一次出现的那一读提交它，而这类单元（AU：两读一致但 SAP 未支持）的存活率只有 75–80%。
- 后验在 AU 类内的 AUC 0.78–0.82；四种加证据办法（尾距、学习头、on-policy 重拟合、K 采样一致性）最多 +0.01。
- 降 θ 是沿同一条前沿移动：edev 上 θ 0.80 → 0.65，代理语音时延 −0.33 s，BLEU 赤字 0.05 → 0.85；越过低谷提交（r1）BLEU −2.6..−3.9。

### 1.3 为什么起草者强化学习失败（change 40–42）
- **token 级探索自我惩罚（change 40）**：采样的 d0 与仍为贪心的 d1 不一致，LCP(d0, d1)/|d0| 从 0.77–0.81 降到 0.41–0.45，该读少提交 0.9–1.5 单元（只有 2% 多提交）。
  独立采样下两份草稿一致的概率等于碰撞概率 Σ p(y)q(y)，即使分布完全没变（p = q）也随熵下降。所以探索得到的回报系统性偏低，梯度只会“贴近贪心”。
- **参数空间探索信噪比不够（change 41）**：扰动成员不再自我惩罚（D2、零提交读持平），但单个成员的效应只有 D2 ±0.05 s、BLEU ±1；
  成员效应在两半数据间相关 0.18，ES 方向在 A 半 +0.33、B 半 −0.28。
- **流水线对浮点扰动是混沌的（change 41–42）**：同一模型只因批次组成不同，14–19% 的条目提交轨迹不同；批次不变内核下仍有 2–5%；换数值内核则约 50%。

### 1.4 共同根因
提交准则是“**贪心草稿的字符串在下一读仍然一样**”。它同时造成三件事：
1. **不连续**：argmax 草稿 + 精确字符串一致 + 硬阈值，是参数的分段常数函数。近似平局的 token 一翻，整条轨迹就变（混沌），学习信号被淹没。
2. **惩罚探索**：任何随机性都会破坏“一致”，所以动作空间强化学习学不到东西。
3. **过于保守**：它等待的是“字符串不变”，而真正的目标是“最终质量”。一个单元以后只是换了个说法（杂务 / 家务、“did it” / “did”），提交它几乎不损失质量，但现在的规则必须等它确认。

所以下一步不该再加证据，也不该在冻结的准则下训练起草者，而是**换提交准则本身**：从“字符串存活”（0-1 损失）换成“提交造成的预期质量损失”（任务损失），并让准则对模型分布连续。

## 2. 主方法 M1：后悔认证的提交（Regret-Certified Commitment, RCC）

### 2.1 思想
- 现有提交规则（LocalAgreement、HSMM 存活后验、SAP 校验）都相当于投机解码里的“无损验证”：只接受与最终结果逐字相同的内容。
- Judge Decoding（ICLR 2025 oral）和 Speculative Cascades（ICLR 2025 oral）表明：按“质量”而不是“逐字一致”来接受草稿，可以大幅提速而不降质。
- RCC 把这一点搬到不可撤回的流式生成：**提交一个单元的代价，是提交后最终译文质量的期望下降（后悔），而不是它将来是否被改写。**

### 2.2 做法
1. **反事实提交 rollout（标签，便宜）**：在训练音频上，于随机读 t 强制多提交 k 个草稿单元（k ∈ {1, 2, 4}，超出 p3h8 的切点），之后按 p3h8 确定性跑到句末；
   同组放一个 k = 0 的空分叉作对照，抵消混沌噪声。后悔 = 对照的句级质量 − 强制提交后的句级质量（chrF / BLEU，参考译文，不是教师输出）。
   这套分叉机制已在 hsc11 实现，P0 每 125 条约 2 分钟 / 卡。
2. **后悔模型（单一双向小模型，方向作输入）**：输入为每个候选单元的现有证据（HSC 后验 P、d0 / SAP token 对数概率、跨视角与读间一致、SAP 支持、年龄、读序、标点、目标语言），
   外加“语义层面的一致”特征（d0 与 d1 / 上一读草稿在未提交尾部的 chrF，而不是逐字 LCP）。输出提交后的期望后悔 r̂。
3. **提交规则**：在 p3h8 的切点之后，继续提交最长前缀，使累计 Σ r̂ ≤ λ。λ = 0 退化为 p3h8。
4. **质量保证（Conformal Risk Control / Learn-then-Test）**：在开放的 UniST dev（edev）上用 Learn-then-Test 选 λ，保证相对 p3h8 的期望句级质量下降 ≤ α 的概率 ≥ 1 − δ
   （有限样本、无分布假设，只要求可交换）。α 设为一个固定值（例如 0.3 BLEU 对应的 chrF），不在测试集上调。

### 2.3 新颖性与 ICLR 论点
- **问题一般化**：不可撤回的流式生成（同传、实时字幕、流式 ASR 的 LocalAgreement、带外部动作的 LLM 代理）。现有方法都用“稳定性 / 一致性”作为提交准则。
- **主张 1（决策论）**：存活准则只在 0-1 字符串损失下是 Bayes 最优；在任务损失下，后悔准则的提交集合包含存活准则的提交集合，质量–时延前沿不劣于后者，差距等于“无害改写”的比例。
- **主张 2（认证）**：首个对流式不可撤回提交给出有限样本质量损失保证的方法（借 CRC / LTT）。
- **主张 3（标签可得）**：可重放的流使反事实后悔可以廉价、精确地测量（不是估计的 Q 值），并用空分叉消除混沌噪声。
- 与已发表工作的区别：同传里的 LocalAgreement、Dynamic Lagging（稳定前缀蒸馏，arXiv 2609.05799）、Learning When to Commit（置信度阈值，arXiv 2610.02612）都以字符串稳定或置信度为准则，没有用质量后悔，也没有认证；
  Judge Decoding / Speculative Cascades 的验证是当场的，没有不可撤回性和未知未来；CRC / CLM 没有用于流式提交。

### 2.4 风险
- r1（change 35）显示越过低谷提交代价很大：如果非存活单元大多有害，后悔模型不会比 P 好多少。预检查 P0-R 直接量这一点。
- 混沌噪声会让单条后悔标签很嘈杂：用 k = 0 空分叉对照，并按组平均。
- 测试集分布与 edev 不同（RealSI 更密），CRC 保证在分布偏移下不严格成立：论文中如实写，并报告实测。

## 3. 辅助方法

### M2：耦合一致性（Coupled Agreement, CA）——让一致性证据连续、让探索不自我惩罚
- 做法：每读用共享 Gumbel 噪声（按条目、输出位置、样本序号固定）同时为两个视角、相邻两读生成 M 份草稿；
  “一致的概率”取 M 份里两读 / 两视角在前缀上逐字相同的比例。贪心 LA2 是 M = 1、零温度的特例。
- 理论：独立采样的一致概率 = Σ p q，p = q 时也随熵衰减（解释 change 40）；Gumbel 耦合下一致概率 ≥ (1 − TV)/(1 + TV)（Daliri et al.），只取决于分布变化，并且对 logits 连续（缓解混沌）。
- 用途：作为 RCC 的特征（降低标签噪声）；也让以后在 RCC 之上训练起草者时，探索不再自我惩罚，并能用公共随机数（CRN）比较不同参数。
- 风险：change 38（独立 K 采样一致性）只给 +0.01 AUC；耦合一致性衡量“分布变化”而不是“熵”，可能不同，但区分能力的提升不确定，所以作辅助而非主方法。

### M3：按信息到达调度重起草（读取粒度）
- 一半单元多等的“一读”是 1 s 时钟造成的。若在 0.5 s 读取下，两读一致的证据仍足够，确认等待可减半。
- 方法化：在计算预算内（例如平均每 0.5 s 一次起草）按“这次起草能让多少单元越过阈值”的期望值决定何时重起草（主动序贯检验、事件触发采样）。
- 新颖性中等（偏系统），但它可能是最大的单项时延来源，值得先量。

## 4. 预检查（都不训练，可并行，合计约 1–1.5 小时）
| 预检查 | 内容 | 门槛（拟） |
|---|---|---|
| P0-R（M1） | e1 新的 500 条 / 方向（第 501–1000 行，未用过），每条 2 个读，k ∈ {0, 1, 2, 4} 强制多提交，p3h8 续跑；k = 0 为空分叉 | (a) 非存活的强制单元中，无害（ΔchrF ≥ −1，相对空分叉）的比例 ≥ 30%；(b) 交叉验证的有害预测 AUC 比只用 P 高 ≥ 0.05；(c) 在 A 半选阈值、B 半检验：每分叉读 ΔD2 ≤ −0.05 s 且语料 BLEU 不低于空分叉 0.2 以上 |
| P0-C（M2） | 同一批条目：耦合采样（M = 4）下重做 token 分叉，看是否仍自我惩罚；耦合一致性在两次不同批次运行间的改变比例；AU 类内 AUC | 分叉平均 D2 不比贪心差 0.02 s 以上；改变比例 ≤ 5%；AUC 比 HSC P 高 ≥ 0.03（达到才作为特征保留） |
| P0-T（M3） | edev 500 条 / 方向，纯 LA2（同一 wave17，无跨视角）在 1.0 s 与 0.5 s 读取下的 BLEU 与代理 D2 | 0.5 s：代理 D2 ≤ −0.15 s 且 BLEU 不低于 1.0 s 0.3 以上 |

- 结论规则：P0-R 通过 → 登记 M1 全量（后悔模型训练、edev 上 LTT 选 λ、测试一次）；P0-T 通过 → M3 与 M1 叠加（M1 的标签在新读取粒度下重做）；P0-C 只决定 M2 是否作为特征 / 训练工具。
- 若三者都不过：在冻结 wave17 下，提交准则、证据和起草者三条路都已穷尽，需要换问题设定（例如允许口头修正、或换评测参照）。

## 6. 需要用户决定
1. 主方法是否采用 M1（RCC）。
2. 预检查跑哪些：建议 P0-R + P0-T 并行（各约 30–40 分钟），P0-C 视 P0-R 结果再定。
3. 质量损失的度量：后悔标签用句级 chrF（低噪声），保证与报告用 BLEU；还是两者都用 BLEU。
