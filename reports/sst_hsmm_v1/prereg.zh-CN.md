## 1. 数据（只用 UniST）

**行：** `data/unist_simul_v1`（hybrid 规则）中、同时在 `data/unist_simul_train_v2` 质量索引里的行，源长 3–15 s。

**排除：**

- UniST 留出：crc32(id) % 50 == 0；
- 与任何评测或测试集源文本重叠：沿用 `wave14_data.harvest` 和 `norm` 的判定。

**划分：**

- 训练：每方向按 sha1("20261122|hsmm|<dir>|<id>") 取前 20000 条。
- 留出：crc32 % 50 == 0 且不重叠的行，每方向按同样的 sha1 取前 1000 条，用于 P0 和 λ 校准。

**单位：** Thinker 对参考译文分出的 token。

- **对应关系：** 每个 token 按字符偏移对应到 `target_words` 中的词。
- **下界：** 每个 token 的最早可写时刻 t̃ᵢ = cummax(该词的 `support_hybrid_ms`)；纯标点 token 继承前一个 token。
- **下界块：** gᵢ = clip(ceil(t̃ᵢ / 1000), 1, C)，其中 C = ceil(X / 1000)。
- **语音时长 dᵢ：** 词的时长 = min(下一词开始, 本词结束 + 300 ms) − 本词开始，按目标语音时间计，在该词的 token 间均分；标点时长为 0，并标记 πᵢ = 1。

**动态加噪（on-the-fly，只用于训练）：**

- 每个样本以 0.5 的概率保持干净；否则从 {music, crowd, sfx} 中均匀选一种环境，噪声池用 `wave1_data.bg_pools("train")`（与 wave5 相同）。
- 噪声强度（BVR）取开放 dev `bench_dev` 的 60 个 BVR 值在 U(0.05, 0.95) 分位处的值，不再用 game/esports 的统计量（那是评测数据）。
- 0.02 s 淡入淡出，峰值限幅 0.99。
- 随机数种子为 sha1("20261122|hsmm|mix|<step>|<rank>")。
- 同一样本的所有前缀都取自同一条混音。

**留出集的带噪版：** 每条用固定种子混一次，写成 wav（评测集可以落盘）。

## 2. 模型与目标

**前缀前向：** 对样本的每个块 c = 1..C，输入为 [wave5 的 prompt 头 + 音频 ≤ min(c s, X)] + 参考译文 + `<|im_end|>`，教师强制，一次前向（C 条作为一个 batch）。由此得到：

- log p_θ(yᵢ | 音频 ≤ c, y_{<i})；
- 在预测 yᵢ 的位置上，等待 token 的概率 P_w(c, i)。

推理时每块也是"音频前缀 + 已写文本"重新输入，与训练逐位一致。

**状态：** (i 已写 token 数, s 语音积压/静音, f 末个已写 token 是否为标点, started)。

- s 以 100 ms 分桶，取值 [−3, +8] s：正值为待播语音，负值为已静音的时长。

**块 c 内的转移：**

- 只有 c ≥ gᵢ 时 token i 可写。
- 写出概率 w = σ(ℓ_θ(c,i) + g_ψ(s, f, started, c/C))，其中 ℓ_θ = log(1−P_w) − log P_w；g_ψ 为 4 → 32 → 1 的 tanh MLP，输出层初始化为 0。
- 写出后的发射为 log p_θ(yᵢ) − log(1 − P_w)。
- 状态更新：
  - 若 started 且 s ≤ −0.3 s 且 f = 0，记一次短语内停顿；
  - s ← max(s, 0) + dᵢ，f ← πᵢ，started ← 1。
- 块结束时以 1 − w 等待，然后 s ← max(s − 1 s, −3 s)。
- 最后一块 C：剩余 token 强制写出，写出时刻按 X 计。

**代价：**

- 每个 token 的延迟为 λ_L · min(e_i, X)，其中 e_i = 写出时刻 + 写后积压（秒）；
- 每次短语内停顿计 λ_P。

**损失：**

L = −(1/n) · log Σ_z exp( Σ log w/(1−w) 转移 + Σ 发射 − λ_L Σ min(e_i, X) − λ_P · #停顿 )

- 在 (i, s, f, started) 格子上逐块、逐 token 精确前向，一次反传，同时更新 Thinker LoRA 和 g_ψ。
- 这是"似然 + 语音层代价"的倾斜边缘似然：转移概率由 Thinker 自身和 g_ψ 给出，路径必须满足下界。

## 3. 步骤与判定

### 3.1 P0（GPU，卡 0–7）

**P0a：LAAL 空间。**

- 在留出集每方向 1000 条、干净和带噪两种条件上，用 UE Thinker 跑 plain LA2（`combo_si_thinker --second-view none`，窗口 1 s）。
- 比较两种文本单位 LAAL：
  - (i) LA2 的提交；
  - (ii) 参考译文按 gᵢ 块写出（oracle）。
- 两者都用 `si_metrics.laal`，单位为提交时刻，参考长度相同。
- 同时按 2 节的语音动态，计算两者的语音延迟代理和短语内停顿次数。
- **GO 条件：** 两个方向（两种条件合并）的 (i) − (ii) 都 ≥ 0.3 s。

**P0b：可行性。**

- 在留出集每方向 300 条上做前缀前向。
- 检查：token i 在 gᵢ 块的对数概率，减去在 gᵢ − 1 块的对数概率，其中位数 > 0。
- 计量：1 张卡上前向加反向每条样本的耗时和显存。

**P0c：λ 校准（只用留出集）。**

- 网格：λ_L ∈ {0.02, 0.05, 0.1, 0.2, 0.5} nat/(token·s)，λ_P ∈ {0.5, 1, 2, 4} nat/次。
- 对每组 λ，在 P0b 的发射上，求"只含发射和代价、转移均匀"的最优路径（Viterbi）。
- 在满足以下两条的组合里，取每 token 发射对数概率最高的一组；并列时取停顿更少的一组：
  - 路径延迟代理 ≤ LA2 的同一代理 − 0.3 s；
  - 短语内停顿 ≤ LA2 的 0.7 倍。
- 都不满足时，取延迟代理最低的一组并报告。

**训练时长规则：**

- 默认 2500 步，每步 16 条（每卡 2 条），即 4 万条、1 个 epoch。
- 若 P0b 估计超过 30 h，按比例减少步数，使其不超过 30 h。

### 3.2 P1a：Thinker + HMM 训练（8 卡，torchrun）

- 学习率：LoRA 1e-4，g_ψ 1e-3，AdamW，余弦衰减到 0，warmup 100 步。
- 种子 20261122；不做梯度裁剪；单一设置。
- 每 500 步保存 adapter 和 ψ，取最后一个。
- 训练完成后，合并 LoRA 得到 vLLM 用的整模型。

### 3.3 推理

- 每 1 s 一块，输入为 prompt 头 + 音频前缀 + 已写文本，vLLM 贪心解码。
- logits 处理器在等待 token 的 logit 上减去 g_ψ(s, f, started, c/C)，其中 s 按每个已写 token 的平均语音时长推进（从训练数据按语言统计）。
- 生成到等待 token 为止，等待 token 本身不写出。最后一块禁止等待，生成到 `<|im_end|>`。
- 输出的块文件格式与 si_infer 的 `--text-policy file` 相同。
- 其后为卡尔曼 + AbS 音色（p3_decide / p3_search，以第一次写出为开口）、T1c（`--speed-policy block`，种子 20261021），以及只做切点前移的播放器。

### 3.4 P1b：Talker 一起优化

- 用 P1a 模型在训练行（干净）上求最优路径 ẑ，把 ẑ 的写出时刻作为新的"支持时刻"列（规则名 hsmm），写成新的 SI 索引。
- 按 T1c 自己的训练配方（从它的启动记录恢复参数），以 T1c 为起点继续训练 500 步，hsmm 轨迹与原池各占 50%。
- 若 T1c 的配方无法恢复，P1b 不做，并在报告中说明。
- 推理时 Talker 用 P1b 的产物；同时报告用 T1c 的版本。

### 3.5 P2：开放 dev 实跑（门槛）

- **数据：** wave17 dev（3286 条）。
- **对照：** `wave17/eval_enc_wise05`（UE 不含 CV-LA，LA2）加 T1c 的已存运行。
- **GO 条件（每方向合并）：** ASR-BLEU 差 ≥ −0.5，语音 LAAL（D2）差 ≤ −0.2 s，短语内停顿次数 −30%。
- 不通过就停下报告，不调参。

### 3.6 P3：测试（10 单元，与 P3 和 S0–S2 相同的协议）

**系统：** B_b、N（UE_mbr）、NEW（HSMM Thinker + 卡尔曼 AbS + T1c）；如果做了 P1b，再加 NEW+Talker。

**规则（NEW 对 N，每格）：**

1. ASR-BLEU 差 ≥ −0.3，且 CI 上界 ≥ 0，10 格全满足；
2. D2 差 < 0 的格数 ≥ 8；
3. NP_in 下降 ≥ 30% 的格数 ≥ 8；
4. NC 下降 ≥ 50% 的格数 ≥ 8。

身份（ECAPA2）差的 CI 下界 ≥ −0.01，报告但不作为判定条件。四条全满足，NEW 才算成立。

## 变更 1（2026-11-22 16:03 CET，P0 运行之前）

**冒烟测试的观察：**

- 测试规模：1 张卡、3 条留出样本，只检查代码，不是结果。
- 前向加反向约 2–3 s/条，显存峰值 66 GB。

**修改：**

- g_ψ 输出层的偏置初始化为 b₀ = −median(ℓ)，取 P0b 发射中所有可写位置（c ≥ gᵢ，不含最后一块）上 ℓ 的中位数，由 p0_analyze 计算并写入 summary。初始时写和等大致各半，梯度可以流动。
- 这等价于给等待 token 的 logit 加一个可学习的常数偏置。推理时 logits 处理器同样在等待 logit 上加 −g_ψ（含该偏置），训练与推理一致。
- 其余不变。

## P0 结果（2026-11-22 18:17 CET）

**运行事故：** 第一次 p0_analyze 卡了 2 小时，原因是 96 个 Viterbi 进程各开 192 个 torch 线程，系统负载约 3500。按 PID 停止后，每进程限 1 线程重跑，32 s 完成。结果是确定性的，与线程数无关。训练脚本同样限为每 rank 4 个 CPU 线程。

**P0a：GO。** 文本 LAAL 中 LA2 比 oracle 多：

| 方向 | 差值 | 干净 LA2 / oracle |
|---|---|---|
| en2zh | +0.602 s | 2.265 / 1.666 |
| zh2en | +0.591 s | 2.323 / 1.719 |

**P0b：通过。**

- 1200 条，token 不匹配 0；
- 各分片 lp(g) − lp(g−1) 的中位数为 0.060–0.087；
- ℓ 的中位数 27.8 nat，门控偏置初值取 −27.8；
- 每条 2.61 s，估计每步 6.2 s，2500 步约 4.3 h，所以用 2500 步。

**P0c：没有组合满足条件**，按规则回退到延迟代理最低的 λ_L = 0.5、λ_P = 0.5。

## 变更 4（2026-11-22 20:15 CET，P1a 停训重训；任何 P2 数字之前）

**发现（变更 3 诊断，step 500，留出 1200 条）：** `hsmm.lattice` 对 c < gᵢ 的块直接跳过，强制等待那一步的转移概率 log(1 − w) 没有计入似然。于是梯度只在"可写时等待"的位置推高 P_wait，其余都在推"多写"：

| | step 0 | step 500 |
|---|---|---|
| 可写位置（c ≥ gᵢ）写出比例 | 50% | 94% |
| 不可写位置（c < gᵢ）写出比例 | 10% | 26% |
| ℓ 中位数（可写 / 不可写） | 27.8 / 23.6 | 32.1 / 24.3 |
| Viterbi 写出块 − gᵢ | 1.26 | 0.05 |

推理时没有 gᵢ，不可写位置上的写出就是在没听到的内容上提前写，会伤 ASR-BLEU。

**修改：**

- **目标（修正为第 2 节的完整概率模型）：** 不可写的块里，路径以 1 − w 等待，记入 log(1 − w)（用该位置的 P_wait 与门控）。最后一块不变；P0c 的均匀转移（uniform）不变。已用暴力枚举在 40 个随机小实例上核对，最大误差 7.9e-7。

3. **训练（`train_risk4.py`）：** 每个样本 λ_L、λ_P 独立按对数均匀抽取（sha1 键 "20261123|p6|lamL|s|j"、"…lamP…"）；损失 q/n + λ_L·L + λ_P·P + 翻译 NLL。没有预算，没有对偶上升；1000 步。
4. **推理（`e2e_si_thinker`，`SST_CTRL`）：** 阈值 0.5、`SST_BLOCK_S=0.2` 不变。

   - λ_L 初值、λ_P 固定值都取范围的几何中点 0.0548。
5. **设定点 L\*（`p6_control.py`，P6 训练前已算好，`p6/control.json`）：**
   - 在 dev 上对已有 5 个 HSMM 系统（P2、P2′、P2″、P2‴、P2⁗）按方向拟合 D2差 = a + b·lag，取 D2差 = −0.10 s（变更 8 的目标）对应的 lag。
