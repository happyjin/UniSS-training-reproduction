# 为什么 HSMM 系列都比 N 差：原因拆分（2026-11-24 17:50 CET）

## 1. 按句拆分：ASR 损失几乎全部来自"停顿将至强提交"

- over>0 = 该句至少有一次停顿将至时的强提交，over=0 = 一次都没有。
- 测试集结果，text BLEU 相对同一批句子上的 N。
- 脚本为 p8_override_split.py，root 换成 p3o / p3m。

| 系统 | 方向/组 | over>0 句数 | over>0 差值 | over=0 句数 | over=0 差值 | over=0 与 N 完全相同的比例 |
|---|---|---|---|---|---|---|
| P11 | en2zh RealSI | 555 | −5.52 | 137 | −0.86 | 72% |
| P11 | en2zh OBSI | 1107 | −7.98 | 648 | +0.98 | 64% |
| P11 | zh2en RealSI | 677 | −6.80 | 185 | +0.34 | 69% |
| P11 | zh2en OBSI | 1045 | −6.52 | 989 | −0.65 | 86% |
| P9 | en2zh RealSI | 289 | −0.37 | 403 | −0.21 | 42% |
| P9 | en2zh OBSI | 479 | +0.33 | 1276 | +1.88 | 54% |
| P9 | zh2en RealSI | 354 | −2.17 | 508 | −0.10 | 57% |
| P9 | zh2en OBSI | 436 | −2.23 | 1598 | +0.16 | 68% |

- 没有强提交的句子与 N 持平（−0.9..+1.9）。也就是说，HSMM 时间模型加局部一致提交本身不伤翻译。
- 损失集中在强提交的句子上：
  - P11 中这类句子占 50–80%，每句 −5.5..−8；
  - P9 用跨模型一致约束强提交，en2zh 基本无损，zh2en 仍为 −2.2。
- P10 / P11 变差的直接原因：
  - 写出头退化为总是写，首次写出更早，强提交频率翻倍（每句 1.06 次，P9 为 0.46 次）；
  - 单模型下强提交的内容就是未经验证的贪心续写，P9 的跨模型一致过滤不再起作用。

## 2. 等时延下 HSMM 确实优于"N + 起播缓冲"

P9 与 N 加缓冲 δ 在相同 D2 下比较：10 个格子停顿全部更少（−22..−52%），见下表。

| 格子 | P9 NP_in | N + δ 的 NP_in | δ (ms) |
|---|---|---|---|
| en2zh RealSI clean / noisy | 0.70 / 0.66 | 0.90 / 0.90 | 834 / 659 |
| en2zh OBSI clean / id2 / ood1 | 0.39 / 0.33 / 0.36 | 0.62 / 0.69 / 0.69 | 418 / 229 / 260 |
| zh2en RealSI clean / noisy | 0.77 / 0.78 | 1.07 / 1.09 | 201 / 0 |
| zh2en OBSI clean / id2 / ood1 | 0.29 / 0.24 / 0.22 | 0.41 / 0.47 / 0.44 | 283 / 103 / 148 |

P9 的 ASR：en2zh 为 −1.0..+1.0，zh2en 为 −0.8..−1.1。

## 3. 结论

1. 停顿来自译文到达得晚。在不增加时延的前提下要消除停顿，只有两条路：
   - **更好的调度：** 无损，但收益有限；
   - **在未确认前提交预测：** 有损。
   调度本身不产生新信息，所以要在 N 自己的时延点上同时满足 ASR 不降、D2 不升、停顿 −25%，必须依赖强提交，代价就是 ASR。帕累托门槛要求在三个维度上都严格不差于 N，按目前的机制几乎不可能。
2. 思路中成立的部分：
   - 语音时间轴感知的写出时机，在等时延下停顿明显少于朴素缓冲；
   - 不强提交时翻译无损。
3. 不成立的部分：
   - 用训练（LoRA 或写出头）让模型学会"何时可以安全地提前提交"：LoRA 改变了译文风格，写出头学不到信号；
   - 在 zh2en 上，语序差异让提前提交天然有损。
4. 建议的定位：
   - 论文主张改为"等时延下停顿更少、ASR 持平"，与 N + 缓冲对比；
   - 强提交只在有独立证据（跨模型一致）时进行；zh2en 若仍有损，则不做强提交，宁可停顿。
