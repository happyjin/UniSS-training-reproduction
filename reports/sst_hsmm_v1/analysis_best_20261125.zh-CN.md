# 当前最好方法分析与下一步方案（2026-11-25，主对照 B_b）

## 1. 当前最好方法：SVC-JM（第 6 轮）

- **按 BLEU 最高算**仍是 N（LA2 + 跨视角一致，wave17 encoder LoRA），但它的语音 LAAL 比 B_b 高约 0.35 s。
- **按 BLEU 与 LAAL 两个主指标综合**，最好的是 SVC-JM：
  - 在 N 的基础上，加一个只学"语音支持边界"的 LoRA（SAP）作为同读验证器。
  - 只有 N 和 SAP 对 token 的概率都 > 0.5 时，才提前提交。
  - 内容永远来自 N，无训练（验证器是第 4 轮训练好的 SAP）。
- **不是 HSMM 方法。** HSMM 线（P2–P11，P9 最好）已在 11-24 关闭。现在的 N / SVC / SVC-JM 都不用 HSMM。

### 读法

- **BLEU：**
  - 10 个单元 SVC-JM 全部高于 B_b：ASR +0.47..+3.89。
  - robust 单元增益最大：zh2en RealSI noisy +3.89，与 N 相同；OBSI 噪声单元 +1.7..+2.6。
  - clean 单元增益小：en2zh OBSI clean 只有 +0.47，N 为 +1.37。
- **LAAL：**
  - clean 和 OBSI 单元与 B_b 基本持平：−0.10..+0.16 s。N 为 +0.17..+0.40。
  - RealSI noisy 仍比 B_b 晚 +0.25..+0.29 s。
- **PESQ / sim：**
  - PESQ 噪声单元 +1.2..+1.7，因为输出语音更干净；音色相似度 +0.004..+0.08。这两项都与 N 持平，略低约 0.01。
- **流畅度 / 停顿（主要短板）：**
  - 每条的句内停顿 NP_in（> 300 ms）比 B_b 多 +0.11..+0.45 个，比 N 多 +0.12..+0.33。
  - 句内停顿总时长 PT_in 多 +0.19..+0.89 s；zh2en RealSI 最差。
  - 浊音中断 NC 比 N 多 +0.05..+0.15。
- **尾部：**
  - EndOffset（源语音结束到译文语音结束）比 B_b 多 +0.05..+0.74 s，比 N 少约 0.2–0.3 s。

## 3. 问题与原因（数据支持）

1. **同等时延下没有严格超过 N（测试）。**
   - dev 上每条第一个额外提交段，与 N 最终译文同位置相同的比例约 0.82。这个比例在 clean / noisy、提交类型、段内位置之间都没有差别。
   - 原因是"已被语音支持 ≠ 译法已确定"：两个共享底座的模型同读都相信当前草稿，但更多音频会改变译法（尤其 zh→en 的语序调整）。
   - 0.5 置信门槛去掉了大部分这类错误，但它只是单样本的不确定性代理。
2. **停顿变多来自更碎的文本到达。**

   | 方向 | 每条的写出块数 B / N / SVC / JM | 提前提交比例 B / N / SVC / JM |
   |---|---|---|---|
   | en2zh | 3.35 / 2.99 / 3.53 / 3.32 | 0.42 / 0.35 / 0.44 / 0.40 |
   | zh2en | 2.80 / 2.50 / 3.33 / 3.14 | 0.34 / 0.28 / 0.43 / 0.38 |

   - 每个提前提交的小段念完后，要等下一次提交（1 s 读取粒度）。与之前结论一致：停顿 = 文本到达，Talker 修不了。
   - dev 上 96% 以上的额外提交发生在播放队列已空时。所以"队列忙时不提交"不会减少错误；这些提交正是降低 LAAL 的那部分。
3. **zh2en 的 ASR 损失大于文本损失。**
   - RealSI clean：文本 −0.15，ASR −0.88（对 N）。
   - 碎片化的英文语音（断词、无后文韵律）让 ASR 出错。这部分损失在 Talker / 播放通道，不在译文。
4. **噪声下时延偏高。** 跨视角约束在噪声下切得更多：RealSI noisy 的 D2 仍比 B_b 晚 0.25–0.29 s。
5. **尾部偏长。** zh2en 仍有 62% 的词在最终读才产生，源语音结束后要念很多。
6. **缺一个关键对照。**
   - dev 子集（674 / 1412 条）上，"同一 Thinker + 纯 LA2（无跨视角）"为 39.10 / 26.29，写出时刻 4.008 / 4.443 s。
   - SVC-JM 为 39.44 / 26.78，写出时刻 4.006 / 4.455 s。即在纯 LA2 的时延下，BLEU 达到 N 的水平（N：39.45 / 26.87）。
   - 测试上还没有这个对照，所以还不能断言 SVC-JM 在质量–时延前沿之上。

## 4. 方案：Support–Determinacy Commit（SDC，支持–确定性分解的提交）

**核心思想：** 提交一个译文单元需要两件事。

- 它已被语音支持（SAP 已能估计）。
- 它在未来读取中不会被改写，即"确定性"。

把后者建模为草稿单元的**改写风险（hazard）/ 存活概率**，再做 Bayes 最优提交。现有策略都是这个框架里手工的存活估计器：

- LA2 = "草稿年龄 ≥ 1 读则存活"；
- CV-LA = "跨视角一致则存活"；
- SVC = "被支持则存活"；
- SVC-JM = "被支持且两模型都 > 0.5"。

SDC 用一个学到的、显式依赖草稿年龄（存在时长）的风险模型统一并超过它们。这也是 HSMM 显式时长建模真正适合的位置：放在提交决策的时长 / 风险上，而不是放在译者训练上（之前失败的位置）。

### 4.1 组件

1. **改写风险模型（新，轻量，译者冻结）：**
   - 数据：在开放 UniST 训练音频上跑冻结的 N（+ SAP）流式 rollout，记录每个草稿单元在之后每一读是否被改写，得到存活标签。
   - 不更新任何译者权重，不以别的模型输出为目标，所以不是蒸馏。
   - 特征：N 与 SAP 的 token 对数概率和 margin，到 SAP 停止点的距离（支持余量），跨视角是否一致，草稿年龄（已连续出现的读数），读取序号，距离上一个标点的单元数，raw / enh 两视角的熵差（噪声）。
   - 模型：离散时间风险模型 h(age | 特征)（小 MLP），存活概率 S = ∏(1 − h)。
2. **Bayes 最优提交：**
   - 提交最长前缀 k，使前缀上每个单元的 S_i ≥ θ（前缀存活的单调约束）。
   - θ 只取一个工作点：在 dev 上让语音 LAAL 等于 B_b（等时延工作点），不扫描测试。
   - 由此得到明确主张：在 B_b 的时延下，BLEU 达到或超过 N。
3. **噪声自适应：**
   - 跨视角不一致只作为风险特征，不再是硬切点。
   - 模型会学到哪些不一致才预示改写，噪声单元的时延应下降（针对问题 4）。
4. **流畅度（次要；停顿已放宽，但要报告）：**
   - 提交终点吸附到 SAP 停止点 / 标点处的短语边界。只在边界离 k 不超过 1 个单元时生效，几乎不增加 LAAL，用来减少 NC 和断词。
   - 针对问题 3（可选，需要改 Talker）：把未提交草稿作为不念出的韵律上下文喂给 Talker，减少碎片的韵律和断词。

### 4.2 为什么有理由期待它能工作

- 问题 1 的误提交与类型、位置无关，但与不确定性相关：JM 的 0.5 门槛已把 dev BLEU 损失从 −1.15 / −0.85 降到 −0.31 / −0.26。
- 一个直接用"是否存活"监督、并加入年龄 / 支持余量 / 视角特征的风险模型，是对这个信号的直接、校准的估计。
- dev 子集已显示 SVC-JM 在纯 LA2 时延下达到 N 的 BLEU。SDC 的目标是把这一点推广并稳定到测试集。

| 步骤 | 内容 | 时间 |
