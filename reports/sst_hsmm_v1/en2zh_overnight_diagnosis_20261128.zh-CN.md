# 夜间 8 轮 en2zh 全部失败的原因与解决方案（2026-11-28 早，只做分析）

- 数据：测试集已有输出，未新跑任何模型，只用 CPU。
- 脚本：`experiments/sst_hsmm_v1/en2zh_analysis/` 下的 a12–a15。
- 口径：官方归一化；离线上限 = wave17 读入完整音频的贪心解码（`ceiling/`，change 20）；"提前提交" = 非最终读写出的部分。

## 1. 是否全部失败

是。en2zh 上没有一个方法通过判定。不过失败分两类：

| 类型 | 方法 | en2zh ΔASR / ΔD2 / 连线 | 统计上 |
|---|---|---|---|
| 没过前置门槛 | B1、B2、C1、SAA（训练） | – | 整句离线 BLEU 已掉 0.9–5.7 |
| 有害 | HCG v2、HCG + B1 | −0.64 / −0.05 / −0.53；−0.63 / −0.08 / −0.46 | ASR CI 不含 0，显著变差 |
| 中性（落在原曲线上） | EGA、CCA、SAA 流式、HCD | −0.01…+0.06 | CI 都含 0 |

## 2. 原因

### 2.1 用词层：两个方向偏离 base 的程度一样，只有中文伤分

下表是提前提交文本的字（词）级精度。"vs 离线"是相对 wave17 离线上限，"vs 参考"是相对测试参考（a12）：

| 系统 | en2zh vs 离线 | en2zh vs 参考 | zh2en vs 离线 | zh2en vs 参考 |
|---|---|---|---|---|
| p3hk | 90.8 | 68.4 | 88.6 | 60.8 |
| HCG v2 | 84.3（−6.5） | **64.8（−3.6）** | 82.9（−5.7） | **60.8（±0）** |
| E1 | 84.6（−6.2） | 65.2（−3.2） | 81.1（−7.5） | 59.4（−1.4） |

- adapter 的用词偏离 base 的幅度，两个方向几乎一样（−6 左右）。差别在于：英文里这种偏离不影响参考命中，中文里会掉分。
- HCG en2zh 的损失全部在"提前文本和 p3hk 不同"的 1004 句里。把这些句子换回 p3hk 的输出，文本 BLEU 恢复 +2.09，ASR 恢复 +0.74，等于总损失。
- HCG v2 的候选池里只有 adapter 的候选，没有 base 候选。这是设计决定的：v1 冒烟时，base 自己的贪心候选在 26 读里赢了 25 读，方法退化成 base，所以 v2 把它拿掉（hcg_base_chosen = 0 因此是必然的；本报告初稿把它误写成数据结果，已更正）。结果是 HCG v2 实际是"adapter 的用词，由 base 重新排序"，摆脱不了 adapter 的语体。
- 语体来源：UniST en2zh 的中文是翻译体书面语，zh2en 一侧的中文是真人说的话。几个语体标志词如下（只用于诊断，不用于选择）：

  | 来源 | 觉得 : 认为 | 女人 : 女性 |
  |---|---|---|
  | UniST en2zh 中文译文 | 0.29 | 0.52 |
  | UniST zh2en 中文原话 | 0.85 | – |
  | 测试参考 | 0.69 | 1.00 |
  | wave17 离线 | – | 1.00 |
  | E1 | – | 0.28 |

- 训练期的修补都过不了前置门槛：中文同义词的概率接近并列，每个 token 0.02 nats 的偏移就让 45% 的句子换了词（C1）。B1 只修好了文本里的英文术语，ASR 没有变化，因为英文人名经过中文 TTS 再 ASR 本来就保不住。

### 2.2 时延层：保持 base 用词的方法只能沿原曲线移动

| 系统 | 提前份额 | 每字写出时间 Δ | 提前文本 vs 离线 | ΔASR | ΔD2 |
|---|---|---|---|---|---|
| p3hk | 0.499 | – | 90.8 | – | – |
| p3hk2（只降 θ） | 0.557 | −0.18 s | 88.4 | −0.50 | −0.24 |
| HCD | 0.549 | −0.14 s | 89.2 | −0.32 | −0.18 |
| CCA | 0.592 | −0.07 s | 90.2 | −0.06 | −0.06 |
| EGA | 0.497 | ≈0 | 90.7 | +0.04 | +0.02 |
| SAA 流式 | 0.481 | ≈0 | 90.6 | +0.09 | +0.04 |

- HCD 的提交统计几乎就是 p3hk2：每读提交 8.57 对 8.78 个单位；草稿和最终译文的一致前缀 11.46 对 11.50。也就是说，在 en2zh 上视野信号的效果约等于降低 θ。
- EGA / CCA 的预判尾部几乎从不被提交：每读只有 0.03–0.05 个单位超出 p3hk 草稿。HSMM 正确地拒绝提交还没听到的内容，所以尾部对时延不起作用。

### 2.3 已排除的解释

- **流式动态不同：** 排除。相邻两读之间草稿的变化类型在两个方向上几乎一样（a14）：
  - 只是变长：26.5% 对 20.2%；
  - 收尾改续写：8.8% 对 11.7%；
  - 同长换词：7.7% 对 8.5%；
  - 结构改写：34.8% 对 38.6%。
  草稿首次偏离最终译文时，属于"插入"（后听到的内容放到前面）的比例也相同（a13）：10.6% 对 9.0%。
- **adapter 更自信所以提交更多：** 排除。adapter 草稿的 token 置信度反而更低，前 8 个 token 平均对数概率 −0.88，base 是 −0.60。
- **TTS 正在说话时提交，语音时延吃不到收益：** 排除。85% 的提前文本在 TTS 空闲时写出（a15）。CCA 语音收益小，是因为它每个字的写出时间本身只提前了 0.07 s。

### 2.4 一句话结论

en2zh 的时延收益，只能靠 adapter 改写已听内容的用词来拿到；而 adapter 的中文用词来自 UniST 的翻译体书面语。收益和损失是同一件事。不碰用词的方法只能沿 p3hk 的时延-质量曲线移动。

## 3. 解决方案（都需要点头）

1. **反向配对训练 en2zh adapter（推荐，直接针对根因）**
   - 做法：把 UniST zh2en 的样本反过来用：UniST 自带的英文目标语音（由它的 BiCodec 码解码）作为输入，原始中文口语转写作为目标。中文目标是真人口语，语体天然匹配；仍是 UniST 数据，没有 teacher，也不碰测试集。
   - 其余不变：同一个双向 adapter，zh2en 一侧照旧；之后接 G0 → HCG 流式。
   - 前提：本地没有 `data/raw/UniST`，需要先从 S3 拉回编码，再解码约 2 万句英文语音。
   - 风险：输入是合成英文语音，和真人语音有域差。
   - 新颖性：属于"分析 + 修复"，可以和 HCG 合写。"原文方向数据"的思路在 MT 文献里已有，不能当独立的新方法。
   - 改的是训练数据的构造方式，需要你确认。
2. **HCG-open（不训练，便宜）**
   - 做法：候选集里加入"去掉句末收尾的 base 候选"，让贝叶斯分数在 adapter 用词更差时可以选 base 的用词。
   - 预期：en2zh 从 −0.53 回到 0 附近，zh2en 基本保住。目标是"同一方法、两个方向都不伤"；en2zh 大概率仍过不了判定。
3. **论文兜底**：en2zh 作为有分析的限制条件，部署前用 G0 门槛决定是否启用 adapter，不启用就退回 p3hk。

不建议继续做的（数据已否定）：
- 在 θ 或提交规则上再做文章：HCD 和 CCA 已显示 en2zh 就在原曲线上；
- 按 TTS 积压调整提交：只影响 5–7% 的提前文本；
- 只训似然比的 adapter：HCD 的损失不是用词泄漏，它的提前文本对参考精度 67.5，和 p3hk2 的 67.4 相同。
