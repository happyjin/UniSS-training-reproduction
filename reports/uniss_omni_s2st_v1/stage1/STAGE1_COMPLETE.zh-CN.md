## 一个贯穿整个阶段的教训

**dev 交叉熵与声学质量反相关,不能用来选检查点。**

```
iter 12,000   dev CE 6.857   语音 29.69 / 33.50
iter 24,000   dev CE 7.075   语音 33.78 / 33.92     ← CE 更差,音频更好
iter 40,000   dev CE ~7.3    语音 34.43 / 34.30
```

原因是 BiCodec 语义码**声学冗余**:不同码序列渲染出几乎一样的声音,
交叉熵惩罚"选了等价码",声码器听不出区别。

这件事误导了我三次 —— 详见 `DEV_CE_IS_NOT_THE_METRIC.zh-CN.md`。
**今后 dev CE 只作健康指示(发散/NaN),选择与验收一律用声学指标。**

## 期间修掉的缺陷

| # | 问题 | 性质 |
|---|---|---|
| 1 | 导出器把 Adam 一阶矩当权重(`.talker.` 子串匹配收进优化器状态) | 产出恒定输出的模型,音频是噪声 |
| 2 | 生成脚本加载了说话人前缀却从不传给解码函数 | 模型在缺失训练条件下运行 |
| 3 | `eval_iters` 超出 dev 容量 | 第一次验证即崩 |
| 4 | 验证集单遍耗尽 | 第二次验证崩 |
| 5 | 训练集单遍耗尽(一个 epoch 就停) | iteration 2,128 崩 |
| 6 | 两条病态长文本(2,000 token 配 468 码)触发 47 GiB 分配 | iteration 13,500 可复现 OOM |
| 7 | 分桶切在微批,8 个 rank 长度差 528,互相等待 | 利用率 62%,每步 502 ms |

1/2 都加了防再犯的检查(RMSNorm 体检、前缀未接入即报错)。
