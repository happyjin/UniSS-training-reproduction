# Stage 1 诊断:条件化项比码嵌入大 36 倍

**checkpoint** step 6000 · 64 条 CVSS-T dev · 均匀基线 ln(8193) = 9.011

## 先说一个我自己判断错的地方

第一版诊断把码流按"文本是否还在到达"切成两段,得到:

```
文本到达时     CE 9.179   (961 个位置)
文本耗尽后     CE 7.694   (17,609 个位置)
```

然后我准备据此说"Talker 在把文本当噪声"。**这个切法是错的** —— 它与位置混淆了:
文本到达的位置**恰好就是最靠前的位置**,那里同时也是自回归码历史最少的地方。
按偏移看的损失单调下降,只说明"上下文越多越好",说明不了文本的作用。

受控的做法是在**相同偏移**上消融文本:每一步都喂常量 pad 嵌入(尾部本来就是这样)。

## 受控对比

| offset | 带文本 | 文本消融 | 文本的净作用 |
|---|---|---|---|
| 0 | 5.60 | 11.82 | **−6.22** |
| 1 | 8.04 | 9.60 | −1.56 |
| 2 | 9.13 | 9.68 | −0.55 |
| 5 | 9.58 | 9.00 | **+0.58** |
| 10 | 9.11 | 8.38 | **+0.73** |
| 20 | 8.40 | 8.19 | +0.21 |
| 40 | 7.94 | 8.04 | −0.10 |
| 60+ | 7.63 | 7.80 | −0.17 |

结论与我原先的猜测**都不一样**:文本没有被忽略 —— 它在 offset 0 上值 6.22 nats,
在 offset 1 上值 1.56 nats,信息还能微弱地带到尾部(−0.17)。但在 **offset 5–20
区间,带上文本反而更差**。

## 为什么

量两个相加项的范数:

```
码嵌入行范数(Omni 原始码行)      4.781
Thinker 末层隐状态行范数          173.183     ← 36 倍
hidden + embed                    173.213     (embed 项范数 1.0,可忽略)
pad_embed / eos_embed 范数          0.508     ← 文本耗尽后加的东西
```

Talker 的 forward 是

```python
inputs_embeds   = embed_tokens(codec_ids) + thinker_reply_part[:, :1, :]
talker_lm_input = thinker_to_talker_proj(inputs_embeds)
```

两项**先相加再投影**。文本到达期间,被加进来的向量是码嵌入的 36 倍,"刚刚发出的是哪个码"
这一信息被压到信噪比 0.028;文本耗尽后加的是范数 0.508 的常量,码重新占主导 ——
这正是 offset 5–20 变差、之后单调变好的形状。

注意 offset 0 不矛盾:那一步**没有码历史可言**,全部信息本来就来自文本,所以文本
在那里值 6.22 nats。受损的是"既有文本又需要用码历史"的那一段。

## 这不是对 Omni 的偏离

相加的形式是 Omni 自己的(见 Stage 0 报告)。差别在于 Omni 的 Talker 与它的码本是
**联合训练**出来的,而我们把码行按 Omni 原尺度重画后,要让它们穿过一个**预训练且
尺度固定**的投影去和 36 倍大的文本项竞争。投影在 Stage 1 里是可训练的,但相加发生在
投影**之前**,线性映射无法把已经相加的两项重新分开 —— 只能在信噪比 0.028 的条件下
尽量提取。

## 可做的三件事(按代价排序)

1. **提高重画码行的尺度**,让两项可比。最小改动,`retarget_talker_codebook`
   已经有 `head_scale`,再加一个 embed 尺度参数即可。**代价:一次短训练对照。**
2. **归一化条件化项**(例如把 hidden 缩放到与码嵌入同量级)。偏离 Omni 构造,
   但直接消除不平衡。
3. **维持现状再训久一些。** 曲线确实还在降,但这一项不会随训练消失 ——
   它是初始化尺度与冻结投影共同决定的。

先让当前 Stage 1 跑完并做声学验收,再用 1 和 3 做等步数对照,而不是凭推理选。
